# ADR 0039：科目二围绕「练车日」组织，不沿用科目一的练习形式

- 日期：2026-09-28
- 状态：已接受
- 影响：`lib/subject2.dart` 重组为四个分区；新增 `lib/readiness.dart`（整场就绪度）、
  `lib/review.dart`（练车后复盘）；`lib/progress.dart` 库版本 8（`drill_notes` 表）
- 关系：在 ADR 0036、0037 之上重组界面，内容与数据不变；评判题（ADR 0036 第 2 节）
  从主入口降为「规则自测」

## 背景

ADR 0036、0037 做出了科目二的零件：动画讲解、评判题、练车错因、简报、点位卡、默演。
但界面是按科目一的思路搭的——「项目卡片 → 单项页 → 评判题」，骨子里是「知识点 + 题库」。

科目二不是这样学会的。它的真实节奏是**一次次线下练车**：车时有限，一天练几项、每项几把；
练完回家，错因和教练的话很快就忘；考前想知道这个水平能不能过。软件的主线应该是这个
循环，而不是题库。

## 决策

### 原则（写进 AGENTS.md）

科目二的界面围绕「练车日」组织：**练车前准备 → 练车后复盘 → 按练车日看趋势 → 考前判断
能不能过**。不套科目一的「阶段 / 章节 / 待练题数」；评判题是规则自测，不是主线。

### 四个分区

1. **练车日**（默认）：
   - 整场就绪度（见下）和距上次练车几天。
   - **练车前 5 分钟**：一个引导流程，对今日重点的每一项依次过点位卡、默演，走完即止。
   - **复盘今天**：练完一次性录入整天。先选今天练了哪几项；每项一张格子表——列是第几把
     （默认 3 把，可加减），行是这一项的错因加常见通用错因，点格子记错（按次计的可以点多次）；
     每一列实时显示这一把按考场规则的分数；每项可以记一段「教练说的话」。保存后每一把写成
     一条练车记录（ADR 0036），教练的话写进 `drill_notes`。原来的「记一把」对话框保留，
     用于只补一把的情况。
   - 今天已经记下的把数和结果。
2. **项目手册**：四项的动画、步骤、点位卡、标准原文、评判条目、经验要点（ADR 0036、0037），
   外加「教练说过」（最近几条教练的话）。
3. **练车日志**：按练车日分组（一天算一次练车），每天练了哪几项、各几把能过几把、教练说了
   什么；每项一条按练车日的能过比例折线，看是不是在进步。
4. **考前**：就绪度的拆解（每项最近能过的比例、平均扣分、最拖后腿的错因）；通用评判当作
   上车检查清单；规则自测（评判题）的掌握情况与入口；四项连起来默演一遍。

### 整场就绪度

GA 1026—2022 6.2.1：科目二**四项合在一起算一个总分**，满分 100、80 分合格；任何一项
不合格即不合格（5.2.1 c 当场终止）。所以单项能过不等于整场能过。

- 每项取最近 5 把（少于 3 把的项算「数据不够」，不给整场结论）。
- 把四项的记录做全组合（最多 5⁴ = 625 种），一种组合能过当且仅当没有不合格、四项扣分
  合计 ≤ 20。**整场能过的比例 = 能过的组合数 / 组合总数**。精确枚举、不抽样，同样的记录
  永远算出同一个数。
- 同时给出「最拖后腿的失分来源」：在不能过的组合里，哪一个错因出现得最多。
- 这是按最近练车表现的**估计**，不是预测考试结果；页面上照实说。

### 教练的话

- `drill_notes` 表（项目、内容、时间），库版本 7 → 8；同步事件 `drill_note`，按「项目 + 时间」
  去重。教练的话是原始记录，点位卡是自己整理过的——两者分开，项目手册里并排显示。

## 后果

- 科目二的首屏从「四张项目卡 + 练题按钮」变成「今天：准备 / 复盘 / 能不能过」。
- 复盘一次录完整天，替代「每把开一次对话框」，录入成本降到能坚持的程度。
- 就绪度依赖练车记录的完整度：只记坏的不记好的会偏低，只记好的会偏高——页面上提示「每把都记」。
- 一天算一次练车：同一天分上下午两次练车会被并成一次，目前可以接受。
