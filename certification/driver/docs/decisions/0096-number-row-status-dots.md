# ADR 0096：易混数字每行标作答状态点——答错红、没全掌握黄、掌握绿、没做过灰

- 日期：2026-10-05
- 状态：已接受
- 影响：`lib/home.dart`（行首微点 `RecallRowDot`、行 → 自测卡题号映射与状态判定）、
  `test/numbers_page_test.dart`
- 关系：延续 0077 决策 3（速记格子上的掌握度微点）到易混数字的行级；口径依赖 0094
  （自测并入作答记录，每张速记卡是有编号的题）与 0095（每行拆条、正向加反向卡）；
  掌握与答错只读作答记录（0020、0052），不新增任何判分

## 背景

0095 之后易混数字自测每行拆条、每个数值再出反向卡，作答全部进作答记录。使用者要求在
页面上直接看见每一行的状态：点开自测之前就知道哪几行答错过、哪几行还没碰过，而不是
进自测才知道。

## 决策

1. **每行左侧加状态微点**，视觉与速记格子上的微点同族（ADR 0077 决策 3）：
   红 = 最近答错过且未掌握；黄 = 答过但没全掌握；绿 = 掌握（最近一次答对）；
   灰 = 没作答过。悬停有文字说明。
2. **口径是这一行自己的自测卡**：每条情形一张填数/选择卡（`f/`）加这个值一张反向卡
   （`r/`），题号由行数据按 0094/0095 的同一规则构造。不拿组级关联真题当依据——
   那会把同组其他行的答题历史错标到这一行头上；反向卡按值合并、被同值的行共享，
   是这个口径下唯一有意共享的部分。
3. **状态判定只读作答记录**：`byQuestion` 里没记录 → 灰；任一卡最近答错且不在掌握
   集合 → 红；所有卡都在掌握集合 → 绿；其余 → 黄。掌握 = 最近一次答对（0020）。

## 取舍

- 只做易混数字：要点类三页的「行」是情景（没有反向卡与数值键），直接套这套映射要另定
  键口径，等有同样的需求再做。
- 微点没做「连对天数/间隔到期」这类高级状态：页面上还有组级「练这组 N 题」与自测入口，
  行级微点的职责就是回答「这行我碰过没有、最近对不对」。

## 验收

- `test/numbers_page_test.dart`：第一行 seed 答错 → 红；第二行 seed 正向答对（反向
  没答）→ 黄；第三行不 seed → 灰。
- `flutter analyze` 通过。
