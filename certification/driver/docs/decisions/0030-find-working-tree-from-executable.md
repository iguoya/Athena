# ADR 0030：直接点开调试包也认得出工作树，一台机器只有一份进度库

- 日期：2026-09-28
- 状态：已接受
- 影响：`lib/app_root.dart`（新）、`lib/progress.dart`、`lib/content.dart`
- 关系：补主仓库 ADR 0053（进度随仓库走）的一个漏洞；ADR 0010 的文件夹同步规则不变

## 背景

应用判断自己在不在工作树里，只看两处：`ATHENA_DRIVER_ROOT` 和当前目录下有没有
`app.json`。从启动器或 `run_dev.py` 起的都满足；但从程序坞、访达或资源管理器
直接点开 `build/` 下的调试包时，两处都没有——当前目录是 `/`。于是这个窗口：

- 进度库退回用户数据目录 `AthenaDriver/learning.db`，跟仓库里的 `progress/learning.db`
  分成两份；
- 题库退回编进包里的 assets，是上次构建时的旧副本。

两份库在同一台机器上，设备名一样，文件夹同步时写的是同一个 `driver-progress-<设备>.jsonl`，
而同步只在启动和每 15 分钟有活动时跑一次。一个窗口关掉之前没赶上同步，它最后答的题就
只留在它自己那份库里。实际发生过：灯光使用答了 71 次，换一个入口打开，这些题全显示没答过。

## 决策

1. 新增 `workingTreeRoot()`：依次看 `ATHENA_DRIVER_ROOT`、当前目录、**可执行文件所在目录
   往上的各级**，第一个同时有 `app.json` 和 `content/` 的就是应用根。调试包就在
   `subjects/driver/build/` 下面，三个平台都能往上找到；拷到别处的发行副本找不到，照旧用
   用户数据目录。
2. 进度库路径和题库读取都走这一个函数，不再各写一套判断。
3. 已经分出去的那份库，一次性按同步的规则（题号 + 时间去重）并回仓库那份；用户数据目录
   那份不删，留作备份。

## 后果

- 同一台机器不管从哪个入口打开，读写的都是仓库里那一份进度库，看到的都是工作树里的题库。
- 用户数据目录那份库只有真正的发行副本才会用到。
- 不靠「退出时补一次同步」来兜底：进程被强杀时退出钩子不会跑，只有「本来就是同一份库」
  才可靠。
