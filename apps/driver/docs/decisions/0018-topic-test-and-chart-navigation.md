# ADR 0018：补一个章节测试入口，图表点一下能跳转

- 日期：2026-09-20
- 状态：**部分撤销**（第 1、2 条已在同日撤销，见文末「后续：撤销章节测试」；
  第 3 条图表点击跳转也在同日撤销，见 ADR 0015 之后的调整——图表恢复纯展示）
- 影响：`lib/home.dart`、`lib/look.dart`
- 关系：复用 ADR 0016 的模拟考草稿续答机制；跟 ADR 0015 的章节正确率图表是
  同一块界面的延伸

## 背景

练习入口之前只有两层粒度：「本阶段练习/本阶段测试」（一整个阶段）和「章节练习」
（单个章节，但只有练习，没有计时判分的测试）。想单独检验某一章学得怎么样，
只能练，练习是随时可停、答完立刻揭晓的日常刷题，没法像模拟考、阶段测试那样
一次性拿一个分数出来。

另外，ADR 0015 加的「各章节正确率」图表只能看，点了没反应——找到最弱的章节后
还得自己去下面的章节列表里找同名那一行再点，多一道手续。

## 决策

1. **加`_startTopicTest(subject, topic)`**，跟 `_startPhaseTest`同一个模式：
   题源换成 `_openTopic(subject, topic)`（单章节），配题量按
   `phaseExamRules(subject.exam, questions.length)` 折算，计时、交卷才判分，
   同样接入 ADR 0016 的草稿续答（`draftKey` 用
   `"<subjectId>.topic.<topicId>"`，用点号分隔和阶段测试的 `.phase<N>`
   区分开，不会互相覆盖）。
2. **章节列表每一行加一个计时器图标按钮**（`_topicRow`），点整行是练习（原有
   行为不变），点这个按钮是测试——两个入口并存，没有互相替代。
3. **`TopicAccuracyChart` 加一个可选的 `onTap(index)`**：传了就把每一行包一层
   `InkWell`，不传保持纯展示（其他调用方不受影响）。点一行直接跳去练那个
   章节——图表数据本来就是排好序的（正确率从低到高），点最上面那行就是
   「去补最弱的那一章」，不用先记名字再去列表里找。

## 后果

- 图表的点击目标是「练习」，不是「测试」——找到弱项应该先巩固知识点，
  用测试检验是练完之后的事，两者顺序不能反。
- `TopicAccuracyChart` 从纯展示组件变成可选带交互的组件，`look.dart` 因此第一次
  出现「点击回调穿到业务逻辑」的模式；这个回调只传下标，不传 `Topic` 对象本身，
  `look.dart` 依旧不需要认识 `Topic` 类型。

## 后续：撤销章节测试（同日）

用了一轮就发现不对：章节测试沿用阶段测试的抽题逻辑，`phaseExamRules` 会尝试凑够
`subject.exam.questionCount`（GA 1026 定的 100 题）——对一整个阶段合理，对一个
章节就离谱，一个章节的题往往远不到 100 道。更根本的问题是使用者的心智模型里
「测试」就该是「科目一综合测试」那个量级（模拟考、阶段测试），章节这一级只需要
练习，不需要单独一份计时判分的成绩。

按钮出现后还带来两个真实的连带问题：一是这个图标按钮离「点整行去练习」的点击
区太近，好几次手滑点成了测试，一旦点开又没有退出机制（这一点后来在 ADR 0019
里单独补了退出按钮和二次确认，但问题的根子还是这个功能本身不该有）；二是章节
测试交卷会把这些题记成「已作答」，答对了就直接计入掌握度，如果手滑进的测试还
稀里糊涂交了卷，会在没打算复习完的情况下改变实际的掌握度和解锁进度，跟使用者
的预期完全对不上。

**处理**：删掉 `_startTopicTest`、`_topicRow` 里的测试按钮、`_topicHead` 里对应
的占位空间。章节这一级恢复到只有「点整行去练习」一条路。

**同日进一步收窄**：连「阶段」这一级的测试也一并撤销了——使用者明确要求「测试
只保留在全科情况」，即整个科目一的模拟考才算「测试」，阶段和章节都只有练习。
删掉 `_startPhaseTest`、侧栏和概览页的「本阶段测试」入口；`phaseExamRules`
这个函数留着不动，因为它被 `test/exam_test.dart`、`test/phase_test.dart` 里
既有的用例直接测试，属于今天改动之外的另一批工作，删掉会破坏那批用例。
ADR 0019 加的「开考前确认、考试中途能退出」两条安全网继续保留，现在只套用在
模拟考这一个入口上。
