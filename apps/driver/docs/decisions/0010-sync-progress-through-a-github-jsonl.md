# ADR 0010：跨机器同步走 GitHub 私有仓库里的一个 JSONL 事件流

- 日期：2026-09-17
- 状态：已接受
- 影响：`lib/progress.dart`、`lib/sync.dart`、`lib/home.dart`、`pubspec.yaml`
- 关系：在仓库级 ADR 0053（进度随仓库走）之上加一条设备之间的通道，不替代它；
  只管 `apps/driver` 自己的进度，不做成跨应用的共用设施（仓库级 ADR 0032、0037）

## 背景

使用者有两台 macOS：一台是开发机，在工作树里跑；另一台只拷了一个打包好的
`.app`。进度库是 SQLite 二进制文件，这带来两个问题：

- **`.app` 那台没有 git**，仓库级 ADR 0053 的「进度随仓库走」够不到它；
- **二进制文件没法合并**：两台各练各的之后只能二选一，留哪份都丢记录。

先考虑过直接把 `.db` 丢进网盘同步，但那等于把「二选一」问题搬了个地方。

## 决策

1. **认清数据的形状：作答记录是只追加的事件流。** `attempts`、`exams`、
   `achievements` 都只增不改，两台设备的合并就是**并集**，没有并发改同一行的
   情况，也就不需要事务型数据库、不需要冲突解决算法。据此**不引入任何数据库
   服务**（Turso、D1、Supabase 一概不用），只需要一个可靠的同步点。
2. **同步格式用 JSONL**：一行一个事件。追加只在文件末尾加行；合并是拼接后按
   主键去重、按时间排序；坏掉一行跳过它不影响其余；git 和 HTTP 的增量传输也只
   走新增的那几行。
3. **落点是 GitHub 上一个私有仓库里的一个文件**，走 REST Contents API
   （`GET`/`PUT /repos/{owner}/{repo}/contents/{path}`）。选它而不是 git 命令，
   是因为**不能假设机器上有 git**——只拷 `.app` 的那台就没有。
4. **合并的主键**：`attempts` 用 `(question_id, at)`，`exams` 用
   `(subject_id, at)`，`achievements` 用 `key`。`notices` 是这些记录派生出来的
   提醒，不同步。
5. **冲突用 sha 做乐观锁**：`PUT` 带上刚读到的文件 sha，远端在这中间被另一台改过
   就会被拒（409/422），此时重新拉取、重新合并、再推，最多重试两次。
6. **令牌存在本机**：`<用户数据目录>/sync.json`，权限 600，不进版本库；在应用内
   的「跨机器同步」页配置。用 fine-grained token，权限只给这一个仓库的 Contents
   读写。
7. **本地 SQLite 仍是唯一的读写来源**。同步是把远端事件并进本地、再把本地的推
   出去；断网时应用照常用，联网了自己追上。

## 后果

- 工作树里的 `progress/learning.db` 保持不变，仍随仓库走（ADR 0053）——开发机
  上它是本地权威，云端 JSONL 只负责设备之间流转。两条路都在，互不冲突。
- 多了一个运行时依赖（`http`）和一个外部可达性假设（GitHub）。使用者明确表示
  网络稳定性由他自己负责，因此不为「连不上」写降级路径，只在界面上如实报错。
- 换落点的成本很低：事件流与合并规则都在 `progress.dart` 里，`sync.dart` 只是
  一个传输实现。将来要换 Gitee、坚果云 WebDAV 或别的，重写传输层即可。
- 这套东西只服务 `apps/driver`。别的应用要同步进度，各自照这个思路做自己的，
  不共用实现——共用会立刻把独立的应用绑在一起。
