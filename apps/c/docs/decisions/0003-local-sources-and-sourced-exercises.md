# ADR 0003：教材落到本地；教案和题目必须有所本

- 日期：2026-09-14
- 状态：已接受
- 依赖：ADR 0002；对齐主程序 ADR 0031 / 随堂考核，以及英语应用 ADR 0008
- 修正：写课「自由发挥」——可以发挥的是 QML 内存条和对照怎么画，不是知识体系和题干

## 背景

ADR 0002 规定章序跟 Beej，节点带 `source_refs`。但参考材料还在网上，写课、出题
时仍容易凭印象补一句，把本机端序讲成 C 的保证。作者随后明确：公开能查到、
写课用得上的教材和习题线索要下到本地，实时对照；教程、随堂、课后都要有所本，
在吸收主程序 C++ 课的教学优势之后，才轮到 C 自己的表达。

主程序已经做对、本应用必须先接上的是：

| 优势 | 主程序怎么做 | 本应用怎么接 |
|---|---|---|
| 三层分工 | 大纲只指方向，过程落实，实验给证据 | 章大纲 / QML 教案 / 实验台 |
| 知识类型 | 概念用正反例，技能用示范加变式 | 已写两节都是概念：对照 + 内存条 |
| 活的路线图 | `requires` / 难度 / 掌握目标画出来，点节点跳 | 首页章图、章内知识点图 |
| 先猜再看 | 预测控件，再给证据 | Callout「先猜再点」 |
| 随堂考核 | 多题、有解析、难度与掌握目标分标 | `Checkpoint.qml` + `exercises.json` |
| 篇幅匹配 | 难度 1 不写成长文 | 已写节保持短 |

C 自己再发挥的部分：内存条、地址箭头、playground 里真实的 C 程序。这些不替代
Beej / DIS 的命题，只负责让那条命题能被看见。

## 决策

1. **公开教材落到 `content/sources/reference/`。** 登记在 `catalog.json` 的
   `local_path`。Beej 源稿允许私下镜像，进仓库；DIS 原样保存 HTML（NC-ND，
   教案不派生其正文）；c-faq 只供本机查阅、HTML 不进 git；Modern C 的 PDF
   从官网手动另存。刷新用 `scripts/fetch-sources.sh`。
2. **教案、随堂、课后每条都有 `source_refs`。** 题库在 `content/exercises.json`，
   按知识点 ID 分成 `in_class` 与 `homework`。题干用中文改写该节事实，不整段
   复制 NC-ND 正文。对不上节号的题不要写。
3. **随堂考核对齐主程序 `CheckpointView`。** 多题、点选后给「为什么」、标难度
   和掌握目标、解析里写出来源。进度库未接前只当场计分。讲解中的「先猜再点」
   仍是单次预测，不算考核。
4. **先吸收上表里的 C++ 优势，再画 C 的图。** 新节不得用内存条发明一条教材里
   没有的规则。本机示意必须写明「这台机器」，不能写成语言保证。
5. **语义基准是 C23，见 ADR 0004。** 教材与标准冲突时两边都引用，以 C23 为准。

## 后果

- 写新节的顺序是：打开本地教材对应文件 → 核对该讲什么 → 写 QML → 按同一节出题。
- 「对象是一段字节」这类从 C++ 课类比出来的说法，只在 Beej §5.1 实际覆盖的范围内用。
- c-faq 的 HTML 被 gitignore；克隆仓库后要跑一次 `fetch-sources.sh` 才能离线翻误区。
