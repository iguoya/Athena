# Athena C — 项目协作规则

本文档是 **`apps/c` 独立应用** 的项目级指令。本应用与 Athena 主程序
（GTK / Meson）**平级、可脱离**。改本应用时以本文为准。

## 定位

- 目标：把 C 语言教成「看见内存」——对象有地址和大小，指针存的是地址。
- **教案用 QML 写**（ADR 0042），不是启动一个演示用的 C 程序。
- 原 LVGL 小程序保留在 `playground/`，需要时单独构建，**不是**图谱入口。

## 向主程序 C++ 课学什么、不抄什么

C++ 分类页的知识图谱节点是**章**（类型与表达式、引用、RAII……），不是知识点。
点进一章之后，大纲里才有该章的知识点路线图；教案从那张图点进来。

C 语言应用对齐的是这套**分层**，不是把几个知识点直接铺成首页：

| 层 | 主程序 C++ | 本应用 |
|---|---|---|
| 知识图谱 | 分类下的章节卡片 + `prerequisites` | 首页七章 + `prerequisites` |
| 教学大纲 | 章内第一标签：方向 + 知识点路线图 | 点章之后：同一件事 |
| 教学过程 | 其余标签 | 章内路线图点白卡片才进入 |
| 教学实验 | 课程类成员函数 | 实验台拉起 `playground/` |

不抄 TypeSemantics 的节标题，也不把 C++ 的引用/RAII/模板再讲一遍。C 的章是从
「对象是一段字节」这条脊长出来的，落点写清和 C++ 哪一章接、哪一句不重讲。

## 技术栈

- **壳**：Qt 6 Quick / Qml（C++20）
- **教案**：`qml/lessons/*.qml` + 共用组件 `qml/components/`
- **课表**：`content/curriculum.json`（章、先修、难度、指向哪份 QML）
- **进度**：后续自建库，前缀 `c.`（ADR 0037）；本期先把课写出来

不引入主程序的 Meson、gtkmm、Blueprint。也不用 Tauri。

## 目录

| 路径 | 职责 |
|---|---|
| `qml/pages/GraphPage.qml` | 首页**章**知识图谱 |
| `qml/pages/OutlinePage.qml` | 一章的教学大纲 + 该章知识点路线图 |
| `qml/lessons/` | 各节教学过程 |
| `qml/components/` | 章卡片、知识点节点、大纲区块、对照、内存条 |
| `content/curriculum.json` | 章与知识点导航 |
| `src/` | C++ 壳：读课表、从磁盘加载 QML、监视文件热加载 |
| `scripts/dev.sh` | 日常入口；主程序图谱也 spawn 这份 |
| `playground/` | 保留的 LVGL 小程序，不从图谱启动 |
| `app.json` | 仅供主程序发现 |

## 开发

```sh
cd apps/c
./scripts/dev.sh
```

改 QML / `curriculum.json` 保存后窗口会自己重新加载。只有改 `src/` 才需要
让脚本再编一次 C++。本机需要 Qt 6（Homebrew `qt@6`）。

不要把产物装进 `/Applications`，也不要把 LVGL 小程序当成教学入口。

## 编写教案

1. **首页只画章。** 节点是 `chapters[]`，箭头是 `prerequisites`，配色是章的难度。
   「学习主干」是对象 → 指针 → 数组 / 堆这条脊。灰章是还没有写成的教案，仍可点进大纲。
2. **点章进入大纲**，大纲只指方向：一句题注 + 五节（痛点、模型、边界、判断、落点）。
   节叫什么由本章知识点决定。知识点路线图画在「先看主次与顺序」里，点白卡片进教案。
3. **各节教学过程**写在 `qml/lessons/`：正反例、内存条、callout、先猜再看。
   不要把大纲五段再贴进每一节。
4. **实验台**打开 `playground/` 里保留的小程序（若已构建）；教案里的内存条是讲解，不是实验替代品。

知识点 ID 以 `c.` 开头。篇幅跟 `difficulty` / `mastery_goal` 匹配。
