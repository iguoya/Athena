# ADR 0010：初级题库先达到可持续练习规模；大题库按短回合加载

- 日期：2026-09-15
- 状态：已接受
- 依赖：ADR 0004、0006、0007、0009

## 背景

初级路线已经能运行，但此前只有 16 个词、10 道例句、2 道英译汉、3 道开放写作和
15 道独立考核。这个数量足以验证流程，不能支撑持续学习。另一方面，直接把数百题
塞进一轮练习会让题目列表和完成反馈失去意义；把作者侧的完整参考词表打进浏览器预览
也会无谓增加构建体积。

进度、错题和考核结果已经写入本机 SQLite。静态课程内容仍需要便于审阅、比较来源和
版本控制；在当前规模下，迁入数据库不能带来可感知的运行收益，反而会增加导入和迁移
路径。

## 决策

1. 初级第一阶段基线为：300 个独立词汇、120 道例句轨练习、其中至少 60 道英译汉、
   30 道短文、30 道开放写作；独立考核至少为词汇 30、例句 30、写作判断 20。
2. `content/curriculum.json` 的一条轨可以继续使用单个 `deck`，也可以使用按顺序合并的
   `decks`。所有单元必须共享同一个 `topic_id` 和 `kind`，进度仍按稳定题目 ID 记录。
3. 普通练习每轮最多 20 个基础条目；跨轨到期复习每轮最多 30 个。排序仍是错题和到期题
   优先，其次才是新内容。从错题本进入时，目标题放在本轮第一题。
4. `scripts/expand-beginner-content.mjs` 是作者工具：从仓库内已经保存的 NGSL、双语句库和
   VOA 原文生成可审阅的普通 JSON。相同输入必须得到相同输出；运行时不执行生成器，
   生成结果随内容一起版本化。
5. 词汇题只有在例句译文能明确支持本句核心义时才投放；多义词的其他常见义优先作为
   干扰项。短文必须保留连续语境，不把作者署名、来源行或残缺引号当正文。
6. 浏览器预览只打包课表、正式练习、考核和来源目录，不打包
   `content/sources/reference/` 下的作者侧原件。桌面端仍从应用内容目录读取正式题库。
7. 继续保持“JSON 是课程内容源，SQLite 是学习状态库”。只有题库进入数万条、出现跨库
   检索需求，或实测启动与筛选成为瓶颈时，才增加由 JSON 构建的 SQLite 索引缓存；缓存
   不成为新的内容权威。

## 后果

- 内容可以继续按单元增长，不需要把一条轨维护成一个超大文件。
- 首页覆盖率以整条轨合并后的题数计算，一轮练习只处理其中一个短回合。
- `npm run check:content` 除结构、来源和考核隔离外，也会拒绝初级题量退回样本规模。
- 数量基线只是最低门槛；抽样语义审查和真实练习体验仍然决定内容是否可用。
