# 与 apps/cpp 的边界和衔接

两个应用都用 C++，内容却不该重叠。这份文档说明边界划在哪，以及写到重叠地带的
章节时怎么和 `apps/cpp` 衔接。

## 边界：看教的是什么，不看用什么语言写

- **`apps/cpp` 教 C++ 语言和标准库的语义**：`unordered_map` 的哈希桶怎么组织、
  负载因子何时触发重哈希、`vector` 扩容让哪些迭代器失效、比较器为什么必须满足
  严格弱序。学完知道**怎么正确地用**这些工具。
- **`apps/dsa` 教手写实现与代价直觉**：自己写一个哈希表并处理冲突、自己写快排
  并分析最坏情况、自己改接链表指针。学完知道**它们内部为什么长这样**、代价从
  哪来。

数据结构与算法原本是 `apps/cpp/resources/athena.json` 里的分类 `da`，23 章里
22 章没有知识点，在提交 `b534cfb` 里删掉，改由本应用承载；首页学科图谱的 `da`
节点是 `ExternalApp` + `app_id: "dsa"`，点击直接启动本应用。设计模式后来走了
同一条路（`apps/design-patterns/`）。所以**本应用是这个领域的唯一承载者**，
不必顾虑 `apps/cpp` 那边还留着什么。

## 重叠地带的衔接

下面几章有对应的 C++ 标准库知识已经在 `apps/cpp` 讲过。写这些章时，标准库的
用法**不用重讲**，但值得拿来做一次对照——"你手写的这个，标准库是怎么选的"
往往比再讲一遍实现更有价值。

| 本应用的章 | `apps/cpp` 已覆盖 | 可以怎么衔接 |
|---|---|---|
| 线性结构（数组 → 链表 → 栈队列） | `STLContainer.sequential_container`：`vector` / `deque` / `list` 的内存布局与复杂度差异、迭代器失效规则 | 手写顺序表之后对照 `vector` 的扩容策略：为什么是倍增而不是每次加一 |
| 哈希表 | `STLContainer.unordered_container`：哈希桶结构、负载因子与重哈希、自定义类型要同时给 hash 和相等比较 | 手写拉链法之后对照标准库：为什么它选链地址而不是开放定址 |
| 树与堆 | `STLContainer.associative_container`：`map` / `set` 基于红黑树的有序语义、对数复杂度、`operator[]` 会默认插入 | 手写 BST 退化成链表之后，说明红黑树在补什么 |
| 排序与查找 | `STLAlgorithm.sorting` / `finding`：`sort` / `stable_sort`、比较器的严格弱序要求、二分查找相关算法 | 手写快排之后对照 introsort：标准库怎么处理最坏情况 |
| 遍历与迭代 | `IteratorRange`：迭代器抽象、范围 for 的引用语义、Ranges 与视图的惰性求值 | 给自写结构加 `begin` / `end` 之后，范围 for 就能直接用——这是最短的"抽象值不值"的证据 |

图、算法范式（分治 / 贪心 / 动态规划 / 回溯）在 `apps/cpp` 没有对应内容，
不存在衔接问题。

## 不要做的事

- **不要为了衔接去读 `apps/cpp` 的配置或源码。** 应用之间不互相引用路径、不读
  对方的内容配置（仓库 `AGENTS.md`）。这份文档就是为了让衔接不需要那么做——
  内容有变动时更新它。
- **不要把标准库用法搬过来当自己的知识点。** 那是 `apps/cpp` 的地盘，两边各写
  一份迟早漂移。需要时在讲解里提一句并说明"那边讲得更细"即可。
