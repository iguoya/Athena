# ADR 0004：体系地图与实操地图并立

- 日期：2026-09-15
- 状态：已接受
- 替代：无（补充 ADR 0001，不修改其取舍准则）

## 背景

首版七张地图把航天软硬融合工程的能力先后、边界和验证方式画清楚了。它们适合
用来判断「为什么先学这个、它在系统里承担什么」。但节点上的 `practice` 仍停在
能力描述层：能说出要做一条有界队列或一次 100 Hz 循环，却没有指向一本买得到的
书、一门课、一块开发板或一套开源方案。普通开发者无法据此开始动手。

把具体教材和产品名写进原图，会把体系地图变成某一年的书单，也违反 ADR 0001：
框架、开源项目和招聘词不能反向定义主干。删掉原图、只留操作步骤，又会失去已经
成立的大方向。

## 决策

1. **两套地图并存，互为投影，互不替换。** `family` 为 `system` 的是体系地图，
   继续承载能力结构、强先修和投入优先级；`family` 为 `playbook` 的是实操地图，
   每个节点必须能回答：读什么、用什么、交出什么。同一能力域用 `companion_map`
   成对指向对方。
2. **实操节点用 `orients` 指向体系节点，不是跨图 `requires`。** 强先修仍只允许
   出现在同一张图内（ADR 0002）。实操图可以因「今晚能买到、能装上」而调整顺序，
   例如地面仿真不必先打 PREEMPT_RT 内核补丁。
3. **实操节点必须带 `kit`。** `reading` 写可获得的书、官方教程或高校公开课的
   具体章节；`tooling` 写可安装的软件或可采购的板卡/仪器；`artifact` 写可检查
   的交付物。来源目录新增教材、官方入门和可采购硬件，种类仍不得压过体系地图
   的取舍。
4. **具体方案是当前可走的路，不是定义。** 把 CSAPP、Nucleo、Yamcs、JSBSim、
   F' 写进实操图，是因为今天能找到、能复现；它们可以被同等能力的其他书或工具
   替换，但不能把体系地图改写成这些产品的功能列表。开源飞控只作 GNC/HIL 样本。
5. 实操图同样遵守 `priority_tiers`：主干只走大众能完成的路径。热门框架、贵重
   仪器或小众硬件放在 `growth` / `specialist`，并用 `enables` 或 `optional`
   连接；不得让大众主干 `requires` 一条专题装备。

## 后果

- Atlas 以成对的体系图与实操图展示。侧栏按 `emphasis` 分组：体系主干、助力方向、
  主干实操、重要参考（十七所实时控制）、相邻参考（机器人）。数量随 ADR 0005。
  详情面板在实操节点上优先给出阅读、工具和交付物。
- 内容维护成本上升：改体系节点时要检查对应实操是否仍可执行；改书或工具版本时
  不得偷偷改体系主干。
- 校验器拒绝：缺 `family`、成对 `companion_map` 不一致、实操节点无 `kit`、
  `orients` 指向不存在或非体系节点、体系节点携带 `kit`。
