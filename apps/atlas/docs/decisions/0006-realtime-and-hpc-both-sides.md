# ADR 0006：以实时与高性能计算约束软、硬件两侧

- 日期：2026-09-15
- 状态：已接受
- 补充：ADR 0001 第 7 条、ADR 0005 的院所取舍

## 背景

二院数字后端、三院飞控/仿真、四院试车测控，公开技能清单里反复出现的不是「会写业务
代码」或「峰值算力很大」，而是两件必须同时成立的事：

- **实时**：周期、截止期、最大抖动、中断与调度、最坏执行时间；用最大值验收，不用
  平均帧率。
- **高性能计算**：在给定时限内搬完、算完数据——吞吐、带宽、流水线、DMA、缓存与
  异构分工；报端到端延迟及分段占比。

只强调软件调度，硬件通路会拖垮周期；只堆 FPGA/GPU，软件没有截止期和背压，系统
同样不可用。大模型若留下，也只允许在地面用可测量的推理延迟/吞吐助力试验与文档，
不得占用弹上实时闭环。

## 决策

1. **实时与高性能是软、硬件双侧的同一条约束，不是两张兴趣图。** 软件侧必须能指出
   任务优先级、最坏延迟、队列深度和超期处置；硬件侧必须能指出时钟、总线带宽、
   流水线填充、存储层次和背压。缺一侧，节点不能进主干。
2. 每张主干图的闭环验收至少包含一次**时间测量**（截止期/抖动/时间戳对齐）和一次
   **计算/搬运测量**（吞吐、分段延迟、丢数）。GNC 与半实物按控制周期的最坏值验收；
   探测数字后端按流水线延迟与采样率验收。
3. 软件高性能不等于互联网吞吐优化：禁止用平均 QPS 替代飞控周期；禁止无限堆内存；
   有界队列、静态分配、DMA/零拷贝优先于「先跑通再改」。
4. 硬件高性能不等于堆芯片：FPGA/DSP/Zynq 必须服务实时数据通路或地面可测加速；
   没有时间预算的峰值 TOP 不进主干。
5. **实时控制的院所对照是四院十七所。** 软件截止期（飞控任务调度、最坏抖动）和
   硬件通路（电气时序、总线、对准与执行窗口）必须同时出现在十七所参考图和主干
   GNC/嵌入式/测发控节点上；缺一侧不能称为「十七所意义上的实时控制」。
6. 大模型助力图必须给出地面推理的延迟与资源边界，并写明与实时飞控隔离。

## 后果

- 实操节点的 `kit.artifact` 应能看出最坏延迟或吞吐数字，而不是「程序能跑」。
- 开源飞控、TensorRT、llama.cpp 只作为测量样本，不定义实时语义。
