# ADR 0012：Atlas 是其他学习应用的路线图与指南针

- 日期：2026-09-20
- 状态：已接受
- 相关：ADR 0001（取舍的远方仍是航天软硬融合）、ADR 0010 / 0011（两章完整学科图）、ADR 0013（桌面表达与可视化实验）、仓库级 ADR 0032 / 0045（各应用平级、可脱离）、仓库级 ADR 0054（宁增勿删）

## 背景

Athena 里已经有多块能练细节的地方：C++、C、数据结构、数学、英语、驾考。缺的不是又一本教程，而是一张能回答下面这些问题的图：

- 我现在站在哪一门学科里，这门学科在全局里干什么？
- 为什么必须学它，而不是跳过直接去学某一门语言或某一块板？
- 学完能掌握什么能力，能交出哪一类技术产出？
- 下一步该进哪一个学习应用，而不是在细节里迷路？

如果 Atlas 自己再去写寄存器、API、某颗芯片的操作步骤，它就会变成第八本教程，和其他应用抢同一件事，工程师仍然没有大局意识——只是多了一个地方背细节。

反过来，如果图上只有技能名词、没有「必要性 / 能力 / 产出」，它又会退化成词云：看起来什么都有，却指不出这门学科学完的人能造什么。

## 决策

1. **Atlas 的职责是指路，不是授课。** 它是其他学习应用的路线图、大方向和指南针：让人先看见学科全景、主次和去向，再决定进哪一个应用练细节。它继续不是课程播放器、不是题库、不是启动器。各应用仍然平级、可脱离（仓库级 ADR 0032 / 0045）；Atlas 只指出「这个能力由哪一类学习承载」，不代替那门课把内容讲完。

2. **要培养的是技术工程师的大局意识。** 读完一张图，人应该能说出：这门学科解决哪一类问题、缺了它全局会断在哪里、学完能判断什么 / 设计什么 / 交付什么。不要求读完就能写下一行代码或焊好一块板——那是下游应用的事。

3. **只着眼大局和全局，忽略具体技术细节。** 节点正文回答三件事，而且只强调这三件：
   - **必要性**：为什么这门学科（或这个能力域）必须学；缺了它，计算机或电子信息的培养目标和实现目标会少哪一块。
   - **能力**：通过这门学科学习能掌握什么——能判断什么、能设计什么、能把哪些部分协调成系统。
   - **产出**：学成之后能造出哪一类技术成果（一类程序系统、一类电子装置、一类可验证的闭环），而不是某一道题的解法或某一个 API 的用法。
   不在 Atlas 里展开：语言语法、库接口、寄存器位域、某颗料号的配置步骤、某一本教材的习题。那些属于对应的学习应用。已有的 `practice` / `validation_note` 可以保留为「产出长什么样」的锚，但写作和界面都要把它们当成例证，不当成教程。

4. **侧栏只按计算机、电子信息两大学科列目录；职业图从界面拿掉。** 现阶段的任务是培养和补全知识体系，不是按就业裁课。侧栏两大类各自展开「知识图谱」与「实践主干」，知识点作为子项列出。职业方向、职业目标**仍保留在内容里**（ADR 0054 宁增勿删），但侧栏、节点专页和跨图跳转都不展示它们，避免干扰当前盘面。

5. **分级继续表达必要性，不靠堆细节抬重要性。** `essential` / `important` / `optional` 只回答「对这门学科的培养目标和实现目标有多必要」。这里的「实现目标」指学科要培养出什么能力、能交出什么技术产出，**不是岗位名称**。可选课仍然要出现在图上（ADR 0011），否则大局里会缺一块。没有真先修就不连线——指南针上的刻度可以并列，不必为了好看串成一条假的学习流水线。

6. **盘面按外部公开标准校准，不以个人经验裁课。** 列课、分级、判「有没有盲点」时，先对照下面这些正在被社区和认证使用的来源，再回头看自己熟不熟。个人岗位用不用得到、自己有没有学过、航天日常碰不碰得到，**都不能**把一门学科核心从盘面上抹掉；不熟的课标成可选或「方向」，不要假装它不存在。新增方向用新节点或新理论科目表达（ADR 0054：宁增勿删，一个 id 不改嫁）。

   校准用的公开来源（写作和补课都必须能指回去）：

   | 来源 | 校准什么 |
   |---|---|
   | [ACM / IEEE-CS / AAAI CS2023](https://csed.acm.org/knowledge-areas/) 十七个知识领域 | 计科盘面有没有整块失踪 |
   | [ossu/computer-science](https://github.com/ossu/computer-science) Core CS（编程、数学、工具、系统、理论、安全、应用、伦理皆必修） | 自学课表里「所有主修都要上」的那一层 |
   | [roadmap.sh](https://roadmap.sh/computer-science) 及系统/后端/安全等分图 | 工程师社区怎么把学科切成可走的方向，不抄它的框架清单 |
   | 中国工程教育认证：计算机类补充标准（程序设计、数据结构、组成、操作系统、网络、软件工程、信息管理；计科另含算法、编译、体系结构） | 国内工科毕业要求 |
   | 中国工程教育认证：电子信息类（物理机制、电子线路、信号与信息获取处理、信息计算与存储、通信传输、网络互联、移动应用） | 电子信息盘面有没有整块失踪 |
   | ABET 电气/电子/通信类课程准则（概率统计、微积分、软硬件系统、电磁与高等数学；名称含 communication 必须有通信理论） | 国际同类专业的广度 |
   | [m3y54m/embedded-engineering-roadmap](https://github.com/m3y54m/embedded-engineering-roadmap)（软件 / 硬件 / 软技能三块） | 嵌入式作为电子信息实现目标时，盘面上不能只剩芯片名词 |
   | INCOSE 系统工程能力框架、IEEE SWECOM | 「大局意识」本身是可校准的能力，不是一句口号 |

## 可行性建议（盘面层，不是教程层）

对照上面这些来源，两章课程图在**学科大局**上至少要能指认下列能力——可以是节点，可以是理论科目，可以是明确标出的方向选修；**不允许整块缺席**。写法仍遵守第 3 条：只写必要性、能力和产出，不写操作细节。社区路线图里的具体框架、云厂商和料号，不进盘面。

**计算机科学与技术（对照 CS2023 + OSSU Core + 认证计算机类）**

| 能力域 | 学完能掌握什么 | 能造出什么 | 外部依据 | 盘面位置 |
|---|---|---|---|---|
| 程序设计与软件开发基础 | 把问题收成可编译、可测的程序 | 可交付的中等规模程序 | CS2023 SDF；认证「程序设计」 | 已有语言与工具链节点 |
| 算法与数据结构 | 判断代价、选结构、证明边界 | 复杂度可控的核心模块 | CS2023 AL；OSSU Core theory | 已有 |
| 计算机组成与系统基础 | 从门电路说到指令在机器上怎么跑 | 能解释一条程序的机器行为 | CS2023 AR / SF；Nand2Tetris | 已有 |
| 操作系统 | 虚拟化、并发、持久化的判断 | 能设计或裁剪一层运行时 | CS2023 OS；认证核心 | 已有 |
| 网络与通信 | 分层、延迟和失败从哪一层来 | 能设计或诊断互联系统 | CS2023 NC；认证核心 | 已有 |
| 编译与程序语言 | 程序如何变成可执行表示；语言不是语法表 | 能解释编译产物，能设计小型语言处理 | CS2023 FPL；认证计科含编译 | 必须在盘面上，不能因为「不写编译器」删掉 |
| 数据管理 | 持久化、事务、查询与一致性 | 能设计可回放、可查询的数据层 | CS2023 DM；OSSU Core applications；认证「信息管理」 | 必须在盘面上 |
| 软件工程 | 变更、验证、协作如何被允许进入产品 | 一组人能改、能查、能交付的系统 | CS2023 SE；认证核心 | 必须在盘面上 |
| 并行与分布 | 多机、共识、失败是常态 | 能判断要不要分布、失败时系统还剩什么 | CS2023 PDC；roadmap.sh System Design | 必须列出；没有 Athena 应用也要占格 |
| 信息安全 | 威胁模型、机密性/完整性/可用性 | 能指出攻击面并给出可验证的收口 | CS2023 SEC；OSSU **Core security 必修** | 安全不是选修点缀，OSSU 把它放进 Core |
| 人工智能 | 从数据里学规律的边界 | 能判断模型适不适合进系统 | CS2023 AI；OSSU Core applications | 已有模型开发；保持方向可见 |
| 图形与交互 | 把计算变成可感知的图像与界面 | 可视化系统、人机界面，而不是「会调库」 | CS2023 GIT / HCI；OSSU 含 Computer Graphics | 必须列出，避免「计科没有图形与交互」 |
| 专业伦理与社会 | 工程决策的责任、隐私、知识产权 | 能在交付物上说清约束，而不是事后补锅 | CS2023 SEP；OSSU Core ethics | 必须列出；这是大局意识的一部分 |
| 数学基础 | 离散、概率、线性代数作为判断语言 | 能给算法、信号、学习一个尺子 | CS2023 MSF；OSSU Core math | 理论科目，不建成操作课 |

**电子信息（对照认证电子信息类 + ABET ECE + 嵌入式公开路线图）**

| 能力域 | 学完能掌握什么 | 能造出什么 | 外部依据 | 盘面位置 |
|---|---|---|---|---|
| 物理机制与器件 | 半导体和电磁现象为什么能变成开关和场 | 能判断器件/介质的适用边界 | 认证「物理机制」；ABET 工程科学 | 不得只剩「会用芯片」；弱则进理论，不能不提 |
| 电子线路（模电 / 数电） | 连续量与离散量怎么设计、怎么测 | 可验证的模拟与数字子系统 | 认证「电子线路」；ABET ECE | 两门都是核心，不能并进「电路入门」就当盖完 |
| 信号与信息获取处理 | 从物理量到可计算的信息 | 传感链路、滤波与变换后的可用特征 | 认证「信号/信息获取与处理」 | 信号与系统（理论）+ DSP（实践）都要在 |
| 信息计算与存储 | 嵌入式侧的计算和落盘边界 | 能在资源上限内完成计算与记录 | 认证「信息计算与存储」 | 微机 / 存储 / 文件系统在嵌入式语境下列出 |
| 通信传输 | 符号如何进信道、噪声里如何捡回 | 一条可测误码的链路，而不是只会插网线 | 认证「通信传输」；ABET 名称含 communication 必有通信理论 | 通信原理 + 数字通信实践 |
| 电磁与射频 | 场、波、传输线，为什么高速不能当集总电路 | 能解释辐射、匹配和完整性 | ABET 高等数学与电磁；IEEE ECE | 电磁场理论 + 射频方向，避免只剩 EMC 词条 |
| 网络互联与移动应用 | 电子系统如何进更大的信息网 | 可互联的终端或网关 | 认证「网络互联、移动应用」 | 与计科网络交叉，但产出是装置不是后台服务 |
| 嵌入式系统 | 计算机作为更大系统的一部分 | 目的明确、资源受限的软硬一体装置 | ISO/IEC/IEEE 24765；GitHub 嵌入式路线图 | 软件 / 硬件 / 过程素养三块都要看见 |
| 控制与系统 | 测—比—执行，动态指标可重复 | 可整定的闭环，而不是开环电路 | 认证自动化类；INCOSE 系统思维 | 电子信息实现目标含系统动态；列出以免只剩静态电路 |
| 概率与随机 | 噪声、误码、估计的语言 | 能给链路和测量一个不确定度 | ABET ECE 必含概率统计 | 理论科目 |

**明确不要从社区路线图里搬进来的**

- roadmap.sh 分图里的具体框架、云产品、编辑器和年度流行栈——那是下游应用或个人工具箱，不是学科盘面。
- 用「航天岗用不到」否决 CS2023 / 认证里的核心知识领域。远方（ADR 0001）决定职业目标图的取舍，不决定计科或电子信息缺不缺编译、图形、伦理、电磁。
- 为了把课连成一条学期链而发明先修。OSSU 自己也允许并行，只要求 Core 齐，不要求唯一拓扑。

## 后果

- 写节点时先写「为什么必须学 / 学完能做什么 / 能交出什么」，再考虑要不要留一句产出例证。先写操作步骤就是写偏了。
- 补课或改分级时先打开第 6 条的外部来源，再动 `atlas.json`。对不上 CS2023、OSSU Core 或认证知识领域的缺席，不能用「我用不着」结案。
- 界面上节点专页应让必要性、能力和产出先被看见；芯片型号、命令行和库名不应成为第一屏的主角。
- 其他学习应用的边界更清楚：它们负责把 Atlas 指出的能力练到可验证；Atlas 不和它们比谁的细节更全。还没有对应应用的能力域（分布、图形、伦理、电磁……）仍然留在盘面上，标成方向，而不是删掉等以后再说。
- 当前界面侧栏只列计算机、电子信息。职业方向与职业目标仍在 `atlas.json` 里，不进菜单、不进专页跳转，避免培养阶段被就业图带跑。
- 地图怎么画、怎么交互，按 ADR 0013 把桌面表达做满；内容契约不给画面让路。
