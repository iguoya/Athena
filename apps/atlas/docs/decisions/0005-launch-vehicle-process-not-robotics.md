# ADR 0005：以二院、三院、四院等军工研制体系取舍

- 日期：2026-09-15
- 状态：已接受
- 修订：ADR 0001 的场景取舍与地图构成；补充 ADR 0004 的地图清单

## 背景

首版把卫星平台、机器人和互联网大模型并列成一级地图。航天科工**二院**（防空反导
与制导雷达、综合电子、军事智能）、**三院**（飞航导弹总体、动力、制导控制、仿真
与数智化）、**四院**（固体火箭发动机与试车，以及**十七所**控制系统总体）以及一院
运载、空间工程总体等单位的公开招聘，画出的是另一条主链：总体与接口、探测与信号
处理、GNC、弹上计算机、动力/能源接口、测发控、半实物试验、产品保证。

**实时控制**的院所标尺优先对照四院十七所：它是科工集团内公开的控制系统总体所，
职责写明固体运载飞行器的地面测试发射、定位定向、全程制导控制以及电气系统抓总。
校招专业覆盖控制、软件、电气、航空宇航、仿真与健康管理。这套公开链用来约束
「实时控制学什么」，本身不升格为与软件/电子/GNC 主干平级的地图。

机器人仍有迁移价值（标定、估计、台架），但会把学习拉向 ROS 和场地急停，只能作为
**相邻参考**。大模型不同：二院公开岗位含军事智能，三院含智能算法与数智化——它帮得
上试验复盘、文档检索和地面知识工作，但帮不上、也不允许进入飞控闭环。因此大模型
保留为**助力图**。

内容停在公开教材、公开招聘技能和可复现仿真；不写战斗部、突防、寻的打击链、
推进剂配方、光学产品战术用途或未公开型号细节。

## 决策

1. **取舍标尺是军工院所研制体系，不是通用兴趣分类。** 二院校正探测、雷达信号处理、
   FPGA/DSP 数字后端与系统软件；三院校正飞航总体、制导控制、动力、仿真、嵌入式
   与数智化；四院校正固体动力的试验、测时序和接口，而不是化学配方。**实时控制**
   另用四院十七所的公开总体链作重要参考。一院运载与空间工程总体作为同族研制流程
   的补充证据。
2. **主干六对地图**：软件工程化、弹上电子与总线、弹箭/飞航研制、GNC、弹上计算机、
   探测信号处理与弹上计算。GNC、弹上计算机、测发控节点的验收口径对照十七所，但
   地图等级仍是主干，不是「十七所专图」。
3. **十七所实时控制保留为一对重要参考地图**（`emphasis: reference`）。节点按公开
   总体链组织：测发控 → 定位定向 / 电气时序 → 全程制导控制 → 飞控软件调度 →
   试验与健康管理。只写程序制导与姿态回路，不写末端寻的、射频对抗或光学导引头。
   侧栏单独成组「重要参考」，默认打开的仍是主干体系图。
4. **机器人保留为一对相邻参考地图**（`emphasis: adjacent`）。侧栏放在「相邻参考」，
   低于主干，也低于十七所对照。不得让主干或十七所节点 `requires` 机器人节点。
5. **大模型保留为一对助力地图。** 只服务地面侧：评测、检索、受控问答、试验数据
   辅助；节点必须写明不得写入飞控、点火或发射控制。它的 `emphasis` 为 `support`。
   不得让主干节点 `requires` 助力节点。
6. 制导写公开的程序转弯、重力转弯、姿态稳定和组合导航；探测写可教材化的滤波、
   时序与数字后端。
7. **公开招聘是时效性技术样本。** 用来确认 C/C++、MATLAB/Simulink、RTOS、CAN/
   RS-422、组合导航、半实物、FPGA/DSP/Zynq、软件工程化、数智化这些被实际索取的
   技能。节点标题写工程能力，不写岗位名，不承诺录用。

## 后果

- 体系/实操主干六对，外加大模型助力一对、十七所对照一对、机器人相邻一对。
- `emphasis` 取值：`trunk` | `support` | `reference` | `adjacent`。
- 开源飞控、Yamcs、开发板、ROS、本地大模型只是可替换样本。
- 把机器人或十七所升为与主干同一侧栏分组必须另立 ADR。
