# ADR 0007：运行时只留一个 Atlas 进程，不做 QML 热重载

- 日期：2026-09-16
- 状态：已接受

## 背景

Atlas 只有开发形态：编排器按 `app.json` 的 `dev` 声明增量构建再跑 `build/athena-atlas`，
没有打包副本（ADR 0046）。这带来两个问题，一个必须解决，一个看起来该解决但不值得。

**必须解决的是"独一份"。** 编排器的 `open` 已经会在应用运行时改为前置窗口而不是
再起一份，但那是经过它的那条路。直接跑 `build/athena-atlas`、或从别的入口重复触发时，
第二个进程会照常开窗口：两个窗口读同一份内容、各自持有选择状态，界面看起来只是
"没反应"或"选择莫名回退"。`runner::activate` 还有一个自己就说明了的缺口——
**Wayland 不允许别的进程抢焦点**，那种情况下只能由应用自己响应"又被启动了一次"。

**看起来该解决的是热重载。** 改一行 QML 要重启进程，确实比 Tauri 那几个应用笨。
但真做了一版之后，代价清楚了：根对象的生命周期得从 `QQmlApplicationEngine` 手里
接过来自己管，还要管窗口几何的保存与恢复、语法错误时保留旧窗口、监视器在"写临时
文件再改名"后丢失路径的补登记。这些都只在开发期走，出问题时症状是"改了没反应"，
排查成本比它省下的重启时间高。而重启这条路本来就通：编排器 `stop` + `open` 是
增量构建，改 QML 时几秒就回来了。

## 决策

1. **应用自己保证进程唯一。** 启动时用 `QLocalServer` 占一个固定 key
   （`athena.atlas`）。占不住说明已经有一份在跑：请它把窗口举到前面，自己立刻
   退出，绝不开第二个窗口。
2. **连接本身就是信号，不约定报文格式。** 第二份连上就断开；第一份收到连接即
   `presentRequested`，把当前窗口 `show` + `raise` + `requestActivate`。
3. **陈旧套接字要主动清理。** Unix 上异常退出会留下套接字文件，不 `removeServer`
   就再也 `listen` 不上——那等于应用从此起不来，比多开一个窗口严重得多。
4. **守卫起不来不拦启动。** `listen` 失败只影响"第二次启动能否前置窗口"这一个
   功能，打一行警告继续跑；为它让整个应用启动失败是本末倒置。
5. **不做 QML / 内容热重载。** 改 QML、改 `content/*.json` 都重开应用。编排器的
   增量构建是这条路的前提，所以 `dev.prepare` 必须保持增量（不清 `build/`）。

## 后果

- 三个启动入口（菜单栏、托盘、`launcher open atlas`）和直接跑 `build/athena-atlas` 的结果
  一致：永远只有一个 Atlas 窗口。
- Wayland 下编排器无法前置窗口时，改由应用自己完成，不再只能提示"请自己切过去"。
- 单实例守卫有回归测试（`tests/atlas_shell_test.cpp`）：第二份退让、崩溃后能重新
  占位。窗口前置本身仍需在 macOS / Windows 上手工验收。
- 改 QML 后必须重开应用。如果将来重开的等待真的成了负担，再按这份 ADR 的代价
  清单重新评估热重载，而不是随手加回来。
