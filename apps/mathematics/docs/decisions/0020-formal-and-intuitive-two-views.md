# ADR 0020：讲解分「直觉」与「严谨」两个视图，逐条对照，不得各写各的

- 日期：2026-09-14
- 状态：已接受
- 依赖：ADR 0005（直观优先与两条防线）、0013（信心）、0015（起点假设）、
  0017（严格表述必须可核对）、0019（题目必须有所本）

## 背景

使用者要求：教案分成两个标签页——一部分是**规范教材的讲解方式**，严谨、符合数学
写作规范；一部分是**从直觉和实践角度**讲，容易理解、可视化。并且特别加了一句：

> **不要割裂两种关系，配合着来。**

### 1. 现状：应用里只有直觉那一半

盘点 16 节的讲解字段——`hook`（为什么需要它）、`overview`（问什么、说什么、
几步走、值得记住的一点）、`walkthrough`（演一遍）、`widget`（动手拖）、
`experiments`（先猜再验）——**全部属于直觉侧**。

严谨表述在哪？只有 `sources` 里的几条外链和 `textbook_ref` 的章节号。也就是说，
**准确的定义、定理的条件、计算方法的步骤，应用里一个字都没有**，要看得跳出去。

这有两个后果：

- **流畅性错觉**（ADR 0014 已论证）在这里最严重：图拖得明白、比喻听得懂，
  一到要写出准确陈述就写不出来，而且**没有东西可以对照着检查自己理解得对不对**。
  ADR 0005 说的「直观必须配反例，否则退化成糊弄」，缺的就是这个对照物。
- 分不清**哪句话是可核对的权威表述、哪句话是本应用打的比方**。「行列式就是面积
  变成几倍」是一句很好的比方，但它不是定义；混在一段里写，读者没法知道哪句拿到
  考场上能用。

### 2. 这两侧的分界已经写过了

ADR 0017 第 1 节那张「自由发挥的边界」表，正好就是这两个视图：

| 直觉视图（本应用负责） | 严谨视图（必须依据来源） |
|---|---|
| 直觉引入、比喻、图示 | **定义**的准确陈述 |
| 预测与验证闭环 | **定理与性质**的条件和结论 |
| 把概念串成一条主线的方式 | **计算方法**的步骤与适用范围 |
| 现实问题的选取 | 术语的标准叫法 |

本 ADR 不新造分类，只是让这张表**在界面上显形**。

## 决策

### 1. 两个视图，不是两篇文章

页面在标题之下放两个标签：**「直觉与图像」**与**「严谨表述」**。

**「配合着来」是本 ADR 的硬约束，靠三条机械保证，不靠写作时自觉：**

1. **逐条配对。** 严谨视图的每一条都必须填 `pairs`，指向直觉视图里讲同一件事的
   那一段；对不上的条目说明两侧内容脱节，lint 报错。
2. **双向可跳。** 严谨条目上显示「直觉侧怎么说的」并可点击跳过去；直觉侧被配对
   的段落带一个角标，点了跳到严谨条目。切换视图后自动定位到对应位置并高亮，
   **不回到页首**——回页首就等于让人重新找一遍，两侧就散了。
3. **一句话桥接。** 每条严谨条目必填 `plain`，用直觉侧的语言复述这条严谨表述。
   它是两侧的接缝，也是检验：**写不出这句话，说明这条严谨表述在直觉侧没有对应，
   不是漏讲了就是讲跑偏了。**

### 2. 严谨视图的内容契约

```json
"formal": {
  "intro": "选填，一两句话说明这一节的严格表述覆盖到哪里",
  "entries": [{
    "id": "f1",
    "kind": "definition",
    "title": "行列式（二阶）",
    "statement": "准确陈述，用词按教材标准叫法",
    "conditions": ["定理的前提，逐条列；定义可省"],
    "source": { "kind": "adapted", "site": "…", "ref": "…", "url": "…" },
    "pairs": "ov-says",
    "plain": "直觉侧那句「面积变成几倍」说的就是这个数"
  }]
}
```

`kind` 五取一，对应数学写作里的几种陈述：`definition`（定义）、`theorem`（定理）、
`property`（性质）、`method`（计算方法）、`term`（术语对照）。界面按 kind 加不同
的标记，**不同类型的陈述要能一眼分开**——定义可以直接用，定理要先核对条件。

`source` 沿用 ADR 0019 的结构且**必填**：严谨视图的全部价值就在它可核对，
没有出处的「严谨表述」比直觉表述更有害，因为它看起来像权威的。

**严谨 ≠ 形式化**（ADR 0022 补充）。这里要的是**准确**——陈述正确、条件完整、
术语标准；不是**形式化**——用最少的原始概念和最一般的记号书写。第一遍写准确的
自然语言陈述加低维的具体式子就够，一般 n 阶的形式定义留到后面的遍数。来源一律
选通俗、免费、可点开核对的（ADR 0022 第 2 节的清单），中文优先。

### 3. 边界：什么不该进严谨视图

- **不是把教材抄一遍**。ADR 0009 的「坐标是导航，不得退化成改写教材」仍然有效。
  进来的只有这一节直觉侧确实讲到的那几条，一条比方对应一条陈述。
  **直觉侧没讲的，严谨侧不要先讲**——那会变成一本塞在标签页里的教材。
- **不是难度升级的地方**。同一节的两个视图讲的是同一件事，深浅由 `mastery_goal`
  决定，不由视图决定。第一遍 `overview` 的严谨视图可以只有两三条。
- **`plain` 不是第二份直觉讲解**。它是一句话的接缝，写长了就成了在严谨视图里
  再讲一遍直觉，两边各写各的——正是本 ADR 要防的。

### 4. 哪些内容不进标签页

只有**讲同一个知识点的两种方式**进标签页。其余始终显示：

| 位置 | 内容 | 为什么 |
|---|---|---|
| 标签页之上 | 坐标、标题、先修、出处 | 导航信息，切视图不该丢 |
| **「直觉与图像」** | `hook`、`overview`、`walkthrough`、`widget`、`experiments` | 现有内容整体归此侧 |
| **「严谨表述」** | `formal.entries` | 本 ADR 新增 |
| 标签页之下 | `examples`、`drills` | **例题与练习是两侧的汇合处**：题干按规范写，解法每步的 `why` 用直觉侧的话讲。把它们放进任一侧，另一侧的读者就看不到 |

### 5. 默认停在直觉侧

打开一节默认显示「直觉与图像」——起点假设是不假设学过（ADR 0015），先给准确
定义会把人挡在门外。但**标签必须一眼可见**，不做成折叠或次级入口：知道「严谨的
说法在那边、随时可以去核对」本身就消解一部分焦虑（ADR 0013）。

视图选择记在会话内，切下一节时保持——愿意读严谨表述的人不必每节点一次。

## 后果

- 每节的编写量增加：直觉侧写完还要写严谨侧，且每条都要配对、找出处、写桥接句。
  **这是本 ADR 的主要代价。** 但其中大部分是本来就该做而没做的——ADR 0017 要求
  严格表述可核对，此前只做到了「给个链接」。
- 存量 16 节都缺 `formal`。与 ADR 0019 的存量处理同样办法：**`formal` 暂不设为
  必填**，lint 只统计覆盖了几节并打印，写到哪节补哪节；等 16 节补齐后升为必填。
  已经有 `formal` 的节，其内部约束（`pairs`、`plain`、`source`）立刻强制。
- 直觉侧的段落需要稳定的锚点 id 供 `pairs` 指向。现有渲染用的是 class，要补 id。
- `plain` 写不出来是一个**有用的失败信号**，应当当作内容有问题来处理，不要硬凑
  一句话应付 lint。
