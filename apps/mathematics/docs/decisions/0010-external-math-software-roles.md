# ADR 0010：外部数学软件按三种角色分别裁定

- 日期：2026-09-13
- 状态：已接受
- 依赖：ADR 0001（符号引擎随包常驻前端）

## 背景

ADR 0001 否决 MATLAB 与 Octave 作为运行时后，未系统考察其他数学软件。使用者
重新提出：从理解数学思想、更好掌握考研数学的角度，是否真的不考虑现有数学软件？

问题成立。ADR 0001 的否决只回答了「**内嵌运行时**」这一种用法，而数学软件在本
项目里其实可以有三种完全不同的角色，**判据各不相同**：

| 角色 | 谁依赖它 | 判据 |
|---|---|---|
| **内嵌运行时** | 最终用户的每次使用 | 可分发、离线、启动快、可被教学逻辑精细控制 |
| **内容生产工具** | 只有作者，在编写内容时 | 产物是静态文件即可，慢和重都能接受 |
| **使用者个人工具** | 使用者自己探索时 | 不进应用，不受本项目约束 |

把三者混为一谈，就会出现「因为不能打包，所以完全不用」这种过度否决。

## 决策

### 1. 内嵌运行时：维持 ADR 0001，不新增

| 软件 | 裁定 | 理由 |
|---|---|---|
| **Pyodide + SymPy** | **采用**（ADR 0001） | 覆盖考纲、纯 Python 可跑 WASM、常驻后毫秒级 |
| **自绘 Canvas / SVG** | **采用** | 交互可完全受控，零体积 |
| GeoGebra | **不内嵌**，见第 2 节 | 见下 |
| Desmos | 否 | 闭源在线服务，离线不可用，有使用条款约束 |
| Wolfram Alpha / Mathematica | 否 | 商业授权 + 在线，同 MATLAB |
| Julia (Symbolics.jl) | 否 | 运行时体积大、启动慢，生态收益不抵成本 |
| SageMath | 否 | GB 级体积，不适合桌面应用打包 |
| MATLAB / Octave / Scilab | 否 | ADR 0001 已裁定 |

### 2. GeoGebra 为什么不内嵌——理由不是「做不到」

GeoGebra 开源、可离线、有 JS API，技术上**确实可以嵌入**，且功能远超本项目自己
能写的。不采用是教学理由，不是技术理由：

1. **教学闭环需要深度联动。** ADR 0002 要求「预测 → 验证 → 对照修正」，需要记录
   使用者的预测、与课表知识点绑定、写入进度库。GeoGebra applet 对宿主是个黑盒，
   做这套联动非常别扭。
2. **通用工具的界面噪音有害。** 它提供大量与本节无关的按钮和自由度；而教学组件
   应当**只暴露这一节要考察的那一个自由度**，其余全部收起。功能多在这里是负担。
3. **自己写的成本并不高。** 二维线性变换可视化约两三百行 Canvas 代码，且完全
   可控、风格统一、零额外体积。

### 3. 内容生产工具：Manim 记为待用，暂不引入

**Manim**（3Blue1Brown 使用的数学动画引擎）是本 ADR 唯一值得新增的候选。

- 它**离线渲染视频**，不能交互——因此它与自绘交互组件是**互补关系，不是替代**。
- 产物是静态视频/GIF，打包后**不引入任何运行时依赖**，故属于生产工具而非运行时。
- 引入成本在作者一侧：Python + LaTeX + ffmpeg 工具链，单个动画渲染以秒到分钟计。

**决定：暂不引入，记为待用。** 第一章不需要它。出现「静态图说不清楚、但交互又
没有必要」的场合时再引入，届时补一份 ADR 说明工具链与产物存放约定。

由此明确三种视觉手段的分工：

| 表达对象 | 手段 |
|---|---|
| 使用者需要操控参数、形成预期并验证 | **自绘交互组件**（Canvas / SVG + 控件） |
| 不可操控但需要看清的过程演进 | 静态 SVG 分步图；确有必要时才考虑预渲染动画 |
| 静态结构、分类、对照 | **静态 SVG** |

### 4. 使用者个人工具：推荐，但不进应用

**GeoGebra 推荐使用者自己装来自由探索**，Desmos 亦可在线用。它们的探索自由度
远超本应用内嵌的受控组件，而这在自学中是有价值的——受控组件服务于某一节的教学
目的，自由探索服务于好奇心。

这条只写入应用内的说明文字（或 README），**不产生任何技术依赖**，也不要求使用者
安装。

## 后果

- 结论与 ADR 0001 一致，但依据从「只考察了运行时」扩展为「三种角色分别裁定」，
  今后再出现「要不要用某某数学软件」的问题，按第 1 节的判据表直接对号入座。
- Manim 的待用状态需要有人记得。写入本 ADR 而非留在讨论里，正是为了让它可被检索。
- 第 2 节意味着交互组件全部自研，**首章即验证这条路可行性**（ADR 0008 第 4 节）。
  若二维线性变换组件的实现成本显著超出预期，应回头重新评估 GeoGebra 内嵌方案。
