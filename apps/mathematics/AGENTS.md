# Athena Mathematics — 项目协作规则

本文档是 **`apps/mathematics` 独立应用** 的项目级指令。本应用与 Athena 主程序
（GTK / Meson / `resources/athena.json`）**平级、可脱离**：不读主程序配置、
不链接主程序代码、不依赖主程序进程即可完成开发、构建与练习全流程。

主仓库根目录的 `AGENTS.md` 只描述主程序与「异构应用」边界；**改本应用时以
本文为准**。可选地，主程序可通过 `app.json` 把本应用当独立进程拉起
（主仓库 ADR 0032），那不是运行本应用的前提。

## 定位

- **一个目标 + 一个约束**，两者地位不对等（ADR 0003）：
  - **目标函数**：用数学思想与工具**认识现实、改造现实**，服务于实际问题并提升
    对现实的认知。所学要用得上，不为文凭、不用完即弃。
  - **约束条件**：通过**研究生入学考试数学二**（ADR 0007）。高等数学约 78%、
    线性代数约 22%，**不考概率论与数理统计**。以后再考虑数学一。**约束需要满足，
    不需要认同**——考纲决定覆盖范围的下限，不决定讲法与组织顺序。
  - **起点假设（显式，ADR 0015）**：**不假设**高数线代学过或记得，**不假设**中学
  代数、三角、函数图像仍熟练，**只假设**会四则运算、看得懂坐标系上的点。需要更高
  前置的地方要么补前置、要么在 `requires` 显式声明，**不得默认读者会**。前置基础
  标 `prereq`，**按需诊断后只补缺口**，不从头重学一遍。
- 范围用 `scope` 标记表达（`math2` / `math1` / `beyond` / `prereq`），**不物理删除**，
    以后开数学一零返工。注意**数学二不是数学一的子集**——曲率是数学二考、
    数学一不考，不能用「数学一减几章」生成。
- **建模独立成线**（ADR 0003）：从现实到数学这一步比从数学到答案难得多，而考试
  只考后者。建模线由**问题**组织、允许跨章，不得用「每个知识点挂个应用例子」
  冒充。
- **应试区显式隔离**：纯为区分度存在的偏难怪题进标注清楚的过关训练区，不混入
  主线。界面文案仍不出现「考研」字样。
- **按直观、直觉、自然的顺序讲**（ADR 0005）：动机先于定义、低维先于一般、
  图像与符号并置、严格化分阶段登场。允许物理式的直观推导，但必须标清它何时失效。
- **禁止 PUA 式表达**（ADR 0015 第 5 节，与 ADR 0013 禁用词表并入同一 lint）：
  不得贬低读者能力（「这都不会」）、用他人施压（「别人都会了」）、用后果恐吓
  （「这都不会就别想考上」）、制造稀缺焦虑（「只剩 X 天了」）。
- **两条防线，不可只守其一**（ADR 0005）：直观必须配反例，否则退化成糊弄；
  反象牙塔不得成为削弱应试的借口——**约束不满足，目标无从谈起**。
- **每个知识点必须标教材与考纲坐标**（ADR 0009）：`textbook_ref`（同济《高等数学》/
  《工程数学·线性代数》）与 `syllabus_ref`（数学二大纲）均为必填，界面显著显示，
  并支持按教材章节反查。组织顺序自由与章节归属清晰不冲突——坐标是导航，不是内容
  来源，**不得退化成改写教材**。教材无对应独立章节时标 `cross_chapter`，
  必须列全 `covers` 与 `prepares`。
- **路径按先修图拓扑序，不按教材章节序**（ADR 0008）。`difficulty` 是单点难度，
  顺序由 `requires` 决定，两者不是一回事。拓扑序有多个合法解时，选**更早接上
  现实**的分支。
- **现实问题当引入动机，不当课后应用**（ADR 0008）：建模线与主线在时间上交织，
  问题在需要某个工具的前一刻出现，工具作为解决它的产物登场。**禁止**把应用统一
  堆到章末或单独的「应用」章节——那是把割裂从前后改成左右。
- **螺旋式三遍，先薄后厚**（ADR 0012）：每个知识点分 `overview`（极薄，知道是
  什么、解决什么、在全局哪里）→ `full`（机制与边界，能做常规题）→ `exam`
  （熟练与速度）三层。**第一遍的验收标准是「走完」不是「学会」**，不设挡路考核，
  允许带着没弄懂的继续走。**编写顺序：先横向铺完一科的 overview，再回头纵向加深**。
  第一遍教材选薄、直观、完整覆盖的，不要考研向。
- **习题是检验器，也是学习动作本身**（ADR 0014）。与「反对重解题轻思想」不矛盾：
  反对的是**以做题为目的**，肯定的是**以做题为检验**。**内容越直观，流畅性错觉
  越强，检验越不可省**——两者配套，不可只做前者。梯度按**变式**（每题只改一个
  维度）＋**渐隐完形**（从补最后一步逐级挖空到独立完成）设计；小批量高频次；
  新学用分块建立自信，巩固改用交错（更吃力但长期更好，须在界面说明这是正常的）。
  随堂测验的错误选项必须是**具体的错误理解**，不设随机干扰项。
- **出题必须有所本，不要轻易自造**（ADR 0019）。每道判分的题都要带 `source`，
  指到一个**实地核对过**的真实出处（`verbatim` 照用 / `adapted` 改编 / `authored`
  自造）。自造题没有难度校准，做对了说明不了什么——**检验器本身就不可信了**，
  反而加固流畅性错觉。`authored` 是例外不是默认，必须写明为什么外部题库覆盖不到，
  且一节内不得过半。**凭印象编出处比自造更糟**：使用者按图索骥扑一次空，从此
  不再信任何一条出处。已核对的习题来源见 ADR 0019 第 5 节。
  例外：`predict`（先猜再验）不判分、不计掌握度，不受此约束。
- **知识点绑定应用，越多越好**（ADR 0024）。每个知识点都该带至少一个现实用法，
  讲解、例题、习题任何一处承载都行；写不出来时是去找，不是跳过。
  **判断标准是「有没有帮助理解」，不是「够不够现实」**——略显牵强但能把抽象概念
  拉到可感知层面的例子，胜过没有例子。该防的是例子**写错**（数学上不成立、比
  概念本身还难懂、拿它冒充建模训练），**不是例子写多**；误判代价不对称，例子多
  一点代价很小，缺席代价很大。唯一硬要求是**不编造事实**：不得声称某个具体公司、
  产品、论文用了某方法而无依据，泛指场景可以写。
  注意 ADR 0003 那句「不得用每个知识点挂个应用例子冒充建模线」管的是**挂例子不能
  代替建模训练**，不是禁止挂例子——不要再引用它去压缩举例。
- **参考来源一律选通俗、免费、可点开核对的，中文优先**（ADR 0022）。第一顺位是
  **可汗学院中文版**，需要一条有编号可引用的准确陈述时用 **Immersive Math**
  （免费在线、图可拖、有定义与定理编号），习题用 **MIT OCW 18.06**。
  **同济教材退回「坐标」角色**——只回答「这属于教材哪一章」，便于和习题集、
  他人进度对齐，**不作讲解与严谨表述的来源**，界面上也不让它显得像主要参考书。
- **严谨 ≠ 形式化**（ADR 0022 第 1 节）。要的是**准确**（陈述正确、条件完整、
  术语标准），不是**形式化**（最少的原始概念、最一般的记号）。第一遍写准确的
  自然语言陈述加低维具体式子就够，一般 n 阶的形式定义、完整证明留到后面的遍数。
  判据：**一个没学过的人能不能读懂它在说什么**；读不懂就是超前了。
- **标题用规范术语，直觉说法降为副标题**（ADR 0021）。`title` 是名词短语形式的
  术语，取自 `syllabus_ref` / `textbook_ref`，**不自己另造说法**，也不能是句子
  （lint 查疑问词、句末助词和长度）；`plain_title` 必填，存直觉说法，与术语
  **同时显示**。两者缺一都不行：只有术语会把人挡在门外，只有直觉则认不出这节
  叫什么、也搜不到它。知识图谱节点只显示术语。
  **这只约束标题**——讲解顺序、讲法、比喻一概照旧，具体讲解仍可用非标准讲法。
- **每节分对等的两遍讲解，各配各的习题**（ADR 0023）。第一部分口语化、直观化，
  第二部分正式化、教材化，**同一问题概念描述两次**。两部分**职责对等**——都要
  「讲清楚 + 示范一遍 + 检验一遍」；只在第二部分列几条定义不算写完。
  **两部分尽量用同一个具体对象**（直觉侧动画演 `[[2,0],[0,2]]` 面积变 4 倍，
  严谨侧就算这个矩阵的 `det`）——换说法不换对象，读者才看得出是一件事。
  **习题不共用**：第一部分测直觉判断（允许不动笔），第二部分测规范计算与条件
  核对（**必须有要动笔算的题**）。有 `formal` 就必须有 `formal.drills`，lint 强制。
  **习题要跟现实结合**，判据见下一条。
- **两个视图表述的是同一个问题，区隔靠语言不靠内容**（ADR 0023 第 2b 节）。
  第一部分是**直观、实用、可视化**（口语、比喻、图、动画、可拖的控件），第二部分是
  **数学严格规范表述**（定义、定理、条件、式子，只有文字与式子）。两边说的必须是
  同一件事，**区别只在怎么说**。
  **最容易做偏的地方**：发现两边读起来像重复，就让第二部分去讲别的内容（第一部分
  讲二阶行列式，就往第二部分塞三阶、余子式）——那是把两个知识点塞进一节，反而真的
  割裂了。诊断「没有区隔」时查的是**两边语言有没有混**：第二部分里有没有混进
  「写成一个十字、对角线相乘」这类口语记忆法，第一部分是不是只抛术语却不讲怎么算、
  凭什么成立。修法是把口语移回第一部分、规范陈述留在第二部分。
- **讲解分「直觉与图像」与「严谨表述」两个视图，逐条对照**（ADR 0020）。前者是
  比喻、图示、动手拖，后者是定义、定理条件、计算步骤，**每条严谨陈述都带出处**。
  **「不要割裂两种关系」是硬约束**，靠三条机械保证：每条必填 `pairs` 指回直觉侧
  讲同一件事的那一段（指到本节不存在的锚点即报错）、两侧双向可跳且跳过去停在
  对应位置、每条必填 `plain` 用直觉侧的话复述一遍。**`plain` 写不出来是有用的
  失败信号**——说明这条在直觉侧没有对应，该补讲或该删，不要硬凑一句应付 lint。
  严谨视图**不是把教材抄一遍**，只收直觉侧确实讲到的那几条；也**不是难度升级的
  地方**，深浅由 `mastery_goal` 决定。默认停在直觉侧，标签一眼可见。
  例题与练习**不进标签页**：它们是两侧的汇合处，放进任一侧另一侧就看不到了。
- **每节配 1–3 道标准例题**（ADR 0019 第 4 节）。它是 ADR 0014 渐隐完形的第一级
  ——完整解答、读懂即可、不作答，此前整个缺失，使用者是从讲解被直接推去做题的。
  每一步的 `why`（为什么可以这么做）必填，只给「怎么算」就退化成了答案。
  数量与掌握目标匹配，不凑数。
- **为专注与持续投入设计**（ADR 0011）：**消除无效挫折**（卡住无出路、进度不可见、
  连续失败无回调、大块未知）——分级提示、步数可见、难度回调、渐进披露；
  **保留有效困难**，绝不降低掌握标准。**禁止**徽章、积分、连击、排行榜等外部奖励
  （挤出内在动机）；激励只来自能力感可见、好奇心闭环、理解的瞬间。要拉长的是
  **累计投入**，不是单次连续时长。
- **通用性决定权重**（ADR 0006）：思想（跨学科）＞ 方法（跨题型）＞ 算法
  （整类问题）＞ 技巧（单题）。前三层进主线且越通用篇幅越重，技巧进应试区。
  数学史是主线的一部分，但**只讲「卡住 → 突破」的关头**——判据是它能否解释某个
  概念为什么长成现在这样；人物轶事与优先权之争不写。
- **界面上不出现「考研」「数学一」这类考试字样**（沿用 `apps/english` 的做法）：
  窗口标题、课表标题、按钮和提示一律叫「数学学习」，用「基础 / 强化 / 冲刺」
  表达进阶。考试目标只写在 `docs/decisions/` 和本文里，不写进用户看得见的文案。
- **工具的角色是裁判，不是计算器**（ADR 0001）。考试闭卷手算，应用必须练用户
  自己的推导：先手写每一步，引擎判等并定位第一处出错的地方。**禁止**做成
  「输入题目 → 输出答案」。
- 不以做成通用 CAS、在线题库、公式速查手册或数值仿真平台为目标。

## 技术栈（本应用自有）

- **壳**：Tauri 2（Rust）
- **界面**：Vite + TypeScript（Web UI，非 GTK）
- **符号引擎**：**本机 Python 常驻进程 + SymPy**（ADR 0025 改，原为 Pyodide）。
  Rust 侧按需 spawn 一个长驻解释器，NDJSON 走 stdin/stdout，只付一次 `import`。
  环境是应用自带的 venv（`engine/.venv`），跑一次 `scripts/setup-engine.sh` 建好。
  **不**每次验算 fork 子进程——实测 `import sympy` 就要 315–584 ms，而判等本身
  只要 7–130 ms。**预热不能只 import**：`simplify` 首次调用还要再拉一批子模块，
  差别是 365 ms 对 11 ms，所以引擎启动时自己先跑一次 `simplify`。
  引擎**只回答 equal / different / unknown 三种**，`unknown` 不许折叠成
  `different`——判不出来不等于用户错了，误判比慢更致命。
- **公式渲染**：KaTeX（本地打包，不走 CDN）
- **公式输入**：MathLive（所见即所得，输出 LaTeX）。数学应用的核心交互是
  「写下我的下一步」，键盘敲 LaTeX 不可接受。
- **可视化**：静态示意用 SVG；需要拖参数实时响应的（ε-δ、泰勒逼近、旋转体、
  方向导数、二重积分区域）用前端 Canvas/SVG 自绘。曲面先用自写正交投影画
  线框，需要鼠标拖动旋转时再评估 three.js，**不**预先引入重型图表框架。
  概念节若「一上来不知道看哪」，课表可带 `walkthrough`：画布按关键帧演一遍，
  同时用系统语音念 `say`（ADR 0018）；不自动播放，演完必须能接着拖。
- **进度**：SQLite，写入用户数据目录 `AthenaMath/learning.db`，自建表、自迁移
  （主仓库 ADR 0037）。知识点 ID 前缀一律 `math.`（目录名是 `mathematics`，
  ID 前缀取短名，两者不同是有意为之）。

**不引入**：MATLAB、Octave（授权、启动开销、方向错位三重问题，见 ADR 0001）；
主程序的 Meson、gtkmm、Blueprint、`athena.json`。**Pyodide 降为备选**，触发条件
是「本应用要发行给不愿装 Python 的人」，在那之前不实现、不下载、不打包（ADR 0025）。

## 内容与教学分层

精神对齐「大纲 → 讲解 → 实验」，载体与主程序无关。课表唯一源是
`content/curriculum.json`。

数学的「实验」分四类，按知识点性质选用，**不强求配齐**：

| 形态 | 练什么 | 怎么做 |
|---|---|---|
| **推导验算** | 准确 | 用户逐步写出自己的推导，引擎判每步等价，定位第一处断裂 |
| **参数实验** | 直观 | 拖滑块看极限过程、级数逼近、曲面变形，先预测再看结果 |
| **现实闭环** | 意识 | 用真实数据/现象得出不用数学就得不到的结论，产出可留存物 |
| **限时做题** | 速度 | 按题型计时作答，判分后错题按错因入错题本 |

讲解侧另有两条思想线，**按杠杆分配、不平均用力**（ADR 0002）：

- **来龙去脉**：这个概念是被什么问题逼出来的。不是背景装饰，是理解的锚。
- **多重面孔**：同一对象在不同视角下的样子，优先写能统一多个章节的那种视角。

- **SymPy 只用来给有出处的母题做变式**（ADR 0019 后果一节收窄了原先的说法）：
  参数随机化生成的题必须挂在一道真实出处的母题上，`source` 继承母题并注明
  「参数随机化自 X」。脱离母题凭空生成的题属于 `authored`，受配额约束。
- 掌握度只由做题与验算结果写入，禁止手动标记熟练。
- 编写讲解时优先图、对照和可交互示意，不堆长文（对齐主仓库 ADR 0033、
  dsa ADR 0001）。概念（如可导与连续的关系）用正反例并排；技能（如换元积分）
  用示范加变式；策略（如选哪种积分法）在情境里选并说明依据。
- 篇幅与难度、掌握目标匹配，不写八股（主仓库 ADR 0040）。

## 架构原则

- **独立可运行**：`./scripts/dev.sh`（`tauri:dev`）不经过主程序。不要启动打包 `.app`。
- **内容驱动 UI**：改课优先改 `content/`，不为新节复制整页。
- **引擎只判不算**：任何把完整答案直接呈给用户的交互路径都需要 ADR 才能加。
- **壳要薄**：Rust 侧负责窗口、路径、进度；业务文案、课树和符号计算都不进 Rust。
- **与主程序零编译耦合**：主程序 Meson / `scripts/check.sh` 不构建本应用。

## 开发与验证

```sh
cd apps/mathematics
sh scripts/setup-engine.sh   # 只需跑一次：建 engine/.venv 并装 SymPy（验算功能要它）
./scripts/dev.sh             # 日常开发：改前端秒级热更新；主程序图谱也走这里
```

**验证改动一律走 `tauri:dev`。** 本应用绝大多数改动在前端（TS / CSS /
`content/*.json`），热更新即时可见；只有动了 `src-tauri/` 才需要重编 Rust。
把「跑一次 release 构建、装进 `bin/` 或 `/Applications`、再打开」放进改一次看一次
的循环里，每次要付两三分钟，是不可接受的（主仓库记忆 `dev-loop-not-release-build`）。
`build:app` / `build:dmg` 只在真正要交付一份可分发的包时才跑，**不是**打开本应用
的步骤，也不要把产物同步到 `/Applications`。

环境变量 `ATHENA_MATH_ROOT` 可强制指定应用根目录（含 `content/`）。

验证以本目录为准：前端 `npm run build`、Rust `cargo check`（在 `src-tauri`）。
**不必**为改本应用而跑主仓库 `scripts/check.sh`，除非同时改了主程序 discover。

只想核对**排版与样式**时，可以 `npm run build` 之后跑 `node scripts/make-preview.mjs`，
它在 `dist/` 里生成一个 `preview.html`，把 Tauri 命令换成读静态 JSON，用任意
静态服务器打开即可在浏览器里看页面。**它不能替代 `tauri:dev`**——进度库、语音、
窗口行为在那里全是假的，只有 HTML 与 CSS 是真的。

Pyodide 首次加载时间是本应用特有的性能预算，改动引擎加载路径后要实测一次
（目标见 ADR 0001 第 4 节）。

## 修改流程

1. 改课：先改 `content/`，再补前端展示类型（若有新实验形态）。
2. 改引擎交互：先确认没有违反「只判不算」，再动 `src/`。
3. 改运行时：只动 `src-tauri`，保持命令表面稳定。
4. 需要主程序图谱入口时，另提主仓库 `domain_graph` 变更（本期不挂）。
