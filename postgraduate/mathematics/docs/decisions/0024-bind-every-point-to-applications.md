# ADR 0024：知识点绑定应用，越多越好

- 日期：2026-09-14
- 状态：已接受
- 修正：ADR 0023 第 4 节（「跟现实结合」的判据整条撤销重写）
- 澄清：ADR 0003 第 3 节那句「不得用每个知识点挂个应用例子冒充」的适用范围

## 背景

ADR 0023 第 4 节写了这样一条判据：

> 判据一句话：**去掉那层情境，题目还成立吗？** 成立就说明情境是装饰，删掉它比
> 留着好。
>
> 标注方式：drill item 可带 `context` 字段。**不强制**——强制会直接逼出假应用。

使用者看到后直接纠正：

> 举现实例子还是很重要的，哪怕看起来不够现实，但有助于直观化理解。
>
> 「禁止给每个知识点硬挂应用例子」——**我没有这样的要求**。我觉得知识点绑定应用
> 是很好的大方向和习惯，**越多越好**。

### 1. 那条判据的方向是反的

「去掉情境题目还成立吗 → 成立就删掉」这条规则，**对几乎所有例子都成立**：数学
例子的情境本来就可以剥离，剥离之后剩下的算式当然还成立。照这条规则执行下去，
结果是**把例子全删光**。

它把一个本该防止「写错」的检查，错用成了防止「写多」。

### 2. ADR 0003 那句话管的不是这件事

ADR 0003 第 3 节写「建模线不得用『每个知识点挂个应用例子』冒充」。它的真实
适用范围是：**挂例子不能代替建模训练**——从现实问题到数学模型那一步（哪些量是
变量、该用什么结构描述、忽略什么）是建模线的独立职责，不能靠在章末附几个应用
就宣称覆盖了。

**它不是禁止挂例子。** 两件事并行不悖，而且都要多做。此前把这句话引用成「少举
例子」的依据，是误读。

## 决策

### 1. 知识点绑定应用是默认动作，不是可选项

**每个知识点都应该带至少一个现实用法。** 讲解、例题、习题，任何一处都可以承载，
不规定放在哪里。写不出来的时候，是去找，不是跳过。

### 2. 判断标准是「有没有帮助理解」，不是「够不够现实」

一个略显牵强、但能把抽象概念拉到可感知层面的例子，**胜过没有例子**。

| 该防的 | 不该防的 |
|---|---|
| 例子在**数学上不成立**（类比会把人带偏、推广到一般情形就错） | 例子不够「真实世界」 |
| 例子**比它要解释的概念还难懂** | 例子看起来简单甚至幼稚 |
| 用例子**冒充建模训练**（ADR 0003 的原意） | 例子数量多 |

误判的代价是不对称的：**例子多一点的代价很小，例子缺席的代价很大**——尤其对
ADR 0015 那个起点（不假设学过，靠直观建立理解）。

### 3. `context` 字段：鼓励填写，覆盖率纳入统计

- ADR 0023 第 4 节「不强制」的理由（怕逼出假应用）**撤销**：假应用的风险由第 2 节
  那张表管，靠的是写的时候判断例子对不对，不是靠少写。
- `context` 仍不设为 lint 的硬错误——但**覆盖率低于一半时 lint 发出警告**，
  让缺口一直可见，而不是悄悄地一直空着。
- 讲解侧已有 `hook`（这一节为什么需要它）承担同样职责，**继续保留并加强**。

### 4. 例子要标出处，但标准比严谨表述宽

现实用法的出处**尽量给**（ADR 0019 的精神），但不作硬性要求：「照片编辑器拉伸
图片面积会变」这种常识性场景，找不到也不该因此删掉。

**唯一的硬要求是不能编造事实**：不得声称某个具体的公司、产品、论文用了某个方法
而没有依据。泛指场景（「搜索引擎给网页排名」「传感器坏了恒输出零」）可以写。

## 后果

- ADR 0023 第 4 节整条作废，以本 ADR 第 2、3 节取代。
- 已写的题要回头补 `context`：行列式第二部分 5 道题目前只有 2 道标了。
- 后续每写一节，把「这个知识点用在哪」当成必答题，而不是有就写、没有就算。
- lint 增加覆盖率警告。
