# ADR 0025：符号引擎改用本机 Python 常驻进程；判据改为教学效果与成本收益

- 日期：2026-09-14
- 状态：已接受
- 修正：ADR 0001 第 2 节（引擎形态）与第 4 节（首选/次选的排序及其理由）
- 依赖：ADR 0001（工具当裁判不当计算器；引擎必须常驻）

## 背景

ADR 0001 第 4 节早就写了本方案，但把它排成**次选**：

> **超预算的回退**：改为 Rust 侧拉起一个长期存活的 Python 进程，用 stdin/stdout
> 通信。它同样只付一次 import，代价是要求用户机器有 Python 与 SymPy——**退回到
> 有外部依赖，故为次选**。

本 ADR 把首选与次选对调。**关键不在于哪个方案变好了，而在于当初排序用的判据
是错的。**

### 1. 「零外部运行时依赖」不是约束

使用者明确纠正：

> 「优先零外部运行时依赖」**前者不是约束，只看是否有必要、成本和收益**。

ADR 0001 给 sidecar 扣分的唯一理由就是「退回到有外部依赖」——把一条**默认倾向**
当成了否决项。正确的权衡顺序是：**教学效果 → 必要性 → 成本**。

更要命的是那次扣分用错了参照系：它拿「发行给陌生用户」的标准去衡量一个
**自用软件**（AGENTS.md 开篇即写明）。在自用场景下，「机器上要有 Python 和
SymPy」的成本是一条命令，而不是一个分发难题。

### 2. SymPy 是必要的，不是可选的

评估期间一度出现过另一个方向的误判：「大多数判等不需要 CAS，随机数值代入
（Schwartz–Zippel）就够」。**这句话对代数变形成立，对高数推导不成立**，而数学二
有约 78% 是高数。

原因是手写推导的中间步骤**经常带着尚未求值的符号**：

```
∫ x·e^(x²) dx
令 u = x²，du = 2x dx
= (1/2)∫ e^u du          ← 与上一步等价吗？
= (1/2)e^u + C
```

`∫e^u du` 代入数值没有意义，数值法判不了这一步；SymPy 可以——两边各求值，
相差常数即等价。`lim`、`Σ`、未展开的 `d/dx` 同理。而这正是 ADR 0001 想做的那件事
的核心场景。

结论：**问题不是「要不要 SymPy」，而是「SymPy 装在哪」。**

### 3. 按教学效果重新排

| | Pyodide + SymPy（原首选） | 本机 Python sidecar（本 ADR 采用） |
|---|---|---|
| **教学能力** | 完整 SymPy | 完整 SymPy **＋ numpy / scipy / matplotlib** |
| 判等速度 | WASM 比本机慢约 2–5 倍；ADR 0001 实测最慢的 `integrate` 62 ms，最坏放大到 300 ms 级，擦着 100 ms 预算的边 | 全速，按实测即 ADR 0001 那张表 |
| 装一次 | 下载 15–25 MB WASM 与 wheel | `pip install sympy` |
| 开发回路 | 每次冷启动等 WASM 编译数秒 | 进程常驻，前端热更新不受影响 |
| 机器需要 Python | 否 | 是——**自用场景下不构成扣分** |

**两处对 Pyodide 的常见误判，本 ADR 一并澄清**，免得日后据此反复：

- 「Pyodide 用不了 numpy/matplotlib」——**不成立**。Pyodide 官方提供 numpy、scipy、
  matplotlib、pandas 的预编译 wasm wheel。
- 「WASM 慢一个量级」——**夸大**。纯 Python 代码通常慢 2–5 倍。

即便澄清了这两点，排序结论不变：本机方案在速度、装配成本、开发回路三项上都更优，
而唯一的劣势（需要 Python）在自用场景下不成立。

### 4. matplotlib 的正确用法：预生成，不是实时

本机 Python 顺带打开了 matplotlib/numpy，但**不要用它做实时交互图**——拖滑块
每帧往返一次 Python 会卡，那部分仍由前端 Canvas 自绘（ADR 0001 第 1 节的
「参数实验」）。

它真正的用处是**写内容时预生成静态插图**：曲面、向量场、旋转体这类前端自绘很
费力的图，生成 SVG 存进 `resources/`，运行时零成本。这条与主仓库「静态示意用
SVG」的取向一致。

## 决策

### 1. 引擎形态：Rust 侧拉起一个常驻 Python 进程

- Rust `run()` 时**不启动**；**首次需要验算时按需启动**并常驻，只付一次 `import sympy`。
- 通信用 stdin/stdout，**一行一个 JSON**（NDJSON）。请求带 `id`，响应回同一个 `id`。
- 引擎崩溃时自动重启一次并如实报告；连续失败则报「引擎不可用」，**绝不退化为
  静默判错**（ADR 0001 第 1 节第 3 条）。

### 2. Python 环境：应用自带 venv，不污染系统

- 位置 `apps/mathematics/engine/.venv`，`.gitignore` 忽略。
- 由 `scripts/setup-engine.py` 显式创建（`python3 -m venv` + `pip install sympy`）。
  **不在构建里隐式执行**——沿用主仓库「scaffold 只能显式运行」的取向。
- 应用启动后检测 venv 与 `import sympy`；不可用时在界面上说明「验算功能需要先跑
  一次 `scripts/setup-engine.py`」并禁用验算入口，**而不是让用户对着转圈等**
  （ADR 0001 第 3 节）。
- 用 venv 而不是系统 `pip install` 的理由与洁癖无关：Python 3.12 起的 PEP 668 会
  直接拒绝往系统环境装包。

### 3. 引擎只回答三种结论

`equiv(a, b)` 返回 `equal` / `different` / `unknown`。

**`unknown` 是一等公民，不许折叠成 `different`。** ADR 0001 第 1 节第 3 条：
判等失败不等于用户错，可能只是 `simplify` 没化开；误判会摧毁工具可信度，比慢
更致命。

### 4. Rust 侧仍然不做数学

ADR 0001「Rust 侧完全不碰数学」继续有效，只是职责从「什么都不做」变成「**管一个
不做数学的进程**」：启动、重启、转发、超时。表达式解析、化简、判等全在 Python 侧，
Rust 不看内容。

### 5. Pyodide 不删除，降为备选

`vendor/pyodide/` 这条路线**保留在文档里**，触发条件明确：**当且仅当本应用要
发行给不愿装 Python 的人**。在那之前不实现、不下载、不打包。

## 实测（2026-09-14，本机 macOS，Python 3.14.7 + SymPy 1.14.0）

| 环节 | 耗时 |
|---|---|
| `import sympy` | 315–584 ms（多次测量，与 ADR 0001 的 508 ms 同量级） |
| **预热**（启动时跑一次 `simplify`） | 120–200 ms |
| 判等 `x²−1 ≟ (x−1)(x+1)` | **7–11 ms** |
| 判等 `sin²+cos² ≟ 1` | 39–107 ms |
| 判等 `∫x·e^(x²)dx ≟ e^(x²)/2` | 131 ms |
| 判等 `Limit(sin x/x, x→0) ≟ 1` | 12 ms |

**一条本来会掉进去的坑**：只 `import sympy` 不够。`simplify` 会在**首次调用时**再拉
一批子模块，实测头一次判等要 365 ms 而后续只要 3–40 ms。这 365 ms 会正好落在
用户写完第一步、最期待反馈的那一刻。因此引擎启动时自己跑一次 `simplify` 把这笔钱
付掉（第 1 节）；加上之后首次判等降到 11 ms。

**判等质量的抽样**（这些决定了工具可不可信，比速度重要）：

| 输入 | 判定 | 对不对 |
|---|---|---|
| `∫x·e^(x²)dx` ≟ `e^(x²)/2` | equal | ✓ 带未求值 ∫，数值法做不到——**这是选 SymPy 的全部理由** |
| `Limit(sin x/x,x,0)` ≟ `1` | equal | ✓ 同上 |
| `(x+1)²` ≟ `x²+1` | different | ✓ |
| `√(x²)` ≟ `x` | **unknown** | ✓ 只在 x≥0 时相等，**判 unknown 才是对的**，判 equal 就错了 |
| `log(xy)` ≟ `log x+log y` | unknown | 偏保守（同样只在特定域成立）。宁可保守，不可判错 |

## 后果

- ADR 0001 第 2 节「Pyodide + SymPy，打包进应用，跑在前端」作废，以本 ADR 第 1 节
  取代；第 4 节的首选/次选对调。
- ADR 0001 的「用户机器不需要装 Python」这条承诺**撤销**。自用软件，可接受。
- 目录表新增 `engine/`；`vendor/pyodide/` 从目录表移除（改列在本 ADR 第 5 节）。
- 前端多一个引擎状态（未就绪/就绪/不可用），验算入口跟着它显隐。
- 跨平台：venv 方案在 macOS 与 Ubuntu 上一致；Windows 未在支持范围内（本应用当前
  只跑 macOS 与 Ubuntu）。
- **已知限制**：首版用纯文本输入 SymPy 记号（`x**2`），不是 ADR 0001 第 5 节要的
  MathLive 所见即所得。SymPy 记号比 LaTeX 源码好写得多，作为试点可接受，
  但**这是临时形态**——MathLive 与 KaTeX 仍待接入。
