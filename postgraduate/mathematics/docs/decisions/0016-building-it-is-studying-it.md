# ADR 0016：编写这个软件本身就是学习动作；但要划清内容与工程的界

- 日期：2026-09-13
- 状态：已接受
- 修正：`docs/REFERENCES.md` 第六节「自造软件在时间上是净支出」的判断
- 依赖：ADR 0014（习题是检验器也是学习动作）、0011（专注）

## 背景

`docs/REFERENCES.md` 第六节曾给出一条判断：若目标仅是通过考试，用现成网课加真题
最高效，**自造软件在时间上是净支出**。

使用者指出这条判断错了：**编写数学软件本身就是把时间和专注力投在数学学习上**，
而这是看讲课视频解决不了的——看视频容易三心二意，缺少交互，缺失即时反馈。

### 那条判断错在哪

它把「写软件的时间」和「学数学的时间」当成了互斥的两件事。对**这个**软件不成立：

写一节内容，必须先把那个知识点彻底想清楚——该怎么讲、动机是什么、误区长什么样、
用哪个反例打破、怎么设计才能验证。这**本身就是最深的加工**。

本应用 ADR 0014 第 1 节列出的机制在这里全部成立，而且更强：

- **生成效应**：自己生成内容比接收内容记得牢；
- **通过教学来学习**（protégé effect）：为了讲给别人而准备材料的人，理解得更深、
  保持更久；
- **ADR 0014 的设计要求把这件事推到了极致**：诊断题的每个错误选项都必须是**一种
  具体的错误理解**，不许用随机干扰项。设计一道这样的题，比做十道题更需要真正
  理解那个知识点——因为你得先知道人会在哪里想歪、为什么那样想。

### 视频的问题

使用者的三条批评都对，而且与既有 ADR 对得上：

| 批评 | 对应 |
|---|---|
| 容易三心二意 | 单向媒介没有需要你做决定的时刻，注意力无处着落（ADR 0011） |
| 缺少交互 | 没有「预测 → 验证」闭环（ADR 0002 第 3 节） |
| 缺失即时反馈 | 反馈延迟破坏心流（ADR 0011 第 3 节） |

还有一条使用者没说但同样成立：**流畅性错觉在视频上最严重**。跟着老师的推导走，
每一步都懂；关掉视频，什么都推不出来（ADR 0014 第 2 节）。

## 决策

### 1. 撤销「净支出」的判断

`docs/REFERENCES.md` 第六节那条判断改为：**对已经学过一遍、只求通过考试的人成立；
对本应用的使用者不成立**——因为编写内容对他而言是深度学习，不是学习的准备工作。

### 2. 但必须划界：内容时间是学习，工程时间不是

这条界不划，本 ADR 就会变成「我一直在写代码所以我一直在学数学」的自欺。

| 类别 | 例 | 算不算学数学 |
|---|---|---|
| **内容** | 设计诊断题的误读选项、想清楚一个概念的动机、找反例、决定讲解顺序、校对数学表述 | **算**，而且是高强度的 |
| **工程** | 调端口冲突、配 Tauri、改构建脚本、排版 CSS、修类型错误 | **不算** |

工程是必要开销，但不应被计入学习时间，也不该成为回避内容的地方——**写代码比想
清楚一个概念舒服得多，这正是它容易被用来逃避的原因。**

判据：这段时间结束时，**你对某个数学知识点的理解有没有变化**？没有，它就是工程。

### 3. 推论：使用者应当参与内容编写，而不是全部外包

第 1 节的收益归**动手编写的人**。如果内容全部由代理写成，protégé effect 归代理
不归使用者，本 ADR 的论证就落空了。

因此建议的分工：

- **代理**承担工程，以及内容的初稿与结构；
- **使用者**至少承担**审读**——发现哪里讲错了、哪里不对劲、哪个误读选项不像真的
  误解。审读本身就是深度加工，且它同时是内容质量的唯一把关（代理会出错）；
- 学完某一节之后，**由使用者自己写那一节的小结或补一道题**，是收益最高的动作。

这不是流程要求，是对收益归属的说明。

## 后果

- `docs/REFERENCES.md` 第六节与第七节需按第 1 节修订措辞。
- 第 2 节的界线意味着项目节奏应当**以内容为主、工程够用即可**。工程上的完美主义
  （更漂亮的架构、更全的边界处理）在这个项目里是负收益，除非它服务于内容。
- 第 3 节意味着不应追求「代理一次性写完全部内容」。更好的节奏是：代理写一节 →
  使用者学 + 审 → 修正 → 下一节。这也正好符合 ADR 0012 的螺旋推进。
- 本 ADR 不改变 ADR 0005 第 7 节的防线二：编写软件带来的理解，不能替代应试区
  必需的熟练度训练。手算速度只能靠手算练出来。
