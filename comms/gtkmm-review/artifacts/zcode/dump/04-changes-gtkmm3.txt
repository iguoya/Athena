### 页 changes-gtkmm3  (page status=pending)
[0] para
  EN: gtkmm-3.0 is an old version of the gtkmm API that installs in parallel with the still older gtkmm-2.4 API and the new gtkmm-4.0 API. The last version of the gtkmm-2.4 API was gtkmm 2.24. gtkmm 3 has no major fundamental differences to gtkmm 2 but does make several small changes that were not possible while maintaining binary compatibility. If you never used the gtkmm-2.4 API then you can safely ignore this chapter.
  ZH: gtkmm-3.0是gtkmm API的旧版本它依旧能与gtkmm-2.4和新的gtkmm-4.0 API并行安装。gtkmm-2.4 API的最新版本是gtkmm 2.24。gtkmm3于gtkmm2之间并没有重大的改变，但确实存在一些微小的变动，这些变动导致无法做到令他们保持二进制兼容。如果你从未用过gtkmm-2.4 API 则你可以放心的忽略本章。

[1] para
  EN: gtkmm 3's library is called `libgtkmm-3.0` rather than `libgtkmm-2.4` and installs its headers in a similarly-versioned directory, so your pkg-config check should ask for `gtkmm-3.0`  rather than `gtkmm-2.4`.
  ZH: gtkmm3库调用libgtkmm-3.0而不是libgtkmm-2.4 并将其的头文件安装于类似的目录下，所以你的pkg-config应该检索gtkmm-3.0而不是gtkmm-2.4。

[2] para
  EN: gtkmm 3 added some new classes:
  ZH: gtkmm3添加了一些新的类：

[3] listitem
  EN: `Gtk::AppChooser`, `Gtk::AppChooserButton`, `Gtk::AppChooserDialog` allow the user to select an installed application to open a particular type of content.
  ZH: Gtk::AppChooser，Gtk::AppChooserButton,Gtk::AppChooserDialog允许用户选择已安装的应用程序用以打开特定类型的内容。

[4] listitem
  EN: `Gtk::Grid` is a new container widget that will eventually replace `Gtk::Box` and `Gtk::Table`. It arranges its children according to properties of those children rather than its own layout details.
  ZH: Gtk::Grid是一个新的容器部件他将在未来完全替换Gtk::Box和Gtk::Table。它根据它的子项的属性而不是自身的布局属性对子项进行排列。

[5] listitem
  EN: `Gtk::Switch` displays On/Off states more explicitly than `Gtk::CheckButton`. It may be useful, for instance, when allowing users to activate hardware.
  ZH: 与Gtk::CheckButton相比Gtk::Switch更明确的显示开/关状态。例如，在允许用户激活硬件的时候，他可能很有用。

[6] para
  EN: gtkmm 3 also made several small changes to the API, which you will probably encounter when porting code that used gtkmm-2.4. Here is a short list:
  ZH: gtkmm3还对API进行了一些小的变更，在移植gtkmm-2.4的代码的时候你可能会遇到这些变更。这是一个简短的清单：

[7] listitem
  EN: `Gtk::CellLayout`, used by `Gtk::IconView`, `Gtk::TreeView::Column` and `Gtk::ComboBox`, now has a `Gtk::CellArea` which can be used to specify more details of how the `CellRenderer`s are arranged and aligned.
  ZH: Gtk::IconView， Gtk::TreeView::Column和Gtk::ComboBox使用Gtk::CellLayout，现在有Gtk::CellArea可以用于指示CellRenderer的排列与对齐方式的详情。

[8] listitem
  EN: Gtk::ComboBox now derives from CellLayout, allowing easier layout and alignment of its `Gtk::CellRenderer`s.
  ZH: Gtk::ComboBox现在从CellLayout派生，从而使更容易对Gtk::CellRenderer进行布局与对齐。

[9] listitem
  EN: `Gtk::Adjustment` and `IconSet` and `Gdk::Cursor` are now used via `Glib::RefPtr`.
  ZH: Gtk::Adjustment和Gtk::IconSet类和Gdk::Cursor类现在通过Glib::RefPtr使用。

[10] listitem
  EN: `Gtk::Box`, `Gtk::ButtonBox`, `Gtk::IconView`, `Gtk::Paned`, `Gtk::ProgressBar`, `Gtk::ScaleButton`, `Gtk::Scrollbar` and `Gtk::Separator` now derive from `Gtk::Orientable`, allowing their
orientation (vertical or horizontal) to be specified without requiring the use of a derived class such as `Gtk::HBox`.
  ZH: Gtk::Box, Gtk::ButtonBox,Gtk::IconView, Gtk::Paned, Gtk::ProgressBar, Gtk::ScaleButton, Gtk::Scrollbar和Gtk::Separator现在从Gtk::Orientable派生，允许在不使用派生类(例如Gtk::HBox)的情况指定其方向(垂直或者水平)。

[11] listitem
  EN: `Gtk::IconView`, `Gtk::TextView`, `Gtk::TreeView` and other widgets derive from Scrollable instead of having their own methods such as get_vadjustment() and instead of having their own set_scroll_adjustments signal.
  ZH: Gtk::IconView, Gtk::TextView, Gtk::TreeView和其他部件派生自Scrollable而不使用他们自己的方法，例如get_vadjustment()拥有自己的set_scroll_adjustments信号。

[12] listitem
  EN: `Gtk::Style` and `Gtk::Rc` were removed, replaced by `Gtk::StyleContext`, and `Gtk::StyleProvider`s, such as `Gtk::CssProvider`.
  ZH: Gtk::Style和Gtk::Rc已被删除，由Gtk::StyleContext和Gtk::StyleProvider替换，例如Gtk::CssProvider。

[13] listitem
  EN: Widget::on_expose_event() was replaced by Widget::on_draw(), which assumes that cairomm is used for drawing, via the provided `Cairo::Context` and does not require you to call Cairo::Context::clip().
  ZH: Widget::on_expose_event()被Widget::on_draw()取代，通过提供的Cairo::Context使用cairomm进行绘制，并且不需要你自己调用Cairo::Context::clip()。

[14] listitem
  EN: `Gdk::RGBA` replaces `Color`, adding an alpha component for opacity. `Colormap` was removed, along with its awkward use to allocate colors.
  ZH: Color被Gdk::RGBA替代，添加alpha分量以支持透明度。Colormap与其笨拙的颜色分配方式一并被删除。

[15] listitem
  EN: `Gdk::Pixmap` and `Gdk::Bitmap` were removed in favor of `Gdk::Pixbuf`.
  ZH: Gdk::Pixmap和Gdk::Bitmap现在被Gdk::Pixbuf所取代。

[16] listitem
  EN: `Gdk::Drawable` was removed, with its methods moving into `Gdk::Window`.
  ZH: Gdk::Drawable被删除，与其有关的方法被移动到了Gdk::Window。

[17] listitem  <<<ZH缺失>>>
  EN: We now use std::vector in several methods instead of the intermediate *Handle types to make the API clearer.
  ZH: (无)

[18] para
  EN: All deprecated API was removed in gtkmm 3.0, though there have been new deprecations in later gtkmm 3.x versions.
  ZH: 在gtkmm 3.0中我们删除了所有弃用的API，尽管在gtkmm 3.x版本中出现了新的被弃用的API。

[19] para
  EN: As a first step to porting your source code to gtkmm-3.0 you should probably ensure that your application builds with the deprecated gtkmm-2.4 API disabled, by defining macro such as GTKMM_DISABLE_DEPRECATED. There are some autotools macros that can help with this by defining them optionally at build time. See the [gtkmm 3 porting wiki page](https://wiki.gnome.org/Projects/gtkmm/PortingToGtkmm3) for more details.
  ZH: 将源代码迁移到gtkmm-3.0的第一步，你应该通过定义GTKMM_DISABLE_DEPRECATED宏以检查你是否使用了在gtkmm-2.4中被弃用的API,然后删除他们。有一些autotools宏可以在编译时帮助你通过构建。访问gtkmm3移植Wiki了解更多详情。
