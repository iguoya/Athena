### 页 sec-listmodel-datamodel  (page status=translated)
[0] para
  EN: Lists are intended to be used whenever developers want to display many objects
in roughly the same way. They are perfectly fine to be used for very short lists
of only 2 or 3 items, but generally scale fine to thousands of items.
  ZH: 凡是想以大致相同的方式展示大量对象时，都适合用列表——极短的列表也完全没问题。

[1] para
  EN: Lists are meant to be used with changing data, both with the items themselves
changing as well as the list adding and removing items. Of course, they work just
as well with static data.
  ZH: 列表为「会变化的数据」而生：无论是条目自身内容变化，还是列表增删条目，都能胜任；静态数据同样工作正常。

[2] para
  EN: The [List Widget Overview](https://docs.gtk.org/gtk4/section-list-widget.html)
chapter in the GTK documentation contains more information about list widgets.
  ZH: GTK 文档的「List Widget Overview」一章包含关于列表控件的更多信息。

[3] para
  EN: Some examples are shown in this chapter. There are more examples in the
[listmodelviews directory](https://gitlab.gnome.org/GNOME/gtkmm-documentation/tree/&url_examples_branch;/examples/book/listmodelviews/)
in `gtkmm-documentation`'s examples.
  ZH: 本章展示了若干示例；gtkmm-documentation 仓库的 listmodelviews 目录里还有更多。

### 页 sec-listmodel-factory  (page status=translated)
[0] para
  EN: Data from the data model is added to the view by a factory, which is a subclass of
`ListItemFactory`. There is only one such subclass in gtkmm,
`SignalListItemFactory`. Data from the model is added to the
view with signal handlers connected to a `SignalListItemFactory`.
  ZH: 数据模型中的数据由工厂（factory）添加到视图。工厂是 `ListItemFactory` 的子类；gtkmm 中只有一个这样的子类——`SignalListItemFactory`。模型数据通过连接到 `SignalListItemFactory` 的信号处理函数添加进视图。

### 页 sec-listmodel-view  (page status=translated)
[0] para
  EN: The View is the widget that displays the model data and allows the user to interact
with it. The View can show all of the model's columns, or just some, and it can show
them in various ways.
  ZH: 视图（View）是显示模型数据并允许用户与之交互的控件。视图可以显示模型的全部列，也可以只显示部分列，并能以多种方式呈现。

[1] para
  EN: An important requirement for views (especially views of long lists) is that they need
to know which items are not visible so they can be recycled. Views achieve that by
implementing the `Scrollable` interface and expecting
to be placed directly into a `ScrolledWindow`.
  ZH: 视图（尤其是长列表视图）的一个重要需求是：必须知道哪些条目当前不可见，以便回收复用。视图通过实现 `Scrollable` 接口做到这一点，并期望被直接放进 `ScrolledWindow` 中。

[2] para
  EN: There are different view widgets to choose from.
  ZH: 有多种视图控件可供选择。

### 页 sec-listmodel-sorting  (page status=translated)
[0] para
  EN: The list can be sorted by wrapping it in a `SortListModel`.
There are two ways to do this.
  ZH: 把列表包进 `SortListModel` 即可排序。有两种做法。

[1] listitem
  EN: In a `ColumnView`, get the
  `ColumnViewSorter` from the `ColumnView`
  and set it to the `SortListModel`. Set a `Sorter`
  to each `ColumnViewColumn`. Then the user of your app can
  sort the items by clicking on a column heading.
  ZH: 在 `ColumnView` 中，从 ColumnView 取得 `ColumnViewSorter` 设给 `SortListModel`，再给每个 `ColumnViewColumn` 设置一个 `Sorter`。这样，应用的用户点击列标题即可排序条目。

[2] listitem
  EN: In any view, set a `Sorter` such as a
  `StringSorter` or a `NumericSorter`
  to the `SortListModel`.
  ZH: 在任意视图中，给 `SortListModel` 设置一个 `Sorter`（如 `StringSorter` 或 `NumericSorter`）。

### 页 sec-listmodel-trees  (page status=translated)
[0] para
  EN: While the deprecated `TreeView` provided built-in support for trees,
the list widgets, and in particular `Gio::ListModel`, do not.
However, gtkmm provides functionality to make trees look and behave like lists for
the people who still want to display lists. This is achieved by using the
`TreeListModel` to flatten a tree into a list.
The `TreeExpander` widget can then be used inside a listitem
to allow users to expand and collapse rows.
  ZH: 已弃用的 `TreeView` 内建了树形支持，而新的列表控件（尤其 `Gio::ListModel`）没有。不过，仍想展示树形结构的人可以用 gtkmm 提供的功能让树「看起来像列表」：用 `TreeListModel` 把树拍平成列表，再在 listitem 内使用 `TreeExpander` 控件展开/收起。
