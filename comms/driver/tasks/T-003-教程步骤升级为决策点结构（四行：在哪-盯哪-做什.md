## 目标

（2026-10-15 采纳 cursor 建议设立）教程正文现在每一步是「做什么 + 扣哪一条」，学员上车
执行不了。把四项的 steps 升级为**决策点**结构，每一步四行：

1. **此刻在哪**（车在场地什么位置、朝向）
2. **眼睛盯哪一对关系**（库角和车尾、内侧后轮和边线……）。只写关系：不写厘米、
   不写「门把手对齐某条线」之类的车型绑定点位——点位留给使用者的点位卡（ADR 0036 边界）。
3. **手脚做什么**。自动挡口径：脚停在刹车上控怠速，挡在 R 或 D。
4. **怎样算这一下做完**（车尾与库边线平行、前轮过线……）。

旁边照旧挂这一下的机器判定（caution + GA 条款），经验要点收进对应的那一下。


## 双视角增强（2026-10-15 19:45 leader 按使用者最终指示定稿）

使用者核心不满：**文字太多，视频/动画太少**。教程正文的视觉主体必须是双画面，
文字退为标注与朗读稿。每一步**两个画面共用一个进度**（点第几步，两边一起停住）：

1. **车外旁观格**（现有动画改造）：机位从俯视换成站在场边看这辆车——车身相对库线/
   弯道在哪、哪个轮靠近哪条线；旁观可见的扣分点（压线、车身出线、中途停车）直接
   标在画面上。
2. **车内操作格**（新增示意画）：从驾驶座看这一下——参照关系（前部过了内角、车身
   走弯道外侧、后视镜里的库角与库边线）、新手本能的**错参照**显式画出（一看见弯就
   打、贴内侧走、探头出窗）、脚/挡/方向状态。
3. **参照物关联（灵魂）**：车内格高亮的参照，要在车外格同步高亮它对应的车外几何
   （同色标注或连线）——把「车里凭感觉的一眼」锚定到「车外可验证的车身与线」。
   两格不是并排的两张画，是同一时刻的两个镜头。
4. **文字瘦身**：成段步骤正文退为朗读稿与悬停详情；画面标注用短标签。注意事项跟
   车内格的手脚走；扣分点跟车外格的结果走。
5. 不做实拍（考场车≠教练车、点位不进仓库、长视频切不开成单步两镜）；具体点位
   （门把手、哪格后视镜）仍只进个人点位卡。
6. schema：steps 每步加双视角字段（车内参照 + 错参照 + 操控；车外焦点 + 扣分标注），
   结构你定，content_test 覆盖；边播边念的讲解稿按「车外先全局、车内再看参照」的
   顺序念（编排你定）；动画步骤条数不变的硬约束照旧。

## 硬约束

- **每项步骤条数不变**：动画步骤与 steps 一一对应，测试守着条数（subject2.json `_` 字段
  说明）；只改字段结构与文案，drill.dart 的动画几何不动。
- 「教练车和考试车分两栏」的点位卡改动**不做**（个人数据功能维持现状，本轮范围外）。
- 边播边念的讲解稿（ADR 0040，narration）跟着新结构念；「怎样算做完」一行念出来正好是
  这一步的完成口令。
- schema 变更（steps 内加字段）要 content_test 覆盖；guide.dart 渲染、subject2.dart
  手册区展示适配。

## 做法（分两批交 review）

- **批一**：curve + corner（步数少，打通 schema 与渲染），交一次 review。
- **批二**：parallel + reverse（步数多，含换向最频繁的倒库），交第二次 review。
- tips 里与步骤重复的条目收编进对应决策点后删除，剩下的保留——同一组东西不写两遍
  （ADR 0040 言简意赅）。
