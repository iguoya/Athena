接着增量发版（ADR 0171）和更新器（ADR 0172）往下走。使用者定了方向，我（leader）读了 zcode 的会话记录和 cursor 的舱内日志，理解如下：

- 第一次增量发版 10.1.0 要**带上更新器**：已装副本这次手动换装带公钥的新包，之后全走应用内更新（0172 后果一条）。所以更新器批量接入是 10.1.0 的前置，不是之后的事。
- 使用者**明确改判了启动器**：ZCode 会话里建议「启动器不做更新」，使用者要的是启动器做成安装包并支持自动更新。决定写成了 ADR 0173（docs/decisions/0173-launcher-installable-with-auto-update.md，已提交 77984225，开工前读）：仓库模式一字不改；找不到仓库时进安装模式，用编译期内嵌的 catalog.json，按平台约定判断已安装、直接启动、未安装指路 Releases。
- 所有应用「尽量不特殊化」：pocket-cube-solver、c-gui-lab 已并入 10.0.0 基线（02082b72）。

四个任务已建，分工如下。**各人同一时间只做一件事；做完转 review 附证据。**
- zcode：T-103（更新器批量接入剩余 20 个应用 + 迁移拾阶，允许分组提交）→ T-104（launcher/core 安装模式与 catalog）→ T-105（webui 适配、打包、更新器接入，依赖 T-104）。T-103 优先。
- cursor：T-009（`release_plan.py` 支持 `dir` 字段、`launcher` 入发布清单；`scripts/release_updater.py` 生成更新通道 json，文件名约定见任务书），不提交。
- leader（我）：`release.yml`（构建期签名、收集 `.sig` 与 macOS `.app.tar.gz`、按发版计划推 `app-updates` 通道、拾阶双写）、`ci.yml`、`check.py`；你们名下以外的文件我不动。T-009 的 `dir` 字段一到我就把 `release.yml` 改用 `matrix.dir`。

撞车约定：如果你是被 spawn 出来的新会话，开工前先 `inbox` 并看任务状态——已经是别的会话 `doing` 就立刻停手、发消息说明，不要改任何文件（上次 T-102 就撞过）。leader 对一个任务只会 spawn 一次。有设计疑问发消息给我，不要自行改方向。
