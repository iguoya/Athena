## 背景
ADR 0171（docs/decisions/0171-incremental-release-per-app-versions.md，必读）：每个应用的真实版本写在各栈原生清单里，CI 不再用 tag 改写，只校验。现在 37 个 Tauri 应用的 `tauri.conf.json` 都是占位的 `0.1.0`（北极星 0.2.0），驾考 `pubspec.yaml` 是过期的 `8.0.0+1`；而 10.0.0 已发布的安装包是按 tag 写入 10.0.0 的。本任务把清单**回填成真实基线**，一个不改行为的提交（旧 `release.yml` 构建时仍会用 tag 覆盖版本，回填期间无害）。

## 名下路径（本任务新增，leader 已写进舱 config）
各应用的版本清单文件（只改版本那一行）：`<root>/<app>/src-tauri/tauri.conf.json`、`certification/driver/pubspec.yaml`、`practice/cpp/meson.build`、`practice/c-gui-lab/package.json`。`package-lock.json` 里 c-gui-lab 自己的版本字段（如有）同步改。

## 要做的事
1. **已发布过的应用一律回填 `10.0.0`**：`.github/workflows/release.yml` 里 `tauri-apps` 矩阵的 22 个应用中，除 `pocket-cube-solver` 外的 21 个（algorithms、c-plus-plus、chinese-chess、comms-console、competitions、cs408、data-structures、design-patterns、earth、embedded、gtkmm、jiuzhou、math-tools、mathematics、octave-manual、polaris、selinger-linear-algebra、siefken-linear-algebra、snake、software、sympy-tutorial）；加上 `postgraduate/ascent`（拾阶，更新器按 semver 比较，**绝对不能低于 10.0.0**）、`certification/driver`（`pubspec.yaml` 写 `10.0.0+<原构建号，没有就 +1>`）、`practice/cpp`（`meson.build` 的 project version 本来就是 10.0.0，核对即可，不用改）。
2. **首发的新应用写首发版本**：`programming/pocket-cube-solver` 写 `1.0.0`；`practice/c-gui-lab`（Electron，本周期才进 `release.yml`，没有发过）的 `package.json` 写 `1.0.0`（leader 按同一道理推定，使用者没有单独确认，交付说明里请单独标一句）。
3. **只改版本那一行**：不要把 JSON 整体重新序列化（会改缩进和换行，污染 diff）。用精确的文本替换，提交后 `git diff --stat` 每个文件应当只有 1 行改动。
4. **不要动 `Cargo.toml` 的版本**（改它会连带 `Cargo.lock`，干扰后面的依赖图判断）。
5. 回填后检查：每个文件的新版本能被 JSON / YAML / meson 正常解析；跑 `python scripts/check.py --sources-only` 与抽查 3 个应用的 `python scripts/check.py <应用>`（选 gtkmm、snake、driver），都要绿（本机 Windows 的环境坑见 `docs/RELEASE-TODO.md` 末尾那条，别踩）。
