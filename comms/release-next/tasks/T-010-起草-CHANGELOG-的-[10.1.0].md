## 背景
10.1.0 是第一次**增量发版**（ADR 0171）：应用各有自己的版本号，只构建有改动的应用；同时所有 Tauri 应用接入应用内自动更新（ADR 0172），启动器做成安装包并可自动更新（ADR 0173）。发版前要有一份写给使用者看的 `CHANGELOG.md` 的 `[10.1.0]` 节。`prepare` 在缺这一节时才会按提交生成机械底稿，我们要手写，不要底稿。

## 要做的事
在 `CHANGELOG.md` 里**直接**新增 `## [10.1.0] - 2026-10-21` 一节（放在 `[10.0.0]` 之前），写完不提交，转 review，我（leader）过目后一起提交。

写法照 `CHANGELOG.md` 文件头的约定和 `[10.0.0]` 的风格（先读它们）：
- 每节就是同名 GitHub Release 的正文，**写给使用者看，不堆提交标题**；按应用或工作线分小节；变化按「新增 / 变更 / 修复 / 移除」分组。
- 有「不兼容、需要手动跟进」的才标 ⚠️。本版的 ⚠️ 条目：**已装的 10.0.0 副本需要手动换装一次带更新公钥的新安装包**（这之后更新全走应用内通道）；`pocket-cube-solver` 与 `c-gui-lab` 首次进入发布。是否还有别的，你读了提交自己判断，别凭印象。
- 本版**没有**写成已完成的东西不要写：看 `docs/RELEASE-TODO.md` 里未勾选的条目（驾考 T-012 等、machine 等 Tauri 迁移、edge-ai 空壳）。

材料来源（都要自己核对，不要凭印象）：
- `git log v10.0.0..HEAD --oneline` 与 `python scripts/release_plan.py plan --base v10.0.0` 的输出（哪些应用有改动、为什么）。注意：更新器批量接入之后，几乎所有 Tauri 应用都会有改动，这是机制带来的，不要把它们每个都写成「更新了功能」——更新器那一条用一句话概括，应用各自的实质变化另写。
- 主线（你来取舍和排序）：增量发版与应用各有版本号；应用内自动更新（启动即静默检查、下载安装、自动重启，失败静默）；启动器可安装、有安装模式；贪吃蛇、中国象棋、C++ 教程、二阶魔方的题库整改；`pocket-cube-solver` 新应用；`c-gui-lab` Windows 安装包；驾考科目二倒库实拍素材；依赖安全升级（electron、katex、maplibre-gl 等）；发版体检 `release.py readiness`；gtkmm 原生演示补 Windows/macOS 两档。
- 具体数字、名称（应用的中文名）以仓库为准，查 `app.json` 的 `title`。

## 验收口径
- 通篇中文、人话，不出现 `feat(...)` 一类前缀；不超过 `[10.0.0]` 节的篇幅的一半（本版是增量，不是重排大版本）。
- 每条能在仓库里找到出处（提交或文档）；我会抽查三条。
- 对照 `python scripts/release.py prepare --minor --dry-run` 的输出，应用名和版本号不能写错（升到几以 dry-run 为准，写作时那份输出可能还会变，你写「X 升到新版本」而不是写死数字，版本表由 CI 自动附在 Release 末尾）。
