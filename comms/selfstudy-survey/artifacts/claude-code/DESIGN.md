# 自考专业调查——设计与采集规程（v1，2026-10-24）

对应 ADR 0186。本稿是 leader 的设计，zcode 先读完再在 T-001 里给反馈；反馈有道理就改本稿（改动记在末尾「修订」）。

## 1. 目标与边界

回答使用者的一个问题：**2025–2026 年，全国各省的自考本科里，计算机类（0809）和电子信息类（0807）到底开了什么、考什么、怎么学。**
不是学某一门课，不替人选专业。三个读者场景（界面编排的依据）：

1. **想找一个能报的专业**：我在某省，专科是 X，有哪些专业可报、谁主考、考几门、总学分多少。→ 省份视图、总览矩阵
2. **想比较同一个专业在各省的差异**：同样叫「计算机科学与技术」，广东和江苏考的课差在哪、实践课有没有、毕业设计怎么做。→ 专业视图的课程对比矩阵
3. **想知道一门课怎么备**：这门课在哪些省出现、用什么教材、有没有实践考核、对应 Athena 里哪门课。→ 课程视图、教材视图

范围：本科（含专科起点本科）；0809 计算机类、0807 电子信息类为核心，0808 自动化类作对照（只收各省实际开考的）；0806 电气类不收。
时间：2025-04、2025-10、2026-04、2026-10 四个考期的现行计划，新旧计划并存的并列。

## 2. 信息来源与可信度

来源等级（写入 `verify.level`）：

| level | 来源 | 能支撑什么 |
|---|---|---|
| `official` | 省教育考试院 / 主考院校官网的原文（公告、专业考试计划 PDF、课程设置表） | 一切 |
| `notice` | 教育部教育考试院；省考试院主管的官方门户（如各省「自考网」若归属考试院）；官方公众号原文 | 一切（须注明是怎样的 notice） |
| `report` | 第三方自考网转载（edu-edu、zikao365、自考本科网等） | **只能作线索**，不能单独写进 `plans`；开设矩阵里可写 `status` 但 `verify.level` 必须是 report，界面会标「待官方核对」 |
| `pending` | 没查过 | 不得带 source/date |

`verify.date` 就抄证据文件头的 `fetched`（同一天）；证据文件头的 `sha256` 定义为「去掉 `sha256:` 那一行后其余全部字节的哈希」，可复现。每省证据目录放一个 `index.md`：证据文件 → 覆盖了哪些字段，抽查直接按它回原文，**抽查以快照为准、不以线上为准**（页面会改版）。

规则：
- 非 `pending` 的条目必须有 `http(s)` 来源（能用 https 就用 https；部分省考试院只提供 http）和 `YYYY-MM-DD` 核对日期（抓取当日）。
- **绝不凭印象、凭邻省、凭往年推断补空**。同一个专业同一个省，页面上看不出是 2025 版还是 2026 版的，要写进 `note`，并把 `version` 写「未标注」。
- 官方站点常用 PDF / 图片 / 动态页发计划：能抽文本就抽；是图片的做一次逐字抄录并在证据清单标「OCR/人工抄录」；抄不准的字段写 pending。
- 页面可能改版下架：证据快照（文本，必要时 PDF）存 `artifacts/zcode/evidence/<省id>/`，文件头：
  ```
  url: https://…
  fetched: 2026-10-24
  sha256: <正文字节的 sha256>
  note: 页面标题、版本、怎么取得
  ```
- 通过率、难度、「好不好过」：官方不公布，**不采集**。

## 3. 数据模型

目录 `mentor/selfstudy-survey/content/`：

```
scope.json            leader   专业类与专业（教育部目录）、核心/边缘分级
athena-map.json       leader   课程代码 → Athena 课程显示名（只写显示名，ADR 0032）
courses/<成员>.json     各自   课程库分片：课程代码 → 名称等（两个代理并行，分文件防覆盖；读取时合并，同键须同内容）
textbooks/<成员>.json   各自   教材库分片
provinces/<id>.json   zcode    一个省一个文件：考试院、考期、政策、开设、计划、变动
```

省 id 用全拼小写：`beijing tianjin hebei shanxi neimenggu liaoning jilin heilongjiang shanghai jiangsu zhejiang anhui fujian jiangxi shandong henan hubei hunan guangdong guangxi hainan chongqing sichuan guizhou yunnan xizang shaanxi gansu qinghai ningxia xinjiang`（陕西 shaanxi、山西 shanxi）。港澳台不在范围。

### 3.1 通用 `verify`

```json
{"level": "official", "source": "https://…", "date": "2026-10-24", "note": "可选，说明怎么取得、哪里不确定"}
```
`pending`：`{"level": "pending"}`，不带别的字段。

### 3.2 `provinces/<id>.json`

```jsonc
{
  "schema": 1,
  "id": "guangdong",
  "name": "广东省",
  "authority": { "name": "广东省教育考试院", "url": "https://…", "verify": V },   // 自考主管机构与入口页
  "calendar": [                                                                   // 2025-04 起至 2026-10 的现行安排，一省有几个考期写几条（广东有 1 月，江苏有 1/7 月）
    { "session": "2026-04", "exam": "2026-04-11~12", "register": "2026-03-01~03-10", "note": "", "verify": V }
  ],
  "policy": {                                                                     // 每项独立 verify；查不到整项 null
    "entry":    { "text": "专科（或以上）毕业方可报本科段；专科专业与本科专业不对口者须加考", "verify": V },
    "graduate": { "text": "毕业学分/门数规定", "verify": V },
    "degree":   { "text": "学士学位授予条件（含学位英语/加试）", "verify": V },
    "exemption":{ "text": "课程免考、学分互认规定", "verify": V }
  },
  "offerings": [                                                                  // 一条 = 省 × 专业 × 方向
    {
      "major": "080901",            // 教育部专业目录代码，scope.json 里必须存在
      "track": null,                 // 方向（如「计算机及应用」「移动商务技术」），没有就 null
      "local_code": "080901",        // 该省实际使用的专业代码（如四川 H080901），不同才写
      "status": "open",              // open 开考 | stopped 停考 | upcoming 新计划已公布未生效 | none 经核实不开设 | pending
      "hosts": ["华南理工大学"],      // 主考院校，可多个
      "plans": ["gd-080901-scut-2021"],   // 引用本文件 plans 的 id，可空
      "verify": V                    // status=none 也必须有 verify（官方专业目录里没有该专业）
    }
  ],
  "plans": [ /* 见 3.3 */ ],
  "events": [                                                                     // 新旧计划切换、停考、代码更换、政策变化
    { "date": "2026-04", "kind": "new-plan", "major": "080701", "text": "…", "verify": V }
    // kind: new-plan | stop | code-change | policy | other；date 精度到月或日
  ]
}
```

### 3.3 `plans[]`：一份具体的专业考试计划

```jsonc
{
  "id": "gd-080901-2026",            // 省前缀-专业-版本，全局唯一；计划全省统一时一省一专业一份，主考院校间计划确有差异才拆多份并在 id 里加院校简称
  "major": "080901",
  "track": null,
  "hosts": ["华南理工大学", "广东外语外贸大学"],   // 主考院校，全省统一的计划列出全部
  "version": "2021版",                // 页面标明的版本；看不出写「未标注」
  "effective": "2021-04",            // 生效考期，不明写 null
  "state": "current",                // current 现行 | legacy 旧计划（过渡期内仍可报考/考完，与新计划并存时两份都写，用 events 说明切换）| upcoming 已公布未生效 | superseded 已完全取代只留档
  "total_credits": 73,               // 计划规定的总学分（含公共课），不明写 null
  "required_credits": 73,            // 毕业最低学分，不明写 null；与 total 不同时在 rules 解释
  "rules": "选考门数与学分要求的原话要点",
  "courses": [
    {
      "code": "15040",
      "name": "习近平新时代中国特色社会主义思想概论",   // 与 courses.json 的 name 一致；该计划里写法不同，放 alias
      "credits": 3,
      "category": "public",          // public 公共课 | required 必考（计划未细分基础/核心时用）| basic 专业基础 | core 专业核心 | elective 选考 | topup 加考（专科不对口须加考的课）| practice 实践课（理论课配套的实践课行带 pair=理论课代码）| graduation 毕业环节
      "elective_group": null,        // 选考组名，必考为 null
      "exam": null,                  // unified | provincial | host；省级课程表通常不标，页面没写就 null，不靠课程代码反推
      "practice": null,              // 课程内含实践考核时：{"type": "上机|实验|设计|项目", "credits": 1, "note": ""}
      "textbook": "tb-xxxxxx",       // textbooks.json 的 id；不明 null
      "note": ""
    }
  ],
  "graduation": {                     // 毕业环节：毕业设计（论文）、答辩、实践考核
    "thesis": true,
    "credits": 0,
    "note": "毕业设计（07999），不计学分，由主考院校组织答辩"
  },
  "source_files": ["gd602026.txt"],   // 可选：计划原文在证据目录里的文件名，便于抽查直接定位
  "verify": V                         // level 只能是 official / notice
}
```

课程行是 plan 内的**行**（学分、类别因计划而异），课程本身的名称等放 `courses.json`，教材放 `textbooks.json`。

### 3.4 `courses.json`

```json
{ "_": "…", "schema": 1,
  "courses": {
    "02331": { "name": "数据结构", "aliases": [], "kind": "theory", "note": "" }
  } }
```
`kind`：`theory` 理论 | `practice` 独立实践课 | `mixed` 含实践考核 | `graduation` 毕业环节。代码是主键，**同代码同名**；同名不同代码（课程换代）都登记，用 `note` 说明替代关系。

### 3.5 `textbooks.json`

```json
{ "_": "…", "schema": 1,
  "textbooks": {
    "tb-ds-2012-qinghua": {
      "title": "数据结构", "authors": ["…"], "publisher": "…", "edition": "2012年版", "isbn": null,
      "kind": "national",   // national 全国统编 | host 主考院校编 | provincial 省编 | other
      "outline": "考试大纲出处 URL 或说明",
      "verify": V
    } } }
```
教材 id：`tb-<关键词>-<出版年>-<出版社简称>`，小写英文数字连字符；ISBN 抄不准就写 null，不猜。

### 3.6 `scope.json` / `athena-map.json`

leader 维护，zcode 不改。`scope.json` 列出专业类（`0807`、`0808`、`0809`）和每个专业（代码、名称、`tier`: core/edge、`degree` 学位门类）；
采集中遇到目录里没有的专业（如各省自设方向），先写进 `offerings` 的 `track`，不新造专业代码。

## 4. 界面编排（给 zcode 看，让数据对得上）

```
┌────────┬──────────────────────────────────────────────────────────┐
│ 总览   │ ▌覆盖进度：31 省 · 12 专业 · 计划 xx 份 · 官方核对 yy%      │
│ 专业   │ ┌ 省 × 专业 开设矩阵 ────────────────────────────────┐   │
│ 省份   │ │         080901 080902 080903 080701 080703 …     │   │
│ 课程   │ │ 北京     ●开考   ○待查  ·无    ●      ○        │   │
│ 教材   │ │ 广东     ●●(2)   ●      ○      ●      …        │   │  点格子 → 该省该专业的计划
│ 实践   │ └────────────────────────────────────────────────────┘   │
│ 变动   │ 筛选：专业类 · 状态 · 核对级别                              │
│ 方法   │                                                           │
└────────┴──────────────────────────────────────────────────────────┘
```

- **专业视图**：选一个专业 → 顶部「全国格局」（几个省开、几个主考院校），主体是**课程对比矩阵**：行是课程（按代码并集），列是各省的计划，格内
  显示学分/类别，没有则空；高亮「全国都有的核心课」和「只有个别省有的课」。
- **省份视图**：考试院入口、考期、政策、该省开考的专业列表（可展开到计划）、变动。
- **课程视图**：搜索课程名/代码；详情显示出现在哪些省/专业、学分与类别分布、教材、实践要求、Athena 对应课程。
- **教材视图**：教材清单，按课程/出版社/类型筛选，显示用于哪些课程。
- **实践视图**：把实践相关汇总——含实践考核的课程、独立实践课、毕业设计/论文的做法，按省/专业对比。
- **变动视图**：时间线，新旧计划切换、停考、代码更换。
- **方法与来源**：来源等级图例、核对规则、各省核对覆盖率表（诚实地露出缺口）。

深色随系统偏好；窗口 ≥ 720 宽；表格宽于窗口时容器内横向滚动。

## 5. 分工与波次（v1，待 T-001 反馈）

| | claude-code (leader) | zcode (worker) |
|---|---|---|
| 设计 | ADR、数据模型、本稿、校验脚本 `check.py` | T-001 评审与反馈 |
| 应用 | 壳、UI、构建、登记文档 | — |
| 采集 | 试点两省（广东、江苏）自写，验证模型 | 同一批独立采集，交叉核对；之后全部省份 |
| 验收 | 抽查原文逐条核对 | 自查 + 证据清单 |

波次：A 省份基线（31 省）→ B 开设矩阵（核心 8~10 个专业 × 31 省）→ C 课程计划（试点五省：广东、江苏、四川、北京、湖北 → 铺开，
覆盖每个「开设矩阵里非 none 的格子」）→ D 教材大纲。波 B 先于波 C，因为矩阵决定了计划采集的工作量与顺序。

核心专业清单（初稿，波 B 之后按实际开考情况增删）：
0809 计算机类——080901 计算机科学与技术、080902 软件工程、080903 网络工程、080904K 信息安全、080905 物联网工程、
080910T 数据科学与大数据技术、080911TK 网络空间安全；
0807 电子信息类——080701 电子信息工程、080703 通信工程、080702 电子科学与技术、080714T 电子信息科学与技术、080717T 人工智能、080710T 集成电路设计与集成系统；
0808 自动化类——080801 自动化（边缘）。
注意：自考的「专业」常带方向（如「计算机及应用」「计算机网络」），以考试院口径为准，登记为 `track`。

## 6. 验收口径（每波通用）

- 结构：`scripts/check.py` 全绿（枚举、引用、verify 规则、id 唯一、课程代码在 `courses.json`、教材在 `textbooks.json`）。
- 抽查：leader 每波随机抽 ≥ 10% 的数据条目回到来源原文逐字段核对；**课程代码、学分、类别、教材版次错一处视为不过**。
- 覆盖：转 review 时 `--note` 写「N 省 M 专业 K 份计划，pending 清单与原因」。有意跳过的省/专业写明原因，不隐藏。

## 修订

- 2026-10-24（采纳 zcode 评审 REVIEW.md）：
  1. 考期不固定四个，一省有几个写几条（`session` 为 `YYYY-MM`）。
  2. 新增 `topup`（加考）类别；新增计划 `state: legacy`（过渡期旧计划）。
  3. 计划全省统一：`host` 改 `hosts[]`，id 去掉院校简称（有差异才拆）。
  4. `exam` 接受大面积 null，不反推。
  5. `verify.date` 抄 `fetched`；sha256 定义与每省证据 `index.md`；抽查以快照为准；计划可挂 `source_files`。
  6. `status: none` 的核实依据强制挂「全省开考专业总表」URL（广东即 2026 年 4、10 月课程表）。
  7. 波 A 与波 B 合并采集（同一批页面，数据仍分层写）；波 D 先采教育部教育考试院的全国统考教材目录，再逐省补省编/院校教材。
  8. 实践视图保留（数据已有广东实践课行单列代码，不薄），若采集后仍薄再并入专业详情。
  9. 新增 `required`（必考，计划未细分基础/核心时用）与实践课行 `pair`（广东实践课与理论课各有课程代码、学分）。
- 经验（leader 的广东试点）：省考试院「新开考专业通知」「专业调整通知」「年度开考课程与教材通知」三类公告的 PDF 附件基本能覆盖计划、课程、教材、主考院校；
  官方站点需带浏览器 User-Agent 才能下载 PDF；第三方自考网证书过期等问题不要绕过，改找官方 PDF。
