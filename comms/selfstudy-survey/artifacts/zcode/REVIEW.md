# DESIGN.md 评审（T-001 第 1 项）

评审人：zcode（worker）· 2026-10-24 · 针对 `artifacts/claude-code/DESIGN.md` v1
（本稿合并了目录中先在的 zcode 草稿 §1~§4 与本轮探路/试采后的补充：§1.7~§1.9、§5 探路印证；两版结论一致处不重复。）
总体判断：模型方向对，来源分级和「不推断」纪律是全文最有价值的部分。以下按「对不上现实的概率」排序，前四条建议必改。

## 1. 模型对不上现实的点

### 1.1 calendar 固定四个考期会漏（建议必改）
DESIGN §3.2 把考期写成 2025-04/2025-10/2026-04/2026-10。现实中**各省考期数不同**：广东一年三考（1、4、10 月），江苏一年四考（1、4、7、10 月），多数省两考。若 calendar 只允许这四条，江苏广东的 1 月/7 月考期没地方放，而「什么时候能考」恰恰是报考者最关心的。
**建议**：session 就是自由字符串（`"2026-01"`），ADR 里「四个考期」改述为「至少覆盖 2025-04 起至 2026-10 的现行安排，省有加考期的照实多列」；再给 calendar 项加 `kind: national|provincial`（全国统考/省加考），与课程行 exam 字段呼应。

### 1.2 加考课没有落点（建议必改）
`plans[].courses[].category` 枚举 public/basic/core/elective/practice/graduation，但「独立本科段」计划里普遍存在**加考课**（专科不对口须加考若干门，如广东部分专业），它既不是选考组也不是毕业环节。
**建议**：category 增加 `topup`（加考），或明确「加考课用 elective_group 表达、组名如 `加考`」。二选一都行，但要写死一种，否则我采集时只能自己发明。

### 1.3 多主考院校会让 plan 重复（建议必改）
`plans[].id` 含主考院校简称（`gd-080901-scut-2021`），但一个省一个专业常有多所主考院校（考生自选），而**课程计划是全省统一的**，差异只在毕业论文/实践环节组织。按现模型，3 所主考院校 = 3 份一字不差的 plan。
广东是实锤：080901 有 5+ 所主考学校、每校不同「专业课程组」（华南师范[深圳大学]、广东财经[嵌入式技术/计算机及应用/移动商务技术]、华南理工[广东外语外贸大学]，2026-08 又增加广东工业大学），而粤考委〔2023〕5 号明文「同一专业代码、名称仅设置一个专业考试计划，之前承担各专业考试计划的主考学校同时成为该专业的主考学校」——一份计划 × 多主考 × 课程组是广东常态。
**建议**：计划全省唯一的，id 用 `<省>-<专业>-<版本>`（如 `gd-080901-2026`），把 host 从 plan 移到 offerings（已有 hosts 数组）；「课程组」正是 offerings.track 的活例子，广东一条专业按主考×课程组拆多条 offering，共享同一 plan id。

### 1.4 四川双轨没有落点（建议必改）
四川同一专业两套省码、两类办学：**社会型 H080901 / 应用型 W080901**（应用型=高校助学），衔接表还区分 B/Y 旧码。模型里没有「办学模式」维度，四川 080901 会挤成一条 offerings 说不清。
**建议**：offerings 加 `mode: social|applied`（面向社会/高校应用型），与 local_code 配合；应用型计划确有独立口径时允许独立 plan。多省都有「系统委托/助学专业」，字段一次建好。

### 1.5 北京没有国标码可对照（建议必改）
北京专业代码是自有体系（`01B0015` = 计算机科学与技术专升本，`01A` 专科段），与 080901 无编码规则映射，只能靠「旧专业名称」+人工核对对照。offerings.major 按国标码填会卡死北京。
**建议**：scope.json 专业加 `aliases`；offerings 允许 major 暂空 + `matched_by`（对照依据：如「01B0015，2026 年安排正文旧专业名称=计算机信息管理，第三方通知佐证」）——**这个映射本身是调查结论**，值得显式建模，别塞 note 了事。

### 1.6 `exam`（命题方式）预期大面积 null
省级课程设置表一般**不标注**该课是全国统考还是省考。这字段只能靠课程代码对照教育部统考课程清单反推——那就成了推断。建议接受它大面积 null（页面写了才填），或者明确允许的推断依据并写进规程；二者取其一，不然验收时会纠结。广东探路补充：同一课程在不同考期命题方还可能不同（1 月省考、4/10 月统考），若要精确到这个粒度，得放 calendar×课程交叉处，plan 行一个枚举装不下——接受 null 最现实。

### 1.7 新旧计划「并行可报」缺一个状态
`state: current|superseded|upcoming` 假设任一时刻只有一个 current。过渡期现实是**考生可选旧计划考完或转新计划**（江苏 2021/2024 并存即如此：过渡期 2024-07~2026-06，老考生自主选择；广东过渡期 2023-11~2025-12-31）。建议加 `state: current-old`（或 `both`），或规定「并存时都写 current，用 events + note 说明切换时间」，写死一种。

### 1.8 学位课程标记缺失（探路新发现）
江苏简编用「◆」、湖北计划备注列写「学位课程」标出学位门槛课——两省官方都直接给了，直接影响「学位授予」角度可用性。**建议**：课程行加 `degree_course: true`（放 note 里课程视图就筛不出来）。

### 1.9 选考规则只有自由文本（探路新发现）
`rules` 是纯文本。江苏「不考外语换考课程组」（00054 管理学原理/00321 中国文化概论/27108 多媒体技术三选）、湖北学位课、广东选考组——这些不结构化，「课程对比矩阵」没法机读「同为选考但组不同」。**建议**：plan 加 `elective_groups: [{name, pick, credits_min, courses:[code]}]`（信息可得时填，不可得 null）。

### 1.10 小点
- `verify.date` 说「抓取当日」，但证据文件头又有 `fetched`——同一信息两处写。建议 verify.date 就抄 fetched，规程里写一句，免得不一致。
- sha256 按现稿是「正文字节的 sha256」，正文边界模糊。建议定义为「证据文件去掉 `sha256:` 那一行后的全部字节」，可复现、可抽查。本轮试采对 PDF/JPG 等二进制证据直接算全文件 sha256（见 evidence/guangdong/EVIDENCE.md），二进制没有「正文」问题，文本快照才需要定义。
- 建议每省证据目录加一个 `index.md`（证据文件 → 覆盖了哪些字段），leader 抽查「回到原文」时不用逐个打开猜。（本轮已按此精神建了 EVIDENCE.md。）
- `verify` 建议加 `evidence: "evidence/<省>/<文件名>"` 引用位，plan→证据直达。
- `policy` 四项塞长文本会失控：北京「自考指南」、江苏湖北免考细则都是长文档。建议 text 限一两句摘要 + `doc_url`。
- courses.json 的 kind（theory/practice/mixed/graduation）与 plan 行 category 语义重叠：建议文档写明 kind 是课程库层（全国视角）、category 是计划行层（省内角色），二者不同轴。
- 实践课五省基本都是**独立代码+独立学分行**（广东 13003/13004、湖北 08947/08948、江苏并排单元格），`practice` 子对象可能极少用到。建议口径写死：实践独立成行时 credits 必填、不再填 practice 子对象。

## 2. 波次与工作量

- A（基线）和 B（开设矩阵）的**原始来源是同一批页面**（省考试院的专业目录表 + 考期公告页）。按省分片、一次导航同时采 A+B，比「全国跑两遍」省一半站点成本。数据仍分层写，只是采集时合并做。
- **波 B 起步用各省「年度全量表」**（探路确认五省都有，且多为文本）：北京 2026 年考试安排（44 专业+新旧名称+状态表）、湖北报考简章、江苏简编目录、广东开考课程时间表（按专业列）、四川计划列表页——一网打尽 open/stopped，比逐专业找「开考通知」高效得多。
- C 波试点五省选得好（广东三考期+图片表、江苏四考期+全文本、四川双码、北京自有码、湖北最全文本），形态覆盖面够。
- **工作量实测**（本会话）：广东两专业试采约占一个会话的一半精力（大半耗在 zip 掐断与图片验证上）；江苏/湖北形态下每专业分钟级。估计 31 省 × 核心 8~10 专业的波 B+C：文本省约 1~2 会话/5~8 省，广东/北京形态的省各需 1 个专门会话。
- D 波建议**先采一次全国统编教材目录**（教育部教育考试院每年发布统考课程教材目录与大纲），能一次覆盖绝大多数课程行的 textbook 引用；省编/主考院校教材才逐省补。否则逐省逐课找教材会非常慢。探路补充：湖北的大纲及教材 xls、广东附件3、北京教材信息表都是课程级全表，波 C 顺手就能把 D 波大半带走。

## 3. 验收口径

可执行。「错一处视为不过」很严，但这类事实数据值得这么严。补三条操作建议：
- 抽查时 leader 只需要证据 index + 快照，不用复爬线上页面（页面会改版，以快照为准）。
- **交叉核对机制化**：leader 与 zcode 双写的数据（如本轮广东两专业）逐字段 diff，差异清单本身就是验收材料——比抽查更能暴露系统性误解（本轮两边对「学分能否从顶替表图片写」的口径差异会直接显形）。
- 「核对超过一年标可能过期」建议改为按考期：自考按考期换版（广东江苏一年 3~4 个考期滚动更新），单条 verify.date 距该省最近考期超过一个周期即标。

## 4. 该加/该删的角度

- **该加**：`offerings[].status` 里 none 的核实依据建议强制挂「全省开考专业目录表」的 URL——这张表是波 B 的锚，五省都有（见 §2）。
- **该加**：`plans` 加可选 `source_files`（计划原文在证据目录里的文件名清单），抽查直接定位。
- **该加**：`provinces[].selfstudy_portal`——各省除考试院外的自考官方门户/管理系统 URL（广东 eeagd.edu.cn/selfec、北京 zikao.bjeea.cn 这类，往往才是计划与教材的真正存放地）。波 A 基线应含。
- **该加**：offerings/plan 记录调查完备度（courses/credits/textbook 三布尔），「覆盖进度」总览直接读它，不从 plans 反推。
- **该删/降级**：界面八视图里「实践」单独成视图略重——实践信息散在课程行和 graduation 里，汇总视图数据薄。可以先做成专业详情页里的一个区块，有数据量了再升视图。（不坚持，UI 你定。）
- **该推迟**：athena-map.json 建议挪到波 D 之后——全量课程库成型前写了也会大改。
- 0808 自动化：探路确认五省都开 080801（广东工业大学主考），scope.json 预登记为 edge，波 B 顺手收。

## 5. 探路印证（五省实测，详见 PROBE.md）

草稿 §1 各点的印证或加重：

1. **§1.1 考期**：实锤。广东 2026-01/04/10 三考期（栏目文章时间线验证），江苏 2026-04/07/10 + 2027-01 已排（一年四考）。
2. **§1.3 多主考**：实锤且比预想复杂——广东多主考还叠「专业课程组」维度（szeb 目录页原文），2026-08 通知又批量增减主考（附件1 增加/附件2 退出两列）。主考学校变动频率高，offerings.hosts 要带自己的 verify。
3. **§1.4/1.5 代码形态**：三种——国标码直用（湖北计划正文）、省前缀码（四川 H/W、湖北时间表 S/X、江苏 X2）、自有码（北京 01A/01B）。北京映射靠「旧专业名称」列（2026 安排正文给了 44 专业的新旧名称+状态表，这是北京波 B 的锚）。
4. **§1.6 exam**：五省的计划表/时间表均无命题方式列。接受 null 的建议维持。
5. **§1.7 新旧并存**：江苏（2021/2024 过渡到 2026-06）、广东（旧计划过渡到 2025-12-31）、北京（01B0015 过渡到 2027-06）三省同时处于并存期，「current-old」的需求是现实。
6. **图片表格的坑（新）**：广东新旧计划顶替表是逐专业 JPG（无文本层），AI 视觉转写**单次不可信**（同一张图两次转写 19 门 vs 25 门、混入相邻专业行），第三次用定向验证问题（「13005 在不在、02333 在不在」）+ 与文本时间表课程并集交叉才稳定。规程必须写明：**图片表禁止一次整表转写直接入库，必须定向验证式转写 + 文本源交叉**。
7. **大文件防掐断（新）**：广东新计划简表所在 zip 52.7MB，服务器 20~27MB 处随机掐断、不支持 Range（curl 与 python 共 14 轮验证）。建议 DESIGN 加「大文件人工兜底清单」：这类文件由使用者人工浏览器下载一次放 artifacts（2 分钟人力），别让代理反复空耗。
8. **政府官网转载的分级（新）**：深圳招考网（.gov.cn）挂粤考委通知全文——按 official 处理（域名+署名）；商业站转载一律 report。这条要写死进规程，避免各省口径漂移。
9. **附件下载三坑（新，给规程）**：①中文文件名 URL 必须百分号编码（北京教材表）；②服务器忽略 Range 时 curl -C - 无效，换流式多轮取最大；③截断 zip 里 GBK 文件名 + deflate 条目，标准 zipfile 全挂，需按 local header 手工流式解（本轮靠此法从 27MB 残件中完整取出了顶替表 JPG 与通知 PDF）。
