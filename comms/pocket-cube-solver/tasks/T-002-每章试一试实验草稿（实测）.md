## 目标
给 `programming/pocket-cube-solver` 每章（02~07，共 6 章；01 章只读不改，不做）起草 **2 个「试一试」小实验**，做法是学习者在自己的 `workspace/<章>/` 副本里改一两处，**先猜、再编译运行、再对照观察**，对应 TEACHING.md 的学习闭环（形成预期 → 实验 → 观察 → 修正）和 ADR 0059（改之前不改一行也能编译运行）。草稿放 `artifacts/cursor/experiments/<章id>.json`，不改 `programming/` 下任何文件。

## 每个实验的格式
```json
{
  "role": "experiment",
  "heading": "试一试：把搜索深度砍到 4",
  "body": "在 workspace/03-layer/solver.cc 里找到 …，把 … 改成 …。保存后点本章的运行按钮重新编译。",
  "predict": "先猜：第三块（DRB）还装得上吗？程序会显示什么？",
  "observe": "实测：…（一两句话，写你亲眼看到的）"
}
```
`body` 是做什么（指明文件、位置、改成什么，**行号不写**，用函数名或唯一字符串定位）；`predict` 一句话问题；`observe` 是实测结果和它说明的道理，一两句。每个实验在页面上占一小段，不是一节课，**宁缺毋滥**：想不出能产生清晰、可观察差异的改动，就少交，不要凑数。

## 选题标尺
- 改动小（一两行）、效果看得见（窗口里显示不同的结果，或 `cube-test` 的失败信息指向性强）。
- 能说明本章那个**核心概念**，而不是玩具参数：例如 02 章改某个面的转动方向让黄金向量测试失败；03 章把 `search` 的剪枝去掉看耗时变化；04 章把 Sune 的第一步改错看判定失败；05 章去掉「先翻顶面」的前置；06 章输入一个非法涂色看 `diagnose` 的消息；07 章把 BFS 换成……（自拟，要能说清为什么这个改动有意义）。
- 不要改成需要读者另装工具才能做的实验；不要建议删光文件。

## 必须实测（核心要求）
每个实验都要在**一份临时副本**里真改、真编译、真运行，并把观察到的结果原样记进 `artifacts/cursor/experiments/evidence/<章id>-<序号>.md`（改了什么 diff、命令、输出摘要）。`observe` 只写你实际看到的，不写推测。Windows 编译：`PATH` 前置 `C:\msys64\mingw64\bin`，`PKG_CONFIG_PATH=C:\msys64\mingw64\lib\pkgconfig`；章节怎么编译见 `programming/pocket-cube-solver/AGENTS.md` 与 `scripts/check.py --native`。**临时副本放系统临时目录，不要放进仓库，不要在 `exercise/` 里改。** 编译不过或结果不稳定的实验直接删掉，在交付说明里说一句。

## 验收口径
- 6 章共 8~12 个实验；每个都有 evidence 文件。
- `predict` 的答案不是显然的；`observe` 的陈述与 evidence 一致。
- JSON 能被解析；中文标点；不出现「很容易」「显然」这类词。
