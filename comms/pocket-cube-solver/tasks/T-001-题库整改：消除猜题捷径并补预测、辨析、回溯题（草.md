## 目标
重做 `programming/pocket-cube-solver/content/chapters/*.json` 里 `questions` 的**草稿**，放进 `artifacts/cursor/questions/<章id>.json`（章 id 如 `03-layer`，内容是该章完整的 `questions` 数组）。leader 审完集成进课程文件，你**不改 `programming/` 下任何文件**。

## 现状问题（已实测）
- 29 题里 20 题的 `answer` 是 1，只有 4 / 4 / 1 题在 0 / 2 / 3；
- 26 题里正确项是四个选项中**最长**的一个，不看题干也能蒙对。

## 做法
1. **旧题保留 `id` 与题意**（ADR 0129：id 不改嫁），只改选项：重排顺序、把干扰项补到与正确项等长且各有来历（写成真实学习者会犯的错，不写显然荒谬的）。`answer` 在四个位置里大体均匀（全课每个位置占 20%~30%）。
2. **每章补题到 6 题**（01 章 5 题即可），补的题优先这三种，每种每章至少各一道：
   - **预测题**（主打）：给出一个状态和一串转法，问结果。需要图时用下面的 `figure` / `reveal` 字段，不要只用文字描述一个魔方状态。
   - **辨析题**：两个容易混的东西（例如 `layer_done` 与 `solved`、Sune 与反 Sune、角块的位置与方向）。
   - **回溯题**（只 02 章起）：需要用到前面章节的概念才能答对，例如第 5 章问到第 3 章的迭代加深。
3. 新题 `id` 用 `cube.<章短名>.<语义>`，与现有风格一致，不与旧 id 重复；`kind` 沿用「重点 / 要点 / 难点 / 考点」；`source_refs` 照现有写法标 `authored`，`note` 写明没有现成题的原因；解释 `explanation` 要说清为什么错误选项错。
4. **预测题的答案必须实算，不得口算**。用 Node 跑 `programming/pocket-cube-solver/src/cube.ts`（`run`、`parse`、`solved`、`layerDone`、`topOriented`；仿 `scripts/check_content_cubes.ts` 的写法，Node 的 `--experimental-strip-types` 或 `pnpm exec tsx` 随你选），把验证脚本和输出存进 `artifacts/cursor/verify-questions.md`。凡是引用数字（步数、情形数）的题，数字必须取自讲解里已有的实测值，讲解里没有的不要新造。
5. 题只考讲解里已经写出的内容和程序里真实存在的函数名；不编造题号、不假设读者看过别的书。

## 新字段（leader 正在壳里实现，你按这个格式写）
```json
{
  "id": "cube.turns.predict-ru",
  "kind": "重点",
  "stem": "从复原态做 R U，F 面右上那块的前面是什么颜色？",
  "figure": { "kind": "cube", "title": "起点", "caption": "复原态", "setup": "" },
  "choices": ["…", "…", "…", "…"],
  "answer": 2,
  "explanation": "…",
  "reveal": { "kind": "cube", "title": "走一遍", "caption": "R 然后 U", "setup": "", "moves": "R U" },
  "source_refs": [ … ]
}
```
`figure` 是题干配图（做题前就显示，静态：只写 `setup`/`state`，不写 `moves`）；`reveal` 是作答后才出现的回放（带 `moves`）。两者的 `kind` 只用 `"cube"`，字段含义和 `expect`/`marks` 与讲解里的 `section.figure` 完全相同（见 `src/cubefig.tsx` 文件头的类型）。普通概念题两者都不写。

## 验收口径
- 全课 `answer` 分布每个位置 20%~30%；每章正确项是最长选项的题不超过 1/3。
- 每章题数达标，三种题型各至少一道（辨析/回溯在 01 章可缺）。
- `verify-questions.md` 里每道预测题都有实算输出，且与你写的 `answer` 对得上。
- JSON 能被 `python -m json.tool` 解析，UTF-8 无 BOM。
