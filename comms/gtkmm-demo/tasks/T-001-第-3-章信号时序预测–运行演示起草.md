## 目标
为第 3 章（`chapter-basics`，页 sec-signals-overview / sec-helloworld / sec-basics-simple-example）起草
**一个「预测–运行」真机演示 + 一个 Web 模拟 + 配套观察题**，让学习者先预测「信号处理器的调用顺序与窗口生命周期」，再在真机上验证。
这是主原型「预测–运行」在第 3 章的第一次落地，样板是第 6 章（`demos/buttons`、`SignalFlowSim`、`btn6-tb-oq1`）。

## 演示要回答的问题（一理论点一演示，C++ ≤150 行，可通读）
演示 id 定为 `demo.basics-signals`，目标 `demo-basics-signals`，窗口里一个按钮 + 一个日志标签：
1. **同一信号连两个处理器，谁先谁后？** 同一个 `signal_clicked()` 依次 `connect` 处理器 A、B（只做最基础的 A、B 两个处理器，按连接顺序调用，不引入 `connect_notify` 等进阶用法）。每个处理器调用时用 `rpc::signal("button","handler","A")` / `"B"` 上报，并把序号追加到界面日志。
2. **窗口生命周期的顺序**：构造完成 →（`Gtk::Application::make_window_and_run` / `signal_activate`）→ 窗口显示（`signal_show`/`signal_map`）→ 用户点关闭 → `signal_close_request`。每个事件同样 `rpc::signal("window", <名>)` 上报。**只用官方第 3 章 Hello World 里出现的写法与 gtkmm4 真实存在的 API**；拿不准的 API 去 docs.gtk.org/gtk4 与 `guide/gtkmm/upstream/gtkmm-documentation/examples/book/` 核对，不要凭印象。
3. 不在 `main` 里手写事件循环；协议部分（`ready`/`initialize`/`ping`/`shutdown`、`--self-check` 构造界面后退出 0）完全照抄 `demos/buttons/src/main.cpp` 的模式，`#include "rpc.hpp"` 用现成的，不改 `rpc.hpp`。
