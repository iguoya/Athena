# 自考高数、线代视频课应用设计（草案，待使用者选定视频后落 ADR）

2026-10-23，claude-code。视频候选见 [CANDIDATES-VERIFIED.md](CANDIDATES-VERIFIED.md)。本文只定**设计**，不预占名字；选定视频后写仓库级 ADR（编号顺延 0185）再建应用。

## 1 目标与边界

- 为自考「高等数学（工本）」00023 与「线性代数（工）」各建一个 `lecture/` 下的视频课应用，沿用翁恺应用（ADR 0182/0183）的**课堂工作台**：视频是界面的一个窗格，节拍 + 任务 + 要点，掌握度只由作答写入。
- 与 `self-study/` 里同科目的**文本应用并存、互不引用**（ADR 0062、0184）：文本应用按教材节讲课、刷真题；视频课应用按视频的课节讲课、做视频里的例题。
- 两门课都对应真实考试，出处档位按 `exam` 档的精神执行（判分内容必须有出处），但出处来源换成「视频里讲到的例题与真题」（见 §4）。

## 2 从翁恺应用带过来的经验（原样复用）

| 翁恺的做法 | 这里怎么用 |
|---|---|
| 一窗两 webview：左课堂区、右 B 站视频页，窗格可收起 | 原样复制壳与播放桥（ADR 0182 决策 3、0183），先不抽共用件（ADR 0132） |
| 节拍（看一小段 → 一个任务 → 一句要点）；一节 3–6 拍、≤10 任务、每拍暂停任务 ≤2 | 原样；`check.py` 同样的数量门槛 |
| 暂停点按「自然播放跨过」判定，拖动越过按已过处理 | 原样 |
| 登录由使用者在窗格里处理，应用不读账号 | 原样；字幕也要使用者登录态才能取 |
| 视频引用只来自课堂脚本的 `video.{bvid,p}`，Rust 侧逐项校验 | 原样，再加 `start/end` 秒（课节在长视频里的区间） |
| 文本底本：优先 B 站字幕，没有才用本机 Whisper，标注「未逐句校对」 | 原样；数学课的转写里公式靠念白，**不可靠**，见 §5 |
| 题源只取自视频里讲的内容，`verbatim`/`adapted` + locator「P41 12:30」，`authored` 不入库 | 沿用，细节见 §4 |

## 3 数学课要改的地方

1. **方法原型换成「问题解决」为主、「检索强化」为辅**（ADR 0113）。翁恺是「预测–运行」，C 语言有机器可跑的结果；数学课的对应物是：**暂停点放在讲师开始解例题之前，让使用者先动笔算，再继续看讲师的解法对照**。这是数学视频课最有价值的一个动作。
2. **任务类型**（沿翁恺，改名与判分方式）：
   - `workout`（先自己算）：暂停点上给题，使用者在纸上算，把答案填回（选择 / 数值），机器核对，进掌握度。
   - `quick`（速答）：概念辨析、判定，选择或数值，进掌握度。
   - `predict`：预测讲师接下来的结果或下一步，机器可判的记「命中」，不进复习队列。
   - `selfexplain`：教学动作，不判分。
3. **机器核对用 sympy 而不是编译器**（翁恺用 C 编译器、西电慕课用 Octave，ADR 0057 基线）：数值题带 `verify`（一小段 Python/sympy，由 `check.py` 复算并要求与 `expected` 一致），算不出来的题不入库。本次 24 + 28 节文本应用的生成器已经证明这条路可行。
4. **课节不是一集**：高数正课单集约 2 小时（P41 起 7000 秒左右），线代单集 20–90 分钟。课节 = 一集里的一段（`video.start/end`），一般 10–25 分钟，一集拆成若干课节；课节 id 形如 `p041a`。

## 4 题源与出处（两门课分开说）

**共同规则**：进掌握度的题必须机器可核对；`source_refs.relation` 只许 `verbatim`/`adapted`；`authored` 不入库；`locator` 写「P41 12:30」且时间要落在讲师讲到该题的位置（用字幕或转写核对，不凭印象）。

- **高数（工本）**：视频的真题解析 P67–P72 覆盖 2015–2019 五年；这些整卷的**题干**要作为 `verbatim` 的依据，需要先有整卷文本。`self-study/advanced-mathematics/content/exams/` 目前为空，采集任务在 zcode 名下（self-study 舱）。视频里的例题（P41–P58）是另一个来源：讲师口述 + 板书，题干需要人工从画面摘录，**转写不够**。
- **线代（工）**：2018 年 4 月真题整卷已入库（`self-study/linear-algebra/content/exams/2018-04.json`），宋浩的课是通用课，没有真题，题源只能是讲课里的例题与习题课；真题题目可以作为 `adapted` 的依据，但两个应用互不引用，需要**把整卷复制成本应用自己的素材**，并注明出处。

## 5 底本：字幕与转写的现实

| 项 | 高数（BV1UU4y1t7ix，转载） | 线代（BV1d7wAzsE8V，宋浩官方号） |
|---|---|---|
| 字幕 | 未核实；录播转载大概率没有 | 未核实；官方号有可能提供 |
| 取字幕 | 使用者登录态（翁恺应用做法） | 同上 |
| 没有字幕时 | 本机 faster-whisper，zcode 已有 `WHISPER-FEASIBILITY.md` | 同上 |
| 数学课的转写风险 | 讲师说「x 平方加 y 平方」，公式细节在板书；转写只能定位**讲到哪一段**，**不能当题干** | 同上 |

结论：转写只用来**切课节、定节拍时间、核对 locator 的大致位置**；题干与解答一律以画面为准、人工摘录并用 sympy 复算。这比翁恺应用多一道人工环节，也是数学视频课工作量的主要来源。

## 6 应用骨架（建应用时用）

- 目录：`lecture/<id>/`，`app.json` 的 `group` 用「自考」（与文本应用同一圈，使用者在启动器里能看到两种形态）。
- id 建议：`advanced-mathematics-video`、`linear-algebra-video`（完整英文单词，不用拼音与缩写；`-video` 区别于 `self-study/` 下同科目的文本应用）。进程 `athena-<id>`；dev 端口 1533、1534（现有最大 1532）；知识点前缀 `advvideo.`、`lavideo.`（沿 `wengc.`、`chenmooc.` 的写法）。
- 内容：`content/curriculum.json`（章 → 课节，章结构跟教材章，课节标注对应的教材 §）、`content/lessons/<课节 id>.json`（课堂脚本，字段同翁恺 `Lesson` 类型，任务类型按 §3）、`content/scope.json`。
- 检查：`scripts/check.py` = 翁恺的结构与数量门槛 + 出处门禁 + sympy 复算 + 公式自检（KaTeX）+ 前端构建 + cargo。
- 同样的文字排版约定（只认公式、加粗、分段、列表，不支持表格），见两个文本应用的 `AGENTS.md`「文字排版」。

## 7 开工顺序（选定视频后）

1. 使用者定视频（两套），并在应用窗格里登录 B 站一次（取字幕要用）。
2. ADR 0185：确立两个应用与第 6 节的骨架。
3. 复制翁恺的壳，建空应用，`check.py` 绿，`launcher open` 能跑。
4. 各挑**一个有代表性的课节**做试点（高数：P41 第一章第一段；线代：宋浩 1.4 行列式按行列展开），zcode 出转写/字幕与节拍草案，claude-code 抽查入库，跑通播放桥 + 暂停点 + 作答 + 复习。
5. 试点通过后按章推进（ADR 0129：没有可交付的第一批不扩张）。

## 8 需要使用者拍板的事

1. 选哪两套视频（我的推荐：高数 BV1UU4y1t7ix，线代 BV1d7wAzsE8V，理由见 CANDIDATES-VERIFIED.md）。
2. 高数那套是 2021 年按旧教材录的、且 P1–P39 是初等数学与一元微积分补课：要不要把补课部分作为 `prereq` 层带进来（教材不含，但自考生常有缺口），还是只做 P40 起的正课？我倾向只做正课，补课用 `prereq` 单独一章、后做。
3. 两个应用的**题源**：是否接受「视频里的例题 + 复制过来的真题整卷」作为全部题源（不再自编）？这决定了每节的题量会比文本应用少很多。
