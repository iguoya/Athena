# 对 DESIGN-v0 的评审与合并意见（zcode，2026-10-21）

使用者指示把我的思路与 claude-code 的 DESIGN-v0 合并讨论。我原思路（字幕精读壳 +
外链跳转）有一半基于 `docs/HANDOFF.md`「视频课」旧条（不嵌播放器、不放视频）；该条
是云会话连不上视频站的妥协，使用者在舱 README 已表态「不受既有应用形态影响」——
**接受本地视频播放路线**。我方原思路存档见同目录 `design-brief-v1.md`，被取代处已标注。

## 一、立场合并

| 议题 | DESIGN-v0 | 我方原思路 | 合并结论 |
|---|---|---|---|
| 播放方式 | 本地文件嵌入播放 | 字幕文本 + 外链、不嵌播放器 | **本地播放为主**；字幕壳降级保留（见三.3） |
| 应用粒度 | 先只做一门（ADR 0132） | 每门课一个应用 | **第一门课就是一个独立应用**（ADR 0032 一个目录一个应用），不预建多课平台；要不要通用壳待内容成熟 |
| 主导原型 | 预测–运行等按课选（ADR 0113） | 预测–运行 + 检索强化 | 一致；第一门课的 ADR 里声明该课主原型 |
| 知识点挂时间戳 | 挂回、点一下跳回 | 时间戳作出处 locator | 一致；本地播放下「跳回」= 壳内 seek，我担心的体验断裂不存在 |

## 二、回应 DESIGN-v0 第 7 节的挑刺清单

1. **暂停点打断观看**：暂停点是这形态的核心价值，但要节制 + 可逃逸。一段 ≤ 2~3 个；
   弹层限时（如 30 秒未答自动放行并记「跳过」，不罚）；答错的对照与错因放在继续播放
   后的浮层，不强制停留。符合 ADR 0113「专注落成会话：一轮有界、作答视图零打扰」。
   默认开，设置里可整体关（关了只记观看位置，掌握度只有片段结束卡能写）。
2. **切片粒度**：同意按概念边界不按时长；3–8 分钟当产出参考而非约束（慕课网单节
   10–25 分钟，一个概念可能不到 3 分钟）。自动切只产粗稿（字幕静音段 + 话题漂移），
   边界人工校对——切片质量决定暂停点质量，值得人工。宁可「只看」段多，不配烂暂停点
   （ADR 0040/0129 宁缺毋滥）。
3. **Whisper 本机可行性**：Windows 本机 faster-whisper（CTranslate2）或 whisper.cpp
   可行，small/medium 中文可用；1 小时课 CPU 约十几分钟到半小时，NVIDIA 卡几分钟。
   但优先级应为：平台现成 CC 字幕 > 讲者提供 > Whisper 兜底。转写只作可搜索文本，
   不逐字入库（与稿子一致）。
4. **本地路径与进度同步（ADR 0155）**：视频路径绝不进同步库。视频用相对 key
   （`videos/<课>/<文件名>`），本机设置配「视频库根目录」（三平台各自选目录）；缺文件时
   自动降级字幕/文本模式，学习与练习照常——换机器、视频缺失都不阻塞。
5. **复制电子书形态之处**：首页=今日到期复习成立，不是残留。真正要警惕的是「知识点
   列表页」这类目录式导航——视频课的主导航应是**视频时间轴 + 片段**，知识点是片段的
   属性而非一级导航；知识点视图按「到期复习队列」出，不按列表出。

## 三、我方补充（DESIGN-v0 未提）

1. **可视化重做（ADR 0056，强制）**：视频里的图示是死的；代表性图示用 @athena/viz
   重做成互动件、与对应片段互链。这是视频壳区别于「挂个播放器」的增值，也是检索
   练习素材（预测–运行的运行端）。
2. **掌握度口径（ADR 0052）**：观看完成度不算掌握度，只作提醒；掌握度只由片段结束卡
   与暂停点作答写入。「看完 ≠ 学会」要写进应用 AGENTS.md。
3. **字幕壳作降级档**：视频文件缺失/未下载时自动切字幕文本模式（段落 + 时间戳可读、
   练习可做），即我方原思路成为内置降级形态而非独立应用。
4. **出处契约**：视频课若选考试对口的课，判分内容按 ADR 0043/0089 要出处且检查阻断；
   技术学习类则出处是习惯。视频课的天然出处就是「课程名 + 集 + 时间戳」，locator
   规范在 ADR 里定死，两档都够用。
5. **与既有应用互不引用（ADR 0032）**：若第一门课与既有线代/数学应用内容相近，壳独立、
   知识点 ID 前缀独立，不交叉引用。

## 四、对「待拍板」4 条的意见

1. 先做哪门课——使用者定。建议第一门选：讲者语速适中、有现成字幕、单节 10–25 分钟、
   概念密度高，先把流水线跑通。
2. 通用 vs 每门一个——见一：单课独立应用。
3. 视频来源——本地文件，同意；在线流不做，付费平台加密不绕（稿子已写）。
4. 分工——同意稿子方案：claude-code 出设计稿与 ADR，zcode 评审设计、立项后负责素材
   切片/转写/初稿，claude-code 抽查验收。

## 五、需要落 ADR 时写清的两处修订

1. `docs/HANDOFF.md`「视频课」条（字幕文本 + 外链、不嵌播放器）由新设计**取代**，写明
   取代关系与理由（云限制 ≠ 本地限制；使用者拍板不受既有形态约束）。
2. `docs/LEARNING-METHODS.md`「不做视频课」措辞建议改为「不做无检索闭环的纯视频被动
   消费」——本设计恰是反被动消费，但要避免字面撞车误导读的人。

归类圈（新分组目录还是进 `guide/`）动仓库结构，由使用者拍板后写进 ADR。
