# 视频类教程应用设计构想 v1（zcode 原思路存档，2026-10-21）

> 本档是 zcode 独立起草的讨论提纲。使用者随后指定在 video-course 舱合并讨论；
> 其中「不嵌播放器、外链跳转」等立场已按使用者「不受既有应用形态影响」的表态调整，
> 合并结论见同目录 `REVIEW-DESIGN-v0.md`。本档保留原貌供追溯。

## 背景：仓库既有立场

- `docs/HANDOFF.md`「视频课」条：一门视频课一个应用；只有字幕或讲稿文本拿得到才建；
  内容为字幕文本 + 原视频外链；**不嵌播放器、不放视频**。做法：yt-dlp / BBDown 取
  字幕 → 段落快照 →「段落 + 时间戳 + 外链」入库；练习自编、可机器核对。候选：
  3Blue1Brown「线性代数的本质」「微积分的本质」（英文字幕在 GitHub `3b1b/captions`，
  云里能取），只缺使用者点头。
- `docs/LEARNING-METHODS.md`：把「纯视频/纯听讲的被动消费形态（不做视频课）」列为不做。
- 相关结构与规范：`guide/` 圈 =「跟随一本外部手册/官方教程精读」（ADR 0143 起）；学习
  应用受跨应用教学规范约束（`docs/TEACHING.md`）；课程类统一 Tauri 2 + React
  （ADR 0133/0138），课程壳共用 athena-course-shell crate（ADR 0161）；进度库本地优先
  （ADR 0037/0155）；内容驱动 UI（ADR 0058）；可视化与交互是内容本身（ADR 0056）；
  每应用声明主导学习方法原型（ADR 0113）；激励与统计一条回路（ADR 0052）。

## zcode 的初步设计构想

1. **归类**：放 `guide/` 圈，一门视频课一个应用（守 HANDOFF，与 guide 一书一应用对齐），
   如 `guide/3b1b-linear-algebra`。判据：「跟随外部底本精读」对视频系列同样成立。
2. **内容结构**：系列 → 集（episode，对应一集视频）→ 段落（字幕段落；最小锚点 =
   段落文本 + 起始时间戳 + 原站外链）。渲染走内容块（ADR 0058），段落块是新块类型。
3. **观看端**：不嵌播放器（守 HANDOFF）。点时间戳跳原站对应位置（B 站 `t=` 秒、
   YouTube `?t=`），壳里负责文本、笔记、练习。
4. **教学闭环**：观看只是输入；设计重心在观看后的检索动作（ADR 0096）——预测题
   （「这一幕的动画会怎么画」）、段落回忆、自编练习机器核对；代表性动画用 @athena/viz
   重做成互动可视化（ADR 0056）。
5. **主导方法原型**（ADR 0113）：预测–运行 + 检索强化，机制模拟为辅。
6. **进度库**：`app.json` 声明 `progress`（ADR 0037/0155），掌握度只由作答写入（ADR 0052）。

## 关键取舍（原六问）

1. 「不嵌播放器」守不守？——倾向守，代价是外链跳转的体验断裂。
2. 归类 `guide/` 还是新圈？要不要在 ADR 里理清 `LEARNING-METHODS.md` 的边界措辞？
3. 3B1B 两个系列是两个应用还是一个应用两门课？——倾向两个应用。
4. 字幕语言：英文字幕 + 机器翻译 + 校对，还是找现成中文字幕？（最终问使用者。）
5. 「回看 xx:xx」是有效教学动作吗，还是只作出处引用？——倾向练习出处锚到段落时间戳，
   「回看」作答错后的补救链接。
6. 与既有线代应用（selinger / siefken / chen / axler）各壳独立、知识点前缀独立、
   不互相引用（ADR 0032）。
