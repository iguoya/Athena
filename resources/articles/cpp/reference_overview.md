# 第 2 章 引用：给对象起别名，而不是造一个新指针

引用不是"更安全的指针"，而是完全不同的东西——它是已存在对象的**别名**，不占用独立的存储身份，从声明那一刻起就跟绑定的对象不可分割。这一章的四个知识点，都是从这一个事实推出来的自然结论。

> 核心目标：分清"引用是别名"和"指针是变量"这两件事的根本区别，并据此判断什么时候该用引用、什么时候引用会带来生命周期风险。

## 2.1 引用基础：别名，不是新变量

```cpp
int x = 10;
int& ref = x;   // ref 是 x 的别名，不是指向 x 的东西
ref = 20;       // 改 ref 就是改 x 本身
```

`&ref == &x` 恒为真——因为它们本来就是同一个对象，只是有两个名字。这带来两个必须记住的约束：

- 引用**必须**在定义时初始化，因为它没有"先声明、后绑定"这一步；指针可以先声明为 `nullptr` 再赋值，引用不行。
- 引用**不能**重新绑定。***`ref = y;` 不是让 `ref` 改指向 `y`，而是把 `y` 的值赋给 `ref` 当前绑定的对象***——也就是通过别名修改了 `x`。这跟指针的 `ptr = &y;`（改变指向）是完全不同的操作，混淆这两者是初学者最常见的错误。

## 2.2 const 引用：能绑定临时对象，还能延长它的寿命

```cpp
const int& r = 42;          // 绑定字面量（右值）
const std::string& cs = s;  // 绑定已有对象
```

普通的非 const 引用不能绑定右值（临时对象），因为右值理论上"用完就该消失"，允许非 const 引用绑定它会给你一个可以修改、却随时可能失效的对象。`const` 引用打开了这个口子，同时编译器会把绑定给它的临时对象的生命周期**延长到这个引用本身的生命周期结束**，避免野引用。这也是为什么 C++ 里"传参用 `const T&`"这么常见——既避免拷贝，又能安全接住临时对象。

## 2.3 值传递 vs 引用传递：函数看到的是副本还是本体

```cpp
void swap_by_value(int a, int b) {      // a、b 是副本
    int temp = a; a = b; b = temp;      // 交换的是副本，调用方毫无变化
}

void swap_by_reference(int& a, int& b) { // a、b 是调用方对象的别名
    int temp = a; a = b; b = temp;      // 交换的是调用方本体
}
```

这两个函数代码几乎一样，效果却完全相反——差别只在参数类型是不是引用。值传递会为每个参数拷贝一份，函数内的修改跟调用方无关，适合小对象、又不想让函数改动实参的场景；引用传递不拷贝、能修改调用方对象，适合大对象（省拷贝开销）或者本来就需要修改实参的场景（比如 `swap`）。选哪个不是风格问题，是看"这个函数要不要影响调用方"。

## 2.4 引用作为返回值：能改，但要小心悬空

```cpp
int& element(int* arr, int i) {
    return arr[i];   // 返回的是 arr[i] 的别名
}
element(arr, 1) = 999;  // 可以直接赋值，因为返回的是左值引用
```

函数返回引用意味着调用方拿到的是"原对象的别名"，可以直接对返回值赋值，这在实现下标运算符 `operator[]`、链式调用等场景很常见。但这里有一个真正危险的陷阱：***如果返回的是函数内局部变量的引用，函数一返回，局部变量就销毁了，你返回的引用立刻变成悬空引用***——继续使用它是未定义行为，且编译器不一定会警告。判断能不能返回引用的唯一标准是：这个引用指向的对象，生命周期是不是比这次函数调用更长（比如调用方传进来的对象、堆上的对象、static 对象）。
