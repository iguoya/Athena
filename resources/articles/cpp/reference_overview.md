# 第 2 章 引用（教学大纲）

> 建立判断：一个名字何时只是已有对象的别名，以及别名在绑定、传参与返回时
> 如何把修改权、复制代价和有效期绑在一起。

## 痛点与来历

上一章已经能分清「副本还是原对象」「对象此刻是否还在」。一进入函数接口，
问题会立刻收紧：形参和返回值到底交出了新对象，还是另一个名字？选错的代价
不是文风问题，而是改不到调用方、偷偷改了调用方，或拿着已经失效的别名继续用。

下面五类风险与本章「判断与代价」的五个检查点一一对应，
后面遇到它们时可以直接回到对应的检查点。

- **把引用当成可改指向的指针。**（① 认别名）以为 `ref = y` 会让别名改绑到
  `y`，实际却是在给当前绑定的对象赋值。
- **别名还在用，对象已经没了。**（② 查寿命）局部对象销毁后，指向它的引用
  仍然“看起来能写”，实际已是未定义行为。
- **函数改的是副本，或误伤了调用方。**（③ 选传参）该共享原对象时用了值传递，
  或不该留下副作用时用了可写引用。
- **把局部对象的别名交还调用方。**（④ 判返回）函数一返回，别名立刻悬空；
  编译能通过并不等于安全。
- **误以为“只要碰到 const 引用，临时对象就会一直活着”。**（⑤ 认延长边界）
  生命周期延长只在特定绑定方式下成立；经函数转发后再绑，临时对象可能早已销毁。

引用进入语言，是为了在不必发明“指针变量”的前提下，给已有对象另一个名字，
并让接口能够表达“我要用原件”。随后 `const` 引用放开了绑定临时对象的口子，
也带上了寿命延长这条特殊规则；传参与返回则把别名推进到跨函数边界。
右值引用、转发引用和引用折叠是更晚的表达能力，服务移动与泛型接口，
不在本章展开——本章先把左值引用这条别名线判准。

## 心智模型

**引用是已存在对象的别名，不是一格可以改指向的独立变量。**
别名与对象共享身份：对别名读写就是对那个对象读写。指针则先是一个对象，
再保存别人的地址；它可以空、可以改指向。把引用理解成“更安全的指针”，
后面四条硬约束都会一起塌掉。

本章先钉住别名的三条硬事实：

- **同身份**：别名不另造对象；两个名字可以指向同一实体。
- **必绑定**：定义时就必须绑上对象，没有“先声明、后指向”。
- **不改绑**：赋值改的是对象的值，不是别名的目标。

再进入跨语句、跨函数时要加的两层判断：

- **只读还是可写**：`const` 限制的是经由这条别名能否修改，不自动保证对象永存。
- **谁活得更久**：别名的作用域可以短于或（在延长规则下）锚定临时对象；
  一旦别名活过对象，就是悬空。

上一章的值类别在这里变成绑定前提：什么表达式能绑到普通引用或 `const` 引用，
先靠值类别判断；绑上之后，本章继续追问修改权与寿命。

## 讲什么与边界

### 先看主次与顺序

**推荐顺序**：引用基础 → `const` 引用 → 值传递／引用传递 → 引用返回值。
基础给出别名与硬约束；`const` 引用补上临时对象与延长边界；传参把别名推进到
调用约定；返回值把寿命判断推到函数边界之外。跳过基础直接传参或返回，后面
只会反复补“到底是不是同一个对象”。

- **先拿下（初中级 + 需要精通）**：别名与同身份、必须初始化、不能改绑；
  传参时副本还是原件、谁被修改、复制代价。这是读函数签名时每天都要用的判断。
- **随后拿下（初中级偏上 + 需要精通）**：`const` 引用的只读语义、绑定临时对象、
  以及寿命延长的适用范围与不适用范围。
- **必须掌握，允许慢一点（进阶 + 必须掌握）**：返回引用的安全条件——对象是否
  比这次调用活得更久；为什么“返回局部变量的引用”即使能编译也不能运行去“试”。

贯穿全章、没有单独实验标题的是**别名背后的对象身份**：每学完一个方向，
回头问一次“此刻这两个名字是不是同一个对象，它还在不在”。

### 分方向的清单

本章的主脊是五个检查点；下面分组只是归类查找，不是第二套学习顺序。
每个方向后标难度与掌握目标（ADR 0029）；两项互不推导。

**别名与绑定**

- 引用与指针在身份、可否为空、可否改指向上的根本区别。〔入门 · 需要精通〕
- 为何必须在定义时初始化，以及“不能重新绑定”在赋值语句里到底意味着什么。
  〔入门 · 需要精通〕
- 上一章已建立的对象身份与值类别，如何成为绑定是否合法的前提。〔贯穿 · 必须掌握〕

**只读别名与临时对象**

- `const` 引用如何限制经由别名的修改，以及它与“对象本身不可修改”的关系。
  〔中等 · 需要精通〕
- 为何普通引用不能绑定纯右值，而 `const` 引用可以。〔中等 · 需要精通〕
- 临时对象寿命延长何时发生、延长到何时结束；经函数参数转发后再绑定为何
  常常不再延长。〔中等 · 需要精通〕

**传参约定**

- 值传递与引用传递分别让函数看到副本还是原件。〔入门 · 需要精通〕
- 如何同时权衡：要不要改调用方、复制代价、对象是否在调用期间保持有效。
  〔入门 · 需要精通〕
- `const T&` 作为只读入参的常见意图，以及它不能代替所有权或寿命约定。
  〔简单 · 必须掌握〕

**返回别名**

- 返回引用如何让调用方继续操作原对象（例如可赋值的下标访问）。
  〔进阶 · 必须掌握〕
- 安全返回的判据：被指对象的寿命是否长于本次调用（调用方提供的对象、
  数据成员、静态存储期对象等）。〔进阶 · 必须掌握〕
- 返回局部对象的引用为何是未定义行为；警告不可依赖，尤其是经指针一层转发后。
  〔进阶 · 必须掌握〕

这些内容在本章讲到能够阅读签名、预测副作用并说明选择依据的程度。

## 判断与代价

面对陌生代码里的引用，可以沿着下面的线索检查；允许往返，不必机械地走固定步骤。

1. **认别名**：这个声明是新对象，还是已有对象的另一个名字？它和指针变量差在哪里？
2. **查寿命**：别名绑定的对象此刻是否仍存在？若是临时对象，延长规则有没有真正生效？
3. **选传参**：这里要副本隔离、只读共享，还是可写共享？代价与副作用是否匹配意图？
4. **判返回**：返回的别名指向谁？它的寿命是否明显长于这次函数调用？
5. **认延长边界**：这是“直接绑定纯右值”的延长，还是经过转发后误以为还活着？

这些检查最终会落到三组经常出现的选择上：

- **要别名，还是要指针？** 需要可空、可改指向或表达可选存在时，别名不够用；
  只是给已有对象另一个名字、并在接口上固定绑定时，引用更直接。不要用“更安全”
  当唯一理由。
- **传值，还是传引用（含 `const`）？** 要隔离修改就传值（并接受复制）；要避免复制
  或需要影响调用方，再选只读或可写引用，并同时承担寿命与副作用责任。
- **返回值，还是返回引用？** 返回引用是为了继续操作原对象；只有能证明对象活得更久
  时才值得。拿不准时，返回副本通常更安全，尽管可能更贵。

先依据语言规则形成预期，再结合编译诊断与运行结果检验。一次运行正常不能证明
别名总是安全，尤其不能排除悬空引用；结果不符合预期时，先回查绑定与寿命前提。

影响；不要求已学类的成员函数或右值引用。

**本章结果**：下面每一条都可以拿一段没见过的代码当场检验；顺序与推荐顺序一致。

1. 指出两个名字是否同一对象，并说明一次赋值是在改对象的值，还是（误以为的）改绑定。
   〔需要精通〕
2. 说明一个 `const` 引用能否绑定眼前的表达式，临时对象是否因此被延长，延长到哪里结束；
   若经函数转发，能否再假设它仍有效。〔需要精通〕

4. 判断一次返回引用是否安全，并说出依据；能指出返回局部对象引用为什么不能当实验去“跑通”。
   〔必须掌握〕

## 小结

本章只有一条主线：**引用是别名**。必须初始化、不能改绑、传参看到原件还是副本、
返回是否悬空，都是同一事实在不同边界上的推论。`const` 引用额外打开了临时对象
的绑定与有条件的寿命延长，但延长不是“碰到 const 就永远安全”。

回顾时尤其检查这些误区：

- 引用不是更安全的指针；`ref = y` 不改绑定。
- 别名有效不等于对象还在。
- `const T&` 形参很常见，它既不给你所有权，也不自动延长经转发而来的临时对象。
- 返回局部对象的引用是未定义行为；警告缺失不能当成安全证明。
- 右值引用与移动不在本章用“引用”一词含糊带过——那是资源转移另一条线。

先说明意图（只读／可写／要不要副本），再依据绑定与寿命规则判断，用实验检验并修正理解。
