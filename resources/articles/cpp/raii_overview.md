# 第 2 章 RAII 与资源管理：把资源生命周期绑定到对象生命周期

C++ 没有垃圾回收，也不强制你手动 `free`/`delete`——它给的答案是 RAII（Resource Acquisition Is Initialization）：把资源的获取绑定到构造函数，把释放绑定到析构函数，让编译器保证的"对象离开作用域必然析构"顺带保证了"资源必然被释放"。这一章的六个知识点，本质上都是 RAII 思想在不同资源类型上的具体应用。

> 核心目标：理解"资源生命周期跟对象生命周期绑定"这一个思想，如何分别演化出智能指针（管理内存）和移动语义（转移所有权而不重复释放）。

## 2.1 RAII 思想：析构函数是释放资源的唯一可靠位置

一个类只要在构造函数里获取资源、析构函数里释放资源，那么无论这个对象是正常执行完作用域、提前 `return`，还是因为异常被栈展开销毁，析构函数都会被调用——这是 C++ 语言规则本身保证的，不依赖程序员记得在每个退出路径上手写清理代码。文件句柄、锁、网络连接、内存，只要包一层 RAII 类，就不用担心某条异常路径忘记释放。这是后面智能指针和移动语义存在的全部前提。

## 2.2 智能指针：把 RAII 用在"谁负责释放这块内存"上

原始指针本身不表达所有权——`int* p` 既可能是"我拥有它，我要释放它"，也可能是"我只是借用一下，不该我释放"，光看类型看不出来。智能指针把所有权语义显式地编码进类型：

**`unique_ptr`：独占所有权**

```cpp
std::unique_ptr<int> p1 = std::make_unique<int>(42);
std::unique_ptr<int> p2 = std::move(p1);   // 所有权转移给 p2，p1 变空
```

同一时刻只有一个 `unique_ptr` 拥有资源，因此它**不可拷贝**（拷贝会产生两个自认为拥有同一块内存的指针，析构时重复释放），只能用 `std::move` 转移所有权。这是开销最低的智能指针，默认应该优先用它。

**`shared_ptr`：共享所有权，靠引用计数**

```cpp
std::shared_ptr<int> a = std::make_shared<int>(42);
std::shared_ptr<int> b = a;   // 引用计数变 2，两者共享同一块内存
```

多个 `shared_ptr` 可以共同拥有同一个对象，内部维护一个引用计数，最后一个持有者析构时计数归零，资源才真正释放。要注意两点容易踩的坑：引用计数的**增减**是原子操作、线程安全，但这不代表**所指向的对象**本身线程安全——多线程同时读写对象内容仍然需要自己加锁；`make_shared` 会把控制块和对象数据一次性分配在一起，比先 `new` 再包一层 `shared_ptr` 少一次内存分配，应该优先使用。

**`weak_ptr`：观察，但不拥有**

```cpp
std::weak_ptr<int> w = a;          // 不增加引用计数
if (auto locked = w.lock()) {      // 尝试提升为 shared_ptr，可能失败
    // 对象还活着，locked 里是有效的 shared_ptr
}
```

`shared_ptr` 有一个结构性弱点：***如果两个对象互相持有对方的 `shared_ptr`（比如双向链表的前后指针），引用计数永远不会归零，造成内存泄漏***——这就是循环引用。解法是让其中一个方向改用 `weak_ptr`：它能观察对象是否还存在，但不参与引用计数，用 `lock()` 尝试临时提升为 `shared_ptr` 来访问，如果对象已经被释放，`lock()` 返回空指针而不是悬空访问。

## 2.3 移动语义：转移资源所有权，而不是复制一份再销毁旧的

**右值引用：区分"这个对象还有人在用"和"这个对象反正要没了"**

```cpp
void f(int& x);        // 只接受左值（有名字、有地址的对象）
void f(int&& x);       // 只接受右值（临时对象、将亡值）
```

左值和右值的区别，本质是"这个表达式背后的对象，之后还会不会被用到"。右值引用 `T&&` 专门绑定那些"反正马上就要销毁"的临时对象——既然它马上要被销毁，那么"掏空"它（拿走它内部持有的资源，而不是复制一份）就是完全安全的，这就是移动语义存在的合法性基础。重载决议会优先把临时对象匹配到 `T&&` 重载，把具名对象匹配到 `T&` 重载。

**移动构造/赋值 与 `std::move`**

```cpp
class Buffer {
    Buffer(Buffer&& other) noexcept
        : data_(other.data_) { other.data_ = nullptr; }  // 偷走资源，把源置空
};

Buffer b2 = std::move(b1);   // b1 之后处于"有效但未指定"的状态，不应再依赖其值
```

移动构造/赋值不复制底层资源（比如堆内存指针），而是把指针本身"偷"过来，再把源对象的指针置空——一次指针拷贝的成本，取代了一次深拷贝，这正是移动语义相比拷贝语义的性能收益所在，对 `vector`、`string` 这类持有堆内存的容器尤其明显。要澄清一个常见误解：***`std::move` 本身不移动任何东西***，它只是把左值强制转换成右值引用类型，"允许"重载决议选中移动版本；真正的搬移动作发生在接下来调用的移动构造/赋值函数体内。被移动之后的对象仍然是一个合法对象（析构、赋值都安全），只是内容不再有意义，不应该继续依赖它原来的值。
