# 第 1 章 类型、初始化与值语义：先看清对象，再决定怎样使用它

C++ 的很多“难点”其实来自同一个问题：一段表达式既有**类型**，也有**值类别**；一个对象还要经过某种**初始化**才能进入可用状态。类型决定允许做什么，值类别决定这个表达式代表持久对象还是临时结果，初始化方式则决定对象最初保存什么值、允许调用什么构造函数。

> 核心目标：看到一段声明或表达式时，能够依次回答“对象是什么类型、怎样初始化、表达式属于哪种值类别、转换是否安全”，而不是只凭语法外观猜测。

## 1.1 初始化：花括号不只是另一种写法

常见初始化形式看起来相近，但编译器采用的规则并不完全相同：

```cpp
int direct(7);       // 直接初始化
int copied = 8;      // 拷贝初始化
int listed{9};       // 列表初始化
int zero{};          // 值初始化，得到 0
```

直接初始化可以调用 `explicit` 构造函数，拷贝初始化不可以：

```cpp
class Distance {
public:
    explicit Distance(int value) : value(value) {}
    int value;
};

Distance first(10);       // 可以
// Distance second = 10;  // 编译错误：不能隐式调用 explicit 构造函数
```

列表初始化最重要的额外能力是**拒绝窄化转换**。圆括号形式允许把 `3.75` 转成 `3`，花括号形式会在编译期拒绝这次潜在的数据丢失：

```cpp
double source = 3.75;
int truncated(source);    // 合法，结果是 3
// int rejected{source};  // 编译错误：列表初始化拒绝窄化
```

***不要为了“证明未初始化变量里有什么”而读取它。*** `int value;` 在普通局部作用域中不会自动得到 0，读取不确定值会产生未定义行为。实验源码只明确展示“不能读”，不会运行未定义行为；需要确定的零值时写 `int value{};`。

## 1.2 类型推导：`auto` 和 `decltype` 回答的问题不同

`auto` 通常用来得到一个便于保存结果的新变量。按值推导时，它会像函数按值传参一样去掉引用和顶层 `const`：

```cpp
const int original = 42;
const int& reference = original;

auto copied = reference;  // int，新对象
auto& alias = reference;  // const int&，仍是别名
```

`decltype` 用来询问“这个名字或表达式的精确类型”。对未加括号的变量名，它返回声明类型；对一般表达式，它会把值类别编码进引用类型：

```cpp
int value = 0;

decltype(value) first = 1;    // int
decltype((value)) second = value; // int&，因为 (value) 是左值表达式
```

多出来的一对括号会改变结果，这是 `decltype` 最容易踩的坑。判断推导结果时，不要只看原对象是什么类型，还要看当前语法是在询问“变量声明”还是“表达式”。

结构化绑定解决的是另一个问题：一次把组合值拆成多个有名字的部分。是否复制仍由 `auto`、`auto&` 或 `const auto&` 决定，不是“用了结构化绑定就一定没有复制”。

## 1.3 值类别：表达式如何指向对象

值类别描述的是**表达式**，不是类型的另一个名字：

- 左值表示有稳定身份的对象，例如具名变量；通常可以取得地址，并能在后续继续访问。
- 纯右值表示临时计算结果，例如字面量或直接构造的临时对象。
- 将亡值表示仍有身份、但资源允许被复用的对象，常由 `std::move` 产生。

```cpp
string name = "Athena";

name;                  // 左值
string("temporary");  // 纯右值
std::move(name);       // 将亡值
```

***`std::move` 不会自己搬走任何数据。*** 它只是把表达式转换成将亡值，让右值引用重载有机会接手资源；只有后续的移动构造、移动赋值或其他接收者才可能真正修改源对象。单独写一次 `std::move(name)`，`name` 的内容不会凭空消失。

值类别之所以重要，是因为它会参与引用绑定和重载解析：`T&` 接收可修改左值，`const T&` 可以只读观察更多表达式，`T&&` 优先接收纯右值和将亡值。后续 RAII 章节的移动语义就是建立在这套规则之上。

## 1.4 命名类型转换：让意图可以被检查

C 风格强转把多种完全不同的操作压在同一套语法里，代码评审时看不出程序究竟想做什么。C++ 的四种命名转换分别表达不同意图：

- `static_cast`：执行编译器能够静态检查的明确转换，例如数值转换或已知类型关系中的转换。
- `dynamic_cast`：在多态继承体系中检查对象的真实类型；指针转换失败返回 `nullptr`。
- `const_cast`：只改变 `const`/`volatile` 访问限定。只有底层对象本来就不是 const 时，通过去除 const 后修改才安全。
- `reinterpret_cast`：在指针或底层表示之间做低层转换。它不验证对象真实类型，也不会让原本无效的访问变安全。

```cpp
Base* base = get_object();
if (auto* derived = dynamic_cast<Derived*>(base)) {
    derived->use_derived_feature();
}
```

选择转换时先问“编译器能否检查我的意图”。能用普通隐式转换就不强转；需要明确数值或类型关系时用 `static_cast`；需要运行时确认多态对象时用 `dynamic_cast`。`const_cast` 和 `reinterpret_cast` 应当很少出现，并且旁边需要有清楚的安全理由。

## 1.5 强类型枚举：让状态留在自己的类型里

普通枚举的成员容易泄漏到外层作用域，还可能隐式转换成整数。`enum class` 同时收紧这两个边界：

```cpp
enum class TrafficLight : unsigned char {
    red = 1,
    yellow = 2,
    green = 3,
};

TrafficLight light = TrafficLight::green;
auto raw = static_cast<unsigned char>(light);
```

成员必须写成 `TrafficLight::green`，不同枚举类型不能随意比较，枚举值也不会悄悄参与整数运算。需要序列化或与外部协议交互时，可以明确指定底层类型，再通过 `static_cast` 显式取值。

强类型枚举适合表达“有限且互斥的一组状态”，例如连接状态、任务阶段、解析结果。它比魔法数字或字符串更容易让编译器发现遗漏和混用。

## 1.6 一条可重复使用的阅读顺序

面对陌生 C++ 代码时，可以按下面的顺序分析：

1. 找出对象或表达式的类型，注意 `const` 和引用是否被保留。
2. 判断采用哪种初始化形式，是否会调用 `explicit` 构造函数或发生窄化。
3. 判断表达式是左值、纯右值还是将亡值，推断会匹配哪个引用重载。
4. 遇到类型转换时检查使用了哪种命名转换，以及它实际保证了什么。
5. 遇到有限状态集合时，优先保留在 `enum class` 自己的类型系统中。

这套顺序不会替你记住所有语言规则，但能把“看起来很玄学”的代码拆成几个可以逐项验证的问题。源码实验会让每一步都产生稳定、可测试的输出；编译期拒绝的反例则保留为注释，避免为了演示错误而把项目本身变成无法构建。
