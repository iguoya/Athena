# 第 1 章 类型与表达式（教学大纲）

这是本章的教学大纲。它只讲**知识的前因后果、发展脉络、要解决现实里的什么问题、
达到什么目的**，不涉及具体语法机制，也不绑定任何练习或实验——那些由学习页在
这份大纲的框架内自行发挥。

## 这一章想给你什么

C++ 程序从头到尾在做两件事：**造出对象**，再用一个个**表达式去读它、改它**。
初学时碰到的一大堆"零碎语法"——两种括号、`auto`、引用、`std::move`、几种类型
转换、`enum class`——摊开看很杂，但它们几乎都在回答同一组问题：

- 这个对象是什么，它怎么拿到第一个值？
- 手上这个表达式，指着一个能长期存在的对象，还是一个转瞬即逝的中间结果？
- 类型要变的时候，谁来把关、什么时候把关？

![本章主线：造出对象 → 读它、改它 → 类型的边界谁来守；五个小节分别落在这三段上，回答的是同一组问题](images/type_semantics_mainline.svg)

这一章不是要你背下这些语法，而是要你**养成一套读代码、做判断的习惯**：看到
一段声明或表达式，能说出对象怎么来的、这步操作合不合法、该选哪种写法、为什么。

## 这些知识是怎么一步步来的

![从 C 到 C++20：类型与表达式相关的能力，每一步都在补上一个具体的工程漏洞](images/type_semantics_history.svg)

**C 的做法，和它的代价。** 最早，给变量赋初值只有等号一种像样的写法。它不
检查"大数塞进小盒子"会不会出问题，也不保证没赋过值的变量是干净的。规则少、
好学，但也因此，"精度悄悄丢了""读到一串垃圾数"成了几十年里最常见的一类缺陷。

**C++ 的第一轮扩充。** C++ 加进了构造函数和引用，让"创建对象"能表达更多意图。
能力多了，规矩也跟着复杂：初始化冒出好几种写法，彼此规则还不一样；"我到底是
想拷一份，还是想操作原件"这个区别，光看代码不容易看出来。

**2011 年的一次集中整顿（C++11）。** 这一版几乎是冲着前面的麻烦来的：

- 加了一种新的初始化写法，**在编译期就拦住可能丢信息的转换**，把原来到运行时
  才暴露的问题提前。
- 让编译器能**替你写出类型**——因为泛型代码里类型名又长又容易和右边对不上。
  但它同时提醒：编译器只是帮你写类型，"要值还是要引用"仍然得你自己决定。
- 为了**避免大对象被反复深拷贝**，引入了"把资源让出去"的机制。这逼着语言把
  "一个表达式到底能不能被搬走"讲清楚，也澄清了一个反直觉的点：写 `std::move`
  并不真的搬东西，只是允许别人来搬。
- 给枚举**关进自己的类型和作用域里**，堵住传统枚举到处泄漏、随便和整数一起
  运算的老问题。

**之后（C++14–20）。** 同一套想法一直往外推：让编译器写类型的能力用到了更多
地方，枚举、转换、初始化的规则也在继续细化。但要你建立的那套判断，从 2011 年
到现在没有变。

## 每一节针对的现实问题

| 小节 | 现实里的麻烦 | 学完要能做到 |
|---|---|---|
| 初始化 | 同一个值放进变量，有时精度悄悄没了，有时该报错的没报，有时读到没写过的内存 | 按"这个值必须不丢失地进去吗"来选写法；知道怎么挡住不想要的隐式转换；分清"清零"和"没初始化" |
| 类型推导 | 类型名又长又容易和初始化表达式脱节；但让编译器写类型后，人容易忘了自己还在选"要副本还是要别名" | 说清编译器替你补了什么、没补什么；按"要不要改到原对象"来选写法 |
| 值类别 | "能不能把这个对象搬走""该走哪个函数版本"成了日常问题，而"有名字"并不等于"不能搬" | 先判断一个表达式属于哪一类，再推出它能绑到哪种引用、会选中哪个重载 |
| 类型转换 | 一种"强转"写法把好几种完全不同的意图混在一起，出了事查不出是哪一种 | 认得每种转换各自的前提和保证，优先用检查最严的那种 |
| enum class | 传统枚举名字会泄漏出去、能随便当整数用、不同枚举还能互相比较，状态容易用混 | 判断一组固定状态什么时候值得单独做成一个类型 |

## 目的

学完这一章，面对陌生的 C++ 声明或表达式，你应该能不慌：先认类型和它的修饰，
再看初始化有没有边界风险，判断表达式是持久对象还是临时结果，确认类型转换的
检查在哪一层，遇到固定状态就考虑独立枚举。**先用这套框架形成预期，再拿代码去
验证——预期和结果对不上的地方，就是这一章最该记住的内容。**

## 和其他章节的关系

- **学这章之前**：知道变量、赋值、基本类型就够了。引用和 `const` 在本章按需讲。
- **学完之后**：这里关于"对象寿命"和"把资源让出去"的理解，是"RAII 与资源
  管理"的地基；"让编译器写类型"是"模板与泛型"里天天要用的工具。

## 小结

C++ 里和"类型与表达式"有关的语法，是几十年里一次次为具体工程事故打补丁攒起来
的：C 的宽松埋下"精度丢失""读到垃圾值"的隐患；C++ 用构造函数和引用换来表达力，
也换来初始化写法分裂、强转难审查的复杂度；C++11 集中做了一轮"把问题提前到编译
期"的整顿，加进新初始化写法、`auto`、移动语义和 `enum class`；之后一直在把同一
套思想推广到更多场合。

本章的五节——初始化、类型推导、值类别、类型转换、`enum class`——各自对着一类
现实麻烦，但要建立的是同一种能力：看到一段代码，能说清对象怎么来的、一次操作
合不合法、该选哪种写法、为什么。学习页会用这套框架带你形成预期，再用真实程序
去验证；预期和结果冲突的地方，就是这一章最值得记住的内容。
