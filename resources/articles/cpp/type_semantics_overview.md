# 第 1 章 类型与表达式（教学大纲）

> 建立判断对象如何初始化、何时有效，以及表达式如何参与传递与转换的基本框架。

## 痛点与来历

读 C++ 代码时，只知道“这个变量存着什么”还不够。同一个结果，可能被复制，也可能
只是被另一个名字引用；看似普通的一次传递，可能丢失信息，也可能留下失效的引用。
本章从这些日常判断出发，把分散的语言规则连成一条线。

- **初值是否可靠？** 数值转换可能丢失信息；未建立可用初值就读取，可能导致未定义行为。
- **操作的是谁？** 本来想修改原对象，却改了副本；本来想保留结果，却留下了指向已销毁对象的引用。
- **传递付出什么代价？** 一次操作可能复制对象、复用资源，或者直接构造结果，需要结合规则判断。
- **类型有没有守住边界？** 把不同含义的整数混用，或用强制转换掩盖差异，会让错误更难被发现。

C++ 的演进既在增强表达能力，也在让这些意图更容易被检查。构造函数和引用让对象的
建立与使用有了更丰富的表达；C++11 集中扩展了初始化、推导、移动和枚举；后续标准
继续改进结果构造与类型表达。下面只取与本章有关的几个转折。

## 心智模型

先分清**对象**和**表达式**。对象是程序中具有身份、承载状态的实体；表达式是代码中
参与求值的部分，可以指向已有对象，也可以计算出用于后续操作或初始化的值。
多个表达式可以指向同一个对象，因此“写法不同”不一定意味着“多出了一份对象”。

![对象关注类型、状态和生命周期；表达式关注类型和值类别，两者通过指向与初始化联系起来](images/type_semantics_model.svg)

本章先从对象的三个方面建立判断：**类型**约束允许的操作，**状态**说明它是否已经
正确初始化、当前承载什么，**生命周期**界定它何时有效。再看表达式的两个方面：
**类型**与**值类别**共同参与引用绑定、重载选择等规则。

值类别描述表达式怎样参与操作，生命周期描述对象何时有效。二者需要分别判断：
不能靠“持久还是临时”直接判定值类别，也不能仅凭值类别保证发生移动；还要看类型、
可用操作和使用场景。这是本章最需要建立的区分。

带着四个问题阅读后面的知识点：

1. 这里建立了新对象，还是在访问已有对象？
2. 类型和初始化方式提供了哪些保证，又留下哪些责任？
3. 表达式怎样参与操作，它所指向的对象此时是否仍然有效？
4. 传递与转换保留了什么信息，付出了什么代价？

## 讲什么与边界

**类型与约束。** 理解静态类型如何表达意图、限制操作，以及只读约束的作用。认识
类型别名与枚举的区别：前者帮助命名，后者可以建立独立的类型边界。

**对象与初始化。** 区分初始化和后续赋值，理解不同初始化方式各自提供什么保证；
建立存储期、对象生命周期和临时对象的基本观念，能够识别需要进一步核对的寿命风险。

**推导与表达式。** 理解让编译器确定类型时，哪些信息会保留、哪些可能改变；区分
副本与别名，认识值类别如何参与引用绑定与操作选择。类型推导不会替代对使用意图的判断。

**转换与边界。** 发现隐式转换，理解显式转换表达的意图及检查边界；知道“写出了转换”
不等于“证明转换安全”。

这些内容在本章讲到能够阅读、预测和说明选择依据的程度。引用先建立别名与有效期的
基本认识，完整的绑定、传参与返回规则在「引用」章展开；类的构造与析构实现放到
「类与对象」，资源所有权与移动操作的实现放到「RAII 与资源管理」，完整模板推导规则
放到「模板与泛型」。整型提升与运算符规则按理解所需引入，内存布局和 ABI 不在本章展开。

## 判断与代价

面对陌生代码，可以沿着下面的线索检查；实际阅读时允许往返，不必机械地走固定步骤。

![认类型、看初始化、查有效期、辨表达式、找转换；依据规则形成预期，再用证据修正理解](images/type_semantics_loop.svg)

**明确类型，还是交给推导？** 推导减少重复，也能适应复杂类型；明确写出类型则能
直接表达接口意图。两者都需要检查是否保留了所需的只读约束与引用关系。

**保留副本，还是共享原对象？** 副本让后续修改相互独立，但可能带来复制代价；引用
避免复制，却要求关心原对象的有效期以及修改是否会影响其他使用者。

**复制结果，还是允许资源转移？** 要先判断是否仍需保留原对象的状态，再结合类型
提供的操作作决定。允许移动并不保证移动发生；发生移动后，也要依据该类型的约定使用原对象。

**接受转换，还是保留类型边界？** 更严格的初始化与独立枚举类型能拦住一部分误用；
与外部数据或旧接口交互时，仍需明确转换，并检查范围、含义和前提。

先依据语言规则形成预期，再结合编译诊断与运行结果检验理解。一次运行正常不能证明
代码总是正确，尤其不能据此排除未定义行为；结果不符合预期时，应回查规则与前提。

## 落点

学这章之前，知道变量、赋值和基本类型即可。引用与只读约束会在这里建立初步认识，
不要求预先掌握完整规则。

学完后，应能说明一段简单代码中对象与表达式的关系，分清副本和别名，指出初始化、
有效期与转换中需要核对的地方，并解释自己的选择依据。

这套判断会继续用于「引用」中的传参与返回、「RAII 与资源管理」中的所有权与资源
转移，以及「模板与泛型」中的类型推导。遇到细节疑问时，按主题回查 C++20 规则：

- [初始化](https://timsong-cpp.github.io/cppwp/n4861/dcl.init)、[生命周期](https://timsong-cpp.github.io/cppwp/n4861/basic.life)
- [类型推导](https://timsong-cpp.github.io/cppwp/n4861/dcl.spec.auto)、[值类别](https://timsong-cpp.github.io/cppwp/n4861/basic.lval)
- [类型转换](https://timsong-cpp.github.io/cppwp/n4861/expr.cast)、[枚举](https://timsong-cpp.github.io/cppwp/n4861/dcl.enum)

## 小结

本章用对象与表达式两条线组织初始化、类型推导、值类别、转换和枚举。对象这一侧
关注类型、状态与有效期；表达式这一侧关注类型和值类别，以及它们怎样参与操作。
把两条线联系起来，才能判断是在创建副本、访问原对象，还是允许某种资源转移。

回顾时尤其检查三个误区：**值类别不等于对象寿命，允许移动不等于一定移动，显式
转换不等于安全转换。** 先说明意图与前提，再依据规则作出判断，用实验检验并修正理解。
