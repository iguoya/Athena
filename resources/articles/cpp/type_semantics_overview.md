# 第 1 章 类型与表达式（教学大纲）

> **这一章承诺解决什么**：把"对象怎么诞生、活多久、表达式指着什么、类型变化谁
> 把关"这几件事，变成读代码时就能判断、编译期就能检查的明确规则，而不是靠程序员
> 的记性和运行期的运气。

这是本章的教学大纲，按 ADR 0028 的范式组织：**痛点与来历 → 心智模型 → 讲什么与
边界 → 判断与代价 → 落点**。它只划方向和范围，不讲语法机制，也不绑定练习或
实验——那些由学习页在这个框架内自行发挥。

## 痛点与来历

在 C++ 把这些规则补齐之前，下面几类事情在真实项目里反复发生，而且大多不是
"初学者才会犯的错"，是几十年里最常见、最难查的一类缺陷：

- **精度悄悄丢了**。一个大数放进小盒子，编译器一声不吭，等到数字对不上时，出错
  的地方离真正的赋值已经隔了很远。
- **读到没写过的内存**。变量没有初始化就被使用，值是上一次留在那块内存里的垃圾。
  它时对时错，换台机器、换个编译选项就变样。
- **对象已经没了，还在用它**。指向临时结果的引用活得比那个临时结果长，代码看着
  合理，运行时读到的却是废墟。
- **一种强转混了好几种意图**。去掉 `const`、把指针当成另一种类型、在继承体系里
  向下转——完全不同风险的操作长得一模一样，出了事没法从代码看出是哪一种。
- **大对象被反复深拷贝**。函数返回一个大容器，中间凭空多出几次完整复制，性能白白
  流失，而代码表面上看不出哪里发生了拷贝。
- **一组固定状态被当成整数**。两个本来不相干的枚举能互相比较、能参与算术，状态
  用混了编译器也不会拦。

这些麻烦不是一次补齐的，而是几十年里一次次为具体事故打补丁攒出来的：

![从 C 到 C++20：类型与表达式相关的能力，每一步都在补上一个具体的工程漏洞](images/type_semantics_history.svg)

**C 留下的起点。** 最早，给变量赋初值只有等号一种像样的写法。它不检查"大数塞进
小盒子"，也不保证没赋过值的变量是干净的。规则少、好学，代价就是上面前两条痛点。

**C++ 的第一轮扩充。** 构造函数和引用让"创建对象"能表达更多意图。能力多了，规矩
也跟着复杂：初始化冒出好几种写法，彼此规则还不一样；"我到底是想拷一份，还是想
操作原件"这个区别，光看代码不容易看出来。

**2011 年的集中整顿（C++11）。** 这一版几乎是冲着前面的麻烦来的：加了一种能在
**编译期就拦住丢信息转换**的初始化写法；让编译器**替你写出类型**，因为泛型代码里
类型名又长又容易和右边对不上；引入**把资源让出去**的机制来避免大对象反复深拷贝，
这逼着语言把"一个表达式到底能不能被搬走"讲清楚；把枚举**关进自己的类型和作用域**，
堵住传统枚举到处泄漏的老问题。

**之后（C++14–20）。** 同一套想法一直往外推：让编译器写类型的能力用到了更多地方，
枚举、转换、初始化的规则也在继续细化。但要建立的那套判断，从 2011 年到现在没有变。

## 心智模型

整章可以压缩成两句话。**一个对象有三个属性，一个表达式有两个属性。**

![对象有类型、值、生命周期三个属性；表达式有类型和值类别两个属性。本章所有内容都是这两句话的推论](images/type_semantics_model.svg)

**对象的三个属性**

- **类型**——它是什么，能对它做哪些操作，编译器能替你检查什么。`const` 是类型的
  一部分，不是贴在旁边的标签。
- **值**——此刻它存着什么。值怎么第一次进去，是初始化要回答的问题。
- **生命周期**——它什么时候诞生、什么时候消失、谁负责结束它。引用和临时结果的
  多数事故，根子都在这一条。

**表达式的两个属性**

- **类型**——这个表达式算出来的结果是什么。
- **值类别**——能拿这个结果做什么：能不能取它的地址、能不能绑到某种引用上、能不能
  把它的资源搬走。**有名字不等于不能搬走，这是最反直觉的一点。**

这两句话推得出全章其余内容：初始化是"值第一次进入对象"，类型推导是"类型由谁写
出来"，值类别是表达式的第二个属性，类型转换是"类型属性发生变化时谁检查"，枚举是
"要不要为一组取值单独定义一个类型"。

拿它派生出四个反复自问的问题，贯穿全章、没有一劳永逸的答案：

1. 这个对象的类型是什么？它怎么拿到第一个值？
2. 它活多久，谁负责让它消失？
3. 手上这个表达式，指着一个能长期存在的对象，还是一个转瞬即逝的中间结果？
4. 类型要变的时候，谁来把关、什么时候把关？

## 讲什么与边界

按上面的模型，这一章该覆盖的内容如下。它是从"类型与表达式这个知识领域本身该讲
什么"推出来的，不是现有实验的目录。

**类型这一侧**

- 静态类型系统的基本观念：类型决定这块内存怎么解读、允许哪些操作、编译器能替你
  检查什么。
- `const` 作为类型的组成部分——它约束的是"能不能改"，而不只是一个书写习惯。
- 类型别名：给复杂类型起一个说得清意图的名字。
- 枚举作为独立类型：一组固定取值什么时候值得脱离整数。

**对象这一侧**

- 初始化的几种形式各自保证什么：哪些会拒绝丢信息的转换，哪些把成员清零，哪些
  什么都不保证。
- 存储期与生命周期：对象在哪里诞生、活多久；临时对象什么时候销毁；哪种引用能
  延长临时对象的寿命。
- 类型推导：类型由编译器写出来时，"要副本还是要别名"的决定权仍在你手上。

**表达式这一侧**

- 表达式同时有类型和值类别，二者回答不同的问题。
- 三种值类别分别意味着什么，如何决定引用绑定、重载选择和资源能否被搬走。

**类型变化这一侧**

- 隐式转换：不写任何东西就发生的转换，是最容易埋雷的地方。
- 显式转换：几种命名转换各自表达什么意图、检查强度差多少。

**明确不在这一章讲的**

| 内容 | 归属 |
|---|---|
| 类怎么定义、构造析构怎么写、运算符重载 | 类与对象 |
| 移动构造/移动赋值怎么实现、智能指针 | RAII 与资源管理 |
| 模板参数推导的完整规则、约束与概念 | 模板与泛型 |
| 完整的整型提升表、运算符优先级表 | 与 C 高度重叠，只在理解 C++ 语义必需时提 |
| 内存布局、对齐、ABI | 不在本平台的教学范围内 |

本章只讲"值类别决定一个表达式能不能被搬走"，不讲"移动构造函数怎么写"——前者是
判断，后者是实现，属于 RAII 那一章。

> **已知缺口**：现有实验覆盖了初始化、类型推导、值类别、显式转换和 `enum class`。
> 上面列出的内容里，**`const` 作为类型的一部分**、**存储期与临时对象寿命**、
> **隐式转换**还没有对应的可运行实验。这里如实记下来，是为了让后续补实验有据可依，
> 而不是反过来把大纲裁剪成现有实验的清单。

## 判断与代价

![读陌生代码的五步判断链：认类型、看初始化、问生命周期、判断值类别、找类型变化；走完得到一个预期，再经由运行实验、观察结果、对照修正回到判断本身](images/type_semantics_loop.svg)

学完这一章，面对陌生的 C++ 声明或表达式，你应该能按固定顺序问自己：

1. **认类型**——出现的类型是什么，`const` 和引用怎么修饰它。
2. **看初始化**——值怎么进去的，会不会丢信息，会不会根本没初始化。
3. **问生命周期**——这个对象活多久，我手上的引用会不会比它活得长。
4. **判断值类别**——这是持久对象还是临时结果，能绑到哪种引用，能不能被搬走。
5. **找类型变化**——哪里发生了转换，是隐式还是显式，检查落在哪一层。

**这条判断链的产物是预期，不是答案。** 答案要靠真实程序给：形成预期 → 运行实验 →
观察结果 → 对照修正。预期和结果对不上的地方，就是这一章最该记住的内容。

之所以说"判断"而不是"正确写法"，是因为每一项能力都有代价：

- **编译期检查越严，写法越啰嗦。** 能拦住窄化的初始化写法，也会拒绝一些你本来觉得
  没问题的转换；挡住隐式构造，就得多写一次类型名。
- **让编译器写类型，省了手写，也让选择变得不显眼。** "要副本还是要别名"这个决定
  仍然在，只是从类型名里挪到了一个不起眼的符号上，更容易被忽略。
- **把资源让出去避免了深拷贝，换来一个新问题**：被移走之后的对象处于什么状态、
  还能不能用。
- **`const` 用对了能让编译器帮你把关，用过头会传染**：一处该改的地方改不了，可能
  牵出一长串签名调整。
- **命名转换比一种通用强转啰嗦**，换来的是出事时能定位到是哪一类转换。
- **`enum class` 挡住了隐式转换**，代价是真的需要底层整数时要显式写出来。

## 落点

- **学这章之前**：知道变量、赋值、基本类型就够了。引用和 `const` 在本章讲。
- **生命周期与"把资源让出去"** → 「RAII 与资源管理」的直接地基。
- **让编译器写类型** → 「模板与泛型」里天天要用的工具。
- **值类别与引用绑定** → 函数重载决议和参数传递的基础。

想深入时的权威出处：

- C++ 标准草案：[初始化](https://eel.is/c++draft/dcl.init)、[类型推导](https://eel.is/c++draft/dcl.type.auto.deduct)、[值类别](https://eel.is/c++draft/basic.lval)、[枚举](https://eel.is/c++draft/dcl.enum)
- [C++ Core Guidelines](https://isocpp.github.io/CppCoreGuidelines/CppCoreGuidelines)

## 小结

C++ 里和"类型与表达式"有关的语法，是几十年里一次次为具体工程事故打补丁攒起来的：
C 的宽松埋下"精度丢失""读到垃圾值"的隐患；C++ 用构造函数和引用换来表达力，也换来
初始化写法分裂、强转难审查的复杂度；C++11 集中做了一轮"把问题提前到编译期"的整顿；
之后一直在把同一套思想推广到更多场合。

它们承诺的不是"更安全"，而是**让意图在代码里显形**，编译器才有可能替你把关。

整章压缩成两句话：**一个对象有类型、值、生命周期三个属性；一个表达式有类型和值
类别两个属性。** 初始化、类型推导、值类别、类型转换、枚举，全都是这两句话的推论。
把新遇到的语法往这两句上挂，就不会觉得它们是彼此无关的零碎规则。

这一章给的是判断依据，不是固定答案——每项能力都有代价，该不该用要看场合。用这套
框架先形成预期，再用真实程序去验证；冲突的地方，就是这一章真正的收获。
