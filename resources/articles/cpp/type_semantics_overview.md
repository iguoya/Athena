# 第 1 章 类型与表达式（教学大纲）

> 建立判断对象如何初始化、何时有效，以及表达式如何参与传递与转换的基本框架。

## 痛点与来历

读 C++ 代码时，只知道“这个变量存着什么”还不够。同一个结果，可能被复制，也可能
只是被另一个名字引用；看似普通的一次传递，可能丢失信息，也可能留下失效的引用。
本章从这些日常判断出发，把分散的语言规则连成一条线。

下面五类风险与本章「判断与代价」的五个检查点一一对应，
后面遇到它们时可以直接回到对应的检查点。

- **不同含义被当成同一种类型。**（① 认类型）枚举、整数和强制转换混在一起时，
  编译器很难替代码守住边界。
- **读取没有可靠初值的对象。**（② 看初始化）代码可能表现不稳定，甚至直接进入未定义行为。
- **对象已经失效，引用仍被使用。**（③ 查有效期）表面上还能访问，实际已经越过对象的有效期。
- **分不清在操作副本还是原对象。**（④ 辨表达式）写法很像，改动却落在不同对象上；
  反过来没察觉产生了副本时，大对象的复制会变成真实的时间和内存代价。
- **精度悄悄丢失。**（⑤ 找转换）数值进入范围更小或表达能力不同的类型后，结果可能已经
  不是原来的值。

这些风险大多是表达能力增强后留下的选择题。构造函数和引用让对象的建立与使用有了
更丰富的表达，也让「这是新对象还是已有对象的别名」成了每次都要判断的事；C++11 的
类型推导省掉重复书写，同时把「副本还是别名」的意图交还给你；列表初始化和作用域
枚举则是反过来收紧检查，把一部分风险挪到编译期。本章要学的判断，就落在这些转折上。

## 心智模型

先分清**对象**和**表达式**。对象是程序中具有身份、承载状态的实体；表达式是代码中
参与求值的部分，可以指向已有对象，也可以计算出用于后续操作或初始化的值。
多个表达式可以指向同一个对象，因此“写法不同”不一定意味着“多出了一份对象”。

![对象关注类型、状态和生命周期；表达式关注类型和值类别，两者通过指向与初始化联系起来](images/type_semantics_model.svg)

本章先从对象的三个方面建立判断：

- **类型**：对象是什么，允许哪些操作，编译器能够检查什么。
- **状态**：对象是否已经正确初始化，此刻承载什么值或资源。
- **生命周期**：对象何时开始存在、何时结束，以及当前访问是否仍然有效。

再看表达式的两个方面：

- **类型**：表达式产生或指向什么类型的结果。
- **值类别**：表达式怎样参与引用绑定、重载选择等规则。

值类别描述表达式怎样参与操作，生命周期描述对象何时有效。二者需要分别判断：
不能靠“持久还是临时”直接判定值类别，也不能仅凭值类别断定会发生移动；还要看类型、
可用操作和使用场景。这是本章最需要建立的区分。

## 讲什么与边界

### 先看主次与顺序

**推荐顺序**：初始化 → 对象生命周期 → `auto` → 枚举 ／ 转换 → 值类别 → `decltype`。
这不是随口排的，它就是知识点之间先修关系的拓扑序——`decltype` 的规则要用值类别
说明，值类别要先知道临时对象何时销毁，跳着学会在后面卡住。

- **先拿下（初中级 + 需要精通）**：初始化的保证、对象生命周期与临时对象、
  `auto` 的副本与别名之分。这三样在后面每一章都会用到，判断错的代价最直接。
- **随后掌握（初中级 + 必须掌握）**：枚举的类型边界、转换的意图与检查位置。
  它们不难，但决定接口能不能替你挡住误用。
- **需要理解，可以慢一点（进阶 + 必须掌握）**：值类别。规则密度高，第一遍能判断
  左值／纯右值／将亡值并说明它影响哪种绑定即可，写模板时会再深入。
- **初学者可以先跳过（进阶 + 一般了解）**：`decltype` 的表达式取类型规则。
  先知道它解决什么问题，等真正写泛型代码时回来补。

贯穿全章、没有独立实验的是**静态类型本身**：它表达什么意图、限制哪些操作、编译器
能检查到哪里——每个方向都会碰到它。

### 分方向的清单

本章的主脊是上一节那五个检查点；下面四组只是把知识点归类摆开，便于查找和定位，

入门／简单／中等属于初中级，进阶／高级属于高级；后一项是**掌握目标**。
两项互不推导——难的不等于可以跳过（值类别就是），简单的也不等于随便看看
（枚举边界很简单，却每次设计接口都要用）。

## 判断与代价

面对陌生代码，可以沿着下面的线索检查；实际阅读时允许往返，不必机械地走固定步骤。

![认类型、看初始化、查有效期、辨表达式、找转换；依据规则形成预期，再用证据修正理解](images/type_semantics_loop.svg)

阅读时可以反复使用这五个检查点：

1. **认类型**：对象和表达式分别是什么类型，`const` 与引用修饰了哪一层。
2. **看初始化**：对象怎样取得初始状态，是否存在信息丢失或未初始化风险。
3. **查有效期**：对象此刻是否仍然存在，引用会不会活得比所指对象更久。
4. **辨表达式**：表达式的类型和值类别怎样影响绑定、重载与后续操作。
5. **找转换**：转换在哪里发生，是隐式还是显式，哪些前提仍需程序员保证。

这些检查最终会落到三组经常出现的选择上：

- **明确类型，还是交给推导？** 推导减少重复，也能适应复杂类型；明确写出类型能够直接
  表达接口意图。两者都需要检查是否保留了所需的只读约束与引用关系。
- **保留副本，还是共享原对象？** 副本让后续修改相互独立，但可能带来复制代价；引用
  避免复制，却要求关心原对象的有效期以及修改是否会影响其他使用者。
- **接受转换，还是保留类型边界？** 更严格的初始化与独立枚举类型能拦住一部分误用；
  与外部数据或旧接口交互时，仍需检查范围、含义和前提。

先依据语言规则形成预期，再结合编译诊断与运行结果检验理解。一次运行正常不能证明
代码总是正确，尤其不能据此排除未定义行为；结果不符合预期时，应回查规则与前提。

## 落点

**学习前提**：知道变量、赋值和基本类型即可；引用与只读约束会在这里建立初步认识。

**本章结果**：下面每一条都可以拿一段没见过的代码当场检验，标注是它对应的掌握目标。

顺序与上面的推荐顺序一致，做到哪一条就检验哪一条。

1. 面对一次初始化，说明它提供了什么保证、可能在哪里丢失信息、谁来检查。〔需要精通〕
2. 说出一个对象从哪一行开始存在、到哪一行结束，并判断某个引用此刻是否还有效。
   〔需要精通〕
3. 指出一段代码里哪些名字指向同一个对象、哪些是各自独立的副本，并说明在一个具体
   场景里该选哪种：是否要改原对象、复制的代价、原对象的寿命够不够。〔需要精通〕
4. 说明一组状态什么时候值得有独立的枚举类型，它挡住了哪些误用。〔必须掌握〕
5. 看到一次转换，说出它表达什么意图、检查发生在编译期还是运行期、哪些前提仍由自己
   保证。〔必须掌握〕
6. 判断一个表达式是左值、纯右值还是将亡值，并据此说明它能绑定到哪种引用。〔必须掌握〕
7. 说明 `decltype` 解决的是哪一类问题，知道它和 `auto` 问的不是同一件事。〔一般了解〕

## 小结

本章用对象与表达式两条线组织初始化、类型推导、值类别、转换和枚举。对象这一侧
关注类型、状态与有效期；表达式这一侧关注类型和值类别，以及它们怎样参与操作。
把两条线联系起来，才能判断是在创建副本、访问原对象，还是允许某种资源转移。

回顾时尤其检查这些误区：

- 值类别不等于对象寿命。
- 使用引用不等于对象一定仍然有效。
- `std::move` 只是把表达式转成将亡值，它自己不移动任何东西——本章的值类别实验里
  可以直接看到它只改变了重载选择。移动怎样真正发生，留到「RAII 与资源管理」。
- 交给编译器推导不等于不再需要表达副本或别名的意图。
- 显式转换不等于安全转换。

先说明意图与前提，再依据规则作出判断，用实验检验并修正理解。
