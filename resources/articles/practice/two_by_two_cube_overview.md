# 第 1 章 2 阶魔方：从状态建模到可交互渲染

“应用实践”这个分类跟 C++ 系列不一样，不是按语言特性拆知识点，而是拿一个完整的小项目，练习"怎么把一整套语言能力组织成一个能跑、能看、能交互的东西"。2 阶魔方（Pocket Cube）是第一个练习对象：规则简单（只有 8 个角块，没有棱块和中心块），但状态建模、坐标变换、渲染管线这几件事一样都不少，是个恰到好处的综合练习。

> 核心目标：状态和转动用什么表示既正确又好验证，渲染层怎么复用同一份状态而不重复画逻辑，交互接口怎么设计才方便后续接真正的求解算法。

## 1.1 状态表示：坐标 + 固连贴纸标记

2 阶魔方摆在以自身中心为原点的坐标系里，8 个角块各占据 `(x, y, z) ∈ {-1, 1}^3` 这 8 个位置之一。每个角块除了位置，还带三个贴纸颜色标记：`color_x`/`color_y`/`color_z`，分别是这个角块当前朝 X/Y/Z 轴方向露出的贴纸颜色——具体朝正方向还是负方向，由该角块自己当前的坐标符号决定。

```cpp
struct Corner {
    int x = 1, y = 1, z = 1;
    Face color_x = Face::R;
    Face color_y = Face::U;
    Face color_z = Face::F;
};
```

这个设计的关键点：贴纸标记是**固连在角块本体上**的，不是"记录这个位置上摆的是哪个初始角块编号"。好处是转动的时候只需要对坐标和标记做同一套线性变换，不需要另外维护一张"位置到贴纸"的置换表——两者本来就是同一个刚体旋转的两个侧面。

## 1.2 转动代数：旋转矩阵 + 用代数性质自证

每个面的转动都是绕一条轴（U/D 绕 Y 轴、L/R 绕 X 轴、F/B 绕 Z 轴）转 90 度，从标准旋转矩阵手推出六个面顺时针各自的坐标变换：

```text
U 顺时针：(x,y,z) -> (-z,y,x)      R 顺时针：(x,y,z) -> (x,z,-y)
D 顺时针：(x,y,z) -> ( z,y,-x)     L 顺时针：(x,y,z) -> (x,-z,y)
F 顺时针：(x,y,z) -> (y,-x,z)      B 顺时针：(x,y,z) -> (-y,x,z)
```

贴纸标记的变换规则更简单：只看"变量对应关系"，不带符号——符号信息已经完全体现在新坐标本身上，颜色标记只是跟着搬家。比如 U 顺时针把 `x` 换成了 `-z`，对应的贴纸变换就是 `color_x' = color_z`（不需要给颜色取负）。

***手推的矩阵不能只靠肉眼看着觉得对，必须验证。*** 这里没有去核对"转完以后哪个颜色该在哪"这种容易出错的主观判断，而是用几条群论上必然成立的代数性质写测试自检：任意一个面连续转 4 次必须回到原状态、顺时针和逆时针互相抵消、转 180 度等于转两次 90 度、转动只影响选中的那一层、转动不改变这个面自己的贴纸颜色。这几条性质只要旋转矩阵写对了就必然成立，写错了符号也大概率会在某一条上露馅——这比"运行一下，肉眼看结果对不对"可靠得多，也是这个项目值得复用到别处的一个工程习惯。

## 1.3 渲染层：3D 视图与展开图互补，同一份状态

魔方有两种可视化，都吃同一个 `CubeState`，都是纯 Cairo 手绘（不引入 OpenGL 或图表库——6 个平面、24 个贴纸格用不上真正的图形管线）：

- **3D 视图**：正交投影 + 鼠标拖拽旋转（`Gtk::GestureDrag` 驱动俯仰角/方位角，每次拖动重新投影重绘），背面剔除 + 按深度排序处理最多 3 个可见面的前后关系，直觉的立体印象，但任意时刻看不全 6 个面。
- **展开图**：标准十字形网格（U 在上、D 在下、L F R B 横排），六个面一次性摊开，没有遮挡，精确读状态用这个。

两个视图共享同一套"给定面 + (u, v) 符号，查询这一格贴纸颜色"的接口（`sticker_at()`），面的儿何角点和状态查询用的是同一份 `face_layout()` 定义，不需要额外维护"渲染格子顺序"和"状态数据顺序"这两份容易走样的对应关系。

## 1.4 交互接口：拉模型 + 手动触发重绘

渲染函数不持有状态，而是接收一个 `function<CubeState()> state_provider`——每次重绘时才去问一下当前应该显示什么，不是把状态值直接存进控件里。状态变化后由调用方手动对返回的 `Gtk::Widget*`（实际都是 `Gtk::DrawingArea*`）调用 `queue_draw()` 触发重绘：

```cpp
auto state = make_shared<CubeState>(make_solved_cube());
auto* view_3d = make_cube_3d_view([state] { return *state; });
auto* view_net = make_cube_net_view([state] { return *state; });
...
*state = apply_move(*state, {Face::U, Turn::Clockwise});
view_3d->queue_draw();
view_net->queue_draw();
```

这套接口刻意保持简单：没有自动响应式绑定，状态改了要显式通知视图刷新——对目前"点一下运行按钮转一步"这种简单交互足够用，以后如果状态变化频繁（比如自动打乱、自动求解逐步演示），也可以在这个基础上加一层节流/动画，不需要重新设计接口本身。

## 1.5 现状与后续方向

目前"运行"按钮点击后只是固定应用一次 U 顺时针转动，用来演示这套接口怎么用——真正的打乱、求解算法和更完整的操控界面（比如逐个面的转动按钮）还没做。2 阶魔方状态空间只有 366 万种（`8! × 3^7`，最后一个角块的朝向由其余角块决定），完全在广度优先搜索可以穷举求最短解的规模内，是这个练习下一步比较自然的方向；状态标签栏也预留了要显示"已探索状态空间数量、当前搜索层次、当前状态的路径来源"这类求解过程信息的想法，等求解器真正写出来再接上真实数据，不提前显示占位的假数字。
