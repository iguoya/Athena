# ADR 0001：立项——第一批范围、验证口径、实验环境与模型文件管理

- 日期：2026-10-12
- 状态：已接受
- 上位决定：主仓库 [ADR 0152](../../../../docs/decisions/0152-edge-ai-course.md)（新增本应用、
  运行时主线、硬件策略、边界）。本文只写本应用内部的做法，不重复上位决定的理由。

## 背景

本应用要让学员对「一个模型落到一台设备上」这件事形成可验证的判断：延迟多少、占多少内存、体积
多大、精度掉了多少，而且这些数能被复现。上位决定已经定了范围和硬件；本文把它落成第一批内容的
边界和每章共用的验证口径，避免每章各立一套。

## 决策

1. **第一批只做 5 章**，顺序固定：① 端侧预算与基线 ② 模型导出与等价性 ③ 训练后量化
   ④ ONNX Runtime 推理与性能剖析 ⑤ 端侧大模型（llama.cpp 与 GGUF）。每章一个实验，在本机 CPU
   上真跑、能自动判定。第 6 章「上板与 NPU」要等开发板到手并有一次实测后再写，写好前不进课表。
2. **验证口径：预算卡。** 实验开始前，学员为自己的设备写一张预算卡——延迟上限、内存上限、体积上限、
   精度下降上限；实验结束，应用拿实测值与预算卡逐项比对，全部满足才算通过，并显示每一项离预算
   多远。预算由学员定，不在课程里写死阈值。
3. **跨设备基准。** 第 1 章落地一个基准脚本，输出统一的测量记录（设备、系统、运行时与版本、
   模型哈希、延迟的 P50/P95、峰值内存、模型体积、精度）。脚本必须在 x86 Windows 与 ARM Linux
   （树莓派 4B）上都能跑，后面每章复用它。记录的具体字段在第 1 章落地时定，写进应用级的下一条 ADR。
4. **测量要可复现。** 每份记录带上能复现它的最少信息（命令、随机种子、线程数、预热次数）；
   没有复现信息的数字不计入通过。
5. **实验环境。** 由 uv 管理，固定 Python 3.12，依赖版本锁定；应用只执行白名单内的预设命令，
   不提供任意 shell（主仓库 ADR 0091 决策 3 同规）。GPU 不足的实验给 CPU 路径并如实标注。
6. **模型文件。** 约 20MB 以内的小模型入库，大模型不入库，由白名单脚本按固定地址下载并校验
   sha256，缓存目录被 git 忽略。新增模型前先核对来源与许可，记入 `content/sources.json`。
7. **出处。** 官方文档当场标注。厂商与社区文档里的事实（RKNN 的主机要求、板子价格与支持范围等）
   写进内容前必须下载原文逐条核对，不凭记忆。

## 后果

- 课表里第 1–5 章先以 `planned` 登记，写好一章改一章；任何一章都不能在没有真跑过的情况下上线。
- 第 1 章的基准脚本是整门课的地基，它的测量口径一旦定下，后面章节不单独改。
- 本应用目前没有进度库；进度库在首次运行时建，建好后进版本库（主仓库 ADR 0053）。
- 应用图标暂时沿用壳的默认位图，`app.json` 的 `icon.renders` 为空；画 `icon.svg` 并渲染位图是
  后续一项独立的小事（主仓库 ADR 0065）。
