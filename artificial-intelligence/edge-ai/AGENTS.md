# Athena 端侧 AI 推理与部署 — 项目协作规则

本文档是 **`artificial-intelligence/edge-ai` 独立应用** 的项目级指令，不依赖任何其他应用即可完成
开发、构建、学习与实验全流程。

仓库根 `AGENTS.md` 写各应用共同遵守的规则；**改本应用时以本文为准**。启动器通过
`app.json` 把本应用当独立进程拉起（ADR 0032），那不是运行本应用的前提。

## 定位

- **学习应用**（主仓库 ADR 0152）：人工智能路线的端侧一环——把模型压小、转格式，在固定设备上测出
  延迟、内存、体积与精度，并让它们满足一张自己写的预算卡。产出是可复现的测量记录和能在设备上跑
  的推理程序，不是论文式的理论。
- **边界**：与 `llm-finetune` 分工是——它讲 LLM 量化的**方法与精度评估**；本应用讲通用训练后量化
  （视觉等小模型）、目标设备上的预算与剖析，LLM 只讲「拿一个量化好的模型在设备上跑」，不重复教
  量化方法。与 `llm-app`：它把模型当黑盒服务，本应用关心模型怎样落到一台设备上。微控制器级的
  TinyML 不在本课，后续另立项。
- **先修与独立性**：先修是 deep-learning。指引写在内容里，不引用其他应用的路径或代码（ADR 0032）；
  可单独使用，开头自带一小节「把 PyTorch 模型导出」的最小补课。
- **出处档位 open**（ADR 0089）：技术学习类；不凭印象伪造出处，官方文档当场标注，AI 现场出题不计入
  掌握度。厂商与社区文档里的事实（RKNN 主机要求、各板子的价格与支持范围）写进内容前必须下载原文
  逐条核对。
- **学习方法原型（ADR 0113）**：主原型**真做校验**——每章做出一个能量出数字的东西；辅**辨析决策**
  ——给预算，选精度、运行时、模型大小。量化误差分布、延迟与精度的取舍等画成活的（ADR 0056）。
- **通过标准是预算卡**：每个实验先让学员写一张预算卡（延迟、内存、精度下降上限，按自己的设备定），
  应用拿实测值与预算卡自动比对判通过。不写死统一阈值，因为设备性能差得远。

## 当前阶段与范围

- 现在是立项与骨架：第 1–5 章在 `content/course.json` 里标 `planned`，按顺序写，写好一章把它
  从 `planned` 改成真实内容。第一批：① 端侧预算与基线 ② 模型导出与等价性 ③ 训练后量化
  ④ ONNX Runtime 推理与性能剖析 ⑤ 端侧大模型（llama.cpp 与 GGUF）。
- **第 6 章「上板与 NPU」要等 RK3588（Debian）开发板到手并有一次实测后才写**，写好之前不进课表
  （ADR 0129 不留占位）。作者无法接触使用者的板子，没有实测的内容不写。
- 运行时主线只有 ONNX Runtime 与 llama.cpp；TFLite、ExecuTorch、Core ML 以及昇腾、Jetson 路线
  不在本期。

## 硬件与验证

- 基线是 Windows 电脑的 CPU：第 1–5 章每个实验都必须在上面能跑、能判。
- 树莓派 4B 是**可选的第二台测量设备**：基准脚本做成跨设备（x86 Windows 与 ARM Linux 都能跑），
  不为它单独加章节；没有这块板子的人跳过它，课程仍然完整。
- 主线 NPU 板是 RK3588（Debian），NPU 走 RKNN。RKNN-Toolkit2 的模型转换据资料需要 x86_64 Linux
  主机，Windows 上用 WSL2；这一条在写上板章节前要核对官方文档。
- GPU 资源不足的实验给 CPU 降级路径并如实标注。

## 技术栈（本应用自有）

- **壳**：Tauri 2（Rust），界面 React 18 + TypeScript + Vite。最初复制自同路线的 `llm-finetune`
  的骨架，此后独立演进（ADR 0062）。骨架阶段只有窗口与定位页；实验引擎随内容填充期落地。
- **实验环境**：由 uv 管理，**固定 Python 3.12**，不使用系统 Python（本机是 3.14，主要的深度学习
  包未必已有预编译包）。实验在本机 Python 子进程真跑，应用只执行白名单内的预设命令，不提供任意
  shell（ADR 0091 决策 3 同规）。
- **模型文件**：约 20MB 以内的小模型直接入库；大模型（如 GGUF）不入库，由白名单脚本按固定地址下载
  并用 sha256 校验，缓存目录被 git 忽略。
- **内容**：`content/course.json`（本目录唯一课表）；出处目录 `content/sources.json`。
- **进度**：SQLite，写入本应用自己的 `progress/learning.db`（随仓库走，ADR 0053），首次运行时建，
  知识点 ID 前缀 `edge.`。骨架阶段还没有进度库。
- 端口 **1515**（strictPort）；进程/二进制 `athena-edge-ai`。

## 内容与教学分层

- **内容驱动 UI**（ADR 0058）；有限的块类型承载全部讲解，不按章手写整页。
- **随堂练习与考核**（ADR 0002）：完成度只由作答按正确率写入；题量以覆盖为准（ADR 0096）。
- **实验给骨架**（ADR 0003）：学员只补 `TODO`，不从零写整程序。
- 每节要有可提取物（一个数、一张图或一段可复现的记录），复习由记录派生（ADR 0096）。

## 开发与验证

```sh
launcher open edge-ai
python3 scripts/check.py          # 骨架阶段默认结构校验
python3 scripts/check.py --full   # 追加前端构建与 cargo check
```

环境变量 `ATHENA_EDGE_AI_ROOT` 可强制指定应用根目录（含 `content/`）。
