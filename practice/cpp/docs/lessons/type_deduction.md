## 3. 可直接用于页面的讲解

### 3.1 为什么需要 auto

> 当初始化表达式已经提供了类型信息，重复写出类型可能没有增加多少信息。容器和泛型代码里的
> 类型还可能很长；改了初始化表达式后，手写的类型也可能需要跟着调整。`auto` 让编译器依据
> 初始化表达式推导声明中的类型部分，减少这些重复。
>
> 但“编译器知道类型”还没有回答另一个问题：你想得到一份值，还是想继续访问原来的对象？
> 这两种选择会影响修改是否传回原处、有没有复制，以及访问是否受原对象寿命限制。
> 本节先把这项选择讲清楚，再讨论更细的推导规则。

版式：正常正文配一个小型“初始化信息 → 类型推导 → 声明意图”的流程图。
不要以“先猜输出”开场，也不需要凭空编造类型推导的历史故事。

### 3.2 先分清对象和值、名字与别名

> 先看一个整数 `original`，它的值是 42。把这个值用于初始化另一个 `int`，就得到另一个对象。
> 两个对象此刻数值相等，但此后修改其中一个，不会自动修改另一个。
>
> 引用则提供访问已有对象的另一个名字。这里的 `alias` 不是第二个整数容器；通过它赋值，
> 修改的是它绑定的 `original`。判断是否互相影响时，先数有几个对象，再看每个名字关联谁。

图中只用实线框表示整数对象，别名用框外标签和连线表示。不要把 alias 画成与 original
相同的“独立整数格”，也不表示真实机器地址。此处是对象身份示意。

### 3.3 三种写法，三种访问意图

以下为教案示例；正式源码区必须从人工源文件加载。这里先限定为一个已存在的普通 `int` 左值。

```cpp
int original = 42;
auto copy = original;
auto& alias = original;
const auto& view = original;
```

> `auto copy = original` 在这个例子里声明了一个新的 `int`。它用 original 的当前值初始化，
> 后续有自己的值。若初始化表达式使用的是这个整数的引用名字，按值推导也不会因此把 copy
> 变成引用。可以把这一步理解为“取出值，创建另一个整数”。
>
> `auto& alias = original` 中的 `&` 是你明确保留的引用意图。这次声明的是 `int&`，
> 没有创建第二个整数。写 `alias = 99` 时，被改变的是 original。
>
> `const auto& view = original` 声明的是 `const int&`。它同样访问 original，但不允许通过
> view 给这个整数赋值。const 限制这条访问路径，不会把一个原本可修改的 original 全局锁住。
> original 若经别的可写名字改变，view 再读取时也会看到新的值。

三条讲解逐段配对应图示；整段读完再给出简短对照表，避免初学者只记住三个符号标签。
规则依据：[C++20 草案的占位类型推导](https://timsong-cpp.github.io/cppwp/n4861/dcl.type.auto.deduct)
与[引用声明](https://timsong-cpp.github.io/cppwp/n4861/dcl.ref)。

### 3.4 让变化说明规则

> 下面每次只执行一个动作。先改副本，再通过别名改原对象，最后从只读名字观察。
> 注意“值相同”与“指向同一个对象”是两件事：数值刚好相同，不能说明对象相同。

动画脚本见第 4 节。播放后补一句：

> 现在 copy 为 7，original 为 99。alias 和 view 都访问 original，所以它们读取到 99。
> copy 与 original 曾经同为 42，只是初始化时复制了数值，并没有建立自动同步关系。

### 3.5 换一个条件，确认理解

> 现在通过 original 把值改为 120。你认为 view 随后读到多少？为什么？

选项为“120，因为仍访问同一个对象”“99，因为只读会冻结数值”“无法读取，因为原对象变过”。
这是学后确认题，不作为未知知识的前测，不更新现有熟练度。

反馈应解释：

> view 读到 120。它限制的是通过自身修改对象的操作，不是保存一张旧值快照。
> 如果你需要修改原值以后仍保留旧值，就应考虑这里的值副本；如果要观察当前值，别名才有这层联系。

允许不答题继续阅读，并能主动展开解释；不答题不挡住原理或实践。

### 3.6 怎样用于真实代码

> 先决定你希望程序做什么，再选择写法。对这里的普通整数，想保留一份可单独修改的值，可以
> 用值副本；想直接修改已有对象，可以用可写引用；想避免复制又只通过当前名字读取，可以用
> const 引用。引用把访问联系到原对象，也因此要求使用时原对象仍然存活。
>
> 这个判断可以带到容器里：如果需要修改一个已存在容器中的元素，就不能误把元素复制出来
> 再改副本。反过来，若是想得到一份独立数据用于尝试修改，也不应意外地保留可写别名。
> 选型时同时考虑目的、复制成本和对象寿命，不把“引用总更快”当成规则。

局部流程图的前提写在图上：“已存在且在使用期间存活的普通对象；非代理引用”。
分支是“需要独立的值？”→ 值方式；否则“需要经此处修改原对象？”→ 可写引用；否则→只读引用。
图后给出三个任务：保存当前整数值供以后比较、修改原有整数、观察原有整数但禁止本处赋值。
让读者说明选择理由，不要求再完成三组机械选择题。

### 3.7 必须当场说明的边界

> 本例是普通整数。`auto` 本身不保证“深拷贝”：复制指针或共享所有权对象，仍可能访问同一份
> 底层资源；从临时值初始化也不能一概称为拷贝。本节的对象图只解释当前例子，不推广成所有类型的内存图。
>
> 只读引用也不自动保证任何对象永久存活。这里引用的是已经存在的 original；临时对象绑定和
> 生命周期延长有专门规则，学习到那些场景时再展开。本例中的引用不能在 original 销毁后继续使用。

边界段默认展开；更完整的列表初始化、数组/函数退化、代理类型等放在可选参考或后续单元。
不要用一个“更多详情”链接替代以上直接影响本页判断的说明。

### 3.8 下一单元：为什么还需要 decltype

> `auto` 帮你根据初始化表达式完成声明。有时我们要问的不是“在这里声明怎样的变量”，
> 而是“这个名字或表达式按语言规则具有什么类型”，以便让另一处声明跟随它。`decltype`
> 就提供这种类型查询；它不会为了取类型而执行其中的表达式。

接着在本页第二单元比较 `decltype(value)` 与 `decltype((value))`：前者对普通未加括号名字
取实体的声明类型，后者进入表达式规则。就近补充“左值表达式关联对象身份”的解释后，
再展示 `T& / T&& / T` 的规则表与本章已有真实实验。不要把该表挪到手册作为必读前提。
结构化绑定等特殊规则在扩展中明确列出，不能把上述普通名字规则宣称为全部情况。
依据：[C++20 草案 decltype](https://timsong-cpp.github.io/cppwp/n4861/dcl.type.decltype)。

第一单元小结：

> 类型推导减少重复的类型书写，但值、引用与只读访问的意图仍由声明表达。
> 在本例里，copy 是独立整数；alias 与 view 都访问 original，其中 view 不能用于赋值。
> 做选择时按“需要怎样的数据关系 → 是否修改原对象 → 复制与寿命代价”思考。
> 数值相等不等于同一对象，只读访问也不等于原对象被冻结。

## 4. 对象图与动画分镜

来源标为“概念演示”：作者按已核对的语言规则编排，不是读取真实运行时内存。
对象位置固定；名字标签与对象框形状不同。修改用数值变化和文字说明同时表达，不只闪颜色。

| 步骤 | 动作 | 可见状态 | 紧邻解释 |
|---|---|---|---|
| 0 | 创建 original | 一个整数对象：42 | 建立最初的对象 |
| 1 | 初始化 copy | 出现第二个整数对象：42 | 新对象用旧对象的值初始化 |
| 2 | 绑定 alias | alias 标签连到 original；不增加整数框 | 增加访问名字，不增加整数 |
| 3 | 绑定 view | view 标签连到 original，标注“只读访问” | 同一对象的受限访问路径 |
| 4 | copy = 7 | copy 变为 7，original 仍为 42 | 改的是独立副本 |
| 5 | alias = 99 | original 变为 99；view 读取 99；copy 仍为 7 | 通过别名修改原对象 |
| 6 | 展示 view = 20 的边界 | 标注“不能通过此名字赋值”，对象数值不变 | 规则说明；未接编译器时不显示伪诊断 |

操作：上一步、下一步、播放/暂停、重置。默认静止，读者开始后才播放；最后一步停止。
切换小节暂停；重置回步骤 0；减少动效模式只更换静态状态。显示“步骤 n / 6”和当前解释，
键盘可操作。下方可展开同样的状态表，让不播放动画的学习者获得完整信息。

动画轨迹只说明语义，不模拟物理内存搬运速度。若未来用真实事件驱动图形，必须由实验结果
提供数据并核对事件顺序，不能悄悄把示意模型改称“真实执行”。
