## 学习内容

- 本应用是为快速渐进学习和掌握 C++ 而开发的自用软件，突出学练合一：把零散的代码知识点学习整合到统一框架中，方便运行验证、测试和自我修正；不以制作完整教程产品为目标。
- 学习内容必须从“学习 C++ 知识点”的角度组织和生成，是知识体系、概念语义、适用边界、
  常见误区和思维模型的主要载体；不得按现有源码的文件结构、类结构或函数实现顺序写成
  源码说明书，也不得通过总结现有实现反向决定应教授哪些知识。
- 所有章节都是同一种：可实验知识点由章节的课程类和成员函数承载，理论、原则和工程思想
  由该章原生学习页的大纲与教学过程承载。`content: article` 章节类型和 `chapter.document`
  字段已由 ADR 0012 废弃，Markdown 分类手册整条路线已由 ADR 0034 删除。
- 章节的核心闭环是“选择知识点 → 查看真实源码 → 运行对应成员函数 → 查看输出结果”。
- 一个课程类对应一个一级主题；一个 public 成员函数对应一个可独立运行的二级知识点。
- **学习内容一律由 GTK 控件承载，没有 Markdown 正文。** 原生学习场景自由使用 Blueprint、
  GTK 控件、图片/SVG、图表、流程图和合适的动态绘制来组织“预期—验证—反馈”，页面顺序和
  表现形式由教学目的决定。`resources/articles/` 下只剩这些页面引用的插图，不再有任何
  `.md`；`category.handbook_documents`、`chapter.overview_document`、`subchapter.teaches`
  和 `chapter.learning_units` 四个字段已由 ADR 0034 废弃，生成器会拒绝。
- **每章第一个标签就是「教学大纲」，不再有「本章导览」（ADR 0039 取代 ADR 0036）**。
  导览当初是为了解决"大纲太长、不知道该看哪里"，但它给出的四块内容大纲全都有，
  只是缩写了一遍——两份内容讲同一件事，迟早漂移。**正确的解法是把大纲写短，
  不是在它前面再加一份摘要。**
  大纲要自己承担"三十秒看清轻重缓急"这件事：主次与顺序放在最前，细节在后；
  **难度与掌握目标必须一眼可见**，靠的是那张按 `requires` 实时绘制的路线图
  ——配色给难度、节点文字给掌握目标、底部细条给当前熟练度，点节点直接跳转。
  **以图为主**：概念怎么串、哪节为哪节铺垫，画出来比列出来快；能由数据算出来的
  结构就画成活的。**能合并的节不要拆**：同一组东西不要既列一遍"风险"又列一遍
  "检查点"，那是把一份内容写成两份。
- **大纲与教学过程都用 GTK 控件表达，Markdown 是衍生物**（ADR 0033）：能由运行时
  数据算出来的（先修依赖、难度与掌握目标、实时熟练度）就画成活的并配上互动——点节点
  跳转、切换对照、逐步推进；不要写成文字让读者自己聚合，也不要做成会和数据漂移的
  图片。纯概念示意按 ADR 0038 选载体（见下文「图文结合」）。不同维度不能共用一套视觉编码。加视觉元素前先问
  "一句话能不能说得同样清楚"，把正文清单排成方框不算可视化。
- 教学实验应短小、聚焦且能直接观察结果；通常以 10–30 行方法体为参考，不为满足行数牺牲完整性和可读性。
- **教学实验有两条路径，并存而不是二选一（ADR 0053）**：
  - **只读实验**：课程类的 public 成员函数，编译进应用，`FunctionRegistry` 调用。
    它展示的是真实工程源码，适合「看懂它长什么样」。
  - **骨架案例**：`resources/cases/<case>/`，挂在知识点的 `labs[]` 上，学员就地
    编辑、本机编译运行。适合「自己写一遍」——值类别、拷贝控制、模板推导这些东西，
    不自己写一遍、不被编译器顶回来几次，理解停在似懂非懂。
  一个知识点可以两者都挂。**值得亲手写一遍的知识点才配骨架案例**，不要求一对一
  （ADR 0059 放宽 ADR 0053）：值类别、拷贝控制、模板推导这类不自己写一遍就停在似懂
  非懂的，优先配；纯概念辨析不配。读懂不等于写得出，所以配了的案例要让这个知识点
  真的被动手练到，而不是几个知识点共用一个、各自只顺带看一眼。
  案例骨架的验收标准是**不改任何一行就能编译运行**，写法与字段见
  `docs/CHAPTER_CONFIG.md` 7.2。编译诊断完整展示不截断——看懂
  `error: cannot bind non-const lvalue reference` 本身就是教学内容。
- 内容优先覆盖 C++ 特有能力。与 C 语言高度重叠的基础内容只有在理解 C++ 语义确实需要时才加入。
- **受众是有两三年编程经验的初中级开发者**，两头都不是：不讲编程通识（什么是变量、
  函数、循环、类），但 C++ 特有的语义——值类别、移动与转发、生命周期与临时对象、
  模板推导、ADL、特殊成员函数的生成规则——**要讲透，不能假设读者已经懂**。术语第一次
  出现给出准确说明，之后直接用。**不要过分拔高**：不因为读者是开发者就跳过难点、
  略过推导、或用「众所周知」把一步带过去。
- **所有教学内容与习题必须有据可依（ADR 0054）**：语义细节以一级规范性材料为准
  （cppreference、ISO 标准草案、C++ Core Guidelines、Microsoft Learn），中文教程站
  只作讲法对照、不作语义判定。知识点与案例用 `source_refs` 指到登记表
  `resources/sources/catalog.json`，`locator` 或 `url` 至少给一个。
  **计入掌握度的题目同样必须有出处**——AI 现场出题不再计入熟练度，它退回讲解与
  答疑；自造题是例外，要写明为什么现成材料覆盖不到，且一节内不得过半。
- **本应用只负责 C++ 语言这一个领域，不替别的领域搭知识框架。** 设计模式、数据结构
  与算法、并发、网络这些都是独立领域，各自归自己的应用（ADR 0045：一个目录一个独立
  应用，彼此平级），打开它们走启动器（ADR 0058 已移除本应用里的跨学科图谱首页，
  ADR 0032 第 5 条随之失效）。
  **不得**在 `athena.json` 里为别的领域开分类、列章节。历史上开过两次，两次都长成
  了空目录表：`da`（数据结构与算法）23 章里 22 章没有知识点，`b534cfb` 删除，内容
  由 `subjects/dsa` 承载；`dp`（设计模式）23 章一个知识点都没有，素材转入
  `subjects/design-patterns/`（该应用尚未开工）。
  空分类比没有更糟——它占着分类首页的位置，让人以为那里有内容。
  判断边界时看**教的是什么**而不是**用什么语言写**：`STLContainer` 讲 `unordered_map`
  的哈希桶与负载因子，属于 C++ 标准库语义，归本应用；手写一个哈希表归 `subjects/dsa`。
- 源码框显示真实源文件内容，不在 UI 或 C++ 中维护另一份教学代码字符串。
- **本应用的三层落地**（仓库级 ADR 0028 的具体形态）：教学大纲就是每章 `.blp` 里的
  「教学大纲」标签，默认按一句题注加五节组织——痛点与来历、心智模型、讲什么与边界、
  判断与代价、落点；五节是参考不是模具，某节只有一句话就并进别处，没有就省略（仓库级
  ADR 0040）；「讲什么与边界」按 ADR 0029 标出每个方向的难度档与掌握目标。
  大纲不写语法机制、代码示例和 API 细节，不绑定练习，鼓励把脉络画出来。
  教学过程是原生学习页，教学实验是课程类的 public 成员函数。
- **图文结合的具体做法**（ADR 0038）：插图不用 SVG 图片承载，按内容里有没有几何关系
  选载体——表格、并排对照、卡片清单用 `.blp` 控件树，文字仍是文字；连线、箭头、时间轴、
  层次布局和由运行时数据算出位置的结构用 `Gtk::DrawingArea` / `Gtk::Snapshot` 自绘。
  选择顺序是能用控件就用控件，需要几何就用自绘，两者都不合适才考虑挂进 icon theme 的
  GTK 内建 SVG 路径；不把 SVG 交给 `Gtk::Picture` / `Gdk::Texture`。
