# ADR 0025：内联微型学习单元与可扩展专注实验工作区

- 日期：2026-09-09
- 状态：部分被 ADR 0026 取代
- 依据：ADR 0023、ADR 0024；对 Execute Program、Brilliant、Observable、
  Rustlings 与 Python Tutor 的学习交互取舍

## 背景

GTK 控件流已替代 WebView，但仅把 Markdown 显示为原生控件并不会自动形成
“学练合一”。若把预测、实验和反馈集中在一张大卡或页末按钮，叙述与证据仍会
脱节；另一方面，把真实源码、输出、对象图和未来的编译诊断都塞进正文，会压缩
阅读宽度，也不利于深度探索。

## 决策

### 1. 正文使用内联微型学习单元（已被取代）

这曾是从 Markdown 工作台过渡到原生控件的中间方案。ADR 0026 已取代它：
学习场景不再从 Markdown 小节或 H2 标签页推导；`learning_units` 仅作为旧式
阅读工作台的迁移期能力保留。以下记录保留当时的边界和数据契约，不能作为新增
学习场景的实现依据。

一个单元只服务一个可判断的语义命题，顺序为：

```text
叙述（Markdown） → 预测（GTK） → 去验证（专注实验） → 反馈 / 迁移提示（GTK）
```

单元由 `athena.json` 的 `chapter.learning_units` 声明，稳定 ID 不从中文问题或
文案推导。每项绑定本章 `overview_document` 中唯一的小节标题，并在该小节的
叙述结束、下一小节开始前插入。Markdown 保持知识解释，不写 Athena 专用标记。

为避免长文档让单页滚动过深，工作台按 Markdown 的 H2 学习小节提供顶层标签页；
标签页服务于概念分段，不强制一条成员函数一个标签。一个小节包含多个关联实验时，
它们仍与同一段叙述留在一起。

第一阶段只支持 `run` 验证：单元连接本章一个已有的真实实验函数。编译失败、
静态断言、对象图和复习调度分别在后续 ADR / 阶段增加；任何 UB 均不得作为可执行
验证。

### 2. 专注实验是独立的标签页工作区

正文中的“去验证”切到已有的专注实验页面，返回后正文和预测状态保持。该页面
保留全部现有源码、运行和观察控件，但使用 `Gtk::Notebook` 分为：

- **验证工作台**：左侧完整、可滚动的 `GtkSourceView`，右侧运行操作、状态和输出；
- **探索（暂定）**：为对象图、生命周期时间线、编译诊断等后续能力保留稳定空间。

标签页只用于需要较大空间的深度工作；它不是正文学习顺序的替代品。

### 3. 边界与验证

- `ChapterCatalog` 是运行期学习单元数据的唯一来源；UI 不复制 JSON 配置。
- 生成器校验单元 ID、目标标题、选项、正确答案和实验函数归属。
- 预测选择仅是暂态 UI 状态，第一阶段不写入数据库，不改变现有熟练度规则。
- 第一条纵切使用“初始化：花括号拒绝窄化”，以真实 `initialization` 实验作为
  运行验证，先验证数据流、插入位置和返回路径。

## 后果

- Athena 获得可重复使用的最小学习循环，而不是为每章手写一套预测卡。
- 专注实验可逐步扩展复杂可视化，不污染文档的线性阅读宽度。
- “编译失败型练习”和间隔复习暂不在本阶段伪装实现，避免把教学文案误当真实证据。
