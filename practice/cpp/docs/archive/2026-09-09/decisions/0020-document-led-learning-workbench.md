# ADR 0020：文档主导的学习工作台与可复用实验坞

- 日期：2026-08-30
- 状态：已接受，第一章原型实施中
- 后续：ADR 0022 已把内嵌实验坞迁到共享的非模态实验窗口；本文保留当时确定的
  “文档发起、实验响应”和 `ExperimentDock` 职责边界，不再代表当前控件布局。
- 依据：`docs/LEARNING_WORKSPACE_PROPOSAL.md`、
  `docs/LEARNING_WORKSPACE_LOOP_ENGINE.md`、`docs/LEARNING_WORKSPACE_BENCH.md`
  及 `docs/LEARNING_WORKSPACE_SKETCH.html` 的对照讨论

## 背景

现有 `CodeChapterPage` 从知识点列表进入源码和运行结果，适合连续浏览实验；分类级
`HandbookPage` 只负责连续阅读。第一版 `WorkbenchPage` 把一章文档和实验放到同一页，
但右侧再次放置完整知识点列表，和文档目录、正文末尾的实验入口形成重复导航；实验坞
宽度也不足以认真阅读真实源码。

Athena 的内容方向已经确定为“学习文档建立知识体系和判断框架，代码实验把思想转化为
可观察行动，正确的 C++ 语义负责仲裁”。工作台应把这条依赖方向直接表达在交互里，
而不是让代码列表反过来驾驶文档。

## 决策

### 1. 工作台成为文档与实验的组合页面

- `WorkbenchPage` 的主体是学习文档；实验由正文小节末尾的入口发起。
- 旧 `HandbookPage` 和 `CodeChapterPage` 在原型阶段保留，不删除、不迁移全部章节。
- 如果工作台以后完整覆盖连续阅读、目录跳转和实验验证，可以再以独立 ADR 决定是否
  让它取代 `HandbookPage`；本 ADR 不提前删除旧入口。

### 2. 文档小节与实验是一对多关系

- 一节文档可以没有实验，也可以挂一个或多个实验；“有文档无实验”是正常状态。
- 一个教学实验必须通过 `subchapter.teaches` 指向一份文档中的一个主要小节；
  `resources/athena.json` 继续是这条关系的唯一数据源。
- 文档标题按知识结构保持简短，解释、边界和学习目标写进标题后的正文，不塞进目录。
- 同一小节的多个实验合并成一个“动手验证”实验组，按 `subchapters` 声明顺序排列，
  插在该小节正文结束、下一个同级或更高层标题之前。

### 3. 实验坞不再提供全章知识点列表

实验坞只显示文档刚刚选中的一个实验：

```text
当前实验标题与本节序号
验证目标
真实源码
运行操作与状态
观察结果
```

全局知识导航由文档目录承担，局部实验选择由小节末尾的实验组承担。实验坞可以收起；
再次点击正文实验入口时恢复显示，并保持文档当前位置。

文档与实验区在宽窗口下约为 `58 : 42`。文档的主导地位由“文档发起、实验响应”的
依赖方向表达，不靠把源码压缩到无法阅读的窄栏表达。Ubuntu 窄窗口适配不属于本阶段
的验收条件，但平台无关的 `ArticleView` 与实验执行契约不得因此破坏。

### 4. 提取可复用 `ExperimentDock`

`ExperimentDock` 统一承担：

- 根据稳定知识点 ID 和源码位置显示真实源码；
- 启动 `ExperimentRunner`；
- 显示运行中状态、耗时和最终结果；
- 管理当前实验，但不解释 Markdown、标题或 `teaches`。

`WorkbenchPage` 负责文档、实验组链接与实验坞的协调；`CodeChapterPage` 保留自己的
知识点列表、AI 和历史入口，但把源码选择和运行结果通道交给同一个 `ExperimentDock`。
`MainWindow` 仍只负责识别页面类型、创建模块和管理生命周期。

## 后果

- 文档目录、实验组和实验坞分别只有一种导航职责，不再重复列出全章知识点。
- 一节可以通过多个短实验从不同角度验证同一语义问题，不需要为了函数数量拆散文档。
- `WorkbenchPage` 与 `CodeChapterPage` 不再各自维护一套源码加载和实验运行状态。
- 学习文档可以独立于 Athena 阅读；渲染期实验组不会写回 Markdown。
- 第一阶段只验证“讲解完成后选择实验、查看源码、运行并观察结果”，不加入预测、
  偏差日志、复习队列或 AI 生成的正确项。
- 是否最终弃用 `HandbookPage` 取决于工作台能否覆盖连续阅读和长期使用体验，不能仅凭
  第一章原型提前决定。
