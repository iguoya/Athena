2.2 const 引用：能绑定临时对象，还能延长它的寿命

普通的非 const 引用不能绑定右值（临时对象），因为右值理论上 「用完就该消失」，允许非 const 引用绑定它会给你一个可以修改、 却随时可能失效的对象。

const 引用打开了这个口子，同时编译器会把绑定给它的临时对象的生命周期 延长到这个引用本身的生命周期结束，避免野引用。这也是为什么 C++ 里 「传参用 const T&」这么常见——既避免拷贝，又能安全接住临时对象。

2.3 值传递 vs 引用传递：函数看到的是副本还是本体

值传递给函数的是一份副本，函数内部怎么改都跟调用方无关；引用传递给函数的 是调用方对象的别名……

5

正确项标的是语义，不是输出

判定依据是预设的语义正确项，运行输出只是证据。输出可能是 UB、实现定义或只是这台机器这次的表现——把它当答案，等于把仲裁权从 C++ 语义交给 stdout。凡属「输出不构成保证」的知识点，正确项由人写死，不交给 AI。

依据：不一致时先依据正确的 C++ 语义核对

为什么绑定不能写在文档里

一旦文档能声明实验，写文档时就会开始考虑「这节能不能挂一个实验」，于是小节切分被实验可得性影响。那是「写成源码说明书」最隐蔽的形式——不是抄源码结构，而是为了让每节都挂得上实验而切节。所以绑定住在 athena.json：是知识点声明「我在哪一节被讲到」，不是文档声明「我这能跑什么」。
