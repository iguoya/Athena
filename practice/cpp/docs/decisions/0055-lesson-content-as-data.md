# ADR 0055：学习页内容改由数据驱动，`.blp` 降为块模板

- 日期：2026-09-16
- 状态：已接受；渲染器与第一章新内容同批落地，存量章节不迁
- 延续：ADR 0024（学习内容由 GTK 控件承载）、ADR 0033（能算出来的画成活的）、
  ADR 0038（插图用控件与 Cairo 自绘）——三条全部保留，见决策第 1 条
- 配合：ADR 0053（骨架案例）、ADR 0054（内容有据可依）

## 背景

`type_semantics` 一章写完后，成本摆在那里：`.blp` 2988 行 + 页面类 1540 行 ≈ 4500 行。
按控件数拆开看：

| 节点 | 数量 |
|---|---|
| `Label` | 400 |
| `Box` | 212 |
| `Frame` | 51 |
| `Button` | 21 |
| **`DrawingArea`** | **5** |

707 个控件节点里**只有 5 个非用代码不可**。其余是「一段话、一个提示框、一段代码、
一张对照表」——按样式类统计：callout 59、代码块 53、正文段落 53、内容区 49，
以及 68 个 `figure-head`/`figure-cell`/`figure-verdict`/`figure-note`，那是**一张
对照表被手拼成了几十个 Label**，而它在数据里不过是一个二维数组。

`lesson_blocks.blp` 已经识别到这件事，它自己的注释写着「该复制的是范式，不是行数」。
但它只消掉了**属性重复**（每个 Label 那四行 `halign`/`wrap`/`xalign`/`styles`），
没有消掉**内容本身写在 `.blp` 里**这个根因。所以下一章照样两千行起步，74 个知识点
里只完成 7 个，成本是主要原因之一。

## 决策

### 1. 分清「由 GTK 控件承载」与「手写 GTK 控件树」

ADR 0024 要消灭的是 Markdown 正文与 WebView 渲染路线，它说的是**内容最终由 GTK
控件呈现**——这一条继续成立，本 ADR 不动它。改变的只是**控件树从哪来**：由数据
实例化模板，而不是逐个手写。

ADR 0033（能由运行时数据算出来的画成活的）、ADR 0038（插图用 Cairo 自绘）同样保留，
那 5 个 `DrawingArea` 一个都不动——变的是**它出现在哪一节由数据决定**。

### 2. 三层分工

```
resources/lessons/<chapter>.json    内容：块序列，纯数据，唯一内容源
resources/ui/lesson_blocks.blp      形态：每种块一份模板
ui/lesson_renderer.cc               渲染：按数据实例化模板，递归处理嵌套
ui/*_figures.cc                     自绘：注册的绘制函数，数据按 id 引用
```

新增一章 = 写一份 JSON，外加（如果有独特的图）几个绘制函数。不碰页面类、不碰
`meson.build`、不加 `.blp`。

### 3. 块类型从现有内容归纳，不凭空设计 schema

第一版九种，全部来自上面那张统计表，不是设想出来的：

| type | 承载 |
|---|---|
| `lead` | 一节的导语 |
| `prose` | 正文段落 |
| `bullets` | 要点列表 |
| `code` | 代码块（等宽，可带说明） |
| `callout` | 提示框，`kind` 取 `why`/`key`/`note`/`trap`/`use` |
| `section` | 带标题的内容区，可嵌套 `blocks` |
| `table` | 对照表：`head` + `rows`，可带 `note` |
| `steps` | 有序步骤 |
| `figure` | 自绘图，`id` 指向注册的绘制函数 |

`section` 与 `callout` 可以嵌套子块——现有 `.blp` 本来就是嵌套的，拉平会丢结构。

**缺什么补什么，不预先设计完备的 schema。** 写第一章时发现某种表达没有对应块，
那才是加块类型的时机；先设计一套「可能用得上」的类型，只会得到一堆没人用的分支。

### 4. 校验归 Python，C++ 只解码

沿用 ADR 0013 的分工：课文 JSON 的结构校验（块类型合法、必填字段齐、`figure` 的 id
有注册、`section` 嵌套不超深）由生成器负责；C++ 侧信任数据、只做解码与渲染。
课文随 GResource 分发，与 ADR 0053 的案例同一条路径。

### 5. 存量不迁

`type_semantics` 那章已经写完，迁移是纯风险没有收益，保持原样。两条路并存：
旧章走原来的 `.blp` + 页面类，新章走数据。等新路子在两三章上跑顺，再决定要不要
回头迁——也可能永远不迁，那不是问题。

## 后果

**得到**：一章的手写量从约 4500 行降到几百行数据；内容可以被独立审阅（一份 JSON
就是一章教案），配合「逐章编写、逐章验收」的节奏；内容与表现分开之后，改排版不用
碰内容、改内容不用碰控件。

**付出**：先要写渲染器（一次性）；块词汇会约束表达方式——对策是缺什么补什么，
而不是硬套已有的块把差异磨平。**这一条是本 ADR 最容易做坏的地方**：如果为了省事
把一张本该自绘的对象图压成 `table`，那就是用数据化换掉了教学信息量，得不偿失。
判据仍然是 ADR 0033 那句——能由数据算出来、需要对照或逐步推进的，画成活的。
