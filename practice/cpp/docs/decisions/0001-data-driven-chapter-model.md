# ADR 0001：athena.json 单一数据源与确定性代码生成

- 日期：2026-08-14（2026-08-15 补记）
- 状态：已接受
- 依据提交：`c5ef1c9` 数据驱动章节目录、`79c5d58` 注册表生成、`1d8ab01` 统一生成器、`799903f` 生成器模块拆分

## 背景

章节目录最初分散在 UI 代码与手写映射中。随着章节增加，`mainwindow.cc` 存在
持续堆叠手写映射的风险，章节注册信息与配置各存一份、难以校验一致性。

## 决策

- `resources/athena.json` 是项目配置的唯一数据源，承载分类、章节、分组和
  知识点元数据；配置契约先于解析器、注册表和生成器定义。
- `scripts/generate_project.py` 统一实现校验、GResource 清单、Blueprint 目标
  与 `FunctionRegistry` 绑定，输出必须确定性（相同输入产生相同内容与顺序）。
- 生成文件带 `DO NOT EDIT` 提示与 `.generated` 后缀，可反复覆盖；`scaffold`
  仅显式运行，且只创建不存在的人工实现文件，永不覆盖人工代码。
- 函数注册表由配置生成，禁止在窗口代码中维护手写课程映射。

## 后果

- 新增章节 = 修改 `athena.json` + 编写实现，UI 层不复制任何章节注册信息。
- 生成器成为构建的关键路径，其行为变化必须同步 `docs/CODE_GENERATION.md`。
- "生成器不得覆盖人工代码"成为代码评审的固定检查项。
