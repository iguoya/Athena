# ADR 0026：原生学习场景与参考资料分离

- 日期：2026-09-09
- 状态：部分失效——「原生学习场景不受 Markdown 约束」仍有效；作为参考资料的
  Markdown 手册已由 [ADR 0034](0034-remove-markdown-handbook.md) 删除，学习页
  不再有可跳转的手册入口
- 取代：ADR 0025 中“Markdown 小节决定学习单元插入位置、H2 决定学习标签”的部分

## 背景

ADR 0024 已经把 Markdown 的呈现从 WebView 改为 GTK 控件，但这只解决了渲染
技术，不等于内容形态自由。若学习页仍按 Markdown 的标题切标签、按文档小节插入
预测卡，Markdown 依旧决定学习过程的结构、顺序和可用媒介；对象关系图、状态迁移、
动画和诊断式练习只能勉强附着在文章后面。

Markdown 仍有价值：它适合人工维护的体系化参考、长篇解释与回顾。但它不应成为
原生学习体验的布局协议。

## 决策

0. **总原则：Markdown 文档不影响、不约束学习过程的表现形式。** 学习页需要的叙述、
   概念对比、判断提示等文字**可以独立撰写**，与手册文档内容**冗余是可接受的**；是否
   把 `DocumentView` 内嵌进学习页渲染某段文档，由各学习场景自行决定，不作强制。
   下面各条都是这一原则的展开。

1. **学习场景与 Markdown 解耦。** 章节可选择专属 Blueprint 根页面；该页面的控件、
   交互顺序、图表和素材由对应的 GTK 模块拥有，不从 Markdown 标题、段落或锚点推导。
   `athena.json` 只继续承担章节导航、Blueprint 资源和可运行知识点元数据，不承载一份
   Markdown 的替代品。
2. **Markdown 降为参考资料。** `overview_document` 和分类手册继续用 `DocModel` /
   `DocumentView` 阅读；原生学习场景可提供“查看参考资料”入口，但学习闭环不依赖
   该文档存在、标题不变或滚动到某个位置。
3. **原生场景由可组合学习块构成。** 静态骨架、卡片和布局写在 `.blp`；运行期状态和
   数据驱动的重复项由模块填充；对象关系、时间线、状态转移等确实需要绘制的内容可由
   `Gtk::DrawingArea` / Cairo 承载。常用块包括概念对比、预测、实验入口、编译诊断、
   对象图、时间线、变体比较与反思提示，但不要求每章都使用全部类型。
4. **专注实验仍是深度验证空间。** 原生场景只发起某个真实实验；源码、运行和观察
   结果继续在既有的主窗口专注实验页中完成。这样视觉化解释不会挤占完整源码与输出。

第一条纵切是“类型与表达式 → 初始化”：使用原生双路径对比、预测单元和真实实验入口。
它同时保留 Markdown 参考按钮，验证两条通道相互链接但不相互驱动。

## 后果

- 新的学习材料可以使用任意合适的 GTK 控件、图片、SVG、图表和后续动画，而无需先把
  它们降级为 Markdown。
- 原 `WorkbenchPage` 的 Markdown 分段能力保留为迁移期/参考阅读能力，不再承担
  TypeSemantics 的主学习页面；后续章节迁移按独立原生场景逐个完成。
- 内容作者需要同时维护“参考资料”和“学习场景”两种有不同目的的资产；这是一项有意的
  分工，不再用 Markdown 的线性结构限制交互教学。
