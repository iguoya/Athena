# 地球 · 项目协作规则

## 定位

地球是**图谱/参考类**应用：把地球的大气分层与内部分层按**真实比例**呈现供查阅，不考核
掌握度、不证明学习者进步——这是它与学习应用的本质区别（仓库三类判据，ADR 0128）。它
存在的理由是一个反教科书的事实：**真实比例下地壳只有地球半径的 0.5%、卡门线 1.6%，薄
到看不见**；教科书的「厚分层」插图全是夸张画法，而本应用把「薄」本身当作第一教学点，
用剖面、聚焦与探针读数表达，**不做任何空间夸张**。

- 界面名**地球**；目录、`id` 与二进制都是 `earth`（`athena-earth`），端口 **1511**。
- 启动器归属：`group: 程序设计`——使用者指派的**暂存**归属，不承载领域判断；挪圈是
  纯配置改动，id 与端口不动（ADR 0128 决策 3）。
- 不建 `progress/learning.db`、不建 `content-contract.json`，跨应用教学规范不生效；
  出处**不做门禁但必须可查**——每个层与关键数值表都声明 `sourceIds`，界面可点开核对。
- 不要在未另行决定前加入学习进度、知识掌握度、账号或网络同步。

## 真实比例原则（本应用的第一约束）

1. **场景单位 1 = 地球平均半径 6371 km**，各层半径是真实比值；不用千米做场景单位。
2. 深度跨度大（贴地公里级到地球静止轨道 5.6 R），WebGL 必须开 `logarithmicDepthBuffer`。
3. **不把薄层画厚**：表达手段是四分之一剖切（切掉 x>0、z>0）+ 径向真实刻度尺 + 相机
   聚焦 + 视野宽度比例尺；界面固定标注「真实比例 · 垂直方向未放大」。
4. 真实地球是 WGS 84 扁椭球（扁率 1/298.257），渲染组整体按极轴压扁；分层深度仍以
   PREM 的球对称模型近似（数据文件 `shape.note` 有说明）。

## 技术与目录

- **壳与视图**：Tauri 2 + React 19 + TypeScript（Vite 8）+ React Three Fiber 9 / three；
  样式 Tailwind 4。壳最初复制自 polaris（同为图谱/参考类、subjects 内最新的 React 壳），
  此后独立演进。Rust 端只做壳：单实例 + 出处链接走系统浏览器。
- **数据是唯一真源**：`content/earth.json` 承载全部标准模型数值（WGS 84、PREM 密度
  分段、US Standard Atmosphere 1976 廓线、WMO 层界、现象锚点、出处目录），前端经
  `@content` 别名直接导入，**不在代码里硬编码任何层界或物理量**；场景、剖面着色
  （PREM 密度 → viridis 色标）、探针读数、图表全部由它生成。
- **严谨靠双侧独立核对**：前端 `src/content/catalog.test.ts` 与 `scripts/check.py` 的
  `check_standards` 各自独立抄录标准值互为备份——两侧不是同一份代码，同时写错同一处
  数值的概率小。改数据必须两侧都过。
- 呈现决定与物理值分开：渲染专用的常量（如外逸层渐隐上界 `EXOSPHERE_FADE_KM = 10000`）
  放代码并注明「这是呈现决定，不是物理值」；物理值一律进数据文件。
- 温度口径分开：地球内部温度是「界面共识值 + 文献区间」的示意廓线（无直接测温）；
  大气 0–86 km 用 USSA1976 精确值，**86 km 以上不冒充标准模型**，读数按带范围的
  参考值呈现。
- 开发：`app.json` 的 `dev` 块跑 `npm run tauri:dev`（端口 1511），前端 Vite 热更新。
- 贴图 `src/assets/earth-blue-marble.png` 是 NASA Blue Marble（公有领域），已离线打包，
  不运行时拉取。

## 开发与验证

```sh
python3 scripts/check.py            # 数据标准值 + 前端构建/测试 + Rust 侧检查
python3 scripts/check.py --skip-rust  # 只改数据或前端时
launcher/target/release/launcher open earth   # 真的打开一次
```
