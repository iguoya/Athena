# 从 C++ 教程继承的实验前置参考

这是一份给数据结构与算法应用维护者、课程作者和实验作者看的**边界说明**。它记录
DSA 实验选用 C++20 时可复用的语言能力，以及这些能力和数据结构 / 算法本体之间的
分工；它不是本应用的教学大纲，也不替代
[`../content/curriculum.json`](../content/curriculum.json)。

## 结论

数据结构与算法的课程、案例、可视化和进度应完全由 `subjects/dsa` 拥有；C++ 只是本应用
当前实验的实现语言。相应地：

- C++ 教程讲“语言和标准库怎样表达数据、资源及泛型操作”；
- DSA 讲“为什么要选择某种结构或算法、它维护什么不变量、复杂度和代价是什么”；
- 同一段 C++ 可以在两边出现，但不能形成两份互相竞争的课表或共享源码。

例如，`std::vector` 的接口、迭代器失效和 Ranges 的使用仍是 C++ 教程的语言内容；
顺序表为何需要扩容、尾插为何是均摊 `O(1)`、何时不应以链表替代数组，则属于 DSA。

## 可引用的 C++ 前置能力

下列名称和范围来自
[`../../cpp/resources/athena.json`](../../cpp/resources/athena.json) 的 `cpp` 分类。引用它们
是为了对齐术语和能力边界，不是让 DSA 读取该文件或依赖 C++ 应用运行。

| 能力 | C++ 侧现有主题 | 在 DSA 实验中的用途 | 不应由它取代的内容 |
|---|---|---|---|
| 对象生命周期、`const` 与拷贝 / 移动 | `ClassObject`、`RAII` | 节点、容器和值对象的构造、销毁、复制与转移；读操作不意外修改结构 | 结构不变量、接口语义和复杂度证明 |
| RAII 与明确所有权 | `RAII` | 链表、树和图的节点归属；异常或提前返回时不泄漏资源 | 把 `shared_ptr` 当作所有权设计的默认答案；先选对所有权模型，再选表达它的工具 |
| 顺序、关联与无序容器 | `STLContainer` | 将手写结构与标准库容器作实现和代价上的对照 | 用库调用遮蔽数组、链表、哈希桶、堆或树的内部机制 |
| 迭代器、范围与视图 | `IteratorRange` | 表达遍历接口；观察遍历时修改结构造成的失效风险 | 把“会用 `begin/end`”误当成理解迭代器模式或遍历算法 |
| 标准算法与比较 / 变换 | `STLAlgorithm` | 为排序、查找和变换提供对照实现，复用比较器等接口形状 | 将 `std::sort` 的调用结果当作排序原理、稳定性或复杂度的证明 |
| 函数对象、Lambda 与回调 | `FunctionCallable` | 比较器、访问器、图遍历的访问动作，以及可替换策略的最小例子 | 把回调语法当作算法策略选择本身 |

## 对当前课表的落点

DSA 的课程唯一源是 `content/curriculum.json`。新增或修订下列主题时，可用上表检查
实验是否假定了尚未交代的语言能力：

| DSA 主题 | 需要留意的 C++ 前置 | 课程核心仍应观察什么 |
|---|---|---|
| `dsa.linear.array`、`dsa.linear.list`、`dsa.linear.stack_queue` | 值语义、RAII、指针或容器引用失效 | 存储布局、操作前后不变量、均摊代价与适用边界 |
| `dsa.hash.table` | 容器、比较 / 哈希接口、对象生命周期 | 冲突、装载因子、扩容与查找代价 |
| `dsa.tree.basics`、`dsa.tree.bst`、`dsa.tree.heap` | 递归调用中的对象生命周期、明确节点归属、比较器 | 递归定义、顺序性质、旋转或堆序，以及操作复杂度 |
| `dsa.sort.*`、`dsa.paradigm.divide` | 迭代器、比较器、标准算法作对照 | 循环不变量、稳定性、分治过程和时间 / 空间代价 |
| `dsa.graph.*`、`dsa.paradigm.backtrack` | 容器、回调、值 / 引用选择 | 邻接表示、访问状态、搜索树和终止条件 |
| `dsa.paradigm.dp` | 容器与值语义 | 状态定义、转移、初值和空间压缩，而不是数组下标语法 |

## 作者和实现约束

1. `content/cases/**` 是 DSA 实验的真源码。不要 include、复制或运行
   `subjects/cpp/cplusplus/**` 来“复用课程”；两个应用必须能脱离对方构建和运行。
2. 某个实验第一次依赖 C++ 语言能力时，在该实验或讲解中用一句话说明该前置，并把
   学习者指向 C++ 侧主题名即可；不要把整段 C++ 教案复制进 DSA。
3. 为了展示算法，优先让 C++ 案例输出可消费的离散事件，再由前端可视化。标准库只可
   作对照或基线，不能吞掉本应观察的比较、访问、入队、出队或状态变化。
4. 这份文档是人工维护的参考快照。C++ 课程变更后，只有在 DSA 的实际前置假设改变时
   才更新它；不建立跨应用同步脚本或共享 schema。
