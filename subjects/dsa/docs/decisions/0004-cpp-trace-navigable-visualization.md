# ADR 0004：实验步进可视化由 C++ 打印状态快照，前端只回放

- 日期：2026-09-14
- 状态：已接受；trace 协议与回放器随本 ADR 落地
- 精神对齐：本应用 AGENTS.md「实验逻辑在 C++：前端不重写一份算法真相；
  需要步进可视化时由 C++ 打印约定事件（如 NDJSON），前端只消费」；
  ADR 0001 第 2 节「示意动画不得冒充真实运行轨迹」

## 背景

ADR 0001 第 2 节已约定「实验输出可被观察区消费」，但观察区至今只过滤
`key=value` 文本行。数据结构最值钱的观察是**过程**：指针怎么改接、元素怎么
挪、栈怎么弹——静态文本给不了。AGENTS.md 预留的方向是「C++ 打印约定事件，
前端只消费」，本 ADR 把它落成协议。

真正的设计选择在「事件」二字：打印**操作事件流**（insert/remove 的增量）
还是**状态快照**（每步一份完整状态）。

## 决策

### 1. 协议：NDJSON 状态快照行，前缀 `#dsa-trace `

案例驱动代码通过 `content/cases/_shared/dsa_trace.hpp`（header-only、零依赖）
向 stdout 打印形如：

```
#dsa-trace {"kind":"list","step":0,"note":"初始 1 -> 3","focus":-1,"values":[1,3]}
```

- **快照而非增量**。每行是「此刻的完整状态」。回放器只画快照，跳到任意步、
  前后对照零成本；若是操作事件流，前端必须复刻一份状态机重放增量——那正是
  「前端重写算法真相」的入口，两份实现必然漂移。
- **显式前缀**。肉眼可辨、`grep '#dsa-trace'` 可查；与普通 `cout` 输出
  （含判分用的 `key=value` 行）共存互不干扰，解析按前缀过滤。
- 字段：`kind`（结构类型，第一版只有 `list`，`array`/`tree`/`stack` 按需
  扩展）、`step`（0 起递增）、`note`（这一步在做什么，给人看的）、`focus`
  （焦点下标，-1 无；用于标注当前步骤关注的结点）、结构自身的字段
  （`list`：`values` 结点值数组）。
- **不设 `head` 字段**：快照约定 `values` 按从头结点遍历取样，头下标恒冗余
  （空表即空数组）。将来出现环、dummy 结点或多链观察需求时再扩字段，
  回放器对未知字段与未知 `kind` 都做降级（列原始 JSON），协议可前向演进。

### 2. 头文件不绑定案例的数据结构类型

`dsa_trace::list(step, note, values, focus)` 只收**值数组与下标**，不收
`Node*`。学员案例的结点类型千差万别，遍历取样由调用方完成（驱动本来就有
print 遍历）。不 include 该头 = 零成本；include 了不用也无输出。

### 3. 前端回放器只消费，不计算

`src/trace-player.ts` 按前缀抽帧，SVG 逐步渲染，控制条支持步进、播放、拖
进度。渲染的是 C++ 亲手打印的状态，不是前端对算法的二次模拟。stdout 无
trace 行的实验保持原 `key=value` 观察区，旧案例零改动。

### 4. 编译接线

`compile_and_run` 给本机编译追加 `-I <content_root>/content/cases/_shared`
（目录存在才加），案例源码 `#include "dsa_trace.hpp"` 即可用。判分不动：
`pass.includes` 照旧消费驱动打印的约定行，trace 行只是额外存在。

## 后果

- 案例作者多一件表达手段：驱动里的 trace 行就是「你会看到什么」的可视化
  版，与 ADR 0001 的「预告—观察—对照」闭环衔接。
- 学员也可以在自己的 TODO 实现里调用 trace 头观察中间状态——它是教学工具，
  不是埋点。
- 协议字段随新 `kind` 增长；回放器对未知 `kind` 降级显示，旧应用不随协议
  演进被迫升级。
