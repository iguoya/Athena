# 从 subjects/cpp 继承的素材

本文是剥离时从 `subjects/cpp/resources/athena.json` 的 `dp` 分类和
`subjects/cpp/registry/domain_graph.cc` 原样搬过来的材料，只做了分组整理，没有改写。
它是**素材不是大纲**——将来写教学大纲时该按「化解哪种耦合」重新组织，而不是照这份
清单一个名词一章（理由见 [`../README.md`](../README.md) 第 5 条）。

## 领域定位

搬自首页学科图谱的 `dp` 节点（`subjects/cpp/registry/domain_graph.cc`）。那个节点
**留在 subjects/cpp**——它是学科导航，不是 C++ 教程的内容；剥离后它从「已开放」
回落为「规划中」，等这个应用真的建起来再改成指向它的 `ExternalApp`。

**讲什么**：创建型 / 结构型 / 行为型三类经典模式的动机、结构、协作方式和适用
边界，以及它们试图化解的耦合问题。

**为什么值得学**：帮你识别「这段代码为什么难改」，并用经过检验的结构重新组织
依赖关系；读框架和大型代码库时，也能一眼认出作者在用哪种套路。

**难在哪**：容易套用过度——为了用模式而增加间接层，反而更难懂。

**为什么依赖 C++**：1994 年《设计模式》成书时，示例代码用的是 C++ 和 Smalltalk；
GoF 的 23 个模式本质上是「如何用面向对象特性化解耦合」的经验总结。策略、装饰器、
观察者、访问者这些都直接依赖虚函数、继承、组合和接口这几样东西。没有一门具备
完整面向对象能力的语言垫底，模式就退化成背结构图。

## 23 个模式

原配置里每章只有名称、中文标题、一句话描述和图标，没有知识点、没有实现、没有
学习页——清单的价值就在这份**中文命名与一句话定位**本身。


### 创建型（5）

对象怎么被创建出来——把创建过程与使用它的代码解耦。

| 类名 | 中文名 | 定位 |
|---|---|---|
| `Singleton` | 单例模式 | 学习控制单一实例及其生命周期和并发问题 |
| `FactoryMethod` | 工厂方法 | 学习把对象创建延迟到子类或具体工厂 |
| `AbstractFactory` | 抽象工厂 | 学习创建相互关联的对象族而不依赖具体类型 |
| `Builder` | 建造者模式 | 学习分步骤构建复杂对象并复用构建过程 |
| `Prototype` | 原型模式 | 学习通过复制已有对象创建新对象 |

### 结构型（7）

对象怎么组合成更大的结构——在不改动已有类型的前提下调整关系。

| 类名 | 中文名 | 定位 |
|---|---|---|
| `Adapter` | 适配器模式 | 学习转换接口以复用不兼容的现有类型 |
| `Bridge` | 桥接模式 | 学习分离抽象与实现，使二者能够独立变化 |
| `Composite` | 组合模式 | 学习用树形结构统一处理单个对象和对象组合 |
| `Decorator` | 装饰器模式 | 学习动态叠加对象职责而不修改原类型 |
| `Facade` | 外观模式 | 学习为复杂子系统提供统一而简洁的入口 |
| `Flyweight` | 享元模式 | 学习共享细粒度对象以降低内存消耗 |
| `Proxy` | 代理模式 | 学习通过代理对象控制对真实对象的访问 |

### 行为型（11）

对象之间怎么分配职责与协作——把「谁在什么时候做什么」显式化。

| 类名 | 中文名 | 定位 |
|---|---|---|
| `ChainOfResponsibility` | 责任链模式 | 学习让多个处理者按链路依次处理请求 |
| `Command` | 命令模式 | 学习把请求封装为对象并支持排队、撤销和组合 |
| `Interpreter` | 解释器模式 | 学习为简单语言定义语法表示和解释过程 |
| `IteratorPattern` | 迭代器模式 | 学习在不暴露内部结构的情况下遍历聚合对象 |
| `Mediator` | 中介者模式 | 学习用中介对象集中管理多个对象之间的交互 |
| `Memento` | 备忘录模式 | 学习保存和恢复对象状态而不破坏封装 |
| `Observer` | 观察者模式 | 学习一对多通知关系和订阅更新机制 |
| `State` | 状态模式 | 学习把状态相关行为封装到独立状态对象 |
| `Strategy` | 策略模式 | 学习封装可替换算法并在运行时选择策略 |
| `TemplateMethod` | 模板方法模式 | 学习在基类中定义算法骨架并允许子类定制步骤 |
| `Visitor` | 访问者模式 | 学习把作用于对象结构的操作与对象类型分离 |

## 搬运时记下的两处细节

- `IteratorPattern` 的类名带了 `Pattern` 后缀，是因为 `subjects/cpp` 里已经有一章
  叫 `IteratorRange`（讲 C++ 迭代器与 Ranges），同一份配置里不能撞名。独立应用
  没有这个约束，叫回 `Iterator` 即可。
- 迭代器模式在 C++ 里是个特例：标准库已经把它做进了语言习惯（`begin` / `end`、
  范围 for、Ranges），讲它的时候绕不开 `subjects/cpp` 的 `IteratorRange` 那一章。
  两边的边界是——那边讲**怎么用** C++ 的迭代器，这边讲**这个模式解决什么问题**。
