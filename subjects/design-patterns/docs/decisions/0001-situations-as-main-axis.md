# ADR 0001：以「问题情境 → 代码组织与规范」为主轴，23 个模式降为工具箱

- 日期：2026-10-10
- 状态：已接受（tiger 2026-10-10：「核心还是以不同情况下 采用不同的代码组织和规范技巧
  处理解决问题为主 不要局限在23种设计模式本身」「软考作为专题 学习 练习 并不是主轴」）
- 关系：细化仓库 [ADR 0121](../../../../docs/decisions/0121-design-patterns-to-programming-group.md)
  决策 2 的章节骨架（0121 写的是「UML → 原则 → 创建型 → 结构型 → 行为型」为主线）；
  软考专题、延伸层的安排沿用 0121 决策 3、4

## 背景

1. 0121 把本应用从「软设第 7 章实践课」改为以设计模式与程序组织为主，但主线仍按 GoF 的
   23 个模式排。tiger 进一步明确：学习者要掌握的是**遇到什么样的代码问题、该用什么组织方式
   与规范去解决**，23 个模式只是其中一部分手段。
2. 现实中的代码问题多数不是「缺一个模式」，而是长函数、重复的分支、参数泛滥、全局可变
   状态、资源泄漏、所有权不清、错误处理混乱。这些问题有成熟、权威的整理：
   - Martin Fowler《重构：改善既有代码的设计》第 2 版（2018）第 3 章「代码的坏味道」与
     重构手法目录（refactoring.com/catalog 有在线目录，66 个手法）；
   - Bjarne Stroustrup 与 Herb Sutter 维护的 C++ Core Guidelines（isocpp.github.io），
     资源、接口、函数、类、错误处理各节有编号规则；
   - Martin Fowler《Inversion of Control Containers and the Dependency Injection pattern》
     （2004）。
3. 取材「有所本」的要求不变：情境篇的症状名、手法名、规则编号都以这些原著为准，在
   每节「取材」里写明出处与编号，记不清的不写。

## 决策

1. **主轴是「情境篇」**：每个知识点是一种代码问题（症状），讲它的识别方式、可选的组织
   手段、各自的代价与适用条件，并给一个可编译运行的重构实验。症状与手法优先采用《重构》
   第 2 版的命名，C++ 规范优先引用 C++ Core Guidelines 的条目编号。
2. **两章情境篇放在设计原则之后、模式之前**：
   - 「情境篇一：从坏味道出发」——重复的 switch、过长函数、过长参数列表、基本类型偏执、
     发散式变化与霰弹式修改、依恋情结与过长的消息链、全局与可变数据、写死的依赖；
   - 「情境篇二：C++ 的资源、接口与错误」——RAII、所有权、零法则与五法则、错误报告、
     接口设计、不变式。
3. **23 个模式改称「模式工具箱」**：创建型、结构型、行为型三章内容不动，定位从主线改为
   被情境篇引用的工具；情境篇讲到某种手段时指向对应模式。
4. **软考专题、延伸篇不变**（0121 决策 3、4）。延伸篇（非面向对象、现代工程）本来就是
   「不局限于 23 个模式」的内容，正式内容写成后去掉延伸标记、并入主线。
5. 新增内容块 `codecompare`：并排展示改造前后的代码。重构教学的核心是「同一段代码的两种
   组织方式」，用文字描述代码对照会失真（ADR 0058：现有块表达不了才加）。

## 后果

- 课程主线变为：UML 读图 → 设计原则 → 情境篇一 → 情境篇二 → 模式工具箱（三章）→
  软考专题 → 延伸篇。
- 首页简介、课程主线（spine）与 AGENTS.md 的定位同步改写。
- 情境篇每个知识点配一个重构实验：骨架是「有坏味道的代码」，学习者按要求改造，并完成一个
  只有改造后才容易实现的新需求；判分仍是输出比对（结构是否真的改了无法机械判定，讲解与
  实验说明里写清楚要求）。

## 补充（2026-10-10，tiger：「方案B」）

延伸篇按「出处扎实的部分」收窄后并入主线（决策 4 的落地）：

1. 「非面向对象世界的模式」章（id `non-oo` 不变）改为**情境篇三：没有类的时候——C 的代码组织**，
   去掉延伸标记，内容是不透明类型（SEI CERT C DCL12-C、Linux 内核编码规范第 5 节）、函数指针表
   （内核 VFS 文档 struct file_operations）、回调的 void* 上下文（POSIX pthread_create）、goto
   集中出口（内核编码规范第 7 节）。原「建设计划」节随之删除。原提纲中的 Unix 哲学、函数式替代、
   Rust 惯用法、ECS 等没有单一权威出处，不写。
2. 新增**情境篇四：并发下的代码组织**（id `concurrency`），依据 C++ Core Guidelines 并发一节
   （CP.2/3/4/20/21/22/42/44/50/60/61）。死锁一节不配实验：会卡住的骨架既不能稳定演示，也会让
   编译验证挂起。
3. 「现代工程的程序组织写法」章仍为延伸篇（含批判课），本次不动。
4. 章节顺序：UML → 原则 → 情境篇一至四 → 模式工具箱 → 软考专题 → 现代工程（延伸）。
