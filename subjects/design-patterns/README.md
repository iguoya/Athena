# 设计模式（尚未开工）

这个目录**还不是一个可运行的应用**：没有 `app.json`，启动器扫不到它；没有
`scripts/check.py`，仓库根的验证入口会跳过它。它现在的全部作用，是替将来真正
开发这个学习应用的人保存素材和结论。

## 为什么从 subjects/cpp 剥离出来

设计模式原本是 `subjects/cpp/resources/athena.json` 里的一个分类 `dp`，挂着 23 个
章节。但那 23 章**一个知识点都没有**，也没有任何实现代码和学习页——它是一张
空目录表，占着 C++ 教程分类首页的位置，让人以为那里有内容。

更根本的问题是领域划分：设计模式是独立领域，不该住在 C++ 教程里。仓库 ADR 0045
定的是「`subjects/` 下一个目录一个独立应用，彼此完全平级」，ADR 0032 要求每个应用
自带内容体系。C++ 教程负责 C++ 语言本身，不负责替别的领域搭知识框架。

数据结构与算法先走过同一条路：它当初也是 `athena.json` 里的空分类 `da`，
在提交 `b534cfb` 里被删掉，内容改由 `subjects/dsa` 承载，首页图谱的节点改成
`ExternalApp` 指过去。设计模式这次照同样的方式处理，区别只是**独立应用还没有
建起来**，所以首页图谱的 `dp` 节点回落成「规划中」，而不是指向某个应用。

剥离之后，`subjects/cpp` 那边不需要改代码：`registry/domain_graph.cc` 本来就有
「标了 Available 但 catalog 里查无此分类就降级为 Planned」的逻辑。

## 将来开工时，请先读这几条

这些不是凭空写的建议，是 2026-09-15 对照 `subjects/dsa`、`subjects/mathematics`、
`subjects/english` 审视 `subjects/cpp` 得出的结论。`subjects/cpp` 在这几条上都吃过亏，
新应用没有理由重走一遍。

1. **内容驱动 UI，不要每章手写一整页。** `subjects/dsa` 用一套有限的块类型
   （`lead` / `compare` / `steps` / `predict` / `practice` / `callout` /
   `summary` / `quiz`）承载全部讲解，整个前端 4357 行就撑起了 7 章 15 个知识点、
   113 个讲解块、127 道题和 20 个实验案例；`subjects/cpp` 是一章一份手写 `.blp`，
   单章 2988 行，于是 74 个知识点里只有 7 个真正写完。判据很简单：**这一节和
   隔壁那一节如果只是文字不同，就不该各写一份界面。**

2. **实验给骨架，不给白板**（`subjects/dsa` ADR 0003）。案例自带接口声明与 `main`
   驱动，学员只补 `TODO`；不改任何一行也要能编译运行。示范与待填可以并存——
   先给一个已实现的参考，再留一个同构的变式。设计模式尤其适合这种形态：给出
   「难改的那版代码」，让学员把它重构成模式结构，跑同一个驱动对照行为不变。

3. **判分要本地可复核，题目要有出处**（仓库 ADR 0043）。`subjects/dsa` 的做法是
   驱动打印约定字段、本地比对。不要学 `subjects/cpp` ADR 0015 的 AI 现场出题：
   自造题没有难度校准，做对了说明不了什么，检验器本身就不可信了。设计模式的
   出处非常好找——GoF 原书的意图与适用性段落、Refactoring Guru、真实框架里的
   用例，比数学好找得多。接入检查时照 `subjects/dsa/content-contract.json` 的办法：
   `blocking: false` 先报告不阻断，存量列进豁免名单，且**名单只能变短**。

4. **先记全再派生，激励与统计是同一条回路**（仓库 ADR 0052）。进度库第一天就
   要有作答流水（条目 id、覆盖的知识点、对错、时间戳、用时），今日量、连续日、
   连对、错题本都从它派生。`subjects/cpp` 只存了一行「最新熟练度」，结果一个派生量
   都算不出来，回路断在第一步。

5. **粒度按先修和掌握目标分，不按名词个数分**（`subjects/dsa` ADR 0001 第 3 节）。
   23 个模式各占一章、每章讲一遍「动机 / 结构 / 参与者 / 适用性」，正是
   `subjects/cpp` 犯过的错，也是八股的温床（仓库 ADR 0040）。设计模式真正的教学主线
   是**它们各自化解哪种耦合**，以及**什么时候不该用**——套用过度、为了用模式而
   增加间接层，是这个领域最常见的失败，比不认识某个模式严重得多。

6. **跨应用共用的是教学规范，不是配置 schema**（仓库 `AGENTS.md`）。照搬
   `subjects/dsa` 的方法论零成本，照搬它的 `curriculum.json` 字段定义会立刻产生耦合。
   共有概念用统一的名字（`source_refs` / `relation` / `locator`），各写各的类型。
