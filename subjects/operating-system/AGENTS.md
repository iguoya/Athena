# 操作系统 应用协作规则

仓库级规则见根 `AGENTS.md`，本文只写本应用自己的约定。本应用目录 id `operating-system`，
知识点前缀 `os.`。本应用是**学习应用**（三类判据见 `docs/REPOSITORY.md`）：
要教会人软考中级·软件设计师「第 4 章」对应的实践课程，并用可观察的证据（实验校验
通过）证明掌握度在进步。跨应用教学规范（`docs/TEACHING.md`）全部生效。

## 应用定位

- **本应用是软考中级·软件设计师「第 4 章」的实践课程**，按仓库 ADR 0103 从考试应用
  独立成挂靠子应用：`parent: software`，单父一层挂靠（ADR 0092、0099），启动器
  画在软件设计师外一圈，也可单独使用。
- 细分判据（ADR 0103 决策 1，三条同时满足）：以子课程为单元；实践性强
  （content-plan 评级 B ✓✓ 及以上或路径 A）；有具体产出——真跑的并发程序与调度/页置换时序观测记录。
- **分工**：承接章的理论侧讲解、viz 演示与纸笔考核留在 软件设计师；本应用
  承接全部实验路径。软件设计师 的课程树在承接章放「去本应用做实验」的文字
  指引（不引用代码，ADR 0032）。
- 与同名或近邻应用的边界见各应用 README；两考试之间的公共课隔离原则
  （ADR 0095 决策 3）对子应用同样成立。

## 技术栈与选型理由

- 壳 **Tauri 2**（Rust + 系统 WebView）。
- 前端：React 18 + TypeScript + Vite（与 software 同体系，ADR 0103 决策 3）；界面体系随内容填充期完善，代码编辑器统一用 CodeMirror 6。
- **实验引擎（本应用的核心差异化架构，ADR 0103 决策 3）**：并发实验在本机 gcc 下真编译真跑（pthread、信号量、互斥锁，白名单 spawn）；调度与页置换用本应用自带的 Rust 模拟引擎——算法以参数注入，前端渲染甘特图/时序图，同一引擎承载教材全部调度策略对照。编辑器用 CodeMirror 6（C 高亮）。
- **安全边界**（沿 ADR 0091 决策 3）：应用只执行白名单内的预设命令与实验断言，
  参数模板化；不提供任意 shell；自由编码区（如有）明确标注在本机执行、无隔离
  保证。
- dev 端口 **1492**（strictPort）；进程/二进制 `athena-operating-system`；窗口标题
  「操作系统」；应用内文案用中文。

## 内容组织

```
content/
├── sources.json            来源登记(出处检查的 catalog)
├── course.json             课程骨架:承接章映射 + 实验节列表
└── experiments/*.json      实验卡:步骤、骨架、校验断言(带出处)
```

- 实验卡三要素（ADR 0059 骨架可运行）：**骨架**（不改一行也能编译运行）、
  **校验断言**（输出比对/结果比对/观测记录）、**出处**。
- **判分条目是实验的 `assertions`**（content-contract.json 的 `itemMarkers`）：
  断言引用教材例题或真题时必须标 `verbatim` / `adapted` 出处（年份与题号严禁
  凭记忆编造）；骨架代码本身标 `authored`，不是出处门禁对象。
- 出处档位 **exam**（ADR 0089）：本应用判分内容直接对应真实考试，档位从严。
  骨架阶段无判分条目，契约 `blocking: false`；内容入库后改 `true`。
- 知识点 id 前缀 `os.`，与目录 id 解耦（ADR 0097 决策 3 同规）。

## 掌握度与进度库

- **掌握度只由作答写入**（ADR 0052）：一个实验节的校验断言全部通过 =
  该节的一次作答，写入 `attempts`；不设「实验币」等旁路激励；激励只展示
  由记录派生的量。
- `progress/learning.db` 随仓库走（ADR 0037、0053），Rust 侧自建自迁移：
  仓库工作树内（以 `app.json` 存在为准）写 `progress/learning.db`，发行包写
  系统数据目录。骨架阶段库由首次运行生成；schema 变更直接改建表语句并保证
  旧库可迁移，不引迁移框架。

## 验证与构建

```sh
python3 scripts/check.py            # 结构校验（骨架阶段默认）
python3 scripts/check.py --full     # + 前端构建 + Rust 检查
python3 scripts/check.py --full --skip-rust   # 只改内容或前端时用
```

- 骨架阶段（ADR 0103：先不考虑内容填充）默认只做结构校验：app.json 一致性
  （id/parent/端口三方对齐）、内容 JSON 语法、course.json 节前缀、出处契约、
  图标齐备。**内容开始填充后把默认翻转成完整构建检查**（改 `check.py` 的
  `DEFAULT_FULL`）。
- 跨应用出处检查由根 `scripts/check-app-sources.mjs` 按
  `content-contract.json` 接入。

## 约定

- 影响本应用架构边界的新决定，在 `docs/decisions/` 增补 ADR 后再动代码。
- 与其他应用构建完全隔离（ADR 0032、0062）：不引用任何应用的路径、配置或
  代码；与 软件设计师 的关系是课程归属声明，不是运行时依赖。
