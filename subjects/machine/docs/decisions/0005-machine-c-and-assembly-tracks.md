# ADR 0005：改名 machine，C 与汇编两条线独立又联合

- 日期：2026-10-03
- 状态：已接受
- 依赖：ADR 0003（教材落到本地、有所本）、ADR 0004（C23 基准）
- 修订：ADR 0002 与 ADR 0004 第 2 条中「章序跟 Beej、Beej 的脊不变」的部分；
  应用 `AGENTS.md` 的「定位」与「只讲 C 的语义」。出处要求与 C23 语义基准**不变**
- 豁免：仓库 [ADR 0080](../../../../docs/decisions/0080-reorg-exemption-when-intent-changes.md) 的首例，
  豁免仓库 ADR 0054 第 2、3 条

## 背景

本应用原来的目标是把 C 教成「看见内存」，章序跟 Beej：内存 → 指针 → 数组 → 字符串 →
结构体 → 动态分配。

使用者的新意图：C 语法相对简单，又属于中高级语言；让它和汇编语言穿插学习，认识高层与底层
如何统一，加深对计算机编程的理解。两边既有各自独立的章，也有协调配合的章；每一章既有理论
讲解，也有实践练习，实践要真能运行（模拟器也可以）。

这不是在原有六章上加一节，而是整个应用的意图变了：章集合、章序、知识点前缀、运行环境都要
重排。

## 决策

**1. 名字。** `id` 改为 `machine`，显示标题「C 与机器」。目录 `subjects/machine`，进程
`athena-machine`，环境变量 `ATHENA_MACHINE_ROOT`，`launcher open machine`。`c` 这个 `id` 与
`c.` 前缀退役。

**2. 豁免范围（依 ADR 0080）。** 允许重写、重组章集合与章序、改 `id`、改写已有教案与题。
不放宽：判分与计入掌握度的内容必须有出处（ADR 0043、本应用 0003）；C 的语义以 C23 为准
（ADR 0004 第 1、3、4、5 条）。重组前在当前提交打 tag `pre-machine-reorg`。

**3. 章分三类，先修方向有规矩。**

| 类 | 含义 | 可以依赖 |
|---|---|---|
| C 独立章 | 只讲 C 本身 | 只能依赖 C 独立章 |
| 汇编独立章 | 只讲汇编、调用约定、指令集 | C 独立章中最基础的一章（内存与变量）与汇编独立章 |
| 联合章 | C 与汇编怎么对应 | **必须同时**依赖至少一个 C 独立章和至少一个汇编独立章 |

禁止反向：C 独立章不依赖汇编章，汇编独立章不依赖联合章。检查脚本校验这条。

**4. 首批章清单**（未写成的章在图上显示为灰章）。

| 线 | 章（括号内是先修） |
|---|---|
| C 独立 | 内存与变量 → 指针 → 数组 → 字符串 → 结构体 → 动态分配；控制流（内存与变量）→ 函数（控制流、指针） |
| 汇编独立 | 读懂汇编（内存与变量）→ 控制流 → 函数调用与栈帧 → ARM64 |
| 联合 | 内存与指针 × 寄存器、栈、寻址；数组与字符串 × 变址与字节循环；结构体 × 偏移与对齐；动态分配 × 调用约定与优化；控制流与函数 × 跳转与栈帧 |

已写成的两节（字节编址、指针存地址）并入 C 侧「内存与变量」「指针」章，可以改写。

**5. 知识点 `id` 按线分段**：`machine.c.<章>.<点>`、`machine.asm.<章>.<点>`、
`machine.joint.<章>.<点>`。现有 16 个 `c.*` 随之改名（如 `c.pointer.deref` →
`machine.c.pointer.deref`）。进度库尚未建立，所以没有历史数据要迁移。

**6. 每一章都是「讲解加练习」。** 讲解是 QML 教案；练习分两种：随堂与课后题（判分、有出处）、
实验（可运行、给骨架，ADR 0059）。C 章的实验与汇编章的实验使用同一个实验台（运行环境见 0006）。

**7. 汇编与 C 语义的边界。** 汇编输出取决于编译器、优化级别与 ABI，一律标注为「某个实现的一次
结果」。关于 C 的结论只来自 C23；关于寄存器、调用约定的结论只来自 ABI 与 ISA 手册。**汇编输出
不能当作 C 规则的证据**，不得把某个目标上的行为（如有符号溢出回绕、端序）写成 C 的保证。

**8. 指令集、ABI 与语法的基准。**
- 主线指令集 x86-64，ARM64（AArch64）作对照，两者各有独立章。
- 基准 ABI 是 System V x86-64；Windows x64 ABI 作对照。ARM64 取 Linux 上的 AAPCS64，macOS
  的差异放附表。
- x86-64 统一用 Intel 语法；汇编器统一用 GNU as（clang 的集成汇编器兼容），不用 MASM、NASM。
  引用的教材若用 AT&T 语法，在 `source_refs` 的备注里注明「已转写」。

**9. 出处。** `content/sources/catalog.json` 新增：Dive Into Systems 的汇编章（要先扩充
`fetch-sources.py` 抓取，原样保存）、System V psABI、Microsoft x64 调用约定文档、Arm AAPCS64
与 Architecture Reference Manual 相关节、Intel SDM 指令参考。没有出处的汇编题不写。

**10. 首批范围外。** 系统调用与操作系统接口（Win32、Linux syscall）不在首批；汇编函数是纯计算，
由 C 驱动程序负责输出。SIMD、浮点汇编是否纳入，后续另议。

## 后果

- 工作量大于「加一条线」：课程图、`curriculum.json`、16 个 `id`、两节教案、检查脚本、实验台都要动，
  所以实施按步骤拆成独立提交（ADR → 改名 → 课程图 → 来源 → 实验台 → 首批教案 → 检查脚本）。
- 应用 `AGENTS.md` 的「定位」「教学结构」「开发」「知识点 ID」随改名一并更新；根 `README.md`、
  `docs/REPOSITORY.md` 的名字对照表同步。
- 旧状态在 tag `pre-machine-reorg` 处可取回。
- 运行环境与平台矩阵见 ADR 0006。
