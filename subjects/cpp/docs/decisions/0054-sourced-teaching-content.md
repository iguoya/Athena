# ADR 0054：教学内容与习题一律有据可依，官方规范优先

- 日期：2026-09-16
- 状态：已接受；来源登记表与校验先行，题库改造随后
- 取代：`docs/CONTENT_REFERENCES.md` 原来那句「不作为章节结构、目录顺序或措辞的来源」
- 收窄：ADR 0015（AI 自测决定熟练度）——AI 生成的题目不再计入掌握度，理由见决策第 3 条
- 对齐：仓库 ADR 0043（内容必须有出处）、`apps/mathematics` ADR 0019、
  `apps/dsa` ADR 0002、`apps/english` ADR 0007

## 背景

本应用在「内容从哪来」这件事上，一直是仓库里最松的一个，而且松在两处相反的方向。

**教材正文那一侧要求原创。** `docs/CONTENT_REFERENCES.md` 列了六个参考站点，却写着
它们「仅作知识点覆盖范围和讲法的对照参考，**不作为章节结构、目录顺序或措辞的来源**」。
这条当初是为了防止把教程抄一遍，但它的实际效果是把写作推向凭记忆发挥——而 C++ 的
语义细节（值类别、生命周期延长的条件、特殊成员函数的生成规则、窄化的判定）恰恰是
最不能凭记忆写的地方。写错了没有任何机制能发现。

**习题那一侧干脆没有来源。** ADR 0015 让 AI 现场生成题目并据此评定熟练度。这是
「想当然」的极端形式：题目每次都不一样，无法复核、无法回归、无法沉淀错题，出错了
也没人知道。`apps/mathematics` ADR 0019 的论证一字不改地适用——**自造题没有难度
校准，做对了说明不了什么，检验器本身就不可信，反而加固流畅性错觉。**

仓库 ADR 0043 早已要求「判分或计入掌握度的条目必须能指到可核对的出处」，并要求靠
机械检查兜住。本应用是六个应用里**唯一没有 `content-contract.json`** 的，跨应用
检查脚本对它报「未接入」。

C++ 在这件事上其实比别的学科占便宜：它有第一手的、公开的、可点开逐条核对的规范性
材料，不需要退而求其次。

## 决策

### 1. 所有教学内容必须有据可依，不得凭记忆发挥

教学大纲、学习页正文、实验案例、例题与习题——凡是讲 C++ 语义的地方，都要能说出
依据的是哪一条材料。`CONTENT_REFERENCES.md` 那句「不作为措辞来源」作废。

**要防的是抄，不是查。** 禁止的是整段复制、照搬目录结构、把某个教程的组织方式当成
自己的章节顺序；要求的是**写之前查、写之后对**：概念的定义、规则的条件、边界的例外
以规范性材料为准，讲法、顺序、例子仍然自己组织。版权上仍不整段复制，引用按各来源的
许可标注。

### 2. 来源分级，官方规范优先

**一级（规范性，优先采用）**——定义、条件、边界、术语以它们为准：

| id | 来源 | 位置 | 许可 |
|---|---|---|---|
| `cppreference` | cppreference.com | <https://en.cppreference.com/> | CC BY-SA 3.0 与 GFDL 双许可 |
| `iso-cpp-draft` | ISO C++ 标准草案 | <https://github.com/cplusplus/draft> | 草案自带版权声明 |
| `cpp-core-guidelines` | C++ Core Guidelines | <https://github.com/isocpp/CppCoreGuidelines> | Standard C++ Foundation 授权：个人与内部使用可复制、修改、创作衍生作品 |
| `ms-learn-cpp` | Microsoft Learn C++ 文档 | <https://github.com/MicrosoftDocs/cpp-docs> | CC BY 4.0 |

**二级（讲法对照）**——只用来看「别人怎么讲得明白」「常见误区是什么」，**不作为
语义判定的依据**：原 `CONTENT_REFERENCES.md` 里那几个中文教程站。一级与二级冲突时
一律以一级为准，不得用二级材料为一个说法背书。

许可与核对日期登记在 `resources/sources/catalog.json`，每条带 `checked_on`。
**凭印象写出处比自造更糟**——按图索骥扑一次空，之后所有出处都不可信了。

### 3. 计入掌握度的题目必须有出处，AI 退出判分

AI 生成的题目**不再计入熟练度**。ADR 0015 建立的「完整自测成绩自动评定熟练度」这条
链路保留其形式，但输入换成**有出处的静态题库**：题目写在配置里，来源指向第 2 节的
一级材料（cppreference 的某个条目、Core Guidelines 的某条规则编号、标准草案的某个
条款），本地判分，可复核、可回归、可沉淀错题。

AI 退回它本来擅长、也一直在做的角色——**讲解与答疑**（`ai_insight`），那条路径不判分，
不写掌握度，不受本条约束。

`authored`（自造题）是例外不是默认：必须写明为什么一级材料覆盖不到，且同一节内不得
过半（沿用 ADR 0043 第 2 节第 4 条）。

### 4. 机械检查兜底，不靠写的时候自觉

- `resources/sources/catalog.json` 登记全部来源；
- 知识点与题目用 `source_refs` 指过去，字段名沿用跨应用统一的那套
  （`source_refs` / `relation` / `source_id` / `locator` / `url` / `note`，ADR 0043）；
- 生成器校验：`source_id` 必须在 catalog 里、`relation` 取值合法、`authored` 必须
  给理由；
- 补 `content-contract.json` 接入仓库的 `scripts/check-app-sources.mjs`。

接入方式照 `apps/dsa` 的办法：`blocking: false` 先报告不阻断，存量列进豁免名单，
**名单只能变短不能变长**——新写的一律当场标出处。

## 后果

**得到**：语义细节有第一手依据，写错时有材料可对；题目可复核、可回归；本应用不再是
跨应用出处检查里那个「未接入」的。

**付出**：写内容多一道查证工序；题库要从零建起来，AI 出题那条路径要改造（这一步比
立规则重）。

**连带**：
- `docs/CONTENT_REFERENCES.md` 重写为分级来源清单，不再是「仅供对照」的站点表。
- ADR 0015 的判分输入被换掉，其余（星级只读、不给部分分、全部答完才写库、
  `floor(对/总×5)`）继续有效。
- 骨架案例（ADR 0053）同样受本 ADR 约束：案例要验证的语义得有依据，不是编一个
  看起来对的现象。
