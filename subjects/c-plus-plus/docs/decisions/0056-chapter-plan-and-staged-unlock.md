# ADR 0056：按多源交叉比对重划章节，知识点分三级并软门禁

- 日期：2026-09-16
- 状态：已接受；结构调整先行，门禁待静态题库就绪
- 依据：ADR 0054 的一级来源（cppreference、ISO 草案、C++ Core Guidelines、
  Microsoft Learn）
- 修订：`docs/CHAPTER_CONFIG.md` 7.1「不禁用运行入口」——改为软门禁，理由见决策第 4 条
- 前置：ADR 0054 第 3 条（AI 出题退出判分，换静态题库）必须先落地，门禁才有可靠依据

## 背景

章节体系一直是按经验划的，没有对照过权威材料。这次的做法是**多源交叉比对**，
不押单一资料——每份资料的组织逻辑都服务于它自己的目的，照搬任何一份都会跑偏：

| 资料 | 组织逻辑 | 照搬的后果 |
|---|---|---|
| ISO 标准草案 | 语言机制的形式结构 | 完备但没有难度梯度，丢掉「先学什么」 |
| cppreference | 同上，偏查阅 | 同上 |
| Microsoft Learn | 按特性文档 | 跨特性的判断与取舍讲得少 |
| Core Guidelines | 「怎么写好代码」 | 得到一份检查清单，不是教程 |

**看它们在哪里一致，那多半是真实的结构；看它们在哪里分歧，那说明存在取舍。**

一致的骨架（类型 → 函数 → 类 → 模板 → 异常 → 并发 → 标准库）现有章节全都有，
不动。真正要判断的是四处分歧。

## 决策

### 1. 四处分歧的判断

**容器 / 迭代器 / 算法：ISO 分四个条款，Core Guidelines 只有一章 → 合成两章。**
ISO 拆得细是因为参考手册必须分别定义迭代器概念的形式要求；教学上迭代器的价值
恰恰在于它把容器和算法连起来，单独成章会悬空（现有 `STLContainer` 只有三个
知识点也偏薄）。合成「容器与迭代器」与「算法与 Ranges」。

**Core Guidelines 独有的四章，采纳两个。**

- `Con` 常量与不可变 → **新增一章**。现在 `const_correctness` 在类那章、
  `compile_time` 在模板那章，被拆散了，而它们是同一条线：什么时候不可变、
  什么时候能推到编译期。
- `I` 接口设计 → **新增一章**。这是对有两三年经验的读者价值最高的一层——参数
  怎么传、返回什么、前置后置条件怎么表达——而语言参考里完全没有。
- `Per` 性能 → **不单列**。脱离场景的性能技巧集没用；内容分散到移动语义
  （拷贝开销）与容器（内存布局）更有效。
- `R` 资源管理 → 已有。

**指针：Microsoft Learn 单列一章 → 并入 RAII 当第一节。**
裸指针的语法与 C 高度重叠（ADR 0002：这类内容只在必要时加），C++ 特有的是
**所有权语义**。把「裸指针不表达所有权」作为 RAII 的动机，比单开一章有价值。

**模块：ISO 与 Microsoft Learn 都有独立章 → 列为前瞻，不配实验。**
实测目标机器 Apple Clang 21：`__cpp_modules` 未定义，`--precompile` 四种写法
全部失败。教了跑不了，破坏学练合一（同 C++26 的反射与契约，见 ADR 0054 讨论）。

### 2. 结果：15 章 → 16 章

合并 −1、新增 +2。变动项：类与对象移出 `const_correctness`、模板章移出
`compile_time`（都进新的「常量与不可变」）；`format` 从 I/O 移入词汇类型；
补 `span`（接口章）、`<=>`（类那章）、`expected`（错误处理）。

### 3. 知识点分三级，章节的级别由知识点派生

新增 `stage` 维度，取 `basic` / `intermediate` / `advanced`：

- **basic**：语言地基，不掌握后面寸步难行（类型、引用、函数、类）。
- **intermediate**：C++ 的核心取舍（值语义、const、RAII、继承、标准库使用、
  错误处理）。这是主体，章数最多是正常的。
- **advanced**：需要前面全部到位才谈得上（模板与泛型、接口设计、并发）。

**分级是知识点级的，不是章节级的。** 同一章里可以有不同级别——`decltype` 在
初级章里属于进阶，`template_basic` 在高级章里属于中级。章节显示的级别由它的
知识点派生。

`stage` 与既有两个维度**正交**，不要混：

| 维度 | 回答什么 |
|---|---|
| `difficulty` 0–5 | 这个知识点本身有多难 |
| `mastery_goal` | 学完要达到什么程度 |
| `stage`（新） | 在整条学习路径的哪一段 |

顺序仍由 `requires` 的拓扑序决定，`stage` 不替代它——一个高级知识点可能只依赖
两个初级知识点，那它照样可以早学。

### 4. 门禁用软的，不用硬锁

未达标的高级内容**默认折叠并降权显示**，点开时明确列出「你还缺 X、Y 两个前置」，
再点一次仍然能进。

**不做硬锁**，三条理由：

1. 现行 `CHAPTER_CONFIG` 7.1 写着「不禁用运行入口——自用平台上跳着学是常态」；
   数学 ADR 0012 的「第一遍验收标准是走完不是学会，不设挡路考核」也是同一判断。
2. 数学 ADR 0011 把「**卡住无出路**」列为必须消除的无效挫折。硬锁正是制造死路：
   某个前置的掌握度上不去，后面整条路径就被封死。
3. **最实际的一条**：掌握度目前的唯一来源是 AI 现场出题（ADR 0015），而 ADR 0054
   已判它退出判分。**拿一个不可靠的信号去锁内容，风险远大于收益。**

所以门禁的实施**挂在静态题库之后**：先按 ADR 0054 把判分换成有出处的题库、
补上作答流水（仓库 ADR 0052 要求的那套），掌握度可复核了，门禁才有依据。

`CHAPTER_CONFIG` 7.1 相应改写：从「不禁用」改为「默认折叠 + 可强行进入」，
「跳着学是常态」这一判断本身保留——软门禁不阻止跳着学，只是让代价显形。

### 5. 两条学习路线，共享同一批知识点

同一批知识点按两种顺序遍历，各自成一条路线。**这不是两套内容**——章节、知识点、
案例、习题都只有一份，变的只是推进顺序与切入角度。

**实务路线（默认）**——「我要写出能用的代码」。标准库提前：真实工作里第一天就要
用 `vector` 和 `map`，而不是先补完值语义。语言机制的深层部分靠后，用到了再回头。

```
类型与表达式 → 函数与可调用对象 → 引用 → 类与对象
→ 容器与迭代器 → 算法与 Ranges → 词汇类型 → 错误处理
→ 拷贝移动与转发 → RAII → 接口与设计约定 → I/O
→ 常量与不可变 → 继承与多态 → 模板泛型 → 并发
```

**思想路线**——「我要理解 C++ 为什么长成这样」。按语言自身的设计逻辑推进：
类型系统 → 值语义 → 资源管理 → 抽象机制，标准库作为这些思想的产物放在后面
（`vector` 是 RAII 加值语义加模板的合成，先懂前三样再看它，它就是推论而不是新知识）。

```
类型与表达式 → 引用 → 类与对象 → 拷贝移动与转发
→ 常量与不可变 → RAII → 接口与设计约定 → 继承与多态
→ 模板泛型 → 词汇类型 → 容器与迭代器 → 算法与 Ranges
→ 错误处理 → I/O → 并发
```

两条路线都受 `requires` 约束：路线只决定**推荐顺序**，先修关系是硬的，
生成器会校验路线顺序不与 `requires` 矛盾（不能把一个知识点排在它的前置之前）。

**默认走实务路线**——本项目的定位是「所学要用得上」，实务优先。

### 6. 「接口与设计约定」的位置：实务路线第 11、思想路线第 7

这一章的两难在于：它讲的判断力越早越好（写任何一个函数都要决定参数怎么传），
但它的判断依据来自值语义（不知道拷贝贵不贵，就无法决定传值还是传引用）。

**判断：不拆章，整体排在值语义之后。** 拆成「基础部分早、进阶部分晚」会把一章
切碎，而它的价值恰恰在于把这些判断放在一起对比。两条路线里它都紧跟在
「拷贝、移动与转发」与 RAII 之后——那时读者刚知道复制的代价和所有权的表达方式，
正是接口决策最需要的两件事。

### 7. 一节内部再分档：显式化难点

`stage` 解决了「这个知识点在整条路上排第几段」，但没解决**一节内部难度跨度大**
这件事——按整章标级时，「用 vector」（难度 1）和「迭代器失效规则」（难度 3）
被压成同一级，中级因此臌到 58%。

两条修正：

**其一，`stage` 主要跟 `difficulty` 走**（难度 1–2 → basic，3 → intermediate，
4–5 → advanced），主线必经点可下调一级（值类别、移动语义、特殊成员函数——它们
难但后面每章都要用，不是可以跳过的深水区）。重算后分布从 18/58/22 变成 41/31/27。

**其二，`section` 块新增 `tier`**，把一节内部再分三档：

| tier | 含义 | 界面 |
|---|---|---|
| `core`（默认） | 不懂就没法用，对应这节的 `mastery_goal` | 直接展开 |
| `deeper` | 机制与边界，遇到坑时回来 | 收进 Expander，标「进阶」 |
| `optional` | 深水区，用到再说 | 收进 Expander，标「选读」 |

**折叠不是把内容藏起来，是明确告诉读者这段可以先跳。** 它与软门禁天然衔接——
折叠就是最轻的门禁，而且不依赖掌握度数据，现在就能用。

### 8. 大章按阶段拆，已完成的章除外

**修订（2026-09-16，取代本节原来「不拆章」的结论）**：使用者要求把大章节明确
分成初阶 / 进阶，理由是「在不同认知阶段明确学习不同章节的内容」。原结论担心拆出
碎章，那个顾虑在**按同一主题的不同阶段拆**（初阶与进阶同名）时不成立——概念关联
由命名保留，而认知阶段的边界变清楚了。

拆分规则：

1. **只拆大章**（知识点 ≥6）。小章内部的难度差异用第 7 节的 `tier` 表达。
2. **拆完两边都要成章**（各 ≥3 个知识点）。不够就补足或不拆——`Ranges` 原本只
   分到两个，补了适配器组合与投影两个核心概念才拆。
3. **已经写完内容的章不拆**。`TypeSemantics` 有 2988 行学习页和整套实现，拆它
   要同时改造学习页与实现代码，纯风险没有收益（同 ADR 0055「存量不迁」）。
   等它的内容真要重写时再拆。

实拆四章：标准算法 / Ranges 与视图、词汇类型初阶 / 进阶、异常的使用 / 异常安全与
错误策略、继承与多态 / 多态的边界与代价。16 章 → 20 章，87 个知识点。

**拆分带来的额外收益：先修可以更精确。** 原先「错误处理」整章依赖 RAII，拆开后
才看清——`try`/`catch` 并不需要 RAII，需要它的是异常安全那一半。这类过严的先修
原本会把实务路线的顺序卡死。

### 8b. 原来的顾虑（保留备查）

考虑过把低难度与高难度的知识点拆到不同章节，让章的级别单一。按「拆出来两边
各自都要成章」筛一遍，真正拆得动的几乎没有：算法拆出的 Ranges 只剩两个知识点；
继承拆出的「陷阱」只剩一个，而虚析构函数是必须知道的坑，不能等踩了再学。
拆出来普遍是 2–4 个知识点的碎章，比不拆更散。

**结论：默认用 `tier` 在章内分档**——同样把难点显式标出来，但不割裂概念、不让
章变薄。等某章确实膨胀到十几个知识点时再拆，那时拆得动也拆得干净。

## 后果

**得到**：章节划分有据可依，不再是凭经验；接口设计与常量不可变这两块补上之后，
「怎么写好」这一层不再缺席；三级分层让学习路径有了粗粒度的顺序感，而 `requires`
继续负责细粒度。

**付出**：结构调整要动 `athena.json` 里的章节归属与 `requires`，已完成的
`ValueSemantics` 不受影响（它是加章不是改章）；`stage` 是第三个维度，写内容时
多一处要判断——判据写在第 3 节，混用时以「这一段路走到哪了」为准。

**两条路线的代价**：多一份顺序要维护。对策是路线只存知识点 ID 的顺序，内容
一份不重复；生成器校验两条路线覆盖的知识点集合一致，漏掉的会报错——避免出现
「某个知识点只在一条路线上存在」这种悄悄的内容分叉。

**未决**：门禁的具体折叠形态（整章折叠还是只折叠知识点）留到实施时定；那时
静态题库已经就位，可以按真实的掌握度分布决定。
