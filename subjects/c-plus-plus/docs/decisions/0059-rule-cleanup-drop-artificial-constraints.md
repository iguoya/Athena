# ADR 0059：规则清理——删过时的、放宽代价大于收益的、能自动化的交给工具

- 日期：2026-09-26
- 状态：已接受
- 修订：ADR 0005（头文件里的 `using namespace std`）、ADR 0053（骨架案例一对一）
- 依赖：仓库级 ADR 0040（范式是参考不是模具）、0051（平台优先级）、0057（开发机基线）、
  0061（AGENTS.md 只放规则）；本应用 ADR 0038（插图退出 SVG）、0058（移除学科图谱首页）

## 背景

对照代码与后续 ADR 逐条核对本应用的规则，发现三类问题：

- **已经和现状矛盾**：规则防的东西不存在了，或者后来的 ADR 已经推翻，但规则还在。
- **代价大于收益**：规则在制造冲突或永久欠账，而它要防的问题并不严重。
- **该交给工具的**：靠人记的双重登记，漏一处就出错。

约束多一条，读规则、遵守规则、判断例外的成本就多一份；和现状矛盾的规则还会误导
读者（人或代理）按不存在的机制做事。

## 决策

**删除或改写已过时的：**

1. 「别的领域只能是首页学科图谱上的一个节点」——ADR 0058 已删掉那个首页。只保留
   「不得在 `athena.json` 里为别的领域开分类」。
2. 「SQLite 使用系统自带 libsqlite3，不随包分发」——Windows 没有系统 SQLite，打包器
   按依赖收集 DLL，本来就随包带。改为按平台如实描述。
3. 只写 macOS 与 Ubuntu 的平台条款——Windows 已正式支持且优先于 Linux（仓库级
   ADR 0051）；「改共享代码后至少跑 Ubuntu 测试」在 Mac 上开发时无法照做。改为三个
   平台的契约，本机跑 `check.py`，其余平台交给 CI。
4. 「mermaid 暂不使用（要打包约 1 MB 的 JS）」——应用里已没有 WebView 和 JS 运行时，删除。
5. 「Athena 是独立桌面应用」——C++ 教程已不叫 Athena，改措辞。

**放宽代价大于收益的：**

6. `using namespace std;`：教学代码（`cplusplus/`，源码框展示给学员）保留；基础设施
   头文件（`ui/`、`render/`、`storage/`、`content/`、`platform/`、`services/`、`registry/`
   等）不再这样写——头文件里写会污染所有 include 它的文件，原规则为此已经不得不维护
   一张例外清单。存量不集中改，改到哪个头文件顺手去掉。修订 ADR 0005 第 24 行。
7. 骨架案例不再要求一对一：值得亲手写一遍的知识点才配。现实是 87 个知识点 6 个案例，
   一对一让整个应用永远不达标；仓库级 ADR 0059 只要求形态（给骨架不给白板），不要求
   数量。修订 ADR 0053。
8. 教学大纲的「一句题注加五节」是默认参考，可以按章合并或省略（仓库级 ADR 0040）。
9. 「不引入新的生产依赖」改为按仓库级 ADR 0057：判据是合不合适；更换 UI 技术栈仍要先问。
10. 规则里的「既有欠账」文件清单移到 `docs/TECH_DEBT.md`，规则只留原则。
11. `docs/CODE_ROLES.md` 从必读移到可选的背景阅读。
12. 「单文件约 500 行是拆分信号」去掉具体数字：拆不拆看职责是否单一、改一处是否要读懂
    无关代码，不看行数。

**交给工具：**

13. `.blp` 清单由生成器统一计算（章节页来自 `athena.json`，共享界面扫 `resources/ui/`），
    Meson 与 GResource 都用它；构建期守卫在清单变化而未重新配置时明确失败。「加新
    `.blp` 要改两处」的规则随之删除。

## 后果

- 规则按仓库级 ADR 0061 的顺序改：先改 `docs/CONTENT_RULES.md`、
  `docs/ENGINEERING_RULES.md` 的完整原文，再同步 `AGENTS.md` 要点。
- 基础设施头文件里现存的 `using namespace std` 记入 `docs/TECH_DEBT.md`。
- 保留的约束（分层与依赖方向、生成文件不准手改、教学内容只从 GResource 读、RAII、
  稳定 ID、默认不写平台分支）都在防真实的问题，不在这次清理范围内。
