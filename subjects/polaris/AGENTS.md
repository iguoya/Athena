# 北极星 · 项目协作规则

## 定位

北极星是其他学习应用的**路线图与指南针**（ADR 0012）：让人先看见计算机、电子信息两门学科的全局、主次和去向，再决定进哪一个应用练细节。它培养的是技术工程师的大局意识——必要性、能掌握什么能力、能交出哪一类技术产出——不是又一本教程。课程图对照 ACM CS2023、OSSU、工程教育认证和公开路线图校准，**不以个人经验或岗位口味裁课**。具体语法、寄存器和操作步骤属于下游应用，不在这里展开。界面与启动器上的名字是**北极星**；目录、`id` 与二进制都是 `polaris`（`athena-polaris`）。

它同时是独立的软硬融合技术体系图谱，不是课程播放器、招聘聚合器，也不是启动器。
职业目标层仍以中国航天军工院所的公开研制体系为取舍的远方——尤其是航天科工**二院**（制导雷达、
数字后端、系统软件）、**三院**（飞航总体、动力、GNC、仿真与数智化）、**四院**
（固体动力试验与接口）以及同族的运载/空间工程总体。机器人保留为相邻参考。大模型保留为地面侧助力：试验复盘、文档检索与受控问答，不得进入飞控闭环。

当前界面侧栏按计算机、电子信息两大学科列目录（知识图谱 + 实践主干 + 知识点子项）。职业方向与职业目标保留在内容里，不进侧栏、不提供跳转（ADR 0012）：现阶段培养和补全知识体系，不按就业组织路径。
**课图必要性先写学科为什么必须学，再兼顾军工里它还支撑什么**，不以某一家控制系统总体所的业务倒过来裁课；对照图仍锁住，不驱动课图分级（ADR 0014）。

当前只做图谱浏览：切图、缩放、平移、悬浮、选点、依赖聚焦与专页。界面按 ADR 0013
把桌面表达深度、可视化与交互当作一等目标，允许为读图推翻当前页面；**内容正确是
底线**——不为构图发明先修、不改嫁 id。不要在未另行决定前加入学习进度、知识掌握度、
岗位匹配分数、账号、网络同步，或启动其他 Athena 应用。
节点将来可以声明链接，但当前内容模型不写 `app_id`、命令行或启动协议。

## 技术与目录

- **壳与视图**：Tauri 2 + React 19 + TypeScript（Vite 8），样式 Tailwind 4，动效 Motion；
  图面以 SVG + DOM 承载（ADR 0015）。Rust 端只做壳：`tauri-plugin-single-instance`
  保证**运行时只有一个北极星窗口**，第二次启动只请第一份把窗口举到前面。
- **开发与热更新**：`app.json` 的 `dev` 块跑 `npm run tauri:dev`（端口 1470），前端改动由
  Vite 热更新，不再需要重开应用。
- `content/polaris.json` 是路线图的唯一内容来源，前端用 `@content` 别名直接导入，**不复制**、
  不得把节点、边或来源再硬编码进代码；`content/sources/catalog.json` 保存来源目录，每个节点
  与每条边都要引用它。
- **内容契约只在 `scripts/contract.py` 里**（ADR 0015 决策 2）：运行时不校验。新增规则只改
  这一个文件，并在 `scripts/test_contract.py` 里配一个会真失败的反例。
- `src/content/`：类型（`types.ts`）、目录索引（`catalog.ts`）、确定性布局（`layout.ts`），
  都是与视图无关的纯 TypeScript，带 Vitest 单测。视图只读它们的输出，不自己推导。
- `legacy-qt/`：旧 Qt 版，原样保留、不再构建；基线是 tag `pre-web-polaris`。等新版覆盖了
  4 张学术图和节点专页后单独一个提交删除（ADR 0015 决策 8）。
- `content/sources/reference/roadmaps/`：路线图对照原料（MIT / CC0，带许可证与 commit，见
  `MANIFEST.json`），由 `scripts/fetch_references.py` 下载。它们是对照，不进界面，也不被搬进节点正文。

## 两套地图

`family` 为 `system` 的是**体系地图**：能力先后、强先修、投入优先级。
`family` 为 `playbook` 的是**实操地图**：读什么书/公开教程、用什么可获得工具、
交出什么可检查作品。两套成对互指（`companion_map`），实操节点用 `orients` 指向
体系节点，不得写成跨图 `requires`。

## 内容边界

取舍先问它是否出现在二院、三院、四院等单位的公开研制链里：总体接口、探测与数字
后端、飞行力学、推进/能源接口、惯性导航与姿态控制、弹上计算机、测发控/遥测、
地面试验（SIL/HIL）、产品保证，以及地面侧的数智化辅助。
跨领域约束收成两条必须同时成立的验收：

1. **实时**（软件调度 + 硬件时序）：截止期、最大抖动、中断/总线时序、时间戳对齐；
2. **高性能计算**（软件数据路径 + 硬件通路）：有界队列、吞吐、DMA/缓存、FPGA/DSP
   流水线与端到端分段延迟。

精度、接口和可靠性验证附着在这两条上，不单独另起一套与时间/算力无关的技能树。

只写公开教材、公开文档和可复现仿真能支撑的能力。不写战斗部、突防、目标毁伤、
推进剂配方或未公开型号细节。VxWorks、1553B、GJB 全文等有许可或非公开约束的对象，
在实操图里用可获得的对照物（FreeRTOS、CAN、公开的过程素养文章）落地，并标明岗位
常见目标是什么。大模型实操只允许地面知识工作流，并写明人工确认与非模型备用路径。

中国航天科工二院、三院、四院及同族院所的**公开招聘**只作时效性技术需求样本：用来
确认主干上有 C/C++、MATLAB/Simulink、RTOS、总线、组合导航、半实物、FPGA/DSP、
软件工程化，助力方向上有数智化/军事智能。不得把岗位名称做成节点，也不得暗示学完
即可入职。

每个节点必须写明 `stable_definition`、`engineering_role`、`practice`、`validation`、
`volatility` 和至少一条 `source_refs`。实操节点另须 `kit`（`reading` / `tooling` /
`artifact`）和 `orients`。地图用 `emphasis` 区分 `trunk`（研制主干）、`support`
（助力，当前为大模型）、`reference`（重要参考）与
`adjacent`（相邻参考，当前为机器人）。每张图用 `priority_tiers` 把节点恰好划入
`essential` / `growth` / `specialist` 一次。`requires` 只表达强先修；大众主干不得
`requires` 专题装备，主干节点不得 `requires` 助力、参考或相邻图节点。默认打开第一
张 `emphasis=trunk` 的体系图。

## 验证

```sh
cd subjects/polaris
python3 scripts/check.py              # 内容 JSON、原料覆盖、内容契约、前端构建与单测、Rust 侧
python3 scripts/check.py --skip-rust  # 只改了内容或前端时用，省掉 Rust 编译
```

检查器依次：解析内容 JSON → 原料覆盖 → 内容契约（`contract.py` 及其反例测试）→ 前端
`tsc -b` 与 `vite build` → Vitest → `cargo check`。界面的实际视觉与交互仍需在 macOS /
Windows 上打开应用验收（ADR 0013）；构建通过不等于读图成立。
