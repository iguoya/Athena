# 北极星 · 软硬融合技术体系图谱

北极星按航天科工二院、三院、四院及同族院所的公开研制体系组织学习。软、硬件两侧都用
**实时**（截止期、最大抖动）和**高性能计算**（时限内搬完、算完）验收。体系图看先后，
实操图给出书、工具和可检查作品。

**某所**的实时控制总体链（测发控、定位定向、全程制导控制、电气、飞控软件、
试验）放在「重要参考」，用来对照主干，不与主干平级。机器人放在「相邻参考」。大模型
留在助力方向，只服务地面评测与知识工作，不进飞控闭环。

公开招聘只校正技术需求，不写成岗位清单，也不承诺录用。开源飞控、地面站和开发板只是
可替换样本。内容停在公开工程能力：不覆盖战斗部、突防、目标毁伤或未公开型号细节。

## 当前能力

- 侧栏按计算机、电子信息两大类列目录：每科下是知识图谱、实践主干和知识点子项；职业方向与职业目标仍保留在内容里，不进侧栏（ADR 0012）；
- 课程图沿用原 C++ 学习首页那张知识图谱：分层先修、实线门槛 / 虚线来路、入门起点、验证方式；
- 实时与高性能从软件调度和硬件通路两侧验收（最坏延迟、吞吐与分段搬运）；
- 每个节点都有投入优先级：大众必备主干、热门·增长方向或小众·专题参考；
- 实操节点给出阅读、工具和交付物；体系节点保持能力定义，不被某一年的书单绑死；
- C++20 对内容、来源、成对地图和强先修 DAG 做验证，并计算稳定的分层布局；
- QML 把学科图当成可飞入的航海图：分层地形、灯塔节点、流动先修、悬停邻域、镜头飞向、毛玻璃 HUD（ADR 0013）；
- 运行时只有一个进程：重复启动只把已有窗口举到前面（ADR 0007）。改 QML 或内容后
  重开应用即可，构建是增量的；
- 不含进度、岗位评分、账号或云服务。

## 运行与验证

```sh
cd subjects/polaris
launcher open polaris

python3 scripts/check.py
```

依赖：CMake 和 Qt 6。macOS 可使用 `brew install qt@6`；Windows 使用 Qt 官方安装器并设置
`CMAKE_PREFIX_PATH`；Linux 安装发行版提供的 Qt 6 Base 和 Declarative 开发包。

## 内容与证据

| 路径 | 职责 |
|---|---|
| `content/polaris.json` | 体系图、实操图、节点、强先修和边的理由 |
| `content/sources/catalog.json` | 公开工程资料、教材/教程、开源样本、高校范围参考与时效岗位样本 |
| `src/polaris_catalog.*` | 内容加载、契约验证、拓扑布局和 QML 模型 |
| `qml/components/RouteMap.qml` | 矢量边、缩放、平移和选点交互 |
| `docs/decisions/` | 内容边界和技术决策 |

来源分级：公开工程/标准资料用于稳定系统能力；教材与官方入门用于实操；开源项目是可替换样本；
高校培养方案校正基础范围；岗位描述只反映当前技术需求，不能变成稳定先修。
