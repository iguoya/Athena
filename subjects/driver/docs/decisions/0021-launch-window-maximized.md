# ADR 0021：桌面窗口启动时直接最大化

- 日期：2026-09-20
- 状态：已接受
- 影响：`lib/main.dart`、`pubspec.yaml`
- 关系：无

## 背景

使用者用的是 27 寸 4K 显示器，Flutter 桌面默认给的初始窗口尺寸在这种分辨率下
明显偏小，每次打开都要手动拖到最大化，多一道手续。

## 决策

**引入 `window_manager` 包**，启动时直接把窗口最大化，不留手动步骤。选这个包
而不是自己写平台专属代码（Windows 端改 `win32_window.cpp` 调 `ShowWindow`），
是因为跨平台优先（主仓库 ADR 0047）：`window_manager` 同一套调用在 macOS、
Windows、Linux 上都成立，不用三份平台代码各写一遍，也不用在这个应用是不是
值得为窗口尺寸单独排除某个平台上做判断——这本来就是个能被抽象吃掉的平台差异。

`main()` 里 `windowManager.ensureInitialized()` 之后用
`waitUntilReadyToShow` 包一层再 `maximize()` + `show()`：先最大化再显示窗口，
避免用户看到「先出现小窗口、再跳变成最大化」的闪烁。

顺带清理：`url_launcher` 依赖已经不再被任何代码调用（详细解释那处的外链
点击行为被撤销了，见前一次改动），这次一并从 `pubspec.yaml` 删掉，不留
没人用的依赖。

## 后果

- 新增窗口管理的运行时依赖，符合本仓库 ADR 0052「该用重依赖就用，不为了
  零依赖退而求其次」的选型判据。
- 没有对最大化状态做记忆或用户可关闭的选项——如果使用者想要非最大化窗口，
  目前只能手动拖小；这不是本 ADR 要解决的场景，需要的话再补一个设置项。
