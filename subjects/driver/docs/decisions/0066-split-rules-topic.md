# ADR 0066：拆分 drive.s1.rules——一个知识点装三分之一的题，薄弱点看不细

- 日期：2026-10-04
- 状态：已接受（本文只定决策与迁移语义；数据迁移与题库改写在后续提交执行）
- 影响：`content/curriculum.json`（topics 列表、exam.blocks）、
  `content/questions/subject1.json`（rules 各题 topic_id 迁移）、
  `lib/progress.dart` 迁移脚本、本机 SQLite 与中心 PG 的 `attempts.topic_id`
- 关系：落实知识点按难度/掌握目标评级与 requires 的既有结构（0029、0030）；
  遵守仓库级 ADR 0054（一个 id 只装一个东西）；模拟考分块见 0023 与
  AGENTS.md「出题」第 5 条；进度库表结构与中心 PG 同名同列（0070）

## 背景

科目一共 2497 题、11 个知识点，其中 `drive.s1.rules`（通行、超车与让行）
装了 795 题、占 31.8%，而最小的 `alcohol` 只有 58 题。掌握度、学习诊断的
「各章差距」、强化练习的薄弱章节优先，全部按知识点统计——一个知识点装三分之
一的题，这三分之一里「哪里薄弱」就看不出来了。

对 795 题按内容聚类（关键词分桶，每题只进第一个命中的桶）：

| 类目 | 题量 | | 类目 | 题量 |
|---|---|---|---|---|
| 让行与会车 | 98 | | 掉头与倒车 | 27 |
| 停放与临时停车 | 71 | | 装载牵引 | 24 |
| 超车 | 66 | | 信号路口通行 | 29 |
| 车道与通行位置 | 56 | | 恶劣天气 | 24 |
| 灯光喇叭 | 52 | | 铁路道口渡口 | 12 |
| 限速 | 50 | | 通行总则（未入桶） | 281 |

恶劣天气、证照资格与 rules 的主线关系弱（恶劣天气在考点速记已有独立组，
科目一另有 lights、occupants 等更贴的知识点），迁移时按题面逐题归位。
`signals`（460 题、18.4%）也偏大，混着信号灯、标志、标线、手势——先记录
为后续观察项，本 ADR 不处理。

## 决策

1. **拆成 8 个知识点，`drive.s1.rules` 拆掉不保留。** 新知识点沿用
   `drive.s1.*` 前缀：`rules.general`（通行总则：右侧通行、信号通行原则、
   交通管制、特种车辆、道路作业、一般安全规矩）、`rules.yield`（让行与会车）、
   `rules.overtake`（超车）、`rules.parking`（停放与临时停车）、
   `rules.speed`（限速）、`rules.lane`（车道与通行位置）、
   `rules.turn`（掉头与倒车）、`rules.load`（装载牵引）。拆掉不保留空壳：
   保留无题的旧 id 会让统计出现幽灵行，也违反「一个 id 只装一个东西」。
2. **52 道灯光喇叭题并入既有 `drive.s1.lights`，不在 rules 里另立灯光类。**
   鸣喇叭、会车用灯这些题的主题就是灯光使用，lights（149 题）已存在；同一个
   主题不拆两处，诊断口径才完整。
3. **历史作答按题重写 topic_id（本机 SQLite 与中心 PG 各跑一遍）。**
   `attempts` 表物化了 `topic_id` 列，统计直接 `GROUP BY topic_id`；但作答的
   业务键是 `question_id`，每题只有一个确定的新知识点——按「题 id → 新
   topic_id」映射重写历史行是确定性、可幂等重跑的。outbox 里尚未上传的记录
   同步重写（上传按业务键 UPSERT，服务端以最后一次为准），中心 PG 侧用服务端
   脚本按同一份映射重写。迁移脚本放进 `scripts/`，先本机后 PG，各自可单独重跑。
   不采用读时归一化（每次统计要 join 题库、跨端口径长期分裂）和切换点方案
   （新知识点长期缺历史、诊断失真）。
4. **模拟考组卷的通行块同步改。** `curriculum.json` 的 `exam.blocks` 里通行 25
   道的 topic 清单改为上述新知识点（general/yield/overtake/lane/speed/turn/load
   及并入 lights 的题不变块归属——块按内容定，已由 0026 确认）；校验脚本断言
   blocks 引用的 topic 都存在。
5. **迁移前打 tag、迁移后用校验兜底。** 动手前打 `pre-rules-split` tag；
   迁移完成后校验：题库无 `drive.s1.rules` 残留、每题 topic_id 都在
   curriculum 的 topics 里、attempts 无旧 topic_id 残留、组卷抽样正常。

## 后果

- 科目一知识点 11 → 18 个（含并入 lights 后 rules 消失），最大知识点占比从
  31.8% 降到约 10%（general 约 250 题），诊断与强化练习的薄弱章节分辨率随之提升。
- 需要一次数据迁移：题库 JSON 的 topic_id、本机库、中心 PG 三处同改；迁移脚本
  要能在只同步了部分设备的场景下安全重跑。
- 掌握度、错题本、考前复习、强化练习按题 id 关联的部分不受影响；按 topic 聚合
  的历史统计在重写后口径连续。
- signals 的粒度问题（460 题混装）留作后续观察，需要时另立 ADR。
