# ADR 0062：同步在外网环境下提速——拉取并行、写入只上传、进行中的写入补跑、内网探测限时（调整 ADR 0070 的同步节奏）

- 日期：2026-10-04
- 状态：已接受；调整主仓库 [ADR 0070](../../../../docs/decisions/0070-driver-client-local-first-rest-only.md) 决策 3 的同步器节奏，
  不改契约、不改本地库与队列格式。0070 原文不改
- 影响：`lib/sync.dart`、`test/sync_test.dart`

## 背景

外网端点要过 Cloudflare 隧道，实测一次请求约 0.7 秒（新连接）。同步器原来的做法在这种环境下处处吃亏：

1. 一轮同步无论有没有新数据，都**逐个**拉 8 类数据、成就、每个科目的模考草稿，约 13 个请求串行，空转也要好几秒。
2. 每次答题写入触发的防抖那一轮也是「上传 + 全量拉取」，答几题就多发十几个「有没有新的」。
3. 「待同步 N 条」要等整轮（含拉取）结束才更新，上传早就完成了，界面还显示在同步。
4. 一轮进行时到来的写入被直接忽略，要等下一次写入或 5 分钟定时器，最后几题会拖很久。
5. 第一次请求先试内网地址，在外网环境里包被丢弃，要等满 15 秒超时才换外网；一旦用上外网，回到家里也不会切回内网。

## 决策

1. **拉取并行。** 资源、成就、草稿共十几个互相独立的 GET，最多 4 路同时发；每个资源自己的翻页仍串行，游标各记各的。
   出了第一个错就不再起新任务，整轮按失败处理，错误类型的处理与原来一致。路由器不大，所以不放开到全部同时发。
2. **写入触发只上传，不拉取。** 防抖触发的一轮只上传；别处的新数据由 5 分钟定时器、启动、手动那一轮拉。
3. **一轮进行中到来的写入记下来，本轮成功结束后补跑一轮（仍是只上传）。** 失败的轮次不补跑，免得断网时每两秒空转，
   交给 5 分钟定时器。
4. **每送完一批就发布待同步数**，不等拉取。
5. **内网探测限时、定期回切。** 内网不是当前在用的端点时，请求它只给 3 秒；失败后 10 分钟内不再先试内网，
   到点后在外网使用期间也先探一次内网，通了就切回直连。时长都是构造参数，测试里可调。

## 后果

- 外网环境下空转的一轮从十几个请求串行变成约 3 批并行，整体耗时约原来的三分之一；待同步数不再被拉取拖住。
- 别处（另一台设备）的新数据最多晚 5 分钟才到本机，与原来的定时器间隔一致；答题时的上传反而更快，因为不再捎带拉取。
- 内网在家里 3 秒探测够用；路由器很忙、内网响应超过 3 秒时会误判成不通而走外网，下一个探测间隔再回来，
  数据不会丢（上传幂等）。
- 并行度 4、探测 10 分钟、探测超时 3 秒都是经验值，没有数据支撑，放在 `lib/sync.dart` 开头的常量里。
