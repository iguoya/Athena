# ADR 0013：启动时同步一次，之后每 15 分钟自动同步一次

- 日期：2026-09-20
- 状态：已接受
- 影响：`lib/home.dart`
- 关系：在 ADR 0010（GitHub JSONL 同步）与后续的云盘文件夹同步之上加一条
  自动触发时机，不改同步本身的合并规则

## 背景

同步原来完全靠手动点按钮（`_runFolderSync` / `_runSync`）。换机器练习时容易忘记
先点一下同步就直接开始做题，练完也可能忘了推出去，等再换回另一台机器才发现进度
没跟上。

## 决策

1. **应用启动时自动跑一次同步**，跟手动点效果一样，只是不用记得先点。这一次
   无条件执行——刚打开应用，人肯定在，不用等活动信号。
2. **之后每 15 分钟检查一次，但不是每次都真的同步**：用 `Timer.periodic` 定时
   触发检查，`dispose` 时取消；只有同时满足下面两条才真的跑：
   - **窗口是前台活跃状态**（`WidgetsBindingObserver` 的 `AppLifecycleState.resumed`）
     ——被切到后台就不去戳云盘目录；
   - **最近 15 分钟内确实新答过题**（本地 `attemptTotal` 比上次 `_reload()` 看到的
     还高，就刷新一次活动时间戳）——长时间没有新作答，说明人不在用，没有新东西
     可推，跳过这次检查。
3. **优先级跟手动同步一致**：配了云盘文件夹就走 `FolderSync`，没配文件夹但配了
   GitHub 令牌就走 `GithubSync`，两个都没配就什么也不做，不弹提示打扰。
4. **跟手动同步共用忙碰撞保护**：自动触发时如果 `_syncBusy` 已经是 true（用户正
   手动点着，或上一次自动同步还没跑完），这次自动同步直接跳过，不排队、不重试。

## 后果

- 同步失败仍然只在界面的同步结果区如实显示错误，不新增弹窗或通知——沿用
  ADR 0010「不为连不上写降级路径，只在界面上如实报错」的态度。
- 定时器只在 `HomePage` 这个 State 存活期间跑，练习页（`SessionStage`）内不触发
  自动同步；回到首页、`SessionStage.onClose` 调 `_reload()` 时才会看到刚才那轮
  作答，进而在下一次定时检查里被算作「最近有活动」。
- 活动信号只看本地作答量有没有涨，不看鼠标键盘——应用开着但只是在读解析、翻
  设置页，不算「活动」，这跟「长时间没有改动就不同步」的字面意思一致，代价是
  纯浏览的时段也不会推送（但反正也没有新东西可推）。
