# ADR 0034：考前复习动态进出——错几次就要连对几次才移出

- 日期：2026-09-28
- 状态：已接受
- 影响：`lib/models.dart`（`reviewExitStreak`、`inReview`）、`lib/progress.dart`
  （`correctStreaksSinceWrong`）、`lib/home.dart`（考前复习页）
- 关系：修订 ADR 0033 第 2 条「答对了也不移走」与其后果第 1 条「只增不减」

## 背景

ADR 0033 让考前复习只进不出，当天就暴露了问题：清单只会越来越长，后期反复答对的题仍然
占着位置，真正还没过关的淹没在里面。使用者的要求：答对次数和答错次数要平衡，后期多次
答对应该移出；错过很多次的题也要有移出的可能。

## 决策

1. **进**：累计答错 ≥ 2 次（不变）。
2. **出**：最后一次答错**之后**连续答对的次数 ≥ `reviewExitStreak(累计错次数)`：
   错几次就要连对几次，**最少 2、最多 4**。错 2 次连对 2 次、错 3 次连对 3 次、
   错 4 次及以上一律连对 4 次。
   - 按错的次数要求连对，是对错两边的平衡：翻车越多，要证明的次数越多。
   - 封顶 4 次，是为了错过七八次的顽固题也有出路，不会永远困在复习区。
   - 只数最后一次错之后的答对：错之前答对过多少次都不抵账。
3. **回**：移出之后只要再错一次，连对清零、累计错次数加一，自然回到复习区，门槛随之提高
   （上限仍是 4）。
4. 一轮练习里每道题只出一次（ADR 0031），「连对 N 次」天然要跨 N 轮，不会一口气刷出去。
5. 页面：每道题标「还错着 · 0/N」或「连对 k/N」；页头统计还错着、订正中、已移出。清单
   按「离移出还差几次」从多到少排，同样差距时错得多的在前。
6. 仍由作答记录派生，不另建表（ADR 0033 第 4 条不变）：进出都是作答记录的函数，同步到
   别的机器结果一样。

## 后果

- 复习区的数字变成真正的待办：做得好就缩，退步就涨。
- 「已移出」只是计数，不单列清单——移出的题再错会自己回来，不需要另一个地方去翻。
- 门槛只在 `reviewExitStreak` 一处；调之前先想清楚对错两边的平衡。
