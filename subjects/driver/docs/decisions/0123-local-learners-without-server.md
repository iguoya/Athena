# ADR 0123：目录连不上也能新建——1000 起的本地学习者；没配外网凭据就不试外网

- 日期：2026-10-09
- 状态：已接受
- 影响：`lib/core/users.dart`、`lib/core/user_directory.dart`、`lib/core/sync.dart`（`ApiConfig`）、`lib/app/user_gate_screen.dart`、`lib/app/api_config_screen.dart`、`lib/main.dart`、`lib/home.dart`
- 关系：放宽 0074 决策 3「新建学习者必须联网」的适用面；落实 0070「本地优先」的最后一处硬依赖；编号段约定进主仓库 `docs/REPOSITORY.md` 的学习者目录节

## 背景

本地优先（主仓库 ADR 0070）之后，做题、查进度都不依赖网络，但仍有两处把「能不能用」押在
连得上中心上：

1. **新建学习者**：登录页输入一个本机缓存里没有的名字，要问中心目录，连不上就只报错
   （「现在连不上学习者目录」）——第一次在断网的机器上用的人被挡在门外。0074 决策 3 说
   「新建与异地首次登录要联网，不为离线新建设计路径」，前提是有一个可达的中心；这个前提
   对没有服务器的机器（没配外网访问凭据、路由器不在身边）不成立。
2. **外网端点**：外网域名是内置默认值，哪怕外网访问凭据（Cloudflare 服务令牌）一个都没填，
   同步器离开内网后仍会去敲外网的门，被 Cloudflare 拦下来报「检查外网访问凭据」——没打算
   配凭据的机器，这条错误永远消不掉。

## 决定

1. **本地学习者**：目录不可达时，登录页提供「在这台电脑上新建（不同步）」。这类学习者只
   存在本机（`users.json` 缓存 + 本地 SQLite 库），**永不参与同步**：不启动 `SyncEngine`、
   不发任何请求。想要同步，就在联网时用中心目录的学习者——两类人互不迁移，规则简单、
   无歧义。
2. **编号段隔离**：中心目录只分配 1～999；**本地学习者用 1000～9999**，本机已有本地学习
   者取最大值加一，从 1000 起。编号是身份，两种编号在 `users.json` 里同列（该文件本就
   「读取方忽略未知条目」），格式不变；主仓库 `docs/REPOSITORY.md` 的 `users[].id` 条目
   补记这个段。本地编号**不发给任何服务端**，所以不存在与中心撞号的可能；`isLocal` 由
   编号段派生（`int.parse(id) >= 1000`），不另设标志字段。
3. **改名只走本机**：本地学习者改名字只写 `users.json` 缓存（`renamed`），不问中心目录；
   名字本来就是称呼（0075），本地学习者的权威就是本机。
4. **没配外网凭据，外网端点不参与**：`ApiConfig` 的外网端点只有在外网访问凭据
   （Client ID + Client Secret）齐全时才进入端点候选（`wanUsableBase`）。同步器与学习者
   目录都按此筛选；配置屏「测试连接」在没填凭据时不再去敲门，直接说明「外网不参与，离开
   内网就是完全本地」。凭据填了却被拦（`SyncAuthError`）的原有报错保留——那是配置错了，
   要人来修。
5. **临时断网的行为不变**：已在本机的中心学习者断网照常用，新数据进出站队列，联网后补发，
   侧栏如实显示「暂不同步」——那是「暂时不同步」，不是「丧失同步」；与本地学习者
   （永不同步）是两回事，界面文案分开说。

## 验收

- `test/users_test.dart`：本地编号从已有最大值加一、1000 起；`users.json` 往返保留本地段；
  1～999 与 1000～9999 都算合法编号，越段越界仍被忽略。
- `test/user_gate_test.dart`：目录不可达时点「在这台电脑上新建（不同步）」得到本地学习者
  （编号 ≥1000）并直接进入；本机重名时先确认；本地学习者改名不碰目录。
- `test/sync_test.dart`：外网凭据没配齐时，端点候选里没有外网——假外网服务器收不到请求。
- 应用 `AGENTS.md` 与主仓库 `docs/REPOSITORY.md` 同步更新。
