# ADR 0057：作答记录带场合标记（kind），单题用时封顶

- 日期：2026-10-03
- 状态：已接受
- 影响：`lib/progress.dart`（表结构、recordAttempt）、`lib/session.dart`（判定处传场合）、
  `practice/nas_admin`（API 字段镜像与聚合）、既有中心库的一次性加列与历史回填
- 关系：延续 ADR 0070（本地优先与 REST 同步）、仓库级 ADR 0068（外网走 REST API）、
  0069（只读仪表盘）；不修订任何条款

## 背景

仪表盘（ADR 0069）做科目一深挖时发现两个数据缺口，都在客户端的记录口径上：

1. **模拟考的逐题作答一直有记录，但分不出来**。`_commit` 对练习和模拟考都调
   `recordAttempt`，12 场考试的约 1200 次作答混在平时练习里（`subject_id` 都是科目），
   「模拟考里哪章丢分」这类统计无从下手。错题本 / 考前复习的场景记在 `subject_id`
   （`wrong` / `review`，旧约定），而「平时练习 vs 模拟考」这一维度没有承载列。
2. **单题用时有挂机脏数据**。用时 = 本题判定时刻 − 上题显示时刻，中途挂机会记出
   十小时级的天文值（库里最大一条 36,947,433 ms），把「平均用时」拉到失真。

## 决策

1. **`attempts` 加 `kind` 列：`practice`（平时练习）或 `exam`（模拟考），默认
   `practice`。** 场景（错题本 / 复习）继续留在 `subject_id` 不动——那是旧同步的
   约定，`kind` 只回答「这次作答发生在什么场合」，两维正交。判定处（`session.dart`
   的 `_commit`）按 `_isExam` 传值。
2. **单题用时在记录处封顶 5 分钟（300,000 ms）。** 超过按封顶值记：挂机时间不是
   答题时间，宁可截断不记天文值；5 分钟对最慢的题也绰绰有余。API 侧原有的 24 小时
   上限继续挡垃圾值，这里是客户端的第一道。
3. **历史数据一次性回填，规则写死并承认近似。** 中心 PG 加列后，把「作答时刻落在
   某场考试交卷时刻往前 50 分钟内、且科目相同」的记录回填为 `exam`（50 分钟 = 科目一
   100 题 45 分钟 + 5 分钟缓冲）。交卷前紧挨着的那段平时练习可能被误标，概率低，
   接受；不回溯更复杂的会话重建。
4. **新列进同步契约**：REST API 的 `attempts` 资源接受可选 `kind`（缺省 `practice`），
   本地库老版本升级自动 `ALTER TABLE` 加列。`hesitant`（迟疑）是历史遗留列，客户端
   早已去掉迟疑概念（本 ADR 前的提交 3c4276b），继续保留但永远写 0，不做统计。

## 后果

- 仪表盘可以给出「模拟考章节丢分」「练习 vs 模拟考正确率」这类对照维度（服务端
  聚合，`kind = 'exam'` 过滤），历史 12 场考试经回填后立即可用。
- 平均用时等统计在服务端同样过滤 `duration_ms ≤ 300,000`，历史脏值不再拉偏。
- 加列后的旧客户端上传（不带 `kind`）由 API 缺省为 `practice`，不破坏兼容；新客户端
  对旧库上传（本地 SQLite 已自动加列）也不受影响。
- `kind` 只有两个合法值，由客户端单点写入；服务端校验非空字符串，不枚举——新增
  场合（如考前模拟计时练）时再放宽并同步本 ADR。
