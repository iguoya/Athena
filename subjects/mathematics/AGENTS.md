# Athena Mathematics — 项目协作规则

本文档是 **`subjects/mathematics` 独立应用** 的项目级指令，不依赖任何其他应用即可完成开发、
构建与练习全流程。仓库根 `AGENTS.md` 写各应用共同遵守的规则；**改本应用时以本文为准**。

「定位」「技术栈」「开发与验证」三节只留要点，完整原文与取舍过程在
[`docs/RULES.md`](docs/RULES.md)（主仓库 ADR 0061）。

## 定位

- **一个目标 + 一个约束**（ADR 0003、0007）：目标是用数学认识、改造现实，所学要用得上；
  约束是通过研究生入学考试数学二（高数约 78%、线代约 22%，不考概率）。**约束需要满足，
  不需要认同**——考纲定覆盖范围的下限，不定讲法与顺序。
- **起点假设**（ADR 0015）：只假设会四则运算、看得懂坐标系上的点。更高的前置要么补上，
  要么在 `requires` 显式声明；前置基础标 `prereq`，按需诊断后只补缺口。
- 范围用 `scope`（`math2` / `math1` / `beyond` / `prereq`）标记，不物理删除。数学二不是
  数学一的子集。
- **建模独立成线**（ADR 0003）：由问题组织、允许跨章，不用「每个知识点挂个应用例子」冒充。
- **应试区显式隔离**：纯为区分度存在的偏难怪题进标注清楚的过关训练区，不混入主线。
- **按直观、自然的顺序讲**（ADR 0005）：动机先于定义、低维先于一般、图像与符号并置、
  严格化分阶段登场；物理式直观推导要标清何时失效。**两条防线**：直观必须配反例；反象牙塔
  不得成为削弱应试的借口。
- **禁止 PUA 式表达**（ADR 0015 第 5 节，与 ADR 0013 的写作禁用词表同一个 lint 检查）：不贬低读者、不拿他人施压、
  不用后果恐吓、不制造稀缺焦虑。
- **教材与考纲坐标必填**（ADR 0009，lint 检查）：`textbook_ref` 与 `syllabus_ref`，界面显著
  显示、可按教材章节反查。坐标是导航，不是内容来源，不得退化成改写教材；教材无独立章节时
  标 `cross_chapter` 并列全 `covers` 与 `prepares`。
- **路径按先修图拓扑序**（ADR 0008）：`difficulty` 是单点难度，顺序由 `requires` 决定；
  多个合法解时选更早接上现实的分支。
- **现实问题当引入动机，不当课后应用**（ADR 0008）：禁止把应用堆到章末或单独的「应用」章。
- **螺旋式三遍，先薄后厚**（ADR 0012）：`overview` → `full` → `exam`。第一遍的验收是「走完」
  不是「学会」，不设挡路考核；先横向铺完一科的 `overview`，再回头纵向加深。
- **习题是检验器，也是学习动作本身**（ADR 0014）：按变式与渐隐完形设计梯度，小批量高频次；
  新学分块、巩固交错（界面说明更吃力是正常的）。随堂测验的错误选项必须是具体的错误理解。
- **出题必须有所本**（ADR 0019，lint 检查）：判分的题带 `source`（`verbatim` / `adapted` /
  `authored`），指到实地核对过的出处；`authored` 写明为什么外部题库覆盖不到，一节内不过半；
  凭印象编出处比自造更糟。`predict`（先猜再验）不判分，不受此约束。
- **知识点绑定应用，越多越好**（ADR 0024）：每个知识点至少带一个现实用法，讲解、例题、习题
  任一处都行；判据是有没有帮助理解。唯一硬要求是不编造事实。
- **参考来源优先选通俗、免费、可点开核对的，中文优先**（ADR 0022、0027）：可汗学院中文版 →
  Immersive Math → MIT OCW 18.06。同济教材只作坐标，不作讲解与严谨表述的来源。
- **严谨 ≠ 形式化**（ADR 0022）：要准确，不要最一般的记号；判据是没学过的人能不能读懂。
- **标题用规范术语，直觉说法降为副标题**（ADR 0021）：`title` 取自坐标、是名词短语，
  `plain_title` 必填，两者同时显示；知识图谱只显示术语。只约束标题，不约束讲法。
- **讲解分直觉与严谨两个视图，讲的是同一件事**（ADR 0020、0023）：直觉侧用口语、比喻、图与
  可拖的控件，严谨侧只用定义、定理、条件和式子；两侧用同一个具体对象，**区隔靠语言不靠
  内容**——别让严谨侧去讲别的内容。严谨侧每条带出处、`pairs` 指回直觉侧、`plain` 复述一句
  （lint 检查）；默认停在直觉侧；例题与练习不进标签页。
- **加深那一遍（`full`）的要求**（ADR 0019、0023、0027）：每节两遍对等讲解、各配各的习题，
  严谨侧必须有要动笔算的题（有 `formal` 就必须有 `formal.drills`，lint 检查）；每节配 1–3 道
  标准例题，每步 `why` 必填。第一遍 `overview` 不要求这些。
- **为专注与持续投入设计**（ADR 0011，仓库 ADR 0052）：消除无效挫折，保留有效困难，不降低
  掌握标准；激励只展示作答记录派生的量；禁止排行榜、积分商城、恐吓断签。
- **通用性决定权重**（ADR 0006）：思想 ＞ 方法 ＞ 算法 ＞ 技巧，技巧进应试区。数学史只讲
  「卡住 → 突破」的关头。
- **工具的角色是裁判，不是计算器**（ADR 0001）：用户手写每一步，引擎判等并定位第一处出错；
  禁止做成「输入题目 → 输出答案」。
- 不以做成通用 CAS、在线题库、公式速查手册或数值仿真平台为目标。

## 技术栈（本应用自有）

- **壳**：Tauri 2（Rust）；**界面**：Vite + TypeScript。
- **符号引擎**：本机 Python 常驻进程 + SymPy（ADR 0025）。Rust 侧按需拉起一个长驻解释器，
  NDJSON 走 stdin/stdout；环境是自带的 `engine/.venv`，跑一次 `scripts/setup-engine.py` 建好。
  不每次验算 fork 子进程；引擎启动时先跑一次 `simplify` 预热。**只回答 equal / different /
  unknown 三种**，`unknown` 不许折叠成 `different`。
- **公式**：KaTeX 渲染（本地打包，不走 CDN），MathLive 输入。
- **可视化**：静态示意用 SVG；要拖参数实时响应的用前端 Canvas/SVG 自绘；曲面与三维用
  three.js。没有具体场景时不预先引入。概念节可带 `walkthrough`（ADR 0018），不自动播放，
  演完能接着拖。
- **进度**：SQLite `progress/learning.db`，随仓库走（主仓库 ADR 0053），发行副本退回用户数据
  目录 `AthenaMath/`；自建表、自迁移（主仓库 ADR 0037）。知识点 ID 前缀是 `math.`。
- MATLAB / Octave 需要时可以引入，符号判等仍用 SymPy。不做 Pyodide 版本。

| `content/` | 课表、知识点、题目与推导模板；**唯一内容源** |

| `docs/RULES.md` | 「定位」「技术栈」「开发与验证」的完整原文与取舍过程 |
| `AGENTS.md` | 本文 |

## 内容与教学分层

精神对齐「大纲 → 讲解 → 实验」，载体本应用自定。课表唯一源是 `content/curriculum.json`。

数学的「实验」分四类，按知识点性质选用，**不强求配齐**：

| 形态 | 练什么 | 怎么做 |
|---|---|---|
| **推导验算** | 准确 | 用户逐步写出自己的推导，引擎判每步等价，定位第一处断裂 |
| **参数实验** | 直观 | 拖滑块看极限过程、级数逼近、曲面变形，先预测再看结果 |
| **现实闭环** | 意识 | 用真实数据/现象得出不用数学就得不到的结论，产出可留存物 |
| **限时做题** | 速度 | 按题型计时作答，判分后错题按错因入错题本 |

讲解侧另有两条思想线，**按杠杆分配、不平均用力**（ADR 0002）：

- **来龙去脉**：这个概念是被什么问题逼出来的。不是背景装饰，是理解的锚。
- **多重面孔**：同一对象在不同视角下的样子，优先写能统一多个章节的那种视角。

- **SymPy 只用来给有出处的母题做变式**（ADR 0019 后果一节收窄了原先的说法）：
  参数随机化生成的题必须挂在一道真实出处的母题上，`source` 继承母题并注明
  「参数随机化自 X」。脱离母题凭空生成的题属于 `authored`，受配额约束。
- 掌握度只由做题与验算结果写入，禁止手动标记熟练。
- 编写讲解时优先图、对照和可交互示意，不堆长文（仓库级 ADR 0056）。概念（如可导与连续的
  关系）用正反例并排；技能（如换元积分）用示范加变式；策略（如选哪种积分法）在情境里选并说明依据。
- 篇幅与难度、掌握目标匹配，不写八股（主仓库 ADR 0040）。

## 架构原则

- **独立可运行**：`launcher open mathematics`（编排器执行 `tauri:dev`，主仓库 ADR 0032、0046）
  不经过任何别的应用。
- **内容驱动 UI**：改课优先改 `content/`，不为新节复制整页。
- **引擎只判不算**：不做「用户输入题目，应用输出答案」的路径；要加这类路径先写 ADR
  （ADR 0027 收窄：标准例题的完整解答、答题后的解析不在此列）。
- **壳要薄**：Rust 侧负责窗口、路径、进度和引擎进程的拉起；业务文案、课树和数学都不进 Rust。

## 开发与验证

```sh
cd subjects/mathematics
python3 scripts/setup-engine.py         # 只需跑一次：建 engine/.venv 并装 SymPy
launcher open mathematics               # 日常开发：tauri:dev，前端秒级热更新
python3 scripts/check.py mathematics    # 验证（在仓库根执行）：lint、构建、引擎、Rust 测试
```

- **验证改动一律走 `tauri:dev`。** 不要把 release 构建、装进 `bin/` 或 `/Applications` 放进
  改一次看一次的循环；`build:app` / `build:dmg` 只在真正要交付可分发的包时才跑。
- `ATHENA_MATH_ROOT` 可强制指定应用根目录（含 `content/`）。
- 只核对排版时可用 `node scripts/make-preview.mjs` 生成静态预览，它**不能替代 `tauri:dev`**
  （进度库、语音、窗口行为都是假的）。
- 符号引擎的首次可用时间是本应用的性能预算，改引擎启动路径后要实测一次（目标见 ADR 0001
  第 4 节，实测数字见 ADR 0026 背景）。

## 修改流程

1. 改课：先改 `content/`，再补前端展示类型（若有新实验形态）。
2. 改引擎交互：先确认没有违反「只判不算」，再动 `src/`。
3. 改运行时：只动 `src-tauri`，保持命令表面稳定。
4. 学科地图在北极星（`subjects/polaris`）。
