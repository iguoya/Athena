# ADR 0002：思想、直观与现实闭环是主线，不是解题之外的装饰

- 日期：2026-09-13
- 状态：已接受
- 依赖：ADR 0001（工具当裁判不当计算器）
- 精神对齐：主仓库 `AGENTS.md`「教学方向由知识点和教学大纲主导」、ADR 0031
  （按知识类型选教学动作）、ADR 0040（篇幅与掌握目标匹配）

## 背景

ADR 0001 解决的是「怎么练对」，没有回答「为什么学」。只按它实现，做出来的会是
一台高效的批改机器——比市面上的解题 App 好，但仍然是应试工具，考完即弃。

本应用的使用者明确拒绝这个结局：数学不该只是入学的敲门砖，要能理解思想的来龙
去脉，要能体会用数学解决现实问题的意识。他同时指出考试形态本身「重解题、轻思想
和实践影响」。

**这个张力是真实的，不要假装不存在。** 考试三小时闭卷手算，靠的是模式识别和
手速；而理解来龙去脉需要绕路、需要慢。时间有限，不承认取舍的结果通常是两头
落空——既没考上，也没真懂。

但张力没有大到需要二选一，因为有一个关键事实：**思想在很多地方不是解题的并列
选项，而是它的上游。** 考纲里不少「技巧」只是思想的退化形式：

| 考纲里的样子 | 上游的思想 |
|---|---|
| 背几个泰勒展开式 | 用多项式在一点附近逼近任意光滑函数 |
| 导数、偏导、梯度、雅可比矩阵（四章） | 都是「用线性的东西局部近似非线性的东西」（一件事） |
| 解特征多项式求特征值 | 线性变换下方向不变的那些方向 |
| 构造辅助函数证中值定理的题 | 把要证的式子认成某个函数的导数 |
| 行列式的展开与降阶技巧 | 有向体积的伸缩比；线性无关性的判据 |

知道上游，下游的技巧不用背——理解思想在这些地方**是效率手段，不是奢侈品**。

反过来也成立：有些考点就是纯计算套路（三角有理式的凑法、部分行列式降阶、级数
判别法的机械套用），没有多少思想可挖，老实练手速才是对的。

## 决策

### 1. 讲解侧增设两条思想线

除 ADR 0001 的实验形态外，讲解必须组织以下两类内容：

- **来龙去脉**：这个概念是被什么问题逼出来的，以及它解决之前人们卡在哪里。
  例：ε-δ 不是折磨人的形式游戏，是 19 世纪为了终结含混的「无穷小」而做的一次
  「把话说清楚」；概率的公理化起于连续情形下古典概型给出的悖论。
- **多重面孔**：同一对象在不同视角下的样子。**优先写能统一多个章节的视角**——
  统一得越多，性价比越高。

两条都不是背景闲话，写进正文主线，不塞进折叠区（主仓库记忆：重要内容不藏折叠）。

### 2. 新增实验形态：现实闭环

在推导验算、参数实验、限时做题之外，增加**现实闭环**。

要求是硬的：**用真实数据或真实现象，得出一个不用数学就得不到的结论。**

- **禁止伪应用题**（「某工厂生产甲乙两种产品……」）。那是套了现实外壳的计算题，
  对「数学意识」零贡献。
- 判据：结论必须是反直觉的、或精确到不算就说不出的。合格的例子——用贝叶斯算
  医学筛查的假阳性率（结论反直觉到令人不适）；用泰勒展开解释单摆小角度周期与
  振幅无关，**并算出角度多大时这个近似开始失效**（精确到不算就说不出）。
- **必须产出可留存物**：一个能跑的模型、一张图、一个记下来的结论。考完不弃的
  前提不是「我学过」，而是「我用它做成过一件事」。

### 3. 思想层同样要有验证闭环，禁止写成长文

这是本 ADR 最容易被违反的一条。

如果把「数学思想」写成一堆要读的段落，使用者会跳过它去做题——因为做题有反馈，
读文章没有。那样思想层会退化成第二套要背的东西，比不写更糟。

**所以思想层照样走「预测 → 验证 → 对照修正」**。例：讲「导数是最佳线性逼近」，
不是写一段话说明它，而是——先让用户猜 `f(x)=x²` 在 `x=1` 附近放大 100 倍是什么
样子 → 拖动放大滑块，看到它确实变成直线 → 再问 `|x|` 在 `x=0` 处放大会怎样 →
看到它无论放多大都是折的 → 「不可导」从此是看见过的东西，不是定义。

### 4. 按杠杆分配，不平均用力

知识点在 `content/curriculum.json` 中标注 `idea_leverage`（`high` / `low`）：

- **high**：理解之后能省掉背诵大量技巧，或能统一多个章节。给足思想线与可视化。
- **low**：纯计算套路。老实给示范加变式练习，**不强行附一段思想**——为凑格式而
  写的哲学是八股（主仓库 ADR 0040）。

与既有的 `difficulty`、`mastery_goal` 一样，**只给已经写出教学内容的知识点评定，
其余留空**，不提前判断（主仓库记忆：不为未涉及章节提前评级）。

### 5. 考纲的地位

考纲决定**覆盖范围的下限**——它列的必须都有。它**不决定**：

- 章节顺序与组织方式（可以按思想线重排，例如把导数/偏导/梯度/雅可比放在一条
  「线性逼近」主线上互相引用）；
- 讲法与详略；
- 是否讲考纲之外的来源与应用。

**禁止**由考纲或题型反向决定教什么讲什么——这与主仓库「不得通过总结现有实现
反向决定应教授哪些知识」是同一条原则在应试场景下的形态。

## 后果

- 内容编写成本显著高于纯题库型应用：每个 `high` 杠杆知识点都要设计可视化与
  现实闭环，而不只是写讲解、挂题目。
- 使用者的总时间被分走一部分。这是自觉的取舍：换来的是下游技巧的背诵量下降，
  以及考后仍然留存的东西。若临近考试需要压缩，应压缩 `low` 杠杆知识点的讲解与
  现实闭环，**保留** `high` 杠杆的思想线——反过来砍会同时损失理解和解题效率。
- 现实闭环需要真实数据，`content/` 要容纳数据文件，不能只有课表和题目。
- 第 3 条要求思想层可交互，因此前端绘图与滑块交互的工作量比 ADR 0001 预估的更
  重，`src/` 的分层要相应更认真。
