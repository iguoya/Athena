# ADR 0027：规则清理——删过时的、放宽代价大于收益的、取消界面不出现考试字样

- 日期：2026-09-26
- 状态：已接受
- 修订：ADR 0022（参考来源「一律」选通俗的 → 优先）；取消「界面不出现考研、数学一字样」
  （原为沿用 `subjects/english` 的做法，写在 AGENTS.md「定位」里，无单独 ADR）
- 依赖：主仓库 ADR 0045（应用平级、无主程序）、0061（AGENTS.md 只放规则）；
  本应用 ADR 0009（考纲坐标界面显著显示）、0012（螺旋三遍）、0019、0020、0023、0025

## 背景

对照代码与内容逐条核对本应用规则，发现几类问题：

- **和现状矛盾**：规则描述的机制已经不是现在的样子。
- **代价大于收益或让人困惑**：规则互相打架、重复，或者按字面永远达不到。
- **规则里夹着历史叙述**：取舍过程写在规则里，读规则的人要先读完一段「原先写的是」。

核对「界面不出现考试字样」时还发现它和 ADR 0009 正面冲突：每个知识点的
`syllabus_ref` 都以「数学二 · 」开头，而 ADR 0009 要求考纲坐标在界面上显著显示，
界面上本来就每节都显示着「数学二」。

## 决策

**改写已过时的：**

1. 「`src-tauri/` 不做数学——符号计算全在前端」是 Pyodide 时代的说法。现在符号引擎是本机
   Python 常驻进程，由 Rust 侧（`src-tauri/src/engine.rs`）拉起并转发。改为：Rust 只负责
   拉起引擎进程与转发，不做数学。
2. 「不必跑主仓库 `scripts/check.py`，除非改了 `subjects/cpp` 的 discover」——根入口是统一
   验证入口，会调本应用自己的 `check.py`；discover 早已不在 cpp。验证命令改为
   `python3 scripts/check.py mathematics`。
3. 引用的「主仓库记忆 `dev-loop-not-release-build`」不存在，且代理记忆换一个代理、换一台
   机器就看不到。删除引用。
4. 以 C++ 教程为参照系的五处写法（仓库级 ADR 0045 已说明「以主程序为中心」的假设过时，
   应用隔离是根规则）合并成「不依赖任何其他应用」。

**放宽或澄清：**

5. 「每节两遍讲解」「每节配 1–3 道标准例题」属于加深那一遍（`full`）的要求，第一遍
   `overview` 不要求——与 ADR 0012「第一遍的验收是走完」一致，也与 lint 只在「有 `formal`
   时」检查的实际行为一致。现状 16 个知识点全部只有 `overview`，按旧字面永远不达标。
6. 两个讲解视图的三条规则（ADR 0020、0023、0023 第 2b 节）在 AGENTS.md 里合并为一条要点，
   完整表述留在 `docs/RULES.md`，语义不变。
7. 规则里的取舍过程（three.js、Pyodide、性能预算、MATLAB/Octave 的来龙去脉）只在
   `docs/RULES.md` 保留，AGENTS.md 只留结论。
8. 「任何把完整答案直接呈给用户的交互路径都需要 ADR」按字面连标准例题的完整解答、答题后
   的解析都算进去了，与「每节配完整解答的例题」冲突。收窄为本意：不做「用户输入题目，
   应用输出答案」的路径。
9. 参考来源「一律」选通俗、免费、可核对的，改为「优先」——不把付费但权威的材料排除在外。
10. 「不要启动打包 `.app`、不要同步到 `/Applications`」在 AGENTS.md 里写了两遍，只留一处。
11. **取消「界面上不出现考研、数学一这类考试字样」。** 它和 ADR 0009 的考纲坐标显示冲突，
    而维持它的收益（界面不显得应试）不值得为此改坐标数据或加检查。「应试区显式隔离」
    保留，只删去其中「界面文案仍不出现考研字样」半句。
12. 验证步骤已全部写在本应用的 `check.py` 里，AGENTS.md 只写入口命令。

## 后果

- AGENTS.md 从 21.6 KB 降到应用级预算（20 KB）以内。
- 保留的约束（目标与约束、起点假设、scope、出处、禁止 PUA 式表达、术语标题、错误选项
  必须是具体误解、引擎三态判等、先修拓扑序、应用不堆章末、掌握度只由作答写入、激励
  规则）都在防真实的问题，其中出处、PUA、教材坐标、先修图已由内容 lint 强制。
