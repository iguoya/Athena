# 追问到底，再动手

目标是在写任何代码或文档之前，和使用者就一个方案达成**完整的共识**：每个分支都走到，
没有默默假设的前提。这个仓库决策多、ADR 多、「动结构先问」是硬规矩，边做边改的代价
比先问清楚大得多。

## 先查，再问

**事实是你的事，决定才是使用者的事。** 能从仓库里查到的，一律自己查，不拿去问人：

- 根 `AGENTS.md` 和涉及应用的 `subjects/<id>/AGENTS.md`（或 `practice/<id>/`）。
- 相关 ADR：仓库级 `docs/decisions/README.md` 索引，应用级
  `subjects/<id>/docs/decisions/README.md` 索引，再读具体条目。
- 代码现状、`app.json`、`git log`（这个方向以前试过吗？被撤销过吗？）。

查的结果用来做三件事：

1. **已经被 ADR 定下的，不再当开放问题问。** 直接说明「ADR 00xx 已定为 X」，只有使用者
   想推翻时，才把「是否新增一条 ADR 修订它」作为一个问题提出来。重提已否决的方案而
   不引用那条 ADR，是这个流程最该避免的失误。
2. **仓库已有判据的，按判据给推荐。** 比如新目录该进 `subjects/` 还是 `practice/`、是学习
   应用还是图谱/参考类，根 `AGENTS.md` 有判据——拿判据推出推荐答案，而不是把判据原样
   抛给使用者。
3. **查不完的别卡住。** 一个事实还在查，只推迟依赖它的那几个问题，其余照常提问。

## 按决策树分轮提问

把方案拆成一棵决策树：每个决定下面挂着依赖它的后续决定。

- **每一轮只问「前沿」**：前提已经定下来、现在就能回答的问题。一个问题的答案如果取决于
  同一轮里另一个还没答的问题，它属于下一轮。
- 一轮一般 3–6 个问题。前沿比这多时，先问影响面最大、最难回退的。
- 每轮问完就停下来等回答。回答会改变树的形状：定下的决定推动前沿向外扩，
  也可能剪掉整条分支。据此重算前沿，再问下一轮。

每个问题用这个格式，编号跨轮连续，方便使用者用「Q7 选 B」这样回答：

```
❓ **Q<n> · <短标题>**
<问题本身。有几个选项就列出来（A/B/C），每个选项一句话说清代价。>

➡️ 推荐：<选项>。<依据：引用 ADR 编号、AGENTS.md 条款或代码事实，一两句。>
```

推荐要有立场。「看你需求」不是推荐；真的两可时，说清楚两边各押的是什么。

## 什么时候算问完

前沿为空——每条分支都走到了，没有剩下的默认假设——就输出一份**决策汇总**：

```
## 决策汇总

| # | 决定 | 依据 |
|---|---|---|
| Q1 | … | … |

**待办**：<按顺序列出接下来要做的改动>
**需要落 ADR 的**：<哪几条，放哪一级；没有就写「无」>
```

然后问使用者是否确认。**确认之前不改任何文件。**

## 落 ADR 的规矩

不是每个决定都值得一条 ADR。只有**影响架构边界、不可逆、或跨多个应用**的决定才写；
临时的、显而易见的、一两个版本后就会变的，不写。要写时先问使用者，并说明放哪一级。

**放哪一级**：只影响一个应用的，放该应用自己的 `docs/decisions/`；影响仓库结构或多个
应用的，放仓库级 `docs/decisions/`。两处各自编号，编号取该目录现有最大号加一，
只增不改，跳号正常。

**怎么写**：

- 照目标目录**最近一份 ADR** 的格式写（标题行、日期/状态/修订三行、背景/决策/后果），
  文件名是 `NNNN-英文短横线标题.md`。以现有 ADR 为准，不要沿用别处的模板。
- 修订或推翻已有 ADR：新 ADR 里写「修订：ADR xxxx（……）」，**旧 ADR 原文不改**，只在
  索引表的「状态」栏补一句「由 00yy 修订」。
- 同一目录的 `README.md` 索引表加一行，放进合适的分类。
- 正文里不写具体院所名，一律「某所」（ADR 0055）；要说明为什么重要，写技术要求本身。
- 内容上宁增勿删（ADR 0054）：记录新方向用新增，不删、不改嫁已有条目。

**不要建的东西**：`docs/adr/`、`CONTEXT.md`、单独的术语表。这个仓库没有这些，建了就是
第三套平行文档。需要界定的术语写进 ADR 正文或对应的 `AGENTS.md`。

写完跑 `python3 scripts/check.py --sources-only`（含院所名扫描），ADR 单独一个提交，
和实现代码分开。

## 语气

用中文，直接，不客套。问题短，推荐有依据。这是把方案问透的工具，不是走流程——
如果第一轮就发现方案其实很简单、没什么可问的，直接说「这个不需要追问，建议直接做 X」。
