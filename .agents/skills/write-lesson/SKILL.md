# 写一节课

这份清单把 [docs/TEACHING.md](../../../docs/TEACHING.md)（学习应用的共同规范）和
[docs/LEARNING-METHODS.md](../../../docs/LEARNING-METHODS.md)（方法原型与界面取舍）落成写作时的
动作顺序。规则的理由在那两份文档和对应 ADR 里，这里不重复。**字段名、文件格式、块类型
各应用自定**——本清单只说「要有什么」，「写成什么样」以本应用为准。

## 0. 先确认这是能写的时候

- **是学习应用吗？** 图谱/参考类（polaris、math-tools、competitions）和 `practice/` 不受
  教学规范约束，本清单不适用。
- **界面样式稳定了吗？** 教案和共用组件的外观绑在一起时（例如 machine 的 QML 教案），样式
  还在变就批量细写，后面要返工。样式没定时只做规划、基础设施、来源核对或使用者点名的
  单课；拿不准就先问。
- **改已有内容？先过宁增勿删（ADR 0054）**：
  - 使用者说「参考 X」「向 X 看齐」，只允许给**已有**条目补深度、验收口径和取舍依据；
    **不允许**据此重划结构、删条目、改条目定位或名字——要动结构，先问。
  - 新视角用**新增**表达（新加一章/一节），旧的可以降级、淡化，不删。
  - **一个 `id` 只装一个东西**：换定位就新起 `id`，不在旧 `id` 上替换内容。
  - 第一次实质改动前，先把原样提交一版作为基线。
  - 例外只有在本应用 ADR 里声明了重组豁免的应用（目前只有 `machine`，ADR 0080），且重组前要打
    `pre-<id>-reorg` tag。

## 1. 读本应用，不套别的应用

按顺序读，读完再动笔：

1. `subjects/<id>/AGENTS.md`：出处档位（`exam` / `open`）、**方法原型**（主原型定单元
   骨架与题型优先级，ADR 0113）、内容文件在哪、块类型有哪些。
2. `subjects/<id>/docs/decisions/` 里与内容格式、题型、实验相关的 ADR。
3. `content-contract.json`：出处字段叫什么、哪些条目算判分内容。
4. 同一应用里**写得最完整的一节**，看现成的块怎么用。

不要因为另一个应用有某种块或题型就搬过来（ADR 0062：约束不继承）。需要新的块类型时，
先确认现有块确实表达不了，再在本应用里加（ADR 0058：有限块类型承载全部讲解）。

## 2. 三层自上而下（ADR 0028）

- **大纲**（一章一份）只指方向：痛点与来历、心智模型、讲什么与边界、判断与代价、落点。
  不写细节。
- **教学过程**在大纲划定的方向内落细节。同一组东西不写两遍，细节下放到对应小节。
- **教学实验**用可运行、结果可观察的证据验证或推翻预期。
- 方向只能自上而下：**不得从现有代码或实验反推该教什么**。文档与代码不一致时，以学科的
  正确语义为准，再让代码跟上。

## 3. 知识点

- 两维评级：**难度**与**掌握目标**分开评（ADR 0029）；先修写进 `requires`（ADR 0030）。
- 类型三选一，教学动作跟着类型走（ADR 0031）：
  - 概念 → 正例反例并排；
  - 技能 → 示范加变式练习；
  - 策略 → 放进情境里做选择，并说明依据。
- **只给已经写出内容的章节评级**，其余字段留空，不提前判断。
- 知识点 ID 用本应用前缀；已进进度库的 ID 不改。
- 软考两应用定章节形态时，同时看三维评级（应用性/实践性/实验性，ADR 0107）。

## 4. 每节必须有可提取的东西（ADR 0096）

写讲解前先回答「这节的提取动作是什么」——题、实验空缺、预测框、追踪题、自查问题，
至少一个。答不出来就按半成品对待，不要交差。

- **预期先于答案**：揭示性内容（结论、解析、运行结果）之前先放一个提取动作，
  揭示要主动点开（LEARNING-METHODS P1）。讲解在给结论前先抛出可以预测的问题。
- 新考点起步至少 1 个完整样例配 2 个练习，然后逐步撤除提示（样例 → 缺步 → 独立）。
- 练习默认跨知识点混合，按章线性刷题要显式说明为什么。
- **实验与练习给骨架，不给白板**（ADR 0059）：接口、驱动和大部分步骤预先备好，学员只补
  明确标记出来的空缺；验收标准是**一行不改也能编译运行**或提交出合法结果。
- 不做「看懂了」自评控件；掌握度只由作答写入（ADR 0052）。

## 5. 出处（ADR 0043、0089）

| 档位 | 应用（以 AGENTS.md 为准） | 要求 |
|---|---|---|
| `exam` | driver、software、ascent、mathematics、cs408 等对应真实外部考试的 | 判分内容必须有出处，检查阻断 |
| `open` | cpp、machine、data-structures、algorithms、gtkmm 等技术学习类 | 默认写出处，未标注只报告 |

全档共同底线：

- **不凭印象伪造出处**。查不到就如实标 `authored`，或者不标——编一个书名页码比不标更糟。
- **你现场编的题不算真题**。AI 依据知识点即时生成、直接判熟练度的内容，任何档都不算数；
  你写的原创题标 `authored`。规则封闭的计算题，可以用进版本库的确定性生成器出参数变式。
- 引用外部材料时守版权：不大段照搬原文。

## 6. 呈现

- **能画的就画**（ADR 0056，强制）：看不见的机制（状态迁移、执行流程、内存布局、调度）
  配图；能由数据算出来的画成活的并配互动，不放会和数据漂移的截图。纯事实、分类对比用表。
  加图前先问「一句话能不能说得同样清楚」；把正文清单排成方框不算可视化。
- **标题用短语**，解释放正文。
- **言简意赅**（ADR 0040）：不套固定标题、不为凑格式写「小结」。篇幅跟掌握目标走——低难度、
  只要求「掌握」的点不该比要求「精通」的写得还长。
- 回顾职责要有落点（小结、随堂题、误区清单任选），形式不固定。

## 7. 写完自查

- [ ] 每节都有提取动作，并且出现在揭示内容之前。
- [ ] 知识点只给已写完的部分评了级，`requires` 指向真实存在的 ID。
- [ ] 判分内容的出处真实可查；`authored` 如实标注。
- [ ] 实验骨架一行不改也能跑通（真跑一遍，不是目测）。
- [ ] 篇幅与掌握目标没有倒挂；同一组内容没有写两遍。
- [ ] 改已有内容时没有删条目、没有改嫁 `id`；要删的已经问过使用者，提交信息写明删了什么。
- [ ] `python3 scripts/check.py <id>` 通过（含出处契约与内容校验）；能打开应用的，打开看一眼
      渲染效果。

提交按知识点或可验证阶段拆分，一个提交一个主题；只 `git add` 自己改的文件。
