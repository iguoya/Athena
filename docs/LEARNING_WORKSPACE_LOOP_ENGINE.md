# Athena 学习工作台：闭环引擎方案

- 状态：参考提案，尚未实施；与 `docs/LEARNING_WORKSPACE_PROPOSAL.md`、`docs/LEARNING_WORKSPACE_BENCH.md` 平行，供对照
- 目的：换一个出发点设计"学习工作台"——把它当成一台**闭环引擎**，而不是一种内容格式
- 约束：同 `LEARNING_WORKSPACE_PROPOSAL.md`——不替代 `AGENTS.md`、`docs/ARCHITECTURE.md`
  或已接受的 ADR；所有名称、字段、交互都是候选，需经原型验证并写入 ADR 才成为实施方向

## 1. 与 Codex 提案的关系

`LEARNING_WORKSPACE_PROPOSAL.md`（下称"提案 A"）已经把学习闭环、页面角色、证据类型、
分阶段路线梳理得很完整。本文（"方案 B"）**不推翻 A 的诊断和目标**，只在一个点上反过来：

| | 提案 A | 方案 B |
|---|---|---|
| 工作台的本质 | 一种**内容结构**：作者按"问题→思想→预测→行动→对照→反思→迁移"组织每个知识点 | 一台**闭环引擎**：作者几乎不写新内容，AI + 运行时 + 一张小表把"看代码+运行"变成完整闭环 |
| 每个知识点的作者成本 | `learning` 对象，4 个提示词字段（`question`/`prediction`/`observation`/`reflection`） | 0 个必填；1 个可选字段 `pitfall`（一句话），只给关键知识点写 |
| 预测的形式 | 自由文本 `Gtk::Entry`（提案 A §10.2） | 2–3 个单选项，AI 生成或作者写死 |
| 台面上的"工件" | （未明确） | **偏差日志**：不断累积的"我以为 X / 实际是 Y"记录 |
| 驱动力 | 作者持续填充学习结构 | 学习者每次运行前的一次预测点击 |

方案 B 的前提判断：**Athena 是单人自用**——作者即学习者。让学习者花时间给 70+ 个知识点
手写学习提示词，是把认知负担从"学"转嫁到"备课"。自用工具应该反过来：人只提供
`description` + 真实源码 + 可运行函数（这些本来就有），其余的教学结构由机器补足。

## 2. 核心资产：偏差日志

工作台 = 工具摊开 + **半成品摆在台面上**。方案 B 里，台面上的半成品是一张表：

```text
divergence
├── knowledge_id        知识点稳定 ID
├── occurred_at         预测发生时间
├── predicted_label     学习者选的预测项文字
├── actual_label        实际结果对应的项
├── matched             预测是否命中
└── review_state        未安排 / 待复习(下次时间) / 已巩固
```

这张表是学习者真正在"打磨"的工件——不是笔记、不是高亮，是**对自己理解盲区的诚实地图**。
提案 A §8 也提到保存"是否识别预测差异"，方案 B 把它提到中心位置：**预测与实际不一致的
地方，就是真正发生学习的地方**（hypercorrection / 生成效应），其余数据都不值得存。

## 3. 布局：三栏骨架不动，右侧换成"闭环导轨"

保留现有 `CodeChapterPage` 的三栏（知识点列表 | 真实源码 | 结果），把结果栏演化为一条
**闭环导轨**——一个约 5 段的竖向流程，是一次学习会话的脊柱：

```text
┌ C++ › 引用 › const 引用 ································· 认知状态 ⚠ ┐
├────────┬──────────────────────────┬──────────────────────────────┤
│知识点   │ 真实源码（聚焦当前函数）  │ 闭环导轨                     │
│列表    │                          │                              │
│引用基础 │ void const_reference(…)  │ ① 问题  临时对象绑定后何时析构?│
│●const  │ {                        │        └ AI 现场生成·可换一题 │
│传引用   │     …                    │ ② 预测  ○立即 ●存活期间 ○返回时│
│返回引用 │ }                        │ ③ 运行  [▶]  实际输出…        │
│        │                          │ ④ 对照  你选「立即」          │
│        │                          │        实际「存活期间」        │
│        │                          │        ⚠ 偏差已入回顾队列      │
│        │                          │ ⑤ 追问  [为什么我错了]         │
│        │                          │        [换个条件再来]          │
└────────┴──────────────────────────┴──────────────────────────────┘
```

窄窗口退化规则同提案 A §4.5：保留知识点标题和导轨阶段状态，源码与导轨改为顺序标签页。

## 4. 关键设计决策

### 4.1 预测是单选，不是文本框

这是对提案 A §10.2 那个 `Gtk::Entry` 的修正。自用工具里没人会往输入框里打字自言自语——
它大概率变成死 UI。而点一个单选项：

- 只花 2 秒，是一个真实的认知承诺（"committing to an answer"）；
- 能被机器直接和实际结果比对，无需自然语言处理；
- 逼出"我到底怎么想的"，而不是运行完看一眼就觉得"嗯我早知道"。

选项来源：优先 AI 生成（和①出题同一次请求）；关键知识点作者可在 `athena.json` 写死
2–3 项。

### 4.2 运行是"软门槛"

`[▶]` 一直可点。**先预测了**，④对照才亮、偏差才入库；跳过预测就跟现在完全一样，直接
出输出。工作台奖励走闭环，但不封锁抄近路——符合提案 A §3.2"不强制锁步骤"和 §12
"不要把预测做成妨碍快速实验的强制表单"。

### 4.3 对照零书写

④ 自动生成一条 `divergence` 记录，学习者不写一个字。预测≠实际 → 进回顾队列。

### 4.4 ⑤ 是现成的 AI，按需触发

Athena 已有 `AiService` / `AiMarkdownDialog`（AI 讲解、AI 自测）。方案 B 复用：

- **"为什么我错了"**：AI 讲解，但提示词专门针对**这次的具体错误信念**——
  "学习者以为 X，实际是 Y，解释这个差异"。纠正直接命中误解时记忆最强。
- **"换个条件再来"**（提案 A §9.1 反事实）：AI 改源码一行（`const T&` → `T&` → `T&&`），
  学习者重新预测、重新跑。深层理解在这一步形成。改动只发生在临时展示副本上，
  不落盘、不进 `FunctionRegistry`。

## 5. 偏差日志驱动的三样东西

都只是"一张 SQLite 表 + 一个列表视图"级别的成本：

### 5.1 回顾队列

学习进度旁边加一个 tab。间隔重现：预测错的知识点在 1d / 3d / 7d / 21d 后重新出现，
要求重新预测——这次对了间隔拉长，又错了归零。这是整套方案里性价比最高的机制，也是
提案 A 第三阶段"预测与反思的持久化"的最小可用形态。

### 5.2 诚实的熟练度

当前熟练度只来自一次性 AI 自测（ADR 0015）。方案 B 补充一路信号：**最近一次预测命中 +
通过一轮间隔复习** = 真实掌握证据。二者如何合并进 `floor(正确率×5)` 之外的口径，需要
单独的 ADR，不在本文决定。

### 5.3 认知地图（进度页升级）

进度页从"星级仪表盘"升级为四态地图：

```text
✅ 预测对了并复习通过     真会
⚠️ 预测错过（在回顾队列）  以为会，其实不会 —— 最该看的一格
👁 读过没验证             读过源码/文档，从没预测过
⚪️ 没碰过
```

"读过没验证"是一个当前不存在、但对自学非常重要的状态：它把"熟悉感"和"真实掌握"
分开——自学最大的失败模式就是把前者当后者。

## 6. 作者的"实务预算"：每个知识点 0 新内容

`description` + 真实源码 + 可运行函数，已经够 AI 生成①问题和②选项。

**可选**（只给真正重要的写，估计 70 个知识点里 20 个）：

```json
{
  "name": "const_reference",
  "title": "const 引用",
  "description": "理解 const 引用的只读语义及临时对象绑定规则。",
  "pitfall": "很多人以为临时对象在完整表达式结束就销毁了。"
}
```

`pitfall` 一句话（约 15 字），把"错误驱动学习"（提案 A §9.2）前置，也让 AI 出的题更
锋利。没有 `pitfall` 的知识点，AI 仅凭 `description` + 源码出题。

**不引入** `question` / `prediction` / `observation` / `reflection` 四件套——那是把
备课成本转嫁给学习者。

## 7. "工作台"这个名字怎么落到实处

两点让它是工作台而不是普通页面：

1. **会话连续性。** 打开 Athena 不是丢到第 1 章，而是打开工作台：
   "上次你在 const 引用预测错了，回顾队列有 3 项" + `[继续]`。台面记得你想到哪了。
2. **台面 = 偏差日志 + 回顾队列。** 学习者真正在积累的工件，不是笔记而是一张自己
   理解盲区的诚实地图。

## 8. AI 不是硬依赖

Athena 的 AI 需要 API key。没配置时闭环降级，但不消失：

- ① 问题：退回显示 `description`；
- ② 预测：无选项，只提示"运行前先想一下"（不比对、不记偏差），或使用作者写死的选项；
- ⑤ 追问：按钮隐藏或提示去"设置"配置。

有 key 时闭环完整，无 key 时至少不倒退回纯"源码 + 运行"。

## 9. 分期

- **Phase 0（一个周末）**：`CodeChapterPage` 上加闭环导轨；预测 = AI 生成的 2–3 单选；
  软门槛；`divergence` 表；④自动记录。**不做回顾队列。** 只在
  `cpp.Reference.const_reference` 和 `cpp.TypeSemantics.auto_deduction` 试用。
- **Phase 1（Phase 0 用得下去才做）**：回顾队列 tab + 间隔调度；进度页变认知地图。
- **Phase 2（一个月后还在用才做）**：反事实"换个条件"；会话连续性 / "继续"落地页。
- **永不，除非被真实使用证明需要**：知识图谱、`LearningSession` 7 阶段状态机、
  Markdown 自定义指令、多种 `EvidenceKind` 呈现器、执行模型改造。
  （这些是提案 A 第二、三阶段的内容；方案 B 认为对单人自用工具而言收益不确定、
  维护成本明确，应无限期观望。）

## 10. Go / No-Go 判据

整套方案赌**一个行为**：学习者会不会在点运行前先点一下预测。

- 会 → 闭环复利，`divergence` 表和回顾队列变成 app 里最有价值的屏幕。
- 不会（反射性直接点运行）→ 导轨是死重量，应回退到提案 A §10 更轻的"引导标签"形态，
  甚至只保留 `pitfall` 一句话。

**Phase 0 两周后只看一件事：`divergence` 表在涨吗。** 这就是唯一的 go / no-go 信号。

## 11. 待进一步验证的问题

在写 ADR 之前，至少通过 Phase 0 原型回答：

1. 运行前点一次单选，是真的促成思考，还是很快变成随手乱点？
2. AI 生成的预测选项质量够稳定吗？错误选项是"合理干扰"还是"一眼假"？
3. "为什么我错了"针对具体错误信念的解释，比通用 AI 讲解更有用吗？
4. 认知地图的"读过没验证"状态，会推动回头验证，还是只是多一个焦虑格子？
5. 间隔重现的节奏（1/3/7/21 天）适合"快速渐进"的学习目标，还是太慢？
6. 无 AI key 的降级形态是否仍值得用，还是不如干脆不显示导轨？
7. 闭环导轨挤占结果区宽度，在 macOS 和 Ubuntu 的常见窗口尺寸下是否可接受？

如果 Phase 0 验证通过，与提案 A 一起收敛出 ADR 0017，明确最终采用的配置字段、
数据表结构、模块边界和迁移策略，再进入正式实现。
