# ADR 0151：新增 chinese-chess——用 gtkmm 章节学做一盘中国象棋

- 日期：2026-10-12
- 状态：已接受（使用者 2026-10-12：「先采用gtkmm技术体系吧」；教程用 Tauri 分章，每章一个独立子程序，放在 exercise 目录，先做出能走子的界面）
- 关系：课程壳遵循 ADR 0138（Tauri 2 + React）；gtkmm 作为被教授的原生界面，按 ADR 0133 的异构准入；归类按 [docs/REPOSITORY.md](../REPOSITORY.md) 的三类判据

## 背景

1. 使用者要以做一盘中国象棋作为掌握程序设计的途径。教程本身用 Tauri，棋盘要求用 gtkmm，并参照常见桌面象棋：红方在下，棋盘居左，右侧有对局双方、棋谱、新局和悔棋。第一版棋子能按规则移动即可。
2. 讲解要分成章节，每章一个循序渐进、能单独编译的子程序，源码按章节放在 `exercise/`。可以先做成型的一盘，再倒过来讲前面几步。
3. 三类判据：要教会人窗口、布局、自绘和走子是怎么写出来的，并用可运行的程序和预测作答作为证据，所以是学习应用，不放进 `practice/`。

## 决策

1. 新增 `programming/chinese-chess`。id `chinese-chess`（完整英文词，不用拼音），界面名「中国象棋」，进程 `athena-chinese-chess`，知识点前缀 `chess.`，端口 **1513**。`group` 为「程序设计」，不设 `parent`。
2. 教程壳是 Tauri 2 + React。棋盘是 gtkmm 4 / C++20 / Meson，五章各自一个工程：空窗口、布局、棋盘、开局棋子、合法走子。第 5 章是当前能下的版本。
3. 出处档位 **open**。学习方法主原型是真做校验，辅预测–运行。
4. 第一版没有引擎，不判长将、长捉。困毙算走方负。
5. 默认的 `scripts/check.py` 不编译 gtkmm，避免没有这套工具链的 CI 失败。本机用 `--native` 编译五章。

## 后果

- 根 `Cargo.toml` 增加本应用的 `src-tauri` 成员。pnpm 工作区已经包含 `programming/*`。
- 发版清单不加入本应用，等棋盘和教程都稳定后再说。
- 五章源码有意重复。合并成一个库会让「这一章当时只有这些代码」讲不清楚。
