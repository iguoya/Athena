# ADR 0071：驾考引入用户维度——同一份题库，多个学习者各一份历史

- 日期：2026-10-02
- 状态：已接受；扩展 ADR 0067「个人数据」的定义（从「仓库主人一人」到「每个学习者」），
  不修订 0067～0070 的任何机制
- 影响：`subjects/driver`（本地库、用户切换、同步）；`practice/nas_admin`（API 表结构、
  迁移脚本、只读仪表盘的适配待办）
- 延续：ADR 0067（个人数据与项目数据区隔）、0068（三层存储、令牌）、0070（本地优先、
  统一走 API）
- 关联：`practice/nas_admin/docs/driver-api.md`

## 背景

应用落地以来隐含「只有一个人在用」：本地库、同步、中心 PG、API 全都没有用户维度。
家里第二个人也要考驾照时，只能共享同一份历史——解锁线（科目一稳 95 才开科目二）、
成就、错题本、练车记录互相污染，两个人都没法用。

题库与课程内容本来就是共享的（`content/` 的 JSON，ADR 0068 决策 2），需要隔离的只有
个人数据。所以解法不是多装一份应用，而是给个人数据加一个**用户**维度。

## 决策

1. **用户是轻量本地身份，无口令。** 用户就是一个名字：本地注册表（用户数据目录
   `users.json`）记录这台机器上有哪些名字，切换就是点一下名字。不加密码、不加找回——
   信任模型与设备令牌一致（内网家人）；口令丢了记录就进不去，得不偿失。
2. **名字即标识，不做改名。** 名字本身是稳定 id（本地文件名、中心 `user` 列存的都是它）。
   重名在注册时拒绝。要换名字就是新建一个用户从头开始——家用场景里改名需求趋近于零，
   换名迁移不值得做。
3. **本地按用户分库文件：`local-<用户>.db`。** 游标、队列、成就、草稿全在各自文件里，
   天然互不可见（0070 的架构红利：隔离不需要任何同步层改动）。照片文件共用
   `points/` 目录（文件名带时间戳不冲突），登记清单按用户分（`photos-<用户>.json`）。
4. **中心表全部加 `user` 列，值为用户名。** `achievements` 与 `exam_drafts` 的主键改为
   `(user, key)`。已存量的全部记录归入首用户 **tiger**（使用者定）。新用户无需在任何
   地方预注册：它的行第一次出现时自然存在（distinct user 即用户全集）。
5. **API 以请求头携带用户：`X-Athena-User`，必填。** 令牌仍是设备身份（ADR 0068 决策 3
   不变），用户是会话状态不是凭据——同一台设备上切换用户不改令牌。服务端按 user
   过滤一切读写：拉取、上传、去重键、成就、草稿、已读、统计。缺头或空值是 400。
6. **表结构变更由 `nas_admin/scripts/driver_migrate_users.py` 一次性完成**（属主连接：
   空库直接按新结构建表——这也是 0070「表结构管理移交服务端」后全新部署的初始化入口；
   已有表则各表加列带默认值、两张小表改复合主键），这是 0070 决策 6 的第一次实操。
   **客户端本地表不加 `user` 列**：本地已按用户分库文件，列在本地没有任何读取方，
   同名同列的原则对中心侧成立，本地少这一列、由 `progress.dart` 的注释说明差异。
7. **切换体验：单用户不打扰，多用户启动时选。** 只有一个用户时直接进应用；两个以上
   时启动先出选择页（记住上次用的）。侧栏常驻当前用户，点击可换人或新增使用者——
   换人即换一份空白历史，互不干扰。
8. **只读仪表盘（ADR 0069）的适配是待办，不在本次范围。** 它按全表聚合，多用户后会
   混排两人数据；接入用户筛选由仪表盘自己的迭代完成（其文件正被并行开发，本次不碰）。

## 后果

- 客户端 `open()` 带用户，`SyncEngine` 带用户；首页、解锁线、成就全部自动按当前用户
  走——它们本来就读个人数据表，不需要逐处传参。
- 中心 `user` 列带 `DEFAULT 'tiger'`（本地/中心一致）：服务端测试的 fixture 不带该列
  也能建数据；真实路径永远显式带值，默认值只是宽松缺省，不是第二套语义。
- 两台机器同名用户是同一个人（并集合并）；故意起同名就会共享历史——这是特性不是漏洞
  （家人想在两台机器续同一份历史，起同一个名字即可）。
- 令牌能读写所有用户的数据（设备级信任）：拿到令牌的人可以冒用任何名字。撤销令牌
  仍然是一台设备一把锁（ADR 0068 的模型没变），「用户间隔离」防的是误看与统计污染，
  不是对抗性隔离。
