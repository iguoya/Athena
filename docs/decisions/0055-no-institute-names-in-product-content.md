# ADR 0055：软件内容不出现具体院所名，一律用「某所」

- 日期：2026-09-16
- 状态：已接受（**强制**，由 `scripts/check.py` 拦截）
- 相关：ADR 0043（内容必须有出处）、ADR 0054（宁增勿删）、atlas ADR 0005 / 0006

## 背景

`apps/atlas` 的技术取舍以某研究所公开的控制系统总体链作为重要参考，这个参考
关系本身是内容的一部分，要保留。但当时的做法是把那个所的具体名称直接写进
界面文案、内容数据、应用元数据、来源目录标题和一批文档——界面上能看见，
内容文件里能搜到。

使用者的要求很明确：**所有可见的页面内容、所有软件内容，都不许出现那个所名。**

## 决策

1. **统一代称「某所」。** 软件内容一律不写具体所名，也不写带编号的所名简称。
   范围是仓库里除历史归档（`archive/`）以外的全部文本：界面文案、内容数据、
   `app.json` 这类应用元数据、来源目录里的条目标题、README、AGENTS.md，以及
   ADR 自身的叙述。

2. **脱敏只改称呼，不改取舍依据。** 参考关系、验收口径、职业目标层那套研制
   口径的认知照旧保留（ADR 0054）；来源目录保留原始 URL，出处依然可追溯。
   需要说明对照对象时，**写技术要求本身**——「控制周期内最坏延迟与抖动必须
   可测」比「对照某所」信息量更大，也更不容易过时。

3. **强制由脚本拦截，不靠自觉。** `scripts/check.py` 扫描全仓，命中即失败；
   本地和 CI 走同一个入口（ADR 0007），所以绕不过去。只写进文档的约束会在
   下一次大改里被忘掉——前一轮内容事故就是这么来的。

4. **禁用词检查的代码把禁用词写成 Unicode 转义。** 检查器必须存有这个词才能
   匹配，写成字面量就等于给全仓扫描留一个永久误报点，反过来逼着人去关掉检查。
   `scripts/check.py` 和 `apps/atlas/tests/atlas_catalog_test.cpp` 都按这条写。

5. **院级单位名不在本条强制范围内。** 「二院、三院、四院」这类院级名称出现在
   取舍依据的叙述里仍然允许，因为它们指的是公开的研制体系分工，不是一个可
   对号入座的具体单位。`apps/atlas` 的内容文件另有更严的自检：连院名也不写，
   由该应用的测试盯着。

## 后果

- 历史 ADR 里的叙述一并改成「某所」。这不是篡改记录——「某所」就是同一个
  对象的统一代称，决策理由和当时的取舍一字未动。
- 新增内容如果需要表达「这一条为什么重要」，判据写成技术要求，而不是单位名。
  这也是技术体系图里重要性分级的写法（见 atlas 的技术体系图相关 ADR）。
- 检查是全仓扫描，所以新应用、新文档天然被覆盖，不需要逐个登记。
