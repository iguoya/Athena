# ADR 0062：每个应用只守自己的约束，不从别的应用继承

- 日期：2026-09-26
- 状态：已接受
- 延续：ADR 0032、0045（一个目录一个独立应用，彼此平级）
- 关联：ADR 0061（AGENTS.md 分仓库级与应用级）

## 背景

应用之间的构建早已隔离（不互相 include、不读对方配置），但**约束**还在互相传：
`subjects/mathematics` 的「界面不出现考试字样」写的是「沿用 `subjects/english` 的做法」，
english 那边早已改口，mathematics 这边却还守着；多个应用的规则里写着「对齐某应用
ADR xxxx」「跟某应用同一个道理」。

继承来的约束有三个问题：

- **来源变了，继承方不知道。** 原应用改了或推翻了，继承方的规则悄悄过时。
- **读规则要跨目录。** 要弄懂一个应用的规则，得先去读另一个应用的 ADR。
- **不适合也被带过来。** 别的应用基于自己的处境做的取舍，搬过来未必成立。

## 决策

1. **每个应用的约束只来自两处**：仓库级规则（根 `AGENTS.md` 与 `docs/decisions/`，只放
   所有应用共同遵守的大原则），和该应用自己的 `AGENTS.md` 与 ADR。
2. **不继承别的应用的约束。** 不写「沿用 X 应用的做法」「对齐 X 应用 ADR」作为约束来源。
   某个做法在本应用确实也成立，就在本应用自己写下来、自己说明理由，之后各改各的。
3. **可以参考，不能继承。** 借鉴别的应用的经验是好事，但写成规则时要在本应用里独立成立；
   背景里提一句「参考了 X」可以，约束的效力不依赖 X。
4. **一条约束多个应用都需要、而且应该一起变**，才提升为仓库级原则，写进根 `AGENTS.md`。

## 后果

- 各应用规则里现存的「对齐 / 沿用 / 同一个道理」式引用，逐个改为本应用自己的表述，
  或者在本应用不成立时删掉。
- 审视某个应用的规则时，只看它自己和仓库级，不去对照别的应用。
