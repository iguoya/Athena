# ADR 0087：强化练习一轮默认 50 题，页面把备选库的总题数摆在最前（修订 ADR 0076 决策 7）

- 日期：2026-10-03
- 状态：已接受；修订 [ADR 0076](0076-attempt-attribution-and-reinforcement-practice.md) 决策 7 里的「默认 20 题」。
  0076、0085、0086 原文不改
- 影响：`subjects/driver` 的 `lib/reinforce.dart`、`lib/reinforce_page.dart`
- 关系：延续 [ADR 0085](0085-reinforce-draws-from-all-wrong.md)、[ADR 0086](0086-reinforce-coverage-then-fade.md)

## 背景

使用者看过强化练习页后提了两点：

1. 总共有多少道题要练，要明确显示在界面上——原来只埋在一整段说明文字里；
2. 一轮 20 题太少，至少 50 题左右。

## 决策

1. **一轮默认 50 题**（`reinforceRoundSize`，一页十题即五页）。变式、覆盖保证按比例随之放大
   （变式 1/4，约 13 题；覆盖名额是错题名额的一半），比例本身不变。`count` 仍是参数，可调。
2. **页面最上方用大号数字块摆出四个数**：还要练的错题（备选库，最醒目）、其中还没在强化练习里测过的、
   已测过且没出错而移出的、每轮抽取多少题。下面的说明文字保留，不删。
3. 备选库不足一轮时，仍按 0085 的顺序用薄弱章节、到期复习、变式、公开错误率补足，总数不变。

## 后果

- 一轮时间约变成原来的 2.5 倍；练习不计时，中途退出的已答题照常记录，所以不设「做满才算」。
- 备选库几十题时，一轮里补足的题（薄弱章节等）占比会变大；这是备选库小的自然结果，页面的数字块会如实显示。
- 测试里依赖「20 题」的纯函数用例显式传 `count: 20`，页面用例按 50 题断言。
