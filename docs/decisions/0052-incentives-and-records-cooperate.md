# ADR 0052：激励与统计是同一套机制，必须互相配合

- 日期：2026-09-15
- 状态：已接受
- 范围：**整个仓库**所有学习应用（`apps/*`）
- 依赖：ADR 0037（各应用自管进度库）、ADR 0043（计入掌握度的内容必须有出处）
- 裁定：`apps/mathematics` ADR 0011 第 4 节「连击天数 / 每日指标」待定项——采用，但只作为
  **由统计派生的可见状态**，不用恐吓文案、不阻断学习、不做成可购买的断签保险
- 对齐：`apps/english` ADR 0009 第 4 条（激励写进课表，不另做社交打卡）

## 背景

使用者要求两件事，而且点明它们不是两套平行功能：

1. 采用互联网软件里已经跑熟的使用激励，改进 Athena 各应用的使用体验；
2. **激励机制和统计机制关系很大，必须互相配合。**

仓库里已经有碎片：英语首页能看见连续天数和徽章；数学 ADR 0011 要求能力证据可见，
却把连续天数放成待定；驾考把作答写进 SQLite，成就表建了，界面上几乎看不见。
各应用各做一块，激励没有数，数没有出口，两边都像装饰。

互联网产品把这件事做成了回路，而不是两个模块。值得学的是回路，不是吉祥物。

### 业界成熟做法里，真正有效的是「数 → 看见 → 再做」

| 产品 | 记下什么 | 激励怎么用这些数 | Athena 可取之处 |
|---|---|---|---|
| **Duolingo** | 每日是否完成一课、XP、连对 | 连续天数、每日目标条、课内进度条 | 目标要一眼能懂；越接近完成越愿意做完（目标梯度）。**不要**学它的内疚通知、联赛、宝石买断签 |
| **Khan Academy** | 每道练习的对错与技能等级 | 熟练度条、会衰退、要复习才保住 | 掌握度来自作答，不是来自打开页面；统计要能区分「走过」和「会了」 |
| **Anki / SuperMemo** | 每次回忆的时间与自我评定 | 到期队列本身就是下一次打开的理由 | 复习排期是统计的产物；激励是「今天这叠该清」 |
| **GitHub** | 每天是否有提交 | 贡献热力图、连续贡献 | 日历把累计投入显形；格子是事实，不是奖章 |
| **Apple 健身圆环** | 活动 / 锻炼 / 站立三类计数 | 闭环是当天的完成感 | 一天可以有两三个可关闭的环， complementary，不是一个高压指标 |
| **LeetCode** | 题解对错、耗时、竞赛分 | 个人最佳、日历、题量 | 跟自己比；没有跨用户排行也能驱动再做一题 |
| **Stack Overflow** | 被采纳的回答、标签下的贡献 | 徽章对应真实行为阈值 | 里程碑必须能指回一次具体记录，禁止「打开 App 送徽章」 |

同一批产品里也有 Athena **明确不学**的：变动比率开宝箱、无限信息流、打断式推送、
用生命值锁内容、用虚拟货币买进度、把连续天数做成焦虑资产再卖保险。那些优化的是
DAU，不是掌握。Duolingo 自己的留存数据和独立观察之间的裂缝已经说明：只优化「明天
还会打开」，可以和学习目标脱节。

### 本仓库的约束

- 使用者是成年自学者（数学 ADR 0011：要能力**证据**，不要廉价符号）。
- 各应用进度库独立（ADR 0037），**不共用一张激励表、不做跨应用排行**。
- 计入掌握度的条目必须有出处（ADR 0043）；激励不得靠自造题刷数。
- 掌握度只由作答写入，禁止手动点亮。

所以不能把「激励系统」做成独立于学习记录的第二套分数。

## 决策

### 1. 激励与统计是一条回路，不是两个功能

所有学习应用遵守同一条因果：

```
作答 / 实验 / 考核被记录
        ↓
由记录派生统计（今日量、连续日、连对、用时、章节正确率、个人最佳……）
        ↓
把统计当成激励的唯一原料（目标条、连续日、里程碑、战绩、当场肯定）
        ↓
激励只奖励「会留下记录的行为」，从而产生下一条记录
```

拆开就算做错：

| 做错 | 为什么废 |
|---|---|
| 只有激励、统计是摆设 | 徽章不能回溯到一次作答，不可信，刷起来也无成本 |
| 只有统计、界面不拿它说话 | 数存在库里，使用者感觉没进步，激励无从发生 |
| 两套各算各的分 | 点一次题加「积分」、掌握度另走一条，使用者不知道该信哪个 |
| 激励奖励打开窗口、停留时长 | 记录与学习无关，统计会被污染，回路开始空转 |

判据沿用数学 ADR 0011 第 5b 节，并收紧成跨应用规则：

> **拿掉这块展示，使用者是否就看不出自己学到哪了？**
> 是 → 它是统计的显形，应当做，这就是激励。
> 否，只是为了让人多点一下 → 不要。

### 2. 先记全，再派生；禁止无记录的激励

每条会改变「会不会 / 做了多少 / 做多快」的学习动作，必须在该应用自己的进度库里
留下足够派生统计的字段。最低限度：

| 记录 | 用途 |
|---|---|
| 条目 id、章节 / 知识点 id、科目或轨道 | 按主题汇总、错题本、覆盖率 |
| 对错（若该动作判分） | 掌握度、正确率、连对 |
| 时间戳 | 今日量、连续日、热力图 |
| 用时（能取到就记） | 速度、迟疑、一眼过 |
| 考核 / 模拟考的分数与是否及格 | 个人最佳、及格里程碑 |

各应用表结构自定，**不抽共享 schema**。共有的是上面这组**概念**，不是列名。

由记录**派生**、不要另存一套平行真相：

- 今日作答数、今日正确数、距每日目标还差多少；
- 连续有记录的日历日（连续日）；
- 当前连对、历史最高连对；
- 去重后碰过的条目数、一眼掌握 / 仍迟疑 / 仍错；
- 章节正确率、近两周每日条形；
- 模拟考或阶段考核的个人最佳。

徽章、段位、闭环节日目标，全部是这些派生量上的阈值，**解锁键必须能指回记录**
（例如 `volume.100` 对应累计作答 ≥ 100）。同一键只响一次。打开应用、浏览大纲、
把窗口挂在前台，不写记录，也就不产生激励。

### 3. 从成熟产品里采用的激励，全部长在统计上

规范统一，界面和字段各应用自定。默认都要有，学科没有「作答」的（例如只跑实验）
就用该学科等价的可记录动作替换，不能不记。

| 激励 | 统计原料 | 成熟来源 | Athena 用法 |
|---|---|---|---|
| **每日目标条** | 今日已记录的学习动作次数 | Duolingo 每日目标、Apple 圆环 | 有默认值（各应用按学科定，例如驾考 30 题、英语复习队列清空）。完成即闭环。未完成不扣掌握度、不锁功能、不发「你要断签了」 |
| **连续日** | 连续日历日是否有 ≥1 条记录 | Duolingo streak（简化为「一天一次」）、GitHub 绿格 | 首页可见。断了就从 1 计，可以明天再接。不提供买断签、不倒计时恐吓 |
| **目标梯度** | 本局 / 本日已完成 ÷ 目标 | Duolingo 课内进度条 | 做题台和首页都能看见「还差几道结束今天」或「本轮 12/40」 |
| **当场连对** | 本次会话连续正确 | 游戏 combo，但数来自当次判定 | 连对是事实；达到 5 / 10 / 20 可以响一次里程碑。连错归零是统计，不是惩罚关 |
| **里程碑** | 累计题量、一眼掌握数、首次及格、章节正确率达标 | Stack Overflow 徽章、Steam 成就里「真的做过」的那类 | 文案写发生了什么（「累计作答 100 道」），不写「你真棒」。必须能打开对应统计 |
| **战绩 / 热力图** | 近两周每日量、个人最佳、均速、覆盖 | GitHub 日历、LeetCode 个人页、Strava 自己的曲线 | 每个应用有一处「战绩」，只跟自己的历史比 |
| **具体肯定** | 本题用时、是否相对上次更快 / 从错到对 | 数学 ADR 0011 的能力证据 | 优先说可核对的变化，而不是通用表扬 |
| **掌握与待练分流** | 最近一次作答的对错、用时、是否一眼 | Khan 技能条、驾考「一眼过才从练习拿掉」 | 统计决定下一次出什么题；这本身就是最强激励——少做已经会的，多做还不会的 |

英语已有的连续天数和本地徽章，按本表视为同一回路的实例，不必另起炉灶。
数学里「走过」和「答对」继续分色：走过不是掌握，统计层就要分字段，激励层就不能
混成同一颗绿点。

### 4. 统计怎么展示，由它要驱动的行为决定

配合是双向的：激励要用统计，统计的口径也要为激励服务。

- **今日目标**用「今日记录条数」，不用「窗口打开分钟」。否则激励会变成挂机。
- **连续日**用「当天至少一条有效记录」，门槛要低（Duolingo 后来把 streak 收成
  一天一课，就是因为跟 XP 绑在一起会让人看不懂）。高目标留给每日目标条。
- **掌握**用最近一次（或该学科规定的考核），不用历史累计正确率冒充「会了」——
  累计率会把早期错误永远摊进去，激励会变味。
- **速度 / 迟疑**（能记用时的应用）用来决定「还要不要再出」，不要用来公开羞辱。
- **通知**是统计事件的收件箱：里程碑解锁、模拟考结果、错题清空。点开是看记录，
  不是系统弹窗抢焦点。默认不发操作系统推送。

三个环可以同时存在（对齐 Apple 圆环的 complementarity），例如：今日题量、连续日、
错题待清。它们读的是同一份记录的不同切片，不要打成三个互不相认的积分账户。

### 5. 明确不做

- 跨应用、跨用户的排行榜、联赛、点赞。
- 变动比率奖励、开箱、积分商城、用虚拟货币买掌握度或断签保险。
- 打断式通知、内疚文案、把连续日说成「资产，失去就没了」。
- 为刷激励而自造题目或允许手动标记熟练。
- 把停留时长、启动次数当学习量。
- 仓库级共用激励数据库（违反 ADR 0037）。启动器可以显示「某应用今天是否有记录」，
  但数据仍由各应用自己写、自己读。

## 后果

- 各应用 `AGENTS.md` 把「激励」和「统计」写成同一条实现义务：做激励必能指回记录，
  做记录必有一处给使用者看、并据此改变下一步出题或复习。
- 进度库迁移以「能否派生第 2 节那组量」为准，缺字段就补字段，不要在界面层硬编数字。
- 数学 ADR 0011 第 4 节待定项按本 ADR 采用：连续日和每日目标**要做**，但它们是统计
  显形，不是 PUA。第 6 节禁止的注意力劫持仍然禁止。
- 英语 ADR 0009 第 4 条保持有效，本 ADR 把它提升为全仓库回路，而不是英语特例。
- 驾考等尚未把成就/通知接到界面上的应用，属于回路断在「统计没有出口」，按本 ADR
  补上，而不是再设计一套独立积分。
- 检查脚本不强制共用表结构；是否达标看应用自己的进度测试和界面是否暴露派生量。

本 ADR 不取代掌握度规则：激励可以庆祝题量，**不得**因为题量把不会的标成会。
统计负责诚实，激励负责让人看见诚实的结果并愿意留下下一条记录。
