# ADR 0050：跨平台稳定之前，CI 推送即跑

- 日期：2026-09-15
- 状态：已接受（**阶段性**，退出条件见下）
- 影响：`.github/workflows/ci.yml` 的触发条件
- 关系：明确 [ADR 0047](0047-portable-by-default.md)「支持哪个平台就在 CI 里跑
  哪个」的**跑法与时限**；成本判据同
  [ADR 0049](0049-portability-is-a-cost-benefit-call.md)

## 背景

2026-09-15 把流水线从 2 个 job 扩到 15 个组合（三个 Tauri 应用 × 三平台、Qt、
GTK4、启动器、内容出处）。第一次真跑就暴露了两件事：

- **它确实在起作用**：dsa 在 Windows 上构建成功，证明当天做的 `npm` → `npm.cmd`
  解析修复是对的；同时抓出两个真问题——`apps/mathematics` 的 `test-speech.mjs`
  spawn `npx` 在 Windows 上 ENOENT（和 `npm` 是同一个坑，当时只改了 Rust 与 Python
  两侧，漏了 Node 侧），以及 `c-windows` 给 aqt 传了 `-m qtdeclarative`（Qt 6 里
  Quick 属于基础包，不是可选 module）。这两个都不是本地 macOS 能发现的。
- **它也确实不便宜**：三个 Tauri 应用各自要在三个平台上编一遍 Rust 壳，无缓存时
  几十分钟起步。

于是问题变成：这个成本值不值得每次提交都付。

## 决策

**1. 现阶段推送即跑，纯文档改动除外。**

```yaml
on:
  push:
    branches: [main]
    tags: ["v*.*.*"]
    paths-ignore: ["**/*.md", "docs/**", ".vscode/**", "LICENSE"]
  pull_request:
  workflow_dispatch:
```

理由不只是抓 bug，更是**对开发过程本身的约束**：知道每次提交都会被十几个平台组合
验一遍，写的时候就不会把「先推上去回头再说」当默认选项。上面那两个 Windows 问题
就是例证——它们在本地开发机上不可能出现。

**2. 成本从砍浪费入手，不从砍触发入手。** 真正的纯浪费是改一行 Markdown 也拉起
全部 runner，`paths-ignore` 排掉即可；代码与内容改动换来的是上面那份约束，不算
浪费。Rust 依赖首次编译很贵，但那是一次性的，cargo 缓存之后不再昂贵——不要拿首次
构建的耗时当常态成本来论证。

**3. 这是阶段性安排，退出条件是「跨平台稳定」。**

当三平台的构建与依赖不再频繁出问题——Windows 上的路径、可执行文件扩展名、包管理器
差异这类坑基本清完，CI 连续多次全绿且没有新增平台特有修复——就该把触发频率降下来，
改成发布、PR 与手动驱动。**判据是稳定性，不是成本**：现在每次都跑是因为跨平台正在
收敛，不是因为 CI 便宜。

## 后果

- 日常提交会跑完整矩阵，纯文档提交不跑。
- 本地统一入口 `python3 scripts/check.py`（ADR 0007）仍然是提交前该走的一步，
  CI 不替代它，也不该被当成「推上去看看红不红」的远程编译器。
- 到达退出条件时要回来改这条 ADR，而不是默默把触发条件调走——什么时候降频、
  依据是什么，应该留下记录。
- 需要更细的中间档时，按路径过滤只跑受影响的 job，比全量跑或全不跑都更合适。
