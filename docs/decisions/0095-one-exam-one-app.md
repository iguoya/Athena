# ADR 0095：一个考试一个应用——考试方向不再作为课程并入已有考试应用

- 日期：2026-10-10
- 状态：已接受（tiger 2026-10-10 决定）
- 关系：修订 [ADR 0092](0092-launcher-tree-attach-and-softcert-rename.md) 决策 3 的
  「新方向出现时按那时再议独立或挂靠」，彻底关闭 [ADR 0090](0090-softcert-splits-esd.md)
  决策 1 的课程扩位预留；应用隔离仍守 [ADR 0032](0032-independent-apps-launched-as-processes.md)、
  [ADR 0062](0062-apps-own-their-constraints.md)

## 背景

0090 拆分时预留了「软考其他方向按一门课程一个目录加进 softcert」；0092 把它
收窄为「新方向出现时再议独立或挂靠」。tiger 现在把这个悬而未决的口子直接定死：
**今后一律一个考试一个应用。**

理由在拆分动机里本来就有：softcert 与 esd 刻意做成两种成体系的备考体验样本
（导航骨架、课程呈现、首页取向、学习与考核流四个层面都不同，见 esd 的
`AGENTS.md`「界面组织」），使用者要在这个粒度上持续对比两种设计。课程并入
会让应用重新变重、边界重新模糊，对比样本也就失真了。

## 决策

1. **「以考试为学科」的应用与考试一一绑定：一个考试（方向）= 一个应用。**
   新考试方向（软考中级的网络工程师、系统集成项目管理工程师等，以及未来任何
   考试考证类学科）一律**独立成新应用**（`subjects/<新id>`，自带进度库与出处
   契约），不再作为课程目录加进 softcert、esd 或任何已有考试应用。
2. **softcert 的多课程结构是历史遗产，保留不动。** `courses.json` 注册表与多
   课程前端数据流是拆分前的产物，不为这条约定做结构性拆除；它当前只注册
   `swd`，今后长期只注册 `swd`。esd 是单课程根结构——两者结构不同本身就是
   两种体验样本的一部分，不强求对齐。
3. **考试之间的公共内容不共享、不互引**（ADR 0032、0062）：软考各方向共用的
   公共课（计算机系统基础、操作系统等）在各应用里按自己的考纲与组织方式各自
   维护，允许内容重复——边界清晰优先于去重；跨应用引用（链接提示文字除外）
   都不做。
4. **启动器归类不新增机制**：考试类应用按领域用同一 `group`（如「软考」），
   子能力挂靠走 `parent`（ADR 0092/0093），现状已够。

## 后果

- softcert 应用级 [ADR 0001](../../subjects/softcert/docs/decisions/0001-reorg-exemption-esd-split.md)
  「课程维度保留，将来可加软考其他方向」一句由本条取代（其状态栏已补注记）；
  `subjects/softcert/AGENTS.md` 对应表述同步改。
- 将来网络工程师等方向落地时：新建应用、新 id、新进度库；界面体系复用哪套
  样本（或再造第三种）由那时的对比结论决定，无默认继承。
- 仓库结构表、名字表在对应应用诞生时照常登记，无需预先占位。
