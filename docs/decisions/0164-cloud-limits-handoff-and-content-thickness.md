# ADR 0164：云会话做不到的事写进交接清单；新应用内容前期要薄

- 日期：2026-10-14
- 状态：已接受（使用者要求：把云会话做不到、需要本地客户端或人工协助的事情都记录下来，写进 ADR 之类的文档，
  便于之后人工或本地代理接手；数学工具若有多本优秀教材就一本一个应用；控制内容厚度，前期简明扼要、有成果有成就感，
  后期再加知识量与复杂度；有成果就合并进主分支）
- 关系：补充 [ADR 0162](0162-linear-algebra-books-in-guide.md)、[ADR 0163](0163-math-tool-tutorials-in-guide.md)

## 背景

云会话（Claude Code on the web）的出口代理只放行 GitHub 与少数包源：视频站、GeoGebra 官网与 wiki、大学站点上的 PDF、
Octave 文档站都连不上；没有显示设备，Octave 的图形后端创建坐标轴会失败；不能打开 Tauri 窗口、不能在 macOS 或 Windows 上构建。
这些限制在做线代教材与数学工具教程（ADR 0162、0163）时反复碰到。散落在对话里的「这个我做不了」很快就丢。

## 决策

1. **统一记在 [docs/HANDOFF.md](../HANDOFF.md)**：凡是云会话做不到、做得不彻底（用了替代办法）、或需要人工或本地代理协助的事，
   都在那里记一条。每条写：现状；为什么云里做不了；接手的人怎么做（尽量是可复制的命令与路径）；做完怎么验收。
   做完的条目不删，打上完成标记并写明提交。ADR 只记规则，条目内容放 HANDOFF，便于持续增删。
2. **新应用内容前期要薄**：首批只给「简明扼要、做完就有成果」的核心；更多的知识量与复杂度作为「进阶」层，
   译文与练习可以照常入库，但界面默认折叠，用户一键展开。落地做法见 `guide/octave-manual`（`scope.json` 的
   `functions` 为基础、`functions_more` 为进阶；侧栏「内容深度」开关）。新增内容先进进阶层，升到基础需要理由。
   完整教材精读类应用（Selinger、Siefken）按原书走，不适用本条。
3. **一本书或一门课对应一个应用**，数学工具若有多本公认的优秀教材，逐本建应用、互不干扰（沿用 ADR 0162、0163）。
   候选书目与取得方式记在 HANDOFF「候选教材」一节，云里能取得的（GitHub 有源）由云会话继续做，其余等人工或本地代理。
4. **阶段性成果及时合并进主分支**：一个应用达到可交付（译文完整、检查通过、能打开），就开 PR 合并，不等全部做完。

## 后果

- HANDOFF 是活文档：任何会话（云或本地）发现新的「做不到」都往里加；本地代理接手前先读它。
- 厚度分档引入「基础/进阶」两层，界面与内容校验要识别 `stage` 字段；其他工具类应用照此办理。
