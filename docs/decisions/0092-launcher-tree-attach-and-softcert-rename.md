# ADR 0092：启动器支持树状挂靠，softcert 定名软件设计师，dsa 挂靠软设

- 日期：2026-10-09
- 状态：**提议（待 tiger 确认）**
- 关系：修订 [ADR 0090](0090-softcert-splits-esd.md) 决策 1 的定位表述与
  [ADR 0091](0091-experiments-inside-subject-apps.md) 决策 1 的承接范围；
  启动器布局扩展 [ADR 0083](0083-launcher-mind-map.md)；改名边界延续
  softcert 应用级 [ADR 0021](../../subjects/ascent/adr/0021-binary-rename-athena-ascent.md)
  同款理由（id 不动，只改显示名）

## 背景

tiger 提出三点（2026-10-09）：

1. softcert 在 ADR 0090 拆分后只剩软件设计师一门课，名字还叫「软考」名不副实，
   应改为「软件设计师」。
2. 独立的 `dsa`（数据结构与算法，自带「可即时编译运行的 C++ 实验」）正是软件
   设计师第 3、8 章的实践路径，应**挂靠**到软设底下。
3. 启动器思维导图（ADR 0083）只有「中心 → 领域 → 应用」两层，应用下不能再挂
   任何东西——不同的子课程挂靠不同软考课程时没有位置，太死板，要允许树枝状
   的同级分支。

现状核实：`related` 是无向细线，`group` 是无向领域归并，`evolves_from` 是演化
线——三者都表达不了「从属于某应用」的有向从属；布局上应用是叶子节点。

## 决策

1. **`app.json` 新增可选字段 `parent`**（字符串，单值）：挂靠的应用 id，语义是
   「本应用是该应用底下的子课程/子能力」，**有向、单父**；写了不存在的 id 忽略
   （与 `related` 同规）。启动器只读，新增应用不改启动器代码（ADR 0046）。
2. **思维导图加第三层**：被挂靠的应用画在挂靠应用的外一圈，用有向实线连接；
   同一挂靠者的多个子应用平分其外弧段。`parent` 只决定层级与连线，领域圈仍按
   `group` 画——一个应用可以身处「算法」领域圈、同时挂在「软件设计师」外圈。
3. **softcert 显示名改「软件设计师」**：`title` 与界面、README、文档同步改；
   `id`、identifier、Cargo 包名、进度库全部不动（与 ADR 0021 同理由）。修订
   ADR 0090 决策 1 的定位表述：softcert 的定位收窄为软件设计师本身，「将来
   软考其他方向加进本应用」的预留取消——新方向出现时按那时再议独立或挂靠。
4. **dsa 挂靠 softcert**（`dsa.parent = "softcert"`），并修订 ADR 0091 决策 1：
   软件设计师第 3（数据结构）、8（算法设计）章的编码实验**由 dsa 承接**——dsa
   的 C++ 即时编译实验就是这两章的实践路径，不再在 softcert 里重建；softcert
   的 `lab` 块承接其余实践章（2 正则、4 进程同步、5 测试、7 设计模式、9 SQL、
   10 网络安全）。softcert 课程树在这两章放「去 dsa 做实验」的内容指引（文字与
   链接说明，不做代码引用，ADR 0032）。
5. **c-gui-lab 从实践面板抽出，挂靠 softcert**（`c-gui-lab.parent = "softcert"`）。
   如实标注边界：它的内容是 C 语言 GUI 框架对比（GTK4/ImGui/LVGL），与软设考纲
   （控制台 C 算法题）重合度低，挂靠语义是「C 语言技术体系的实践出口」，不是
   考纲对齐。**面板归属规则**改为：有 `parent` 的应用在学习面板的挂靠位置展示，
   不再出现在实践面板网格；无 `parent` 的应用维持按目录归属（ADR 0060）。目录
   仍留在 `practice/`——是否转学习应用（补进度库、教学规范）等它真的承担学习
   职责时再议，挂靠本身不触发类别变更。
6. **cpp 预留挂靠**（`cpp.parent = "softcert"`，必要时启用）：cpp 已带可运行
   实验，启用时同步修改其 description「与其他应用平级」的自述。是否启用由软设
   内容建设驱动——出现需要 C++ 语言的实验（如面向对象对照）时挂上，现在不挂。
7. **启动器布局的实现**由启动器当前的开发线执行，本 ADR 只定数据模型与布局
   语义（三层、有向实线、弧段均分、面板归属）；`launcher/README.md` 的字段
   说明补 `parent`。

## 后果

- 思维导图可能出现三层圈，窗口默认尺寸与滚动阈值重审；布局纯函数的单元测试
  补三级用例。
- `docs/REPOSITORY.md` 名字表补「softcert = 软件设计师」；dsa 的 description
  「可单独使用」补「亦是软考软件设计师的实践实验环境」；c-gui-lab 的
  description 补挂靠语义。
- 挂靠是展示与课程关系声明，**不引入任何代码或数据依赖**：dsa、c-gui-lab 与
  softcert 仍是完全隔离的独立应用（ADR 0032）。
- 面板归属规则变化影响所有 `practice/` 应用：现仅 c-gui-lab 声明 `parent`，
  其余实践应用不受影响。
- 未来某应用要求多父（一个子课程挂两门课）时再扩展，本条先守单父。
