# ADR 0072：学习者 ID 与显示名分离，允许改名（修订 ADR 0071 决策 2）

- 日期：2026-10-02
- 状态：已接受；修订 ADR 0071 决策 2 的「名字即标识，不做改名」，其余各条继续有效
- 影响：`subjects/driver`（用户注册表、切换页、侧栏）；服务端**零改动**——中心 `user`
  列与 `X-Athena-User` 存的本来就是标识串，从名字换成 ID 对服务端透明
- 延续：ADR 0071（多用户隔离的全部机制）、0070（本地优先）

## 背景

ADR 0071 把名字定为稳定标识以换取实现最简，代价是两条：

1. **不能改名**——名字起错、想换称呼，都只能新建用户从头开始。
2. 改名与「两台机器同名共享历史」互相矛盾：一旦支持改名，另一台机器还用旧名字
   就会生成另一个身份，历史静默分裂。

使用者明确提出要有改名。名字当标识是根源，把它拆开：**ID 是身份，名字只是称呼**。

## 决策

1. **每个学习者一个唯一 ID，ID 永不变。** 本地注册表生成：`u_` + 16 位十六进制随机
   （`Random.secure`）。中心 `user` 列、`X-Athena-User` 请求头、本地库文件名
   （`local-<ID>.db`）、照片清单名（`photos-<ID>.json`）用的都是 ID。
2. **显示名随便改。** 名字只存在于本地注册表（`users.json` 里 ID→名字），改名即时生效、
   不触碰任何同步数据。仍拒绝重名——ID 才是身份，重名没有意义，还会让选择页认错人。
3. **首用户的 ID 就是字面量 `tiger`。** 0071 落地时中心存量 `user` 列全是 `tiger`，
   ID 定为 `tiger` 让这些记录无缝归位，不需要任何数据迁移；它的初始显示名也是
   `tiger`，想改随时改。之后的新用户一律随机 ID。
4. **跨设备续用从「起同名」改为「输入学习者 ID」。** 同名不再是共享的依据（改了名就
   对不上号了）。选择页提供「续用已有的学习者」入口：输入另一台机器上显示的 ID，
   本机注册表收录该 ID，之后同步的就是同一份历史。
5. **ID 可见、可复制。** 选择页每个学习者一行，点开能看到完整 ID——它是「我是谁」
   的最终答案，不藏在任何地方。

## 后果

- `users.json` 结构变为 `{users: [{id, name}], last: <ID>}`；旧结构（名字数组）升级时
  按名字建 ID（唯一存量 `tiger` 直接映射为 ID `tiger`）。
- 服务端、中心表、迁移脚本零改动；本 ADR 是纯客户端修订。
- 「同名共享是特性」的表述（0071 后果）作废：共享的唯一途径是同一个 ID。
