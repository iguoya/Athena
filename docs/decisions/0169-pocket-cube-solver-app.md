# ADR 0169：新增 pocket-cube-solver——从初学者解法出发，做一个能解任意状态的二阶魔方程序

- 日期：2026-10-18
- 状态：已接受（使用者 2026-10-18：「模仿中国象棋应用的方式改造二阶魔方的项目，现有的魔方代码保留作为旧版或者参考；从初学者解决二阶魔方的角度分层次阶段规划章节，尽可能采用可视化的方式，编写一个解决任意状态下二阶魔方的解法程序，尽可能分阶段地把步骤和解法操作可视化」；技术路线、id、交付范围经三问确认：象棋同款壳加 gtkmm 章节 / `programming/pocket-cube-solver` 且旧版原地不动 / 先交 ADR、章节规划、求解核心和前几章）
- 关系：教程壳与章节程序的做法同 [0151](0151-chinese-chess-app.md)、[0153](0153-snake-app.md)（壳复制自 chinese-chess，此后独立演进）；教程壳遵循 ADR 0138（Tauri 2 + React），gtkmm 按 ADR 0133 的异构准入；归类按 [docs/REPOSITORY.md](../REPOSITORY.md) 的三类判据；内容厚度按 [0164](0164-cloud-limits-handoff-and-content-thickness.md)（前期要薄，进阶默认折叠）；旧版 `practice/pocket_cube`（ADR 0060）不动

## 背景

1. 仓库里已有 `practice/pocket_cube`：一个 gtkmm 的 2 阶魔方项目应用，做了状态表示、转动、3D 视图和展开图，**没有打乱与求解**。它是「能跑的东西」，不教人，也没有进度库。
2. 使用者要的是另一件事：站在一个**初学者怎样把二阶魔方拧回来**的角度，分阶段、分层次地讲，并且一边讲一边把这个解法**写成程序**——最终能解任意状态，每个阶段、每一步转动都看得见。这和中国象棋、贪吃蛇是同一种东西：用做一个东西来学，每章一个能独立编译运行的子程序，前一章的缺口由后一章补上。
3. 三类判据：要教会人二阶魔方的层先法（认识、记号、三个阶段、公式）和把它写成程序的办法（状态表示、搜索、宏步骤、最短解），并用可运行的程序和预测作答作为证据，所以是**学习应用**，不是 `practice/` 项目应用。旧版按原样留作参考。
4. id 不得改嫁（根 `AGENTS.md`）：旧版 id 是 `pocket-cube`，新应用用新 id，旧版 id、目录与代码一概不动。

## 决策

1. 新增 `programming/pocket-cube-solver`。id `pocket-cube-solver`（完整英文词），界面名「二阶魔方」，进程 `athena-pocket-cube-solver`，知识点前缀 `cube.`，端口 **1522**。`group` 为「程序设计」，不设 `parent`。
2. **旧版保留**：`practice/pocket_cube` 的代码、id、目录名和测试都不动，只在 `app.json` 的标题与说明、`AGENTS.md`、`README.md` 里标注「旧版，供参考」，并指向新应用。新应用的章节不 include、不链接旧版文件（应用之间不互相引用）；旧版里有价值的做法（以 3D 坐标推出转动、展开图的布局）在新应用里自己重写一遍并写下理由。
3. **教程壳**是 Tauri 2 + React，最初复制自 `programming/chinese-chess`，此后独立演进。壳不画魔方，只读章节、记录作答、按白名单编译并启动某一章；讲解页内另有轻量的网页魔方图（展开图 + 步骤回放），用来在讲解里把公式的效果画出来。网页图自带一份与 C++ 同构的小模型，两边的一致性由 `scripts/check.py` 里的黄金向量核对。
4. **章节程序**是 gtkmm 4 / C++20 / Meson，每章一个 Meson 工程、**一个窗口**（界面文件 `ui/window.blp` 写控件树，`ui/style.css` 写颜色；C++ 放入自绘的魔方视图并接信号）。魔方没有「用代码搭出同一扇窗」的对照价值，这一点与 ADR 0151 的两窗口做法不同，由本应用 ADR 0002 记录。章与章不共用库，后一章是前一章长出来的样子，源码另写一份。
5. **章节按初学者的解法阶段切**，共七章。前两章是认识与表示，中间三章是层先法的三个阶段（每章一个阶段，前一章的求解随之带上），后两章把任意状态和最短解补全：
   1. `01-net` 看见魔方：24 张贴纸、8 个角块、展开图怎么读。
   2. `02-turns` 转一转：Singmaster 记号，用 3D 坐标推出转动，画出层转动的动画；转动的数学性质（`U⁴ = 1`、`(R U R' U')⁶ = 1`）进测试。
   3. `03-layer` 做第一层：把底面一层拼好。程序用迭代加深搜索找出这一阶段。
   4. `04-orient` 把顶面翻成一色：七种情形，公式 Sune；程序用宏步骤广度搜索。
   5. `05-permute` 把顶层角块摆到位：相邻交换与对角交换两个公式。
   6. `06-solver` 合体——任意状态：逐格涂色输入、合法性判定（角块齐全、朝向和为 3 的倍数、手性）、摆正姿势、三阶段串成一条流水线、阶段时间线与逐步回放。
   7. `07-optimal` 最短解：从复原态反向广度优先，建 3 674 160 状态的距离表，任何状态不超过 11 步（半转计一步）。
   写完的章节才登记进 `content/course.json`；没写完的章节只在 `AGENTS.md` 的章节规划里留位置，不放空目录（ADR 0129）。
6. **姿势约定**：白色在下（D 白）、黄在上（U 黄）、绿在前（F 绿）、蓝在后（B 蓝）、右橙（R 橙）、左红（L 红）。这是白面朝下、绿面朝前时真实魔方的手性（把常见的白上绿前配色绕 F 轴转半圈得到），不是自定。2 阶魔方没有中心块，转 U/R/F 三面即覆盖全部本质不同的转法，左下后角块（DBL）永远不动，作为参照；输入的任意状态先摆正到这个姿势再求解。
7. **出处档位 open**。学习方法（ADR 0113）：主原型**问题解决**（把一个没头绪的状态拆成三个有可判定子目标的阶段），辅**预测–运行**（公式作用在这个状态上会得到什么，先猜再看回放）。题目标 `authored`，写明为什么没有现成题，不编造题号；题目只考讲解里已经写出的重点、要点、难点、考点。
8. 默认的 `scripts/check.py` 不编译 gtkmm，避免没有这套工具链的 CI 失败；本机用 `--native` 编译各章并跑规则与求解测试。

## 后果

- 根 `Cargo.toml` 增加本应用的 `src-tauri` 成员，pnpm 工作区已包含 `programming/*`。
- 仓库里同时有新旧两个魔方应用，启动器里旧版标题带「（旧版）」。旧版想删时按 ADR 0129 显式删除、写明取回方式，不在本 ADR 范围内。
- 七章源码有意重复，理由同 ADR 0151：合并成一个库会让「这一章当时只有这些代码」讲不清楚。
- 本轮只写完前若干章（见应用 `AGENTS.md` 的进度表）；其余章节待使用者验收样式与深度后继续，不先批量细写。
- 发版清单暂不加入，等章节写完并稳定后再按 ADR 0168 的标准处理。
