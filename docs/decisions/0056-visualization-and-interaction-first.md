# ADR 0056：可视化与交互是学习内容本身，不是装饰

- 日期：2026-09-17
- 状态：已接受（强制方针）
- 影响：`apps/` 下全部学习应用的内容形态与界面实现
- 对齐：ADR 0028（学习内容三层）、ADR 0052（激励与统计是同一条回路）、
  `apps/mathematics` ADR 0011（为专注与持续投入而设计）

## 背景

学习类软件最容易走的下坡路是退化成「一段文字 + 一道选择题」：内容都在，
却没人看得进去。仓库里已经有过两次正反对照——

- 驾考应用把标志从文字描述改成自绘图形、把考场的图片题和动画 GIF 取进来、
  把只写不读的模拟考成绩画成柱状图之后，同样的知识点明显更抓得住；
- 而在此之前，标志自绘画了 36 种、题库里只有一道题用到，`exams` 表从建库起
  只写不读——能力做了却没有接到内容上，等于没做。

问题不在于「要不要配图」，而在于没有统一的方针：可视化与交互一直被当成有空
再补的装饰，于是永远排在后面。

## 决策

1. **能画的就画。** 概念结构、状态迁移、执行流程、分类对比、数量关系，优先
   做成图或表；纯文字只在图确实说不清时才是首选。判断标准是「一句话能不能说
   得同样清楚」——把正文清单排成方框不算可视化。
2. **能算出来的画成活的。** 由运行时数据、作答记录、实验结果派生的东西一律
   现场绘制并可交互，不做会跟数据漂移的静态图片。纯概念示意才用静态图。
3. **交互优先于展示。** 能点、能拖、能改参数、能立刻看到结果的，胜过只读的图；
   做题、实验、模拟都要给即时反馈，反馈要分层次（对错 → 为什么 → 下一步做什么）。
4. **反馈与战绩必须看得见。** 记了的数据要有出口：进度、掌握度、连对、里程碑、
   历次成绩都要在界面上呈现（ADR 0052）。只写不读的表视为缺陷。
5. **素材自绘优先，真素材随仓库走。** 图标、标志、图表优先用代码绘制
   （CustomPaint / SVG / Canvas），便于随主题与数据变化；照片、动画、音频这类
   画不出来的，下载进仓库版本控制，不依赖外部服务器。
6. **不因为「还没实现」缩内容。** 内容需要什么呈现形式，就把那个能力补上，
   而不是把能力的缺口写成内容标准（`apps/driver` ADR 0008 第 4 条是这条的先例）。
7. **各应用按自己的技术栈实现，不共享组件库。** 复用的是这套方针，不是代码——
   共享 UI 库会立刻把独立的应用绑在一起（ADR 0032）。

## 后果

- 界面工作量增加，且这部分工作不再算「优化」，属于内容工作的一部分：内容评审
  时要同时问「有没有该画没画的、该交互没交互的」。
- 仓库体积会因为收录真实素材而增长（驾考的 884 张题图约 41MB），这是接受的代价。
- 新增能力（绘图组件、交互控件）落地后要回头把已有内容接上，否则就是第二次
  「画了 36 种标志只用一种」。
