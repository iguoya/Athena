# ADR 0132：共享层暂缓——课程结构未充实前不抽象

- 日期：2026-10-11
- 状态：已接受（tiger 2026-10-11：共享问题存在，但现在不是解决的时候；课程结构还不充实，不值得抽象共享）
- **范围已由 [ADR 0135](0135-share-low-cost-build-layer-first.md) 收窄**：只暂缓 schema 与内容抽象，构建层低成本项不再暂缓
- 暂缓实施：[ADR 0130](0130-shared-build-and-schema.md)、[ADR 0131](0131-shared-layer-location-and-pilot.md)
- 恢复生效：[ADR 0032](0032-independent-apps-launched-as-processes.md) 决策 2（构建完全隔离）、
  [ADR 0043](0043-sourced-content-across-apps.md) §1（schema 不共用）、
  [ADR 0037](0037-independent-apps-own-their-progress-store.md)（各应用自管进度库）

## 背景

ADR 0130、0131 是在盘点出「进度表结构已在三个应用间漂移」之后立的。使用者随后判断：
问题是真的，但**抽象的前提不成立**——各应用的课程结构还不充实，现在能看到的共同点
有多少是真共性、多少是各自还没长全，无从分辨。过早抽象出来的公共 schema 会把未定型
的形状固化，之后每个应用都得迁就它。

这与 ADR 0129（宁缺毋滥）同向：先把内容做扎实，再谈提炼。

## 决策

1. **暂缓，不否定。** 0130 指出的问题（schema 漂移、重复实现、磁盘膨胀）仍然存在，
   但现在不解决。0130 的方向声明保留为「已知问题与候选方案」，**不作为当前规则执行**。
2. **0131 不执行。** 不建 `shared/`，不动 `gtkmm` 的进度层，不迁移任何数据，
   `scripts/check.py` 的根目录白名单不登记 `shared/`。
3. **构建与 schema 回到现行规则**：应用之间构建隔离、不互相引用路径与配置，共用规范
   不共用 schema；各应用自建自管自己的进度库（0032 决策 2、0043 §1、0037）。0130 对根
   `AGENTS.md`、`docs/REPOSITORY.md` 和四个应用 `AGENTS.md` 的改写随之撤回为「暂缓」口径。
4. **允许重复，不强求一致。** 暂缓期间各应用的进度表、阅读器、测验各自演进，不因为
   「将来要共享」而提前对齐字段，也不新建以共享为目的的抽象层。
5. **重新评估的触发条件**（任一出现，再由使用者决定是否重启 0130）：
   - 至少有三个应用的课程结构稳定、内容达到可日常使用的规模；
   - 某项通用能力（如间隔复习）要在多个应用同时落地，逐个重做的成本明显超过抽取；
   - 漂移已经造成实际故障或数据丢失，而不仅是「看起来不统一」。
6. **本 ADR 之外不变**：ADR 0129（宁缺毋滥）、ADR 0062（约束不继承）照旧。

## 后果

- 文档里不再出现「构建共享、schema 共享」作为现行规则；0130 的位置与试点结论
  （`shared/`、`gtkmm`）作为备选记录保留，重启时可直接沿用。
- 下一阶段的精力放在内容上：盘点应用、处置空骨架、充实主线应用，而不是基础设施。
