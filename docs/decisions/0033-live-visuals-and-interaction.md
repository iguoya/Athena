# ADR 0033：大纲与教学过程都用活的可视化和互动元素表达

- 日期：2026-09-11
- 状态：已接受；`type_semantics` 大纲已改造，教学过程逐节跟进
- 延伸：ADR 0027（学习页的多媒体教案）扩展到**大纲层**，并把"数据驱动"和
  "可互动"从建议提升为首选
- 修订：ADR 0024 之后遗留的做法——大纲仍以 Markdown 为权威表达

## 背景

章节教学大纲一直是一份 Markdown，由 `DocumentView` 渲染。Markdown 只有标题、段落、
列表、表格和图片这几种块，结果是：知识点的难度与掌握目标只能写成「〔中等 · 需要精通〕」
这样的括号标注，先修关系只能用文字描述，学习者当前学到哪了根本无从表达——所有结构
信息都被摊平成正文，读者得自己在脑子里重新聚合。

而这些信息本来都在程序里：`requires` 有依赖图，`difficulty` / `mastery_goal` 有评级，
学习库有实时熟练度。用 Markdown 表达它们，等于把已经结构化的数据降级成文字。

ADR 0027 已经要求学习页充分使用多媒体，但它只管教学过程（第二层），没覆盖大纲；
而且它说的多媒体偏静态素材与可控动画，没有把"由运行时数据驱动"和"可互动"作为首选。

## 决策

1. **大纲与教学过程都用 GTK 控件表达，Markdown 降为衍生物。** 权威表达是 `.blp`
   加必要的 Cairo 绘制；Markdown 仍可保留供分类手册和离线阅读，但它不再决定内容的
   组织方式，也不构成表现形式的上限。
2. **能由运行时数据算出来的，就画成活的，不要写成文字或做成图片。** 判据：这份信息
   是否已经存在于配置、依赖图或学习库里？是，就让它随数据变化——依赖关系画成连线，
   评级画成配色与徽章，学习进度画成实时状态。写死的图片会和数据漂移，文字则要读者
   自己聚合。
3. **优先给可视化配上互动**，让学习者能做出原本做不了的动作：点节点跳到对应小节、
   切换两种写法看差异、逐步推进一个语义过程、展开某个分支看细节。互动的价值在于
   "他做了一个选择"，不在于界面会动。
4. **静态 SVG 仍有位置**：概念示意、不随数据变化的关系图、需要精细排版的插画。
   区分标准就是第 2 条——数据驱动的用绘制，纯概念的用 SVG。
5. **不为可视化而可视化。** 加一个视觉元素之前先问：它表达的信息，一句话能不能说得
   同样清楚？能，就写那句话。把正文已有的清单排成方框不算可视化——这类图在
   `type_semantics` 大纲里已经删掉四张。
6. **实现边界不变。** 仍是 Blueprint + GTK + Cairo，不引入 WebView、运行时 JS、
   图表库或通用动画引擎（沿用 ADR 0027 第 7 条）。静态或半静态的控件树仍写在 `.blp`
   里；只有"结构由运行时数据决定"和"`.blp` 表达不了的绘制"才用代码（AGENTS.md
   GTK 规则第 2、3 条）。
7. **可视化不能是唯一通路。** 颜色编码要有文字标签配套，动态过程要能停下来看静态
   状态，图里的信息要在正文里有对应说明——停止动效、放大字号、只用键盘时仍要学得下去。

## 后果

- 大纲页从"一篇文章"变成"一块面板"：风险带检查点编号、推荐顺序是步骤条、主次是
  分色卡片、知识点路线图随熟练度实时更新并可点击跳转。
- 一处新增维度（比如再加一维评级）要同时想好它的视觉编码，否则加了字段也传达不出来。
  同时**不同维度不能共用一套视觉编码**——路线图的配色只表示掌握目标不表示难度，
  否则会让人以为"难 = 要精通"，正好抹掉当初拆成两维的意义。
- Markdown 与控件两份内容并存期间会漂移。当前接受这个代价；后续要么从控件描述生成
  Markdown，要么让手册也读同一套描述，届时另开 ADR。
- 教学过程的每一节都要回答"这一节有什么是值得画成活的、值得让学习者动手点的"，
  而不是默认写成文字加一道选择题。
