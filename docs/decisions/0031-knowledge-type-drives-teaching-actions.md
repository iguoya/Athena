# ADR 0031：知识类型决定教学动作

- 日期：2026-09-10
- 状态：已接受；`type_semantics` 章已标注，其他章节留空待写到时再补
- 修订：ADR 0029 的评级维度（使用频率并入掌握目标，不单列）

## 背景

原生学习页此前对所有知识点用同一套结构：一段讲解加一道确认题。但教学设计里，
不同类型的知识需要不同的教学动作，这是有稳定结论的：概念要靠正例与反例辨清边界，
程序性技能要靠示范和变式练习，条件性知识要在具体情境里做选择并说明理由。
用统一模板套所有知识点，最省事，也最容易停在“看懂了”而没到“会用”。

## 决策

1. **新增 `subchapter.knowledge_type`**，取值 `concept` 概念、`skill` 程序性技能、
   `strategy` 条件性策略。
2. **各自的教学动作写进 [LEARNING_DESIGN](../LEARNING_DESIGN.md) 第 3 节**，并列出
   反模式：概念只给一个正例、技能缺模仿这一步、策略被做成机械选择题。
3. **界面显示知识类型徽章**，让作者和学习者都看得见这一节该用什么方式学。
4. **使用频率不单列成维度。** 频率是判据，掌握目标是结论，分成两个字段等于把同一个
   判断记两遍。评定 `mastery_goal` 时按“日常使用频率 × 用错的代价”判断，
   这一条写进 ADR 0029 的字段说明。
5. **只给已经写出教学内容的章节标注**，其他留空。

## 后果

- 学习页不再是统一模板：概念型的节要给出正反例并排，策略型的节要给情境和判据，
  技能型的节要有完整示范和变式练习。这会让页面之间的结构差异变大，是预期结果。
- 一个类型标注不到位的知识点，写页面时会立刻显出来——找不到合适的教学动作，
  通常说明类型标错了，或者这一条其实是两个知识点。
- `type_semantics` 章七个知识点里没有 `skill`，因为这一章本身是判断类内容。
  这不是漏标，而是这个维度确实有区分力的证据。
