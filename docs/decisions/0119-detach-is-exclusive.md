# ADR 0119：夺走即独占——画布上一个节点只出现一次

- 日期：2026-10-10
- 状态：已接受（tiger 2026-10-10：「还是尽量避免一个节点在界面上多次出现吧」）
- 关系：修订 [ADR 0118](0118-heavier-exam-owns-course-body.md) 决策 1 的「其余考试以引用
  节点承接」与决策 3 的挂法效果；`also_under` 字段与引用节点机制保留（0116 不废），
  当前清单没有应用使用

## 背景

ADR 0118 把五门 408 科目课的本体夺到 cs408 时，软件设计师一侧按当时的写法放了五个引用
节点，同一门课在画布上出现两次。tiger 看到界面后收窄了原则：节点重复出现本身就是负担，
能不重复就不重复——「夺走」应当是独占，不是共享。

## 决策

1. **画布上一个应用节点只出现一次**：本体挂在权重更高的考试下（ADR 0118），被夺走的一侧
   不再放引用节点。课程归属关系不靠第二个图块表达，靠各自课程树的文字指引承接
   （ADR 0103 以来的分工方式，本就不依赖引用节点）。
2. **五门 408 科目课删除 `also_under`**：软设外圈不再显示这五门课的图块。软设第 1、3、
   4、8、10 章的承接 = 两边课程树里互放「去某某应用学习」的文字指引，路径不变。
3. **`also_in` 领域圈引用不受本条影响**：english、mathematics 的考研圈引用是
   [ADR 0117](0117-merge-english-into-ascent-and-group-reference.md) 的明确决定——22408
   的入口要在考研圈呈现英语二与数学二，那是它们唯一的考研圈表达，去掉就没了；与「被夺走
   一侧的冗余副本」不是一类东西。要收回先修 0117。
4. **机制保留**：`also_under` 的解析规则与引用节点渲染照旧（0116），只是当前清单没有应用
   使用；启动器代码零改动。

## 后果

- 画布恢复一门课一个图块：考研圈的 cs408 外圈挂五门课本体，软设外圈只剩 database、
  design-patterns（真挂靠）与 c-gui-lab。
- 软设学习者去实验课程的路径不变（课程树文字指引直达对应应用）；损失的只是「软设外圈
  看得见这五门课的图标」。
- `also_under` 成为暂无使用者的通用机制，下次要用时不需要新 ADR。
