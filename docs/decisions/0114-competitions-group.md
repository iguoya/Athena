# ADR 0114：新增「大赛」领域圈，首个成员是赛历参考应用 competitions

- 日期：2026-10-10
- 状态：已接受（tiger 2026-10-10：「新建一个大赛分组 有哪些适合学生参赛 有哪些允许
  社会人士参赛」；形态选「先建赛历参考应用」）
- 关系：领域圈由 `app.json` 的 `group` 生成（ADR 0092、0101）；应用分类按
  [REPOSITORY.md](../REPOSITORY.md) 三类判据归**图谱/参考类**（先例 polaris、
  math-tools，ADR 0084）；赛事训练应用的拆分口径参照 [0095](0095-one-exam-one-app.md)
  「一个考试一个应用」

## 背景

1. 启动器里的领域圈只来自应用的 `group` 字段，没有应用就没有圈。要开「大赛」圈，
   得先定圈里第一个应用是什么。
2. 竞赛与考试不同：赛事多、方向散、规则每年变，而且参赛资格差别很大——大多数只限
   在校生（ICPC、蓝桥杯、电赛、数学建模），少数向社会人士开放（Codeforces 等在线赛、
   CCF CSP 认证、Kaggle/天池/CCF BDCI、强网杯/网鼎杯等 CTF）。学习者首先要的是
   「我能参加哪些、和我在学的课怎么对上」，这是查阅需求，不是学习闭环。
3. 训练类内容（真题、限时赛）工作量大且必须有出处的真题，适合在确定要冲哪个赛事
   之后按赛事单独立项。

## 决策

1. **新增领域圈「大赛」**，首个成员 `subjects/competitions`，title「赛历」，图谱/
   参考类应用：不判分、不建进度库、不建 `content-contract.json`、跨应用教学规范
   不生效。端口 1502，进程 `athena-competitions`，壳为 Tauri 2 + Vite TypeScript。
2. **赛事条目的收录口径**（`content/competitions.json`）：
   - 字段：名称、方向、主办方、参赛资格（是否允许在校生、是否允许社会人士、补充
     说明）、常规时间窗、官网、对应的 Athena 课程（只写显示名，不引用别的应用的
     路径或代码，ADR 0032）。
   - **资格必须带核对信息**：来源 URL、核对日期、来源等级（官方章程 / 往届通知 /
     第三方报道）。查不到当届条款的如实标「待核对」，不凭印象写「允许」。
   - 赛事规则每年变：核对日期超过一年的条目，界面标为「可能过期」。
3. **界面**：按「在校生可参 / 社会人士可参」与方向筛选；每条显示资格、来源等级与
   核对日期，官网用系统浏览器打开。
4. **训练应用以后另立 ADR**：某个赛事要做真题训练时（如 CSP 认证或蓝桥杯算法），
   按「一个赛事一个应用」单独建学习应用，进本圈或挂靠 competitions 届时再定；
   赛历不长出练习功能。

## 后果

- 启动器多一个领域圈「大赛」和一个参考应用；启动器代码零改动。
- 赛历是事实性信息，正确性靠核对日期与来源等级维持；条目过期要重新核对，而不是
  静默沿用。
- 训练需求出现时有现成的落点，不会把练习塞进参考应用。
