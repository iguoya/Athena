# ADR 0099：dsa 恢复挂靠软件设计师——澄清 0095 决策 3 的误读

- 日期：2026-10-10
- 状态：已接受（tiger 澄清）
- 关系：修订 [ADR 0098](0098-minimal-links.md) 决策 3；恢复
  [ADR 0092](0092-launcher-tree-attach-and-softcert-rename.md) 决策 4 的挂靠表达

## 背景

tiger 对 0095 决策 3 的表述「数据结构和算法直连软考不合适」被误读为「取消 dsa 的
挂靠」。tiger 澄清（2026-10-10）：树形分支的挂靠树是对的，「直连不合适」指的是
dsa 不应作为与软考课程平级的顶层兄弟出现——它**就应该挂在软件设计师底下**，
是软设的子分支。

## 决策

1. **恢复挂靠**（dsa.parent 现指向 `software`——软件设计师 id 随 ADR 0097/后续改名迁移）：dsa 回到思维导图的挂靠层，画在软件设计
   师外一圈；领域圈仍是「算法」（ADR 0092 决策 2：领域圈按 group 画）。
2. 0095 的其余决策不变：related 与演进线维持删除；挂靠深度一层维持；
   math-tools↔mathematics 维持保留。
3. dsa 承接软件设计师第 3、8 章编码实验的分工不变（ADR 0092 决策 4）。

## 后果

- 0095 决策 3 作废；「非必要不特意连线」的原则继续适用于并列兄弟之间
  （related、evolves_from），不适用于有真实从属关系的挂靠（parent）。
