# ADR 0048：菜单栏启动器保留为 macOS 专属，但只许消费编排器的结论

- 日期：2026-09-15
- 状态：已接受
- 影响：`launcher/macos`（Swift）、`launcher/core`（新增 `athena-dev list --json`）
- 关系：为 [ADR 0047](0047-portable-by-default.md) 要求的「平台专有代码必须在 ADR
  里写明理由与降级」补上 `launcher/macos` 这一条；执行路径仍遵循
  [ADR 0046](0046-unified-dev-orchestrator.md)

## 背景

仓库有两个启动器前端：跨平台的 `launcher/gui`（Slint，托盘常驻）和 macOS 专属的
`launcher/macos`（679 行 Swift，菜单栏常驻）。ADR 0047 定下跨平台优先，并要求
只在部分平台可用的东西「要么找等价替代，要么在 ADR 里写明为什么值得、其他平台
怎么降级」——菜单栏版一直没有这份说明，每次审视仓库都会被重新提出来当作待砍项。

同时它有两处真实的重复：自己解析一遍 `app.json`，以及把 `athena-dev list` 输出的
中文状态（"运行中"/"启动中…"）反解析回枚举。后者尤其脆——编排器改一个字，
菜单栏就会静默把所有应用显示成"未运行"，不报任何错。前者已经开始漂移：
`symbol` 的兜底值一边是 `book`、一边是 `book.closed`，只是碰巧每个 `app.json`
都写了才没暴露。

## 决策

**1. 保留菜单栏版，明确它是 macOS 专属的自用件。**

理由是主力开发在 macOS，这是自用软件，不是要发行的产品。菜单栏常驻、全局热键
（⌃⌥A）、预热——这三样是 macOS 上每天都在用的收益，为了三平台对称而砍掉它们，
是拿真实的日常便利换一个整齐的架构图。

**2. 其他平台的降级是明确的，不是「不支持」。**

跨平台的 `launcher/gui` 在三个平台上都提供完整的列表、启动、停止、状态与日志；
终端的 `athena-dev` 同样三平台可用。Windows 与 Linux 上少的只有菜单栏常驻、
全局热键和预热，没有任何功能只能靠菜单栏版才能完成。

**3. 代价是：菜单栏版不得自己理解清单，只能消费编排器的结论。**

保留一个平台专属前端的前提，是它不产生第二份事实。为此 `athena-dev` 新增
`list --json`，一次给出 id、title、summary、symbol、目录、匹配前缀、二进制名、
是否可启动、当前状态与日志路径；状态用 `stopped` / `starting` / `ready` 这组
**不会变的标识符**，中文 `label()` 只留给人看。菜单栏版据此不再读 `app.json`、
不再拼日志路径、不再反解析中文。

## 后果

- 清单怎么解析、默认值是什么、日志放哪，全仓库只有 `launcher/core` 一处说了算；
  Swift 侧少了一份会漂移的副本。
- 编排器的人类可读输出从此可以自由改措辞，不会波及任何前端。
- 仍然重复的一处是 `AppSupervisor.runningApplication(for:)`：它按同样的规则
  （路径前缀 + 二进制名）再找一次进程。这一条是正当的——预热要拿到
  `NSRunningApplication` 才能 hide/unhide，Rust 那边给不出这个对象。它的匹配
  依据来自编排器给的 `matchPrefix` 与 `binary`，不是自己另立一套。
- 这条决定绑在「主力开发在 macOS」这个前提上。前提变了，或者预热与全局热键被
  移植进 Slint 版，就该重新评估——届时删掉 Swift 版不会丢失任何能力。
