# ADR 0102：软件设计师与嵌入式系统设计师各为一级大类（计算机 / 电子信息）

- 日期：2026-10-10
- 状态：已接受（tiger 2026-10-10：「把嵌入式设计师和软件设计师都作为一级大类」）
- 关系：修订 [ADR 0090](0090-softcert-splits-esd.md) 决策 2 的「group 同为『软考』」；
  与 [ADR 0101](0101-domain-circle-siblings-no-links.md) 的兄弟原则衔接——两应用不再
  同圈，自然不再是兄弟；启动器连线语义仍按 [ADR 0083](0083-launcher-mind-map.md)、
  [ADR 0092](0092-launcher-tree-attach-and-softcert-rename.md)

## 背景

软考拆分后两应用同挂「软考」分组，在思维导图上是同一领域圈的两个成员。
tiger 复核布局效果后决定：把两者各自提升为一级大类——嵌入式系统设计师、
软件设计师各领一个领域圈，平级、互不从属，也不再同圈；「同挂软考分组」
带来的兄弟呈现问题（一内一外、挤圈）随之消失。

## 决策

1. **`subjects/software` 的 `group` 改为「计算机」，`subjects/embedded` 的
   `group` 改为「电子信息」。** 启动器思维导图上各自为一个一级领域
   大类（胶囊 + 成员应用），「软考」分组退役；大类名用领域名（计算机 /
   电子信息），不沿用考试名——圈是领域，应用是圈里的成员；两应用在图上互为平级大类节点。
2. **挂靠关系不变**：algorithm → software（ADR 0099）、c-gui-lab → software
   （ADR 0092）照旧，挂靠节点画在「软件设计师」大类外一圈。
3. **id、进度库、内容、端口一切不动**——本条只改 `group` 展示字段。
4. 启动器上「考试类应用各自成大类」是默认做法：一门考试一个大类，大类名即
   考试名（完整名，不用缩写）；同门考试内的子能力才用 `parent` 挂靠。

## 后果

- 思维导图：领域圈 +2（计算机、电子信息），「软考」胶囊消失；
  两应用各自贴着自己的大类胶囊，不再有同圈挤位问题。
- `docs/REPOSITORY.md` 等文档中「同挂软考分组」的表述随本条理解为历史。
