# ADR 0045：C++ 教程降级为 apps/cpp，所有学习应用平级

- 日期：2026-09-14
- 状态：已接受
- 影响：整个仓库结构；`AGENTS.md` 分层；`docs/` 与 `scripts/` 分家；CI 与发布工作流；
  `platform/app_paths.cc`；`launcher/macos` 的清单发现

## 背景

ADR 0032 把各学科做成 `apps/` 下的独立应用，但没有动 C++ 教程自己——它仍然占据
仓库根：根目录就是它的源码（`main.cc`、`mainwindow.cc`、`ui/`、`render/`、`cplusplus/`…）、
它的 `meson.build`、它的 `scripts/`、它的 `docs/`，`AGENTS.md` 里大半篇幅是它的
架构原则、GTK/Blueprint 规则、代码生成规则和 macOS 发行规则。

这带来的不是"看起来不整齐"，而是一连串真实的特权：

- **别的应用是"外部应用"，它是"主程序"**。打开任何学科都要先把它启动起来，
  在它的图谱上点一次——ADR 0044 做启动器时，它甚至需要在代码里单开一条分支
  （读仓库根那份 `app.json`）才能和别人并列。
- **仓库级和应用级混在一起**。`scripts/check.sh` 只检查它，`docs/ARCHITECTURE.md`
  只描述它，但两者都住在仓库根，看起来像是全仓库的。
- **新增应用要绕开根目录的一堆东西**才知道自己该放什么；新来的人（和工具）
  看不出"根其实是一个应用"。

学习应用之间本来就是平等的：数学不比 C++ 低一级，C++ 也不该因为写得早就占着根目录。

## 决策

1. **C++ 教程整棵搬进 `apps/cpp/`**，和 `c`、`dsa`、`english`、`mathematics` 平级。
   目录名按领域取（`cpp`），与其他应用一致。仓库根不再有任何 C++ 源码、构建文件、
   脚本或文档。
2. **`AGENTS.md` 分层。** 仓库级只留所有应用共同的东西：中文思考的强约束、仓库结构、
   应用之间的边界、跨应用教学规范（三层分工、难度与掌握目标、知识类型、篇幅、
   回顾自查、内容有出处）、Git 提交规则、统一验证入口。C++ 应用自己的架构原则、
   GTK/Blueprint 规则、代码生成规则、编码规则、发行规则全部移入
   `apps/cpp/AGENTS.md`。两处不重复同一条。
3. **ADR 分家，编号不重排。** 影响仓库结构或多个应用的留仓库级 `docs/decisions/`；
   只管 C++ 应用教学内容与实现的移入 `apps/cpp/docs/decisions/`。**不重新编号**——
   重编会让所有交叉引用、提交信息和记忆里的"ADR 00xx"全部失效，两边各自延续序列、
   接受跳号是更小的代价。
4. **仓库根保留一个转发式验证入口**（ADR 0007 的延续）：`scripts/check.sh` 依次调用
   跨应用检查和各应用自己的 `scripts/check.sh`，具体逻辑归各应用。新增应用放一份
   自己的 `check.sh` 就会被带上，不用改根入口，也不用改 CI。
5. **启动器删掉主程序特例。** `launcher` 只扫 `apps/*/app.json`，代码里没有任何针对
   某个应用的分支。C++ 教程在那张列表里和别人一样排着。
6. **发布工作流在 `apps/cpp` 里执行**（job 级 `working-directory`），产物路径相应
   前缀化。版本仍以 `apps/cpp/meson.build` 为单一来源（ADR 0008 不变）。

## 后果

- `external_apps_root()` 的查找方向变了：本程序自己也在 `apps/` 下，所以 `apps/`
  不在内容根里面而在它上面，改为从内容根向上找几级。发行包里找不到时仍返回空，
  提示"独立应用不随本包分发"，行为不变。
- 旧的仓库根 `builddir/`、`build/`、`dist/` 作废，构建目录现在在 `apps/cpp/` 下，
  可以直接删掉重建。
- 文档之间的相对链接大量变化，这是这次搬迁最主要的机械工作量。
- 代价是 `git log --follow` 之外的历史查找会略麻烦（搬迁是一次纯 `git mv`，
  内容没变，`--follow` 可用）。
