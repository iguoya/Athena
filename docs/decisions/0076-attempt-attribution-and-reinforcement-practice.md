# ADR 0076：作答记录补充归因字段，新增「强化练习」（driver 先行）

- 日期：2026-10-03
- 状态：已接受（2026-10-03，使用者确认按建议实施；实施中发现需要调整的，以新 ADR 修订）
- 影响：`subjects/driver`（本地库、作答与考试的写入、选题、侧栏入口）；`practice/nas_admin`
  （API 字段与新资源、中心库加列、仪表盘派生统计）；中心 PostgreSQL 表结构
- 延续：主仓库 ADR 0068（三层存储）、0069（只读仪表盘）、0070（本地优先、REST 同步）、
  0043（判分内容必须有出处）、0052（激励与统计同一条回路）；driver ADR 0057（`kind` 与用时
  封顶）
- 不修订任何既有条款

> 编号提示：主仓库与 driver 各有一套 ADR 编号，会重号（两边都有 0043、0052）。本文凡引用
> driver 的 ADR 一律写「driver ADR n」，引用主仓库的写「主仓库 ADR n」。

## 背景

driver 的作答记录（`attempts`）目前只有 `question_id`、`topic_id`、`subject_id`、`correct`、
`duration_ms`、`at`、`kind`。仪表盘（主仓库 ADR 0069）基于它已经能算章节正确率、错题消化曲线、
顽固错题榜、模拟考丢分构成等，但要回答「下一步学什么」还差几块信息：

1. **不知道选了哪个选项**，只知道对错。无法区分「不会」和「总把 A 当成 B」（混淆），多选题也看
   不出是漏选还是多选。
2. **模拟考的逐题作答与考试记录之间没有关联键**。driver ADR 0057 只能用「交卷前 50 分钟内」
   的时间窗回填 `kind`，承认是近似。
3. **不知道一次练习从哪到哪**。没有会话边界，就算不出疲劳曲线（一次练习里正确率随题序下降）、
   休息间隔的影响。
4. **不知道答错后有没有真的看解析**。driver ADR 0038 要求停留至少 5 秒，但没有记录停了多久。

另一方面，现有三样东西各管各的，没有合起来选题：错题本只看最近一次、考前复习（driver
ADR 0033）只看累计错次、模拟考组卷按 GA 1026 配比抽题且不看薄弱点。把「错题、薄弱章节、
同考点的其他问法」合成一张需求清单再选题，可以更有效地检验和巩固。

## 决策

### A. 记录：作答与考试补充字段

1. **`attempts` 新增三个可选列**（追加型，缺省为空，不参与去重键）：
   - `chosen`：所选选项。用题库里 `Choice.id`（稳定标识，不是界面展示的位置），多选按 id
     排序后用逗号拼接。
   - `session_id`：这次作答所属的会话，见第 3 条。
   - `reason`：仅「强化练习」使用，记这道题为什么被选中，取值见第 6 条；其余场合为空。
2. **`exams` 新增两个可选列**：`session_id`（与该场考试内所有 `attempts.session_id` 相同，
   这就是「作答属于哪场考试」的关联键）、`used_ms`（整场实际用时，不含挂起）。
   **不单设 `exam_id`**：考试本来就是一种会话，一个概念承担两件事，避免两个标识各自漂移。
   中心库的自增 `id` 因设备而异，不能当关联键，必须客户端生成。
3. **`session_id` 由客户端随机生成**（16 位十六进制，不含任何个人信息或设备信息）。一次练习、
   一次错题复习、一场模拟考、一次强化练习各是一个会话：从开始到结束或离开页面。模拟考草稿
   续答（driver ADR 0043）沿用草稿里保存的同一个 `session_id`，不另起新会话。
4. **解析停留不加列，作为独立的追加型资源 `explain-views`**：字段 `question_id`、
   `attempt_at`（对应那次作答的 `at`）、`dwell_ms`（封顶 300000，同 driver ADR 0057）。
   原因：作答在判定时刻写入，解析停留在之后才知道；若回头更新那一行，会破坏「追加型、幂等」
   的同步模型，而且 `SyncEngine` 防抖 2 秒就会上传，早于最短 5 秒的停留，必然有竞态。
   独立事件按 `(question_id, attempt_at)` 去重，与现有资源同一套机制。
5. **历史数据全部为空，不回填**。`chosen` 没有任何途径还原；`kind` 的时间窗回填（driver
   ADR 0057）继续作为旧考试作答的兜底。仪表盘对新旧数据分别处理，空值不当作 0。

### B. 强化练习

6. **新增独立入口「强化练习」，它是练习，不是考试。模拟考不变：仍从整个题库按考场配比整体
   抽取，不看薄弱点、不偏向错题。**强化练习不计时收卷、不打分过关、不占模拟考成绩。模拟考按考场配比固定组卷（driver ADR 0023、
   0032），是对照考场的标尺，不能自适应，否则分数失去可比性。强化练习的作答 `kind` 为新值
   `reinforce`（driver ADR 0057 已留放宽的口子），不计入模拟考成绩、解锁线与过关判定；
   作答照常写入掌握度（掌握度只由作答写入）。
7. **选题来自现有题库，不让 AI 现场造题**（主仓库 ADR 0043）。每道题算一个「需要度」，
   由四类信号组成：
   - 题本身：最近一次是否错、累计错次、连对次数；
   - 所在章节：该章的稳定正确率，用收缩估计（样本少时向总体均值靠），作用于该章**所有**题，
     包括没错过的——薄弱章节里没错过的题可能只是没遇到或蒙对；
   - 间隔到期：已经答对的题按连对次数定复习间隔（连对 0、1、2、3、4、5 次以上分别隔
     1、2、4、8、16、32 天），到期且超期越久越优先，防止「答对过就再也不看」；
   - 关联题：与错题同考点的其他问法（见第 9 条）。

   **间隔到期是强化练习的一个信号，不另设「今日待复习」队列**：错题本、考前复习、强化练习
   已经是三个相近的入口，再加一个只会让人不知道点哪个。

   `reason` 取值：`retest`（复测错题）、`weak`（薄弱章节的新题或久未见的题）、`due`（间隔
   到期的已答对题，兼作抽检已掌握内容、发现遗忘）、`variant`（错题的同考点变式）。初始配额
   retest 40%、weak 30%、due 30%；某类不足时按 retest、weak、due 的顺序补足；考点簇就绪后
   variant 占 retest 配额的一半。默认 20 题，可调。
8. **沿用既有出题约束**：每题每轮最多一次（driver ADR 0031）、偏难怪题封顶（driver
   ADR 0032）、科目一过关才开科目四（driver ADR 0006、0044）。可选题不足或新学习者没有数据时，
   退回按公开错误率抽题（driver ADR 0027），并在结果页说明。

### C. 考点簇与派生统计

9. **考点簇由离线脚本生成只读索引**，不作为数据源头、不进 git（同主仓库 ADR 0068 对生成索引
   的定位）。原因：`topic_id` 太粗——科目一 2497 题只有 11 个知识点，同知识点只等于同章节；
   出处条款作键又太稀，绝大多数条款只被一道题引用。因此用「出处条款加题干文本相似度」聚类，
   **上线前人工抽查一批簇的质量**。没有索引时 `variant` 不出现，配额并入 `weak`。
10. **派生统计分两批，都由记录派生、不新建表**（主仓库 ADR 0052）。数据量只有几千条作答、
    基本一个学习者，样本小，章节与题目的估计一律用收缩，不用裸正确率。
    - **本期做**（只用现有记录）：掌握度漏斗（新题、学习中、巩固=连对 2 次、稳固=连对跨过
      至少两个日期）；优先章节（按「该章预计丢分」排序，说明强化练习为什么偏向这些章）；
      通过概率（按模拟考抽题规则做蒙特卡洛抽卷）。**通过概率必须与最近几场模拟考的实测成绩
      并列展示，并给出区间，不单独给一个精确百分比**：实测比模拟更可信，模拟只在「还有很多
      题没做过」时才提供额外信息。
    - **后做**：个人遗忘率、错因分类（用时加对错加 `chosen`）、混淆对、与公开错误率对照
      （自编题没有错误率，覆盖不全）、强化练习的转正率与变式差距。其中不需要题库内容的
      （遗忘率、错因分类）适合放仪表盘从作答直接算。

### D. 兼容、顺序与边界

11. **兼容与上线顺序**：
    - 服务端现状是**拒绝未知字段**。若客户端先升级，新字段会得到 400，被同步器判为
      `SyncInvalid` 而**标死**。所以必须**先部署服务端，再发客户端**。
    - 本地库老版本升级自动 `ALTER TABLE` 加列（沿用 driver ADR 0057 的做法）。
    - 中心库加列与建 `explain_views` 表由属主脚本完成（API 角色没有 DDL，主仓库 ADR 0068
      决策 6），幂等。
    - 旧客户端不带新字段上传，服务端缺省为空，不受影响。
12. **边界（不做）**：
    - 不记「迟疑」或自评信心（driver ADR 0020 刻意撤掉了迟疑，防止出现答对却卡在中间态的
      死角）；
    - 不采集设备、系统账号、主机名等标识来区分学习者（编号已是身份，主仓库 ADR 0075）；
    - 不做跨学习者的聚合挖掘，家里几个人既没有样本，也不该互相比较。

## 后果

- 作答记录的体积略增，同步契约多一个资源；旧数据这些列为空，统计要区分空值与零。
- `session_id` 要同时写进考试草稿，草稿结构随之多一个字段（续答兼容旧草稿：缺失则新起会话）。
- 强化练习的选题是纯函数（输入记录和题库，输出题单），可以脱离界面单测。
- 仪表盘与 API 的并行改动区（`practice/nas_admin`）会受影响，实现前要与正在改它的人错开。
