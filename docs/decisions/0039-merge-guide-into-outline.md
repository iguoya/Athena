# ADR 0039：撤销「本章导览」，主旨并入教学大纲

- 日期：2026-09-12
- 状态：已接受；`cpp.TypeSemantics` 已合并，后续章节不再新建导览标签
- 取代：ADR 0036（「本章导览」置于首位，作为极简概要）
- 延续：ADR 0028（大纲 / 教学过程 / 教学实验三层分工）、ADR 0033（能算出来的画成活的）

## 背景

ADR 0036 在章节页第一位放了「本章导览」，定位是极简概要：只给结论不给理由，
回答"这一章有什么、怎么串起来、哪个重哪个难"，理由留给第二个标签「教学大纲」。

实现之后对着页面看，两个标签的实际内容是这样的：

| 导览里的块 | 大纲里的对应 |
|---|---|
| 「这一章要解决什么」 | 同名 Frame，**同一句话**，外加五类风险与心智模型 |
| 「读代码时的五个检查点」 | 同名 Frame，五条逐条展开，外加一张判断流程图 |
| 「每个知识点解决什么，学到什么程度」四档清单 | 「先看主次与顺序」四档 callout，同样的分档，外加每档的评定理由 |
| 按难度配色的知识点路线图 | 按掌握目标配色的知识点路线图，同一批数据 |

四块内容没有一块是大纲没有的。导览提供的"少"不是别的信息，而是**同一份信息的
缩写**——这正是 ADR 0034 删掉 Markdown 手册时要消灭的东西：两份内容讲同一件事，
改一处忘另一处，迟早漂移。事实上它已经漂了：导览的图注写着"要知道为什么这样排，
进「教学大纲」"，而大纲的对应位置没有任何指回导览的话，两边的读者路径并不对称。

ADR 0036 的判断里有一条是对的：**读者需要先看见轻重缓急，再进入细节**。但那件事
大纲自己就能做，靠的是它内部的顺序——「先看主次与顺序」本来就排在讲什么与边界
之前。为此多开一个标签，收益抵不上多维护一份内容的代价。

## 决策

**章节页不再有「本章导览」标签。** 第一个标签就是「教学大纲」，它继续承担
ADR 0028 第一层的全部职责：指方向、划边界、标难度与掌握目标、说明理由。

导览独有的那一点东西并入大纲：

- 知识点路线图改用**难度**配色，节点上写掌握目标文字，底部细条仍是当前熟练度。
  一张图同时给出先修顺序、难度、掌握目标、熟练度四项，四项各自有独立的视觉编码，
  不违反 ADR 0033「不同维度不共用一套编码」。原先大纲那张按掌握目标配色的图与
  「先看主次与顺序」的四档 callout 表达的是同一件事，改配色之后不再重复。
- 其余三块（这一章要解决什么、五个检查点、四档分级）大纲本就有更完整的版本，
  直接删掉导览里的缩写版。

## 后果

**得到**：一章一份大纲，不存在"两份内容会漂移"的结构；读者不必在两个标签之间
判断该看哪一个；路线图从两张减到一张，维护和视觉编码都更清楚。

**付出**：大纲比导览长，想要"三十秒扫一眼"的读者需要自己往下翻——这由大纲内部的
排序来解决（主次与顺序在前、细节在后），不再靠单开一个标签。

**连带**：`AGENTS.md` 里「每章第一个标签是「本章导览」」那条规则随之作废；
`render/roadmap_view` 的两种配色仍然都保留（它是通用组件，别处可能用到），只是
这一章现在只实例化一张；相关测试的标签页数从 9 改为 8。
