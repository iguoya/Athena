# ADR 0153：新增 snake——用做一只贪吃蛇学游戏循环

- 日期：2026-10-12
- 状态：已接受（使用者 2026-10-12：「行吧 按照你说的来。参照中国象棋项目的写法，分步骤循序渐进，讲解演示整个实现过程，逐层推进、每层留痕」；技术栈在此之前已议定为 C++ + raylib + CMake）
- 关系：教程壳遵循 ADR 0138（Tauri 2 + React），复制自 chinese-chess 壳；贪吃蛇本体按 ADR 0133 的异构准入用 raylib；归类按 [docs/REPOSITORY.md](../REPOSITORY.md) 的三类判据；每章独立工程的做法与 ADR 0151 同理由

## 背景

1. 使用者要以一只贪吃蛇作为游戏开发的入门练习，先易后难，逐层推进。技术栈议定为
   C++ + raylib + CMake；raylib 把窗口、输入、绘制、音频吃进一个库，是 immediate
   mode，没有 gtkmm 那样的界面文件层。
2. 讲解分五章，每章一个循序渐进、能独立编译的子程序，源码按章节放 `exercise/`。
   第 5 章是当前能玩的版本。
3. 三类判据：要教会人游戏循环、固定步进、输入缓冲、状态机和插值渲染是怎么写出来的，
   并用可运行的程序和预测作答作为证据，所以是学习应用，不放进 `practice/`。

## 决策

1. 新增 `programming/snake`。id `snake`（完整英文词），界面名「贪吃蛇」，进程
   `athena-snake`，知识点前缀 `snake.`，端口 **1514**。`group` 为「程序设计」，不设
   `parent`。
2. 教程壳是 Tauri 2 + React，照 chinese-chess 壳改名而来；壳不画蛇，只读章节、记录
   作答、按白名单编译并启动某一章。贪吃蛇本体是 raylib 5 / C++20 / CMake，五章各自
   一个工程：窗口与循环、网格与步进、蛇身与输入、状态机与计分、手感与测试。
3. 出处档位 **open**。学习方法主原型是真做校验，辅预测–运行。
4. 只有键盘输入，没有 AI 对手。最高分演示性持久化在进程工作目录，真实程序应写用户
   数据目录，这一差别在第 4 章讲解里说明。
5. 默认的 `scripts/check.py` 不编译 raylib，避免没有这套工具链的 CI 失败。本机用
   `--native` 编译五章并跑第 5 章的逻辑测试。

## 后果

- 根 `Cargo.toml` 增加本应用的 `src-tauri` 成员。pnpm 工作区已经包含 `programming/*`。
- 发版清单不加入本应用，等贪吃蛇和教程都稳定后再说。
- 五章源码有意重复，理由与 ADR 0151 相同：合并成一个库会让「这一章当时只有这些代码」
  讲不清楚。raylib 没有界面文件，每章只有一份程序，讲解直接以主程序为主路径。
