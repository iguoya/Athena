# ADR 0078：登录合并为一步——名字不存在就直接新建（修订 ADR 0075 决策 3）

- 日期：2026-10-03
- 状态：已接受；修订 ADR 0075 决策 3（「新建是显式动作，与进入分开；新建后显著展示编号」）
- 影响：`subjects/driver`（登录页、进入应用后的提示）；ADR 0075 的其余各条继续有效
- 延续：ADR 0071（无口令的信任模型）、0075（按名字登录）、0077（应用里不认证）

## 背景

ADR 0075 把「进入」和「新建」分成两个动作：名字不存在时提示去点「新建」，新建成功后弹一个
挡住界面的「你的学习者编号是 N」对话框，点掉才进入。新学习者因此要经过三步：输入名字点进入、
看到「没有这个学习者」、再点新建、再点掉编号弹窗。

使用者的判断是：学习者体系本来就**弱限制、效率方便为主**（无口令，几个家人用），这些确认步骤
是为一个很少发生的情况（输错名字）付出的固定代价，应该合并。

## 决策

1. **「进入」一步到位。**输入名字点进入（或回车）：
   - 恰好一个同名者 → 进入；
   - 不止一个 → 页面上出现编号输入框（同一页），输入后进入；
   - **一个都没有 → 直接新建这位学习者并进入**，不再让使用者去另找「新建」按钮。
2. **编号不再用弹窗拦人。**新建后直接进入应用，用一条不挡路的提示条告诉使用者分到的编号，
   并说明「在别的电脑登录遇到同名会问这个编号」，十几秒后自动消失，也可以点掉。
3. **输错名字的代价很小，不另加确认。**输错会得到一个空白的新学习者；侧栏点学习者行就能换人、
   也能改自己的名字，所以输错的补救是「换回正确的名字」或「把这个名字改对」。目录里留下一个
   没用的空学习者无害（不提供删除，编号上限 999 对家用足够）。
4. **保留「新建」按钮，降为次要入口**，只用于「另一个人和已有的人同名」这种少见情况；名字已有人
   用时仍先确认一次（ADR 0075 决策 3 的那条确认保留在这条路径上）。
5. **界面里不再出现「令牌」一词。**设备令牌已取消（ADR 0077）；外网访问凭据在界面里称为
   「Cloudflare 给的一对 ID 和密钥」，且只在离开内网时才需要。

## 后果

- 新学习者的流程从三步变成一步；已有学习者不受影响。
- 手误会建出空学习者，且无法删除；换回正确名字即可，不影响任何已有记录。若将来目录里冗余的
  条目多到碍事，再加「合并或删除」，不在本 ADR 范围。
- 登录页的回调多一个「是否新建」的信息，由启动门在进入后显示提示条。
