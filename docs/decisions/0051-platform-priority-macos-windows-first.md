# ADR 0051：平台优先级——macOS 与 Windows 优先，Linux 降级

- 日期：2026-09-15
- 状态：已接受
- 范围：**整个仓库**，所有学习应用与启动器
- 关系：给 [ADR 0047](0047-portable-by-default.md) 的「跨平台优先」和
  [ADR 0049](0049-portability-is-a-cost-benefit-call.md) 的成本收益判断补上**权重**；
  影响 [ADR 0050](0050-ci-runs-on-release-not-every-push.md) 的矩阵构成

## 背景

ADR 0047 把三个平台并列对待，ADR 0049 把跨平台改成成本收益判断，但两条都没说
**收益在不同平台上是不是等价的**。实际执行时这个空缺会带来错判：同样是一份移植
成本，花在 Linux 上和花在 Windows 上被当成一回事。

事实不是这样。用户主力开发在 macOS（ADR 0048），而实际使用与分发面向的是桌面主流
的 macOS 与 Windows。Linux 桌面是「能跑更好」，不是必须保住的那一档。

## 决策

**优先级：macOS ≈ Windows > Linux。** 不是放弃 Linux，是排序——遇到取舍先保前两个。

**1. 技术选型**：候选方案在 macOS 与 Windows 上的成熟度是**硬指标**，Linux 上的
表现是加分项。在 Linux 上是一等公民、却要在 Windows 上跟上游缺陷缠斗的框架，在这个
排序下是**减分**的。

**2. CI 覆盖**：Windows 的 job 不该停留在 `continue-on-error` 的实验性探测位——
它是优先平台，就该是正式门槛。Linux 的 job 反过来可以放松，回归了不阻塞发布。

**3. 修问题的顺序**：同时冒出来的平台问题，先修 Windows 与 macOS 的。Linux 特有的
坑（Wayland 出于安全不允许抢焦点、GNOME 默认没有托盘区）停在如实降级提示上就够，
不投入进一步工作。

**4. 已排除的仍然排除。** 本条不推翻 ADR 0049 的排除清单——排除是按成本判的，
优先级只改变「值不值得投入」的权重，不改变「上游不修就是修不了」的事实。

## 后果

- CI 矩阵里 macOS 与 Windows 在前、Linux 在后，Windows 转为正式门槛。
- **`apps/cpp` 的技术选型与这条优先级方向相反，需要一次单独的决定。** 它用
  GTK4/gtkmm：在 Linux 上是一等公民，在 macOS 上可用，**在 Windows 上被上游的
  包版本脱节挡住**——MSYS2 仓库里 glib 已到 2.90，glibmm 还停在 2.86，而上游
  glibmm 2.89.0（2026-08-10）早已适配（ADR 0049 的实测更正写清了全部细节）。
  这既不是 gtkmm 不能用于 Windows，也不是上游未解决：属于我们自己代码的那两处
  POSIX 专有写法（`LC_MESSAGES`、`M_PI`）已经修完，MSYS2 的包一跟上就能通过。
  也就是说，仓库里最核心的那个应用，恰好只在新排序里最次要的平台上表现最好。
  三条路各有代价，本 ADR 不替它做选择：
  1. 接受 C++ 教程只在 macOS 与 Linux 可用——与本优先级冲突，但零成本；
  2. 等上游修好 gtkmm 的头文件冲突——时间不由我们决定；
  3. 换界面技术（例如像 `apps/c` 那样走 Qt）——Windows 与 macOS 都能拿到一等
     公民待遇，代价是重写整个界面层，是这个仓库里最大的一笔工程。
- 新增应用选型时，这条优先级即刻生效：先确认 macOS 与 Windows，再看 Linux。
