# ADR 0159：互联网上能找到的数据一律默认公域，九州学术层直接入库

- 日期：2026-10-14
- 状态：已接受（使用者：自用项目，网上能找到的数据一律默认公域，不要自我束缚）
- 取代：[ADR 0158](0158-jiuzhou-local-academic-maps-expressiveness.md) 的决策 1、2
  （学术层只放本机 `.cache`、禁止入库）；[ADR 0157](0157-athena-maps-shared-package.md)
  决策 3 与背景第 2 条、[ADR 0156](0156-jiuzhou-history-atlas.md) 中「禁止再分发、仅本机可选、
  不入库」的表述
- 保留：0158 的决策 3–5（表述手段、实施顺序、`@athena/maps` 职责）不变

## 背景

0156–0158 把 CHGIS / Hartwell / 谭图数字化这类数据定为「禁止再分发、本机可选、不入 git、
无则降级」。这与使用者一贯的立场相冲突：Athena 是自用软件，网上能找到的材料直接用，不按
授权分「公开 / 只放本机」，出处照记（此前已为同类分流撤过一整套机制，见 ascent ADR 0026）。
代理又一次凭「许可证可能禁止再分发」自己给自己加了约束。

这套约束的实际代价已经显现：

- `.cache/maps/academic`、`chgis` 至今是空的，九州一直只跑示意底图，学术层没起过作用。
- 前端并未读取 `manifest.json`（`INTENT-CHECKLIST` 第 14 项），`prepare_local_maps.py`、
  `ATHENA_MAPS_DATA`、「有则叠、无则降级」基本只是脚手架，却要求以后每一步写两条路径。
- 数据只在一台机器上，换机器、云会话、新 clone 都拿不到。

## 决策

1. **通则：互联网上能找到的数据，一律默认公域。** 不查许可证、不为授权设计分流机制
   （「只放本机」「本机可选」「有则叠、无则降级」「勿提交」），不以授权为由拒绝入库，
   也不反复提醒。出处照记，ADR 0043 的底线（不凭印象伪造出处）不变。写进根 `AGENTS.md`。
2. **学术地理数据直接入库**：CHGIS / Hartwell / 谭图数字化等转成 WGS84 GeoJSON 后，放
   `packages/maps/geo/academic/`，随仓库提交、推送。体积大的包先按朝代或年份切文件，
   以应用能按需载入为度；确实过大再按工程理由另议，不预先设计。
3. **取消本机分流机制**：删除 `prepare_local_maps.py`、`ATHENA_MAPS_DATA`、
   `.cache/maps/manifest.json` 与 `LOCAL-MAPS.md`；应用直接读包内数据。示意疆域帧
   （`territories.json`）照旧作为学术层覆盖不到的时段的底色，按 `schematic` / `snapshot`
   标注，它是内容分级，不是降级路径。
4. **出处照记**：数据旁放一份说明，写来源、版本与下载地址。不凭印象写，写之前下载原包核对。
5. **体积不是授权**：整本 PDF、GGUF 模型这类大文件放不放仓库，按工程理由（体积、可重新
   下载）定，与授权无关；`.cache/` 继续放可重新下载的中间物，如 Natural Earth 原始 zip。

## 后果

- 九州在任何机器、云会话上都能看到同样的学术层。
- 仓库会变大；按第 2 条控制，超限时再单独决定。
- 其他应用里已有的类似表述（如 `machine` 的 `fetch-sources.py` 与 `catalog.json` 里
  「PDF 不进 git」「只供本机查阅」）不在本 ADR 内改动，遇到时按第 1 条处理。
