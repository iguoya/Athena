# ADR 0029：知识点按难度与掌握目标两个维度评级

- 日期：2026-09-10
- 状态：已接受，全部 77 个知识点已评定
- 取代：原 `subchapter.importance` 单一字段

## 背景

`athena.json` 原来只有一个 `importance` 字段（0–5），文档说它是“内容难度／重要度”，
两种含义混在一起。界面上因此出现了互相矛盾的表述：章节页把同一个数值显示为
“内容难度：简单／一般／正常／复杂／极难”，学习页的标签提示却写“知识点重要度 n/5”。

对学习者来说，这一个数字回答不了两个不同的问题：

- **这个知识点有多难？** 决定现在学还是先跳过。高难度内容排在前面会劝退初学者。
- **要学到什么程度？** 决定花多少时间、要不要反复练。难度和掌握要求并不同步：
  移动语义难，但必须掌握；`const` 正确性简单，却要精通到能一眼看出接口是否写对；
  协程难，日常却只需知道它存在。

用一个数值同时表达这两件事，结果是两件事都表达不清，学习者既分不清主次，也分不清难易。

## 决策

1. **`importance` 拆成两个独立字段。** `difficulty` 只表达难度，`mastery_goal` 只表达
   掌握目标。两者分别校验、分别显示，不互相推导，也不合成单一评分。
2. **`difficulty`：0–5。** 0 未评，1–5 依次为入门、简单、中等、进阶、高级。
   **1–3 是初中级**，初学者应当拿下；**4–5 是高级**，可以先跳过、以后回来补。
   沿用原 `importance` 的数值和色阶，不重新评分。
3. **`mastery_goal`：三档。** `master` 需要精通（反复使用，要能解释边界并写对）、
   `required` 必须掌握（能正确使用，并说明为什么这样选）、`familiar` 一般了解
   （知道它存在和适用场景，需要时能查）。空串表示未评定，只有练习类章节才留空。
4. **精通要稀缺。** 如果多数知识点都标成需要精通，这一维度就失去了分清主次的作用。
   当前 77 个知识点里约四分之一是 `master`，集中在天天要用、写错代价高的地基上。
5. **两个维度都是内容作者的只读标注**，与 AI 自测得出的“熟练度”是不同概念：
   后者是学习者的当前状态，存在本地数据库；前者只存在 `athena.json`。
   字段取名 `mastery_goal` 而不是 `mastery`，正是为了不和熟练度混淆。
6. **教学大纲也要按这两个维度说明重点。** 大纲负责指方向，因此要写清哪些是本章
   必须拿下的地基、哪些是初学者可以暂缓的高级内容，并与配置里的评级保持一致。

## 后果

- 新增知识点时要同时给出两个评级；只给难度不给掌握目标，等于没说清它在学习路径里的位置。
- 界面上知识点标题旁并排显示难度徽章与掌握目标徽章，色系分开：难度用绿→红表示“多难”，
  掌握目标用蓝／青／灰表示“要学到什么程度”，避免颜色互相暗示。
- 评级会随着内容实际写出来而调整。改评级要同时看两个维度，不能只改一个数字。
- 章节难度（知识图谱节点上的那一项）仍取本章已评知识点 `difficulty` 的平均值；
  掌握目标不参与平均，因为“精通”不是可以被平均掉的要求。
