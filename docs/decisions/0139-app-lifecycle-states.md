# ADR 0139：应用生命周期状态——`app.json` 新增 `lifecycle` 字段，启动器按状态分层呈现

- 日期：2026-10-11
- 状态：已接受（tiger 2026-10-11：采纳「活跃学习 / 建成待学 / 冻结归档」三档，做成 `app.json`
  字段，启动器按状态决定呈现层级）
- 衔接：[ADR 0129](0129-prefer-quality-over-quantity.md)（宁缺毋滥：本篇给「空骨架该删」
  提供一个比删除温和的中间态）；[ADR 0093](0093-drop-practice-panel.md)（`hidden` 是显示层
  的永久开关，语义不变，与本字段独立）；[ADR 0094](0094-no-category-labels-in-launcher.md)
  （启动器无类别标签——生命周期不是领域类别，不违反）；[ADR 0083](0083-launcher-mind-map.md)
  （思维导图呈现）

## 背景

1. **应用数量已经超过一个人能真实学习的数量。** 32 个应用平铺在启动器里，其中 11 个是
   ADR 0122「一次落齐」的占位壳（内容文件不足 60 行、全 placeholder），另有 linux、
   organization、cs408 的章目录齐全但 topics 全空。判据驱动（REPOSITORY.md「三类判据」）
   解决的是「这是什么类」，解决不了「现在还学不学」。
2. **呈现上没有中间态。** 应用要么正常出现，要么 `hidden` 彻底消失（ADR 0093，语义是
   生产服务不进面板）。「内容已建成等待排期」「暂时冻结、可能回来」这两种真实状态
   在启动器里都与活跃应用同等权重，注意力被持续收税。
3. ADR 0129 已确立「宁缺毋滥」：空骨架不留占位。但删除是重动作（要打 tag、写清取回
   方式），对一个「立项没错、只是还没轮到」的应用过于激进。

## 决策

1. **`app.json` 新增可选字段 `lifecycle`，三档枚举**：
   - `"active"`（活跃学习，**默认**，不写即是）：正在学或工具常驻。
   - `"built"`（建成待学）：教学内容已成体系、真实学习还没排上——呈现但降视觉权重。
   - `"archived"`（冻结归档）：当前不在学习计划里——默认不呈现，可按需显示。
2. **呈现层级（启动器 webui，两个视图一致）**：
   - `active`：正常呈现。
   - `built`：节点淡显（3D 行星与标签、思维导图图块均降透明度），悬停可看清；
     含义是「看得见、在待办上」。
   - `archived`：catalog 与思维导图默认均不呈现（过滤规则与 `hidden` 同层叠加）；
     思维导图工具栏提供「显示归档」开关，打开后归档节点以淡显 + 灰度出现。
     3D 轨道视图不做开关——要看归档清单，切思维导图。
3. **布局拓扑不变。** `lifecycle` 不参与 mindmap/layout3d 布局：归档应用从可见清单消失后，
   指向它的 `parent` / `related` / `also_under` 连线按既有规则自动忽略（找不到的 id 布局时
   忽略）。恢复 active 归位，无需迁移任何关系数据。
4. **`hidden` 语义不变（ADR 0093）。** `hidden` 是显示层的永久开关（nas-admin 这类生产
   服务），`lifecycle` 是学习生命周期的阶段标注；两者独立声明、过滤规则叠加。编排不受
   任何一档影响：`open` / `stop` / `sync` 对归档应用照常可用。
5. **机器可读出口：`launcher list --json` 每行带 `lifecycle`。** macOS 菜单栏版（ADR 0048）
   消费该字段自然跟进，不阻塞本决定落地。
6. **校验：根 `scripts/check.py` 结构卫生检查 `lifecycle` 枚举合法**；启动器解析到未知值
   时点名并按 `active` 处理（与 `icon.renders` 写错同策：不让启动器起不来，但要说清是谁）。
7. **首批标注（判据：未来六个月会不会真的坐下来学，按内容与使用证据，不按工程劳动）**：
   - `archived`（13）：python、machine-learning、deep-learning、llm-app、llm-finetune、
     os、network、database、firmware、microcontroller、rtos（11 个 ADR 0122 占位壳，
     内容不足 60 行）+ linux、organization（章目录全空）。
   - `built`（3）：design-patterns、data-structures、algorithms——实验内容已成体系
     （2.2 万 / 3.7 千 / 1.2 千行可跑实验），但进度库全表 0 行，真实学习未启动。
   - **其余一律不写字段**（默认 active）。cs408 是否归档牵动五门课本体的挂靠呈现，
     machine 改造进行中，均留待使用者单独拍板；practice/ 与图谱/参考类默认 active，
     字段对它们语义弱，不标。
   - 标注不是判决：改一行 JSON 即可调档，无需任何代码或数据迁移。
8. **改名不删位。** 本字段不授权删除任何应用；按 0129 真要删除时，仍走该篇的显式删除
   程序（打 tag、提交信息写清取回方式）。

## 后果

- 启动器默认视图从 28+4 个节点收敛到真实在学的十几个，归档内容一条开关之遥，不再
  需要时也不丢。
- 「建了壳等着将来做」从此有了诚实的表达：要么标 archived 承认不在计划上，要么按
  0129 删——不再有第三种「看起来在计划上」的占位。
- 3D 视图无归档开关是刻意的：归档是低频查看，不值得为它在常驻视图常设控件。
- `fingerprint`（launcher-core manifest）因 `App` 增字段自动把 lifecycle 纳入清单指纹，
  改档即触发界面重建，无需额外处理。
