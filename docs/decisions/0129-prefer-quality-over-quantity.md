# ADR 0129：内容工作宁缺毋滥（取代 ADR 0054 的「宁增勿删」）

- 日期：2026-10-11
- 状态：已接受（tiger 2026-10-11：「宁增勿删」大原则改为「宁缺毋滥」）
- 取代：[ADR 0054](0054-prefer-adding-over-deleting.md) 的总原则与第 2 条（新方向只增不覆盖、旧的先留着）
- 保留：0054 第 1、3、4、5 条（见决策 3），[ADR 0080](0080-reorg-exemption-when-intent-changes.md) 对第 3 条的豁免继续有效

## 背景

ADR 0054 是针对一次具体事故定的：执行者把「参考 X」读成重划结构的许可，沿用 `id` 悄悄
替换内容，原内容差点永久丢失。当时的结论「宁增勿删」是防止**悄悄丢东西**的手段。

事后一个月，这条原则的副作用显现了：

- 仓库有 33 个应用，其中约 14 个只有 1～2 个文件的内容骨架（4～8KB），却各自配齐了
  壳、`AGENTS.md`、`app.json` 和检查脚本——「先占位，以后再写」被「旧的不删」鼓励成习惯。
- 「新方向用新增表达、旧的先留着」让冗余只增不减，侧栏、启动器、规则文本一起变长；
  规则文本膨胀又让每次会话读入的上下文变大。
- 学习内容的价值在于**被认真做过、被证明有效**，而不在于数量。占位的空壳和过时的
  内容不是中性的：它们占用维护成本，也稀释使用者对「这里有什么」的判断。

## 决策

1. **总原则：宁缺毋滥。** 内容的取舍标尺是质量与真实学习价值，不是数量或覆盖面。
   没打算认真做的条目、空骨架、已被更好表达取代的旧内容，**不保留占位**；该删就删，
   该替换就替换，该合并就合并。
2. **取代 0054 第 2 条。** 「旧的看起来过时也先留着」「新方向只用新增表达」不再是默认。
   新视角可以新增，也可以直接改写旧条目；旧条目确实被取代的，删除。
3. **0054 的操作安全网保留，因为删除合法之后它们更重要**：
   - **参考不得悄悄重划结构**（0054 第 1 条）：使用者说「参考 X」只授权补深度、验收
     口径和取舍依据；要重划结构、改条目定位或名字，先问。这是授权边界，与增删无关。
   - **`id` 不改嫁**（第 3 条）：换定位就新起 `id`，旧 `id` 要么保留原意、要么删掉，
     不在原位上换内容。0080 的重组豁免仍可用于这一条。
   - **动内容之前先入库**（第 4 条）：第一次实质改动前先提交一版原样。
   - **删除必须显式**（第 5 条）：提交信息写清删了什么、为什么、在哪能取回（提交、
     分支或 tag）。大批量删除前打 tag。
4. **0080 的适用面收窄。** 重组豁免原本是为绕开 0054 第 2、3 条而设；第 2 条已取消，
   现在只剩对第 3 条（`id` 不改嫁）的豁免，`pre-<id>-reorg` tag 的做法保留。
5. **不受影响**：出处与语义基准（ADR 0043、0089）、先问再动结构的做法、ADR 只增不改。
   「宁缺毋滥」约束的是**要不要放进来**，不放宽「放进来的必须有出处、语义正确」。
6. **不自动清理存量。** 本 ADR 不删除任何现有内容或应用。哪些骨架保留、休眠或删除，
   由使用者逐个确认后分批执行（先出清点表，再动手）。

## 后果

- 新增内容的门槛提高：「以后再写」的空壳不再合规；新建应用要有可交付的第一批内容，
  `new-app` skill 据此补一条门槛。
- 审视旧内容时，「过时 / 低质 / 无人使用」成为删除的正当理由，不必再找降级位置安置。
- 依赖「宁增勿删」措辞的下游引用（`AGENTS.md`、`write-lesson`、`grill` 等 skill，
  各应用 ADR 的相关段落）改指本 ADR；已写入各应用 ADR 的历史引用保留原文。
- 误删的风险转由「先入库、显式删除、tag」兜底，而不是靠「不删」。
