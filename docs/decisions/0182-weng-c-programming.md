# ADR 0182：新增 `guide/weng-c-programming`——翁恺《C语言程序设计》视频课，确立「课堂工作台」（视频窗格 + 节拍 + 任务）

- 日期：2026-10-22
- 状态：已接受（使用者指示：「视频课程本身应该是我应用程序界面的一个组成部分，而不是全部」「把课堂练习、本节要点、课堂节奏、各种任务类型做出来，不能单纯看视频」；
  试点定为 B 站 2022 年版《浙江大学翁恺教你C语言程序设计！》第 3 集；登录与清晰度由使用者自己在应用内登录窗口处理）
- 关系：履行 [ADR 0180](0180-chen-linear-algebra-mooc.md) 决策 9（翁恺《C 语言》另立 ADR）；**修订**其决策 3 的播放档位 ③（见下）；
  形态沿 [ADR 0143](0143-guide-directory.md)；方法原型 [ADR 0113](0113-method-archetypes-per-course.md)、
  检索与间隔 [ADR 0096](0096-retrieval-spacing-interleaving-lead-curriculum.md)；掌握度只由作答写入 [ADR 0052](0052-incentives-and-records-cooperate.md)；
  应用独立 [ADR 0032](0032-independent-apps-launched-as-processes.md)；公域口径见 AGENTS.md 与 [ADR 0159](0159-jiuzhou-academic-layer-in-repo.md)；
  宁缺毋滥 [ADR 0129](0129-prefer-quality-over-quantity.md)
- 设计过程与验证：`comms/video-course/artifacts/claude-code/DESIGN-v2.md`、`SPIKE-player-bridge.md`；zcode 的评审与范例在 `artifacts/zcode/`

## 背景

ADR 0180 只做到「文本为底、视频外链」。使用者进一步要求视频成为应用界面里的**一个窗格**，应用要掌握课堂节奏、随时发任务，
而不是让人被动看视频。2026-10-22 的验证（`SPIKE-player-bridge.md`）表明：B 站官方外链播放器页面（`player.bilibili.com/player.html`）
放进 Tauri 应用的 webview 后，注入脚本能读播放时间、seek、暂停、续播，自然播放跨过暂停点能触发，拖动越过不触发；
还能用多 webview 把它与应用界面停靠在同一个窗口里。已知问题：页面偶发自己暂停（原因未明）；窗口不可见时定时器被降速；
未登录只有 360p，登录后清晰度才升高。

候选课程里，B 站有两份翁恺转载：2018 年 BV1Ls411w7rx（132 集、19.4 小时、播放 219 万）与 2022 年 BV1dr4y1n7vA
（100 集、14.2 小时、播放 **2119 万**，分集编号规整 `1.1.1` 起，含 PAT 习题解析与 ACLLib 附录，只覆盖入门 11 章）。
两者都是转载、都没有官方字幕。

## 决策

1. **新增 `guide/weng-c-programming`**，`group` 为「程序设计」。id 与目录名按「作者-课程」惯例；进程 `athena-weng-c-programming`；知识点前缀 `wengc.`；
   dev 端口 1532；进度库 `AthenaWengCProgramming/learning.db`，`attempts` 表 append（ADR 0037、0155）。学习应用，出处档位 `open`。
2. **底本版本**：以 B 站 **2022 年版 BV1dr4y1n7vA** 为准（播放量最高、编号整齐、有习题解析、入门部分完整）；2018 年版 BV1Ls411w7rx 记为备选，
   并作为进阶部分（第 11 章之后）的候选来源，要用时另行核对。视频只登记外链，不下载、不入库。
3. **课堂工作台**（修订 ADR 0180 决策 3 的档位 ③）：视频只是界面的**一个窗格**。窗口左侧是课堂区（节拍条、任务卡、要点卡、上机区），
   右侧是视频窗格；窗格可收起，收起后课堂区自己完整可用（课件段落、任务、要点、复习）。播放档位定义改为：
   ① 文本 + 外链；② 本地文件；③ **播放窗格**——B 站外链播放器页面 + 注入的播放桥。档位 ③ 的约束：
   - 停靠用 Tauri 多 webview（需 `unstable` 特性），升级 Tauri 时回归；退路是独立的伴随窗口；
   - 页面只被放行**一个**命令（`bridge_report`），capability 的 `remote.urls` 只含 `https://player.bilibili.com/*`；
   - 脚本只读时间/状态、执行 seek/pause/play，不下载、不抓取、不改页面内容，不依赖 B 站私有 API（只用标准 `<video>`）；
   - 暂停点以「自然播放跨过」判定，拖动越过按已过处理；意外暂停是正常状态，课堂区显示「已暂停，点这里继续」；
   - 播放窗格要保持可见，隐藏时暂停点精度不保证。
4. **登录与清晰度由使用者处理**：应用内提供「登录 B 站」按钮，打开 B 站**官方**登录页的独立窗口，登录状态存在应用自己的 webview 数据目录，
   应用不读取、不保存账号与密码；清晰度由使用者在播放窗格里自己选。
5. **课堂脚本与任务**：一节课 = 一串**节拍**（看一小段 → 一个任务 → 一句要点），开场有预测，收尾有出口题与要点确认；
   任务类型库见 DESIGN-v2（预测、填空补全、你来做、找错、排序、自我解释、速答、要点确认、回看）。
   每个节拍最多一个「重任务」，连续只看不动手的间隔默认不超过 4 分钟。数据以课堂脚本文件入库，时间戳由「边看边标」半自动产生。
6. **主原型 P 预测–运行，辅 E 真做校验**（ADR 0113）。「你来做」任务用本机 C 编译器编译运行并比对输出（ADR 0057 基线）；骨架代码不改一行也能编译运行（ADR 0059）。
7. **题源与出处**：进掌握度的题必须机器可核对（选择、数值、编译运行输出比对）。题源只许取自**视频里的例程与习题解析**（来自本课程自身），
   `relation` 只许 `verbatim`/`adapted`，`authored` 不入库；`locator` 写「P<分集号> <mm:ss>」，如「P3 05:12」。预测、自我解释、要点确认是教学动作，不判分、不进掌握度。
8. **文本底本**：本课程没有可下载的课件，文本底本是**本机语音转写**（Whisper）的段落快照，入库时注明「机器转写，未校对」并标取得日期与视频版本；
   例程代码以视频画面为准，转写里的代码念白只作索引。转写错误由使用者或 zcode 逐段校对后才进入精读文字。
9. **试点**：先只做 **2022 年版第 3 集**（`1.1.2 计算机的思维方式：重复是计算机最擅长的`，9 分 44 秒）一节，跑通播放桥 + 课堂脚本 + 登录 + 复习闭环，
   再按周推进（ADR 0129：没有可交付的第一批不扩张；没做的集不留占位）。分集编号注意：第 2 集是 `1.1.1`，第 3 集才是 `1.1.2`。
10. **与现有应用并存互不引用**：`machine`（C 与机器，Beej 系统视角）、`chen-linear-algebra-mooc` 与本应用各自独立；播放桥代码先在本应用里，
    等第二个视频课应用需要时再抽共用层（ADR 0132）。
11. **掌握度与观看分表**：掌握度只由作答写入；「观看位置」另表、本机存、不同步；视频路径/外链登记在内容里，不含个人信息。

## 后果

- 新增一个应用；登记 `REPOSITORY.md`、根 `README.md`、根 `AGENTS.md` 结构树、`ci.yml`、`LEARNING-METHODS.md` 画像。
- 应用需要开 Tauri `unstable` 特性并给 B 站播放器域名开放一个命令；这是新的安全面，已把范围收到最小，并写入 capability 与应用 `AGENTS.md`。
- 转写与节拍切分由 zcode 出初稿、claude-code 抽查（comms 舱 `video-course`）。
- 平台风险：B 站播放器页面改版可能使桥失效；只用标准 `<video>` 元素降低这个风险，失效时退回档位 ①（文本 + 外链）。
- 本机验证过 Windows（WebView2）；macOS、Linux 未验证，按 ADR 0051 的优先级逐个回归。
