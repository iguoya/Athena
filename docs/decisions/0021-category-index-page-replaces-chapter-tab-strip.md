# ADR 0021：分类索引页取代常驻章节标签条

- 日期：2026-08-30
- 状态：已接受，实施中
- 依据：与 ADR 0001（数据驱动章节模型）、`docs/ARCHITECTURE.md` 第 3、7 节的导航
  描述对照；用户对首屏空间和横向标签条的反馈

## 背景

进入一个分类后，顶部是常驻的横向章节标签条（`window.blp` 的 `chapter_tab_box`
FlowBox），下方是 `chapter_stack`。cpp 分类有 14 章，加上"欢迎页面 / 学习进度 /
手册"三个合成标签，条子在常见窗口宽度下换行成多排，占掉首屏可观高度；dp 分类有
23 章，问题更明显。

cpp 的"欢迎页面"是一份手写 `welcome.blp`：一个 560px 的老虎主视觉 + "学习路线预览"
+ "学习特色"三块通用文案，真正能帮助导航的信息（有哪些章节、每章讲什么）反而不在
这一页。欢迎页也只有 cpp 有，其余分类进去直接落在第一章。

## 决策

### 1. 每个分类有一张生成的索引页，作为进入分类的默认页

- 索引页由 `MainWindow` 依据 `ChapterCatalog` 为每个分类构建（与首页分类网格、
  学习进度页同类：数据驱动、非 `athena.json` 章节），实现放在 `ui/chapter_index_page`。
- 版式是自适应流式网格（复用首页 `home-tile` 的视觉），每格一章：图标 + 标题 +
  简介，点击进入该章。章节按 `athena.json` 声明顺序排列，不引入 `stage` 之类新字段；
  真正需要分组时另开 ADR。
- 不做字面"九宫格"：分类章节数从 1 到 23 不等，格子数由宽度自适应换行决定。

### 2. 移除常驻章节标签条

- `window.blp` 删除 `tab_scroll` / `chapter_tab_box` 及其下的分隔线；`content_area`
  只剩 `chapter_stack`。
- `ui/chapter_nav_strip` 重命名为 `ui/chapter_page_stack`：只封装 `Gtk::Stack` 的
  子页占位、替换、切换和常驻页保留，不再装配 ToggleButton 标签。这是"边界划错就
  重新切分"（`AGENTS.md` 架构原则）——标签条职责消失，模块随之收窄。

### 3. 章节间横向切换由顶栏的章节切换器承担

- 顶栏（`top_bar`）在"首页"按钮和面包屑之后放一个 `Gtk::MenuButton`：在索引页显示
  "目录"，进入某章后显示该章标题。
- 弹出层按顺序列出：目录（回到本分类索引页）、本分类各章、（仅 cpp）学习进度、手册。
- 面包屑文本保持 `›  <分类标题>`；进入章节后追加 `›  <章节标题>`。

### 4. 欢迎页面退场

- `athena.json` 删除 cpp 的 `Welcome` 章节，删除 `resources/ui/chapters/welcome.blp`
  及其资源测试。老虎主视觉 `resources/icons/tiger.svg` 只被欢迎页引用，一并删除；
  应用图标是另一份 `resources/icons/scalable/apps/cn.athena.icon.svg`，不受影响。
- "学习路线预览""学习特色"这类通用文案不迁移：索引页用真实章节标题和简介表达
  同样的信息，且始终与配置一致。

### 5. 学习进度与手册

- 两者仍是 cpp（进度）/ 各分类（手册）的合成页面，登记进 `chapter_page_stack`。
- 入口从"标签条上的合成标签"改为"索引页网格里的特殊卡片 + 章节切换器里的条目"。
- 手册页仍常驻 Stack、懒构建一次；进度页仍每次激活时重建（与 ADR 保持一致）。

## 后果

- 进入分类先看到完整章节地图，首屏不再被换行标签条占据；老虎图标腾出的空间给了
  真实内容。
- 导航模型对四个分类一致：首页（分类）→ 索引页（章节）→ 章节页；横向切换走顶栏
  切换器，不依赖常驻控件。
- `MainWindow` 不再有"遇到欢迎页就插入进度/手册标签"的顺序耦合逻辑；索引页和切换器
  各自从 catalog 派生条目。
- `ARCHITECTURE.md` 第 3、7 节及依赖图需同步：`ChapterNavStrip` → `ChapterPageStack`，
  新增 `ChapterIndexPage`。
- `gtk_resource_test` 删除三个欢迎页用例，`window.ui` 用例去掉 `chapter_tab_box` 断言。
- 与 `docs/LEARNING_WORKSPACE_*` 提案不冲突：工作台改的是"进入某章之后"的文档与
  实验交互，本 ADR 改的是"进入某章之前"的分类内导航。

## 修订（2026-08-30，同日）

按用户反馈微调，不改变"无常驻标签条 + 分类索引页 + 顶栏切换器"的核心决策：

- **cpp 分类索引页顶部加一条学习路线预览条**：`chapter_index_page` 在章节网格上方
  渲染 `ChapterIndexSpec::roadmap`（五个阶段：基础入门 / 面向对象 / STL 标准库 /
  现代 C++ / 项目实战），阶段数据由 `MainWindow` 在 `category_name == "cpp"` 时填入，
  不来自 `athena.json`，其他分类不提供。这是进入具体章节前的一次性全局印象，不是
  可点击入口，也不恢复已删除的 `welcome.blp`。§4"通用文案不迁移"仅放宽这一条。
  （放在分类内而非首页：首页是跨分类入口，C++ 专属路线摆在那里逻辑不对。）
- **面包屑分类名可点击**：`breadcrumb_label`（Label）换成 `breadcrumb_box`（Box），
  分类名渲染为 `breadcrumb-link` 按钮，点击回到本分类索引页；其余层级仍是纯文本。
  §3"面包屑文本保持 `›  <分类标题>`"相应更新为分类名是链接。
- **应用底纹**：`.app-content` / `.athena-window` 叠一层极淡的 CSS 渐变（两个对角
  光晕 + 白→浅灰纵向过渡），不引图片资源。项目仍只有浅色一套调色板。

## 修订（2026-08-31）：C++ 索引与知识图谱合一

用户实际使用独立知识图谱后确认前置关系很有价值，同时指出它和 C++ 章节网格重复。
因此 C++ 分类的“目录”直接改为知识图谱，不再保留独立“知识图谱”工具卡片、Stack
页面或顶栏切换器条目；其他分类仍使用原来的自适应 FlowBox。

- 图谱节点沿用章节卡片的信息密度，不压缩成只有标题的统计标签：显示章节图标、标题、
  两行简介并点击进入章节。
- 节点同时显示三个明确分开的指标：章节重要度是本章已评知识点 `importance` 的平均值
  四舍五入到 1–5；掌握程度是达到 5 星的知识点数；完成程度沿用既有“平均熟练度 / 5”
  口径，1–4 星同样计入进度。
- 三个指标分别使用节点边框、灰/橙/绿掌握徽章、由浅到深的蓝色完成进度条；右侧说明栏
  列出颜色和计算方式，不能让颜色依赖用户猜测。
- Cairo 只绘制前置连线和箭头；节点使用真实 GTK Button，以保留图标、多行排版、
  Tooltip、hover、键盘焦点和无障碍语义。
- 2026-08-30 修订里增加的静态五阶段“学习路线预览条”由真实 `prerequisites` 图谱取代，
  避免同时维护抽象阶段和具体依赖两套路线上下文。
- C++ 返回目录时按最新 `LearningStore` 熟练度重建图谱；学习进度与手册仍是图谱之外的
  工具入口，不伪装成有前置依赖的知识节点。

## 修订（2026-08-31）：以 2K 屏幕为图谱布局基线

实际使用设备最低为 2K，图谱不应继续按小窗口的固定卡片尺寸居中收缩。节点取消固定
宽高和两行省略：每层按真实最大并列数划分等宽轨道，轨道使用图谱主区域的全部宽度，
节点高度由完整标题、描述和指标自然测量。描述、指标和说明栏字号同步提高；Cairo 连线
读取 GTK 排版后的真实节点边界，因此节点内容增高或窗口宽度变化时不需要维护第二套尺寸。
