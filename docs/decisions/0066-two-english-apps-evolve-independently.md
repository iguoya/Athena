# ADR 0066：并入 ascent（拾阶），两个英语应用各自独立发展

- 日期：2026-10-01
- 状态：已接受
- 影响：仓库新增 `subjects/ascent`；`subjects/english` 界面名改为「磨砚」；两者的关系规则
- 延续：ADR 0032、0045（一个目录一个独立应用）、0054（宁增勿删）、0062（约束不继承）
- 关联：拾阶自己的 ADR 0020、磨砚（english）自己的 ADR 0012

## 背景

使用者有两个英语项目：Athena 里的 `subjects/english`（考研英语二）和独立仓库
iguoya/English（Lumi 英语学习，英语师范生的四六级、专四专八，77 个提交）。要把后者并进
Athena，取消独立仓库的日常开发，同时两者**必须继续各走各的路**：目标人群、考试、教学方法、
界面和技术栈都不同，分成两份就是为了尝试不同的做法，最后长成一模一样就违背了初衷。

## 决策

1. **并入方式**：`git merge --allow-unrelated-histories` 把 English 仓库的全部历史并到
   `subjects/ascent/`；先原样提交一版作为基线，改名与适配在后续提交里做（ADR 0054）。
   历史在改名前以 `subjects/lumi/` 为路径，`git log --follow` 可追溯。
2. **名字**：按各自目标起隐晦的名字——表层不露考试，内在目标清楚。

   | 目录 / id | 界面名 | 英文名 | 面向 | 进程 | 知识点前缀 |
   |---|---|---|---|---|---|
   | `english` | 磨砚 | Whetstone | 考研英语二 | `athena-english` | `en.` |
   | `ascent` | 拾阶 | Ascent | 英语师范生的四六级、专四专八 | `athena-ascent` | 无（进度在用户数据目录，见第 4 条） |

   `english` 只改显示名，目录与进程名不动。拾阶的 `identifier`、`productName`、Cargo 包名
   不动：它们决定已安装版本的数据目录和自动更新，改了等于换一个应用。
3. **两个英语应用独立发展，不趋同**：
   - 内容、路线、界面、教学方法、技术栈各自演进，不为「保持一致」而对齐对方；
   - 对方只是参考素材：好的做法按自己的目标重想再写，不整段搬运，不当验收标准，
     对方改了不要求自己跟；
   - 两边相同的做法，要能说出是自己的目标需要它。
   这是 ADR 0062「约束不继承」在这一对应用上的具体化，也不改变「参考不得重划结构」（ADR 0054）。
4. **拾阶按学习应用对待，已知差距如实记录**：它追踪掌握度，但进度库在用户数据目录、没有
   `progress/learning.db` 随仓库走（ADR 0053），知识点也没有难度/掌握目标评级。这些**不在
   并入时顺手补齐**——是否补、怎么补由使用者决定，拾阶 ADR 0020 有清单。
5. **端口**：拾阶开发端口 1440（原 1420 与 `subjects/dsa` 冲突）。

## 未决

- 旧仓库 iguoya/English 暂不动。归档或删除前要先定自动更新（拾阶 ADR 0018）怎么办：
  updater 端点还指向旧仓库的 Releases，旧仓库没了，已安装版本就收不到更新。
- `subjects/ascent/.github/workflows/release.yml` 在子目录里不会被 GitHub 执行，发布流程
  何时迁到仓库根另议。
- CI 的 `workflow_dispatch` 选项与 Tauri 构建矩阵尚未加入 `ascent`（ADR 0064 显式触发）。
