# ADR 0128：新增 earth——真实比例的地球分层可视化（「程序设计」圈，图谱/参考类）

- 日期：2026-10-10
- 状态：已接受（tiger 2026-10-10：地球分层用 3D 视图画，地理信息按真实比例画，追求严谨；「暂时挂在程序设计之下」）
- 关系：归类按三类判据（[docs/REPOSITORY.md](../../docs/REPOSITORY.md)）；图谱/参考类先例：polaris（ADR 0015）、competitions（ADR 0114）

## 背景

1. 使用者要一个 3D 视图的地球分层呈现：大气分层（对流层/平流层/中间层/热层/外逸层）
   与地球内部分层（地壳/地幔/外核/内核），要求**按真实比例**、追求严谨。
2. 真实比例的核心事实：地球平均半径 6371 km，地壳平均约 35 km（0.5%），卡门线
   100 km（1.6%）——按真实比例，薄层就是看不见的。教科书插图的「厚分层」全是
   夸张画法；本应用反其道而行，把「薄到看不见」本身作为呈现对象，配合剖面与
   放大手段表达，不做空间失真。
3. 三类判据：主问题是把真实数据按严谨比例**呈现供查阅**，不考核掌握度、不证明
   学习者进步 → 图谱/参考类，不是学习应用。仓库已有三类先例可循。

## 决策

1. 新增 `subjects/earth`：`id` 与目录名 `earth`（完整英文单词），界面名「地球」，
   进程 `athena-earth`，端口 **1511**（1509 之后首个空闲号，1510 已被 softcert 占用）。
2. **归类图谱/参考类**：不建 `progress/learning.db`、不建 `content-contract.json`，
   跨应用教学规范不生效；出处（NASA、USGS、标准模型）照标是内容习惯，不做门禁。
3. 启动器归属：`group: 程序设计`（使用者指派，**暂时**；「程序设计」圈现有成员
   design-patterns、gtkmm、linux），不设 `parent`。后续挪圈只改 `group`，id 与
   端口不动。
4. 技术栈：Tauri 2 + React 19 + TypeScript（Vite 8）+ **React Three Fiber /
   Three.js**；壳复制自 polaris（同图谱/参考类、subjects 内依赖最新的 React 壳），
   此后独立演进。Rust 端只做壳，不做渲染。
5. **真实比例原则**（渲染层）：
   - 场景单位 1 = 地球平均半径 6371 km，各层半径是真实比值，不用千米做单位；
   - 开 `logarithmicDepthBuffer`：贴地（公里级）到整个系统的深度跨度用默认
     深度缓冲必然 z-fighting；
   - **不把薄层画厚**：四分之一剖切 + 沿径向的真实刻度尺 + 相机聚焦到薄层 +
     动态比例尺；视图标注「真实比例，未放大」。
6. **数据用标准参考模型**（数据层，数据与渲染分离，前端从数据文件生成场景）：
   - 形状：WGS84 椭球（赤道 6378.137 / 极 6356.752 km，扁率 1/298.257），不用正球；
   - 地球内部：PREM（Preliminary Reference Earth Model），密度/波速随深度连续，
     驱动剖面着色与径向探针；
   - 大气：US Standard Atmosphere 1976（0–86 km 温度/压力廓线），分层界线按 WMO
     定义，卡门线注明是航空约定；外逸层上界不封闭，画成渐隐；
   - 地表：NASA Blue Marble（公有领域），离线打包进应用，不运行时拉取。

## 后果

- `docs/REPOSITORY.md`（结构树、名字表、图谱/参考类清单）、根 `README.md`、
  根 `AGENTS.md`、`.github/workflows/ci.yml`（workflow_dispatch 选项与 tauri
  矩阵过滤）随本次新增登记。
- 「程序设计」圈出现非编程成员：圈的语义是「使用者指派的归属」，不承载领域
  判断；这是暂存安排，挪圈是纯配置改动。
- 应用不判分，根校验的出处检查对它无条款；严谨性靠数据文件里的出处标注与
  单元测试对数值的核对（如分层界线、椭球参数与标准值一致）。
