# ADR 0155：学习进度本地优先、不进 git，联网时由启动器同步到路由器 PostgreSQL

- 日期：2026-10-13
- 状态：已接受（使用者 2026-10-13：「允许脱离 6.1 局域网环境使用，建立本地数据库，但数据库数据不同步到仓库；如果有访问 6.1 数据库的条件，允许同步到该路由器数据库中」；一次全迁、同步对使用者透明）
- 关系：把 ADR 0067~0070（driver 的做法）推广到其余学习应用；**修订 ADR 0053**（进度库随仓库走，对迁移后的应用不再适用）与 ADR 0067 决策 2 的「一应用一库」（中心侧改为逻辑上一应用一份，见决策 4）；延续 0037（各应用自管本地库）、0062（约束不继承）、0077（不设设备令牌，内网可信、外网 Cloudflare Access）；不改 0132（不共享 schema）

## 背景

1. ADR 0053 让进度库 `progress/learning.db` 进版本库、用 `launcher sync` 推 git。它的两个代价
   0067 已经指出：分叉无法合并、同步是手动仪式。现在还多一条：仓库是公开的，学习记录
   不该出现在 GitHub 上。
2. driver 已经用「本机 SQLite 缓存 + 待发队列 + 路由器 PG 权威」跑通（0067~0070），
   断网照常使用、联网补发。其余学习应用目前仍是 0053 的形态。
3. 实测历史上全部 `.db` 版本只有 44 个、压缩后约 0.2 MB，不是仓库体积问题；动机是
   隐私与分叉，不是体积。
4. 十几个 Tauri 应用各自在 `lib.rs` 里写 SQLite 存取，表结构有六种不同的样子；把同步
   逻辑抄进每个应用不现实，按应用写类型化 API 也不现实。

## 决策

1. **三条总纲**：本机库永远可用（离开局域网照常学习与记录）；学习进度库**永不进 git、
   不推 GitHub**；能连上路由器时同步到中心 PG，两边互为副本。
2. **本地库放用户数据目录**，不再放 `<app_root>/progress/`。各应用的库路径函数不再认
   `ATHENA_*_ROOT`（该变量继续只管内容与实验目录），统一用 `<data_dir>/<目录名>/learning.db`；
   目录名沿用各应用原来的回落名，登记在 `app.json` 的 `progress.dir`，启动器据此找库。
   `.gitignore` 加 `*/*/progress/*.db`，已跟踪的库 `git rm --cached`（历史版本保留，
   不改写历史）。
3. **同步由启动器外置完成，应用不内嵌同步代码。** `launcher` 新增同步代理：
   启动应用前先推后拉（把上次改动推上去、再拉别处的改动合进本地），应用停止后推送，
   另有手动命令 `launcher progress sync`。拉取合并会写应用的库，所以只在应用没在跑时做；
   推送只读，随时可做。路由器不可达就静默跳过，下次再来；**同步状态不进应用与启动器
   界面**，只写日志 `<data_dir>/AthenaSync/sync.log`，要排查时用命令行。在启动器之外
   直接运行的应用不触发同步，接受。
4. **中心侧通用存储**：`nas_admin` 新增 `/api/progress/v1`，PG 里一张表按
   (学习者, 应用, 表名, 主键) 存 JSONB 行，带更新时间、设备标识、删除标记与单调序号；
   不照各应用的表结构建表（0132 不共享 schema，且按应用写 API 要写十几套）。
   学习者沿用全局目录的编号（0074、0075），请求头 `X-Athena-User`，目前只有一人。
   认证沿用 0077：内网直连，外网走 Cloudflare 域名。
5. **合并规则按表声明**，写在应用 `app.json` 的 `progress.tables`：
   - `append`（事件表，如作答、运行历史）：按业务键取并集，已有则忽略；
   - `lww`（可变表，如掌握度、草稿、设置）：按更新时间新者胜；
   - 主键缺省取表的 `PRIMARY KEY`，没有主键的表必须显式写 `key`。
   应用的表没有时间戳也不要求改：同步代理在自己的旁路库（`<data_dir>/AthenaSync/state.db`）
   里记每行的指纹与最近同步时间，据此识别「本地改过」「本地删了」，不动应用的表结构。
   与 0070 的合并规则一致（事件并集、可变取新）。
6. **备份**：`launcher progress backup` 把本地库与中心库导出成带时间戳的文本快照，
   存本机目录，不进 git；手动 `pg_dump` 继续有效（0068）。GitHub 不再是副本，本机加
   路由器是仅有的两份，这一点明知且接受。
7. **一次全迁**：所有有 `learning.db` 的学习应用同批迁移，不分试点。顺序是：服务端部署并
   验证 → 启动器同步代理 → 逐个应用改路径函数并把已有库一次性推入中心（核对行数）→
   最后统一撤出 git。**在中心确认收到数据之前，不撤任何一个库出 git。**
8. driver 已有自己的通路（`/api/driver/v1`、`AthenaDriver/local.db`），不动，也不并入
   通用接口；归档的 `archive/driver-progress-pre-pg/` 不动。

## 后果

- 换机器不再 `git clone` 就带着进度，而是装好后连上路由器自动拉回；从未连过路由器的机器
  只有本机数据。
- 静默同步的代价：同步长期失败使用者不会察觉。缓解只有日志与手动命令，这是使用者
  明确选择的（同步是内部机制，不需要被感知）。
- 仓库公开期间，历史提交里的旧进度库仍可被看到（保留历史，不强推）。
- `launcher sync`（提交推送 `progress/`）对已迁应用不再收集其路径；`db-textconv.py` 与
  `.gitattributes` 里的 sqlite diff 配置随最后一个库撤出而退役。
- `nas_admin` 同时承载驾考 API、学习者目录与通用进度接口，路由器仍是单点，缓解见决策 6。
- 各应用 `AGENTS.md` 里「进度库随仓库走」的表述，迁移时同步改。
