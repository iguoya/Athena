## 背景

仓库至今的教学应用都从电子书或手册出发。使用者想要从**视频教程**出发的应用，且不受既有
应用形态约束。两处既有文字却把这条路堵着：

- `HANDOFF.md`「视频课」条：「一门视频课一个应用，只有字幕或讲稿文本拿得到才建，内容为字幕
  文本加原视频外链，不嵌播放器、不放视频」。它的理由栏写的是「视频站云里连不上」——那是
  **云会话的限制，不是教学原则**，本机没有这个限制。
- `LEARNING-METHODS.md`：「纯视频/纯听讲的被动消费形态（不做视频课）」。它禁的是**被动消费**，
  而不是「以视频为原材料、以检索动作为主导」的课程，字面却撞车。

视频的教学风险是线性、被动、容易产生「看懂了的错觉」。所以应用的主角不是视频本身，而是
「视频 + 暂停点 + 检索练习 + 上机 + 复习」这条闭环；视频是原材料。

首发课程《实用大众线性代数（MATLAB版）》是西安电子科技大学在中国大学 MOOC 的官方慕课
（陈怀琛、杨威、樊松涛主讲，14 周、5 章、约 45 小节、5 个章测验、全程上机）。它有三点让它
适合先做：

1. 文本底本**不靠字幕**：官方课件（8 个 PPT 共 393 页）与程序集（115 个 `pla*.m`）已在仓库
   `guide/chen-linear-algebra/upstream/`，zcode 核对过课件章结构与课程五章一一对上；
2. 上机有机器可复算的核对源（程序集例题号），题源门禁有现成先例（ADR 0177）；
3. 平台视频流是加密的，明文本地文件取不到——正好逼出「文本为底、播放可选」的数据设计，
   而不是依赖视频文件。

## 决策

1. **确立「视频课」形态**：以一门外部视频课为底本，一门课一个应用，放 `guide/`。视频是
   原材料；**允许**视频课，**禁止**无检索闭环的纯被动观看形态。同步修订
   `LEARNING-METHODS.md` 措辞为「不做无检索闭环的纯视频被动消费」，并在 `HANDOFF.md`
   「视频课」条标注「播放约束由 ADR 0180 取代：云会话仍拿不到视频站，但应用形态不再禁止
   播放」。
2. **新增 `guide/chen-linear-algebra-mooc`**，`group` 为「数学」。id 与目录名按「作者-课程」惯例
   （同 `chen-linear-algebra`）加 `-mooc` 区分底本形态；进程 `athena-chen-linear-algebra-mooc`；
   知识点前缀 `chenmooc.`；dev 端口 1531；进度库 `AthenaChenLinearAlgebraMooc/learning.db`，
   `attempts` 表 append（ADR 0037、0155）。学习应用，出处档位 `open`。
3. **播放三档，数据以时间锚点为核心**：
   ① 文本 + 外链（降级档）：课件段落 + 起止时间戳 + 原站外链，点击跳原站；
   ② 本地文件：应用内 `<video>` 播放，才有「暂停点」；
   ③ 在线内嵌：可选，不保证。
   **首发只做档位 ①**；内容模型从第一天起记录时间锚点（`start`/`end` 秒、课件页码、外链），
   使 ②③ 以后只是增加播放源适配、不改内容。视频文件由使用者自行取得、应用只读本机路径，
   **应用不内置、不下载、不绕过任何平台保护**；视频路径用相对 key + 本机视频库根目录配置，
   不进同步库、不进 git，缺文件自动降级到档位 ①。
4. **学习单元是「节」**（对应课程页大纲里的一小节）。单元骨架（主原型 P **预测–运行**，
   辅 E **真做校验**，ADR 0113）：看前提示（看到 mm:ss 先暂停想一想；档位 ② 起升级为自动暂停点）
   → 课件精读（逐页锚点）→ 片段检索卡（看完不回看作答）→ Octave 上机任务（先预测输出，
   再运行对照，`verify` 复算）→ 章内交错练习。首页是「今日到期复习 + 继续上次的节」，
   主导航是**周/节时间轴**，不是知识点列表页。
5. **文本底本与题源**：文本主底本是官方课件与程序集，平台字幕/Whisper 转写只是补充，
   取得与否不阻塞立项。题源硬门禁沿 ADR 0177 决策 2：入库题目必须带 `source_refs`，
   `relation` 只许 `verbatim`/`adapted`，`authored` 不入库；`locator` 写「课程名 + 周-节 +
   课件页码」「课件第 N 章 p.x」「程序集 plaXXX」，不凭印象。看前提示与暂停点提示是教学动作，
   不判分、不进掌握度；进掌握度的题必须**机器可核对**（选择、数值、Octave 复算输出）。
6. **掌握度只由作答写入，观看不算**（ADR 0052）。「观看位置」（续播用）与「掌握度」是两张表，
   首发无播放，观看位置表随档位 ② 一起加，本地存、不同步。
7. **与图书应用并存、互不引用**：`guide/chen-linear-algebra`（以书题为单位，重原书）与本应用
   （以周→节为单位，重观看后检索与上机）内容有重叠（同作者、同程序集、部分例题），但壳独立、
   知识点前缀独立、不互相引用路径与内容配置（ADR 0032、0062）。重叠的素材各自入库、各自登记
   出处；不为「将来共享」提前对齐字段（ADR 0132）。
8. **首批范围：第 1–2 周**（线性方程组与矩阵；用 MATLAB 解线性方程组），做深做透作样板，
   再按周推进（ADR 0129：没有可交付的第一批不建；其余周次不留占位）。章测验不照搬平台题，
   练习取自课件习题与题解。
9. **翁恺《C 语言》**（B 站公开版，实操录屏型）不在本 ADR 范围：它验证的是档位 ② 的完整
   本地播放闭环，待使用者确认视频文件形态与底本版本后另立 ADR；那时再决定是否抽取两个视频课
   应用的共用层（ADR 0132）。
10. **技术栈**：Tauri 2 + React（ADR 0138），壳最初复制自 `guide/chen-linear-algebra`，此后独立
    演进；视频课专有的内容块（节头、课件段落块、看前提示块）按内容驱动 UI 新增（ADR 0058）。

## 后果

- 新增一个应用与一类形态；`HANDOFF.md`「视频课」条与 `LEARNING-METHODS.md` 措辞改动，
  登记 `REPOSITORY.md`、根 `README.md`、根 `AGENTS.md` 结构树、`ci.yml`。
- 档位 ② 的暂停点触发要用 `requestAnimationFrame` 轮询 `currentTime`（`timeupdate` 精度约
  250 ms），拖进度条越过暂停点按「已过」处理、不强制回跳，该点的题在片段结束卡补问——
  实现层风险，档位 ② 动工时再细化。
