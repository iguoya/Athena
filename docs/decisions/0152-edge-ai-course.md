# ADR 0152：新增 AI 路线第 6 门 edge-ai（端侧 AI 推理与部署）

- 日期：2026-10-12
- 状态：已接受（使用者要求：「优先端侧 AI 路线」；形态、硬件、运行时、边界、第一批范围等
  15 个问题经逐轮追问确认）
- 关系：修订 [ADR 0120](0120-ai-group-and-llm-curriculum.md)（路线表加第 6 门、端口 1515、边界补
  一条）；目录依 [ADR 0150](0150-dissolve-course-by-group.md)（`artificial-intelligence/`）；
  学习方法原型按 [ADR 0113](0113-method-archetypes-per-course.md)；出处档位按
  [ADR 0089](0089-source-tiers-by-app-nature.md)；内容取舍按 [ADR 0129](0129-prefer-quality-over-quantity.md)

## 背景

1. 使用者要走端侧 AI 开发：把模型压小、转格式、在固定硬件上测出延迟、内存、精度并满足预算。
   ADR 0120 的五门课偏大模型应用与服务端：`llm-finetune` 有「量化、ollama/vLLM 本地推理、GPU
   基础」，但没有目标设备上的预算、导出、运行时剖析与真机。
2. 现有五门课（python、machine-learning、deep-learning、llm-app、llm-finetune）的章节全部是
   「占位」，与 ADR 0129「新建应用要有可交付的第一批内容」不符。本条不处理它们，只保证新课
   一开始就有真实内容。
3. 使用者的硬件：这台 Windows 电脑（CPU，无 NVIDIA GPU）、树莓派 4B、龙芯 2K1000，没有 NPU 板。

## 决策

1. **新增 `edge-ai`：端侧 AI 推理与部署，AI 路线第 6 门。** 目录
   `artificial-intelligence/edge-ai/`，进程 `athena-edge-ai`，知识点前缀 `edge.`，端口 **1515**，
   group「人工智能」。壳 Tauri 2 + React，出处档位 open，实验在本机 Python 子进程真跑、应用只执行
   白名单内的预设命令（ADR 0091 决策 3 同规）。
2. **先修靠文字指引，可单独使用**（ADR 0120）：先修是 deep-learning。开头自带一小节「把
   PyTorch 模型导出」的最小补课，不另去写 python、deep-learning。
3. **与相邻课程的边界：**
   - 与 `llm-finetune`：它讲 LLM 量化的**方法与精度评估**（GPTQ、AWQ、GGUF 量化），产出量化好的
     模型；`edge-ai` 讲通用训练后量化（视觉等小模型）、目标设备上的预算与剖析，LLM 只讲「拿量化
     好的模型在设备上跑」，不重复教量化方法（ADR 0040）。
   - 与 `llm-app`：它把模型当黑盒服务；`edge-ai` 关心模型怎样落到一台设备上。
   - 与 `electronics/`：微控制器级的 TinyML 不在本课，后续另立项，再和该圈课程衔接。
4. **运行时两条主线：** ONNX Runtime（通用与视觉模型）与 llama.cpp（端侧大模型）。TFLite、
   ExecuTorch、Core ML 以及昇腾、Jetson 路线不在本期。
5. **硬件与验证：**
   - 基线是这台电脑（CPU）：第 1–5 章每个实验都必须在上面能跑、能判。
   - 树莓派 4B 是**可选的第二台测量设备**：第 1–5 章的基准脚本做成跨设备（x86 Windows 与
     ARM Linux 都能跑），不为它单独加章节。
   - 主线 NPU 板是 **RK3588（Debian），NPU 走 RKNN**。板子尚未购买，建议 16GB 内存版。
   - RKNN-Toolkit2 的模型转换据网上资料需要 x86_64 Linux 主机；这台机器用 WSL2 的 Ubuntu。
     **这一条在写上板章节前要下载官方文档逐条核对**，本条只记录当前的理解。
   - 龙芯 2K1000 不纳入。
6. **第一批只做第 1–5 章：** ① 端侧预算与基线（延迟、内存、体积、精度的统一测量）；② 模型导出与
   等价性（PyTorch 导出 ONNX、输出对齐）；③ 训练后量化（INT8 校准，精度、体积、速度的权衡）；
   ④ ONNX Runtime 推理与性能剖析；⑤ 端侧大模型（llama.cpp 与 GGUF：每秒生成词数、首词延迟、
   内存）。**第 6 章「上板与 NPU」在板子到手并有一次实测后再写**，写好之前不进课表（ADR 0129 不留占位）。
7. **教学方式：** 主原型**真做校验**，辅**辨析决策**（给预算，选精度、运行时、模型大小）；每个
   实验先写一张**预算卡**（延迟、内存、精度下降上限，按自己设备定），应用拿实测值自动比对判定；
   量化误差分布、延迟与精度的取舍等画成活的（ADR 0056）。
8. **模型文件：** 约 20MB 以内的小模型直接入库；大模型（如 GGUF）不入库，由白名单脚本按固定地址
   下载，用 sha256 校验，缓存目录被 git 忽略。
9. **实验环境：** 由 uv 管理，固定 Python 3.12，不使用系统 Python（本机是 3.14，主要的深度学习
   包未必已有对应的预编译包）。

## 后果

- ADR 0120 的路线表变为六门；端口预留 1505–1509 与 1515；知识点前缀增加 `edge.`。原 ADR 0120 正文不改，
  索引表状态栏补「由 0152 修订」。
- 使用者需要自行购买 RK3588 板子（建议 Orange Pi 5 Plus 16GB，现价到官方店核实）并配电源与散热；
  第 6 章要等板子到手、使用者跑通一次实测后才能写，因为作者无法接触这块板子。
- 本条里关于昇腾板、Jetson、RKNN 的事实来自网上检索与厂商/社区文档，**未经下载核对**，属于
  写对应章节之前必须验证的内容；价格是 2023 年发布价，仅作参考。
- 仓库级 ADR 编号：0151 已被 `programming/chinese-chess` 占用，本条为 0152。
- 应用的立项 ADR（应用级 `docs/decisions/0001-…`）、四件套和根文档登记在建应用时一并落，另起提交。
- **勘误（2026-10-12）**：本条初稿把端口写成 1510，但 1510 已被 `launcher/webui` 占用（它的
  `tauri.conf.json` 与 `vite.config.ts` 都用 1510），建应用前核对时发现。改为 **1515**（现有最大
  端口加一）。初稿只扫了各应用的 `app.json`，漏了启动器；以后查端口要同时扫 `app.json`、
  `vite.config.ts`、`tauri.conf.json`。
