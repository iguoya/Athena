# ADR 0075：按名字登录，学习者 ID 改为服务端分配的短数字，重名才问编号（修订 ADR 0074）

- 日期：2026-10-03
- 状态：已接受；修订 ADR 0074 决策 1（ID 格式）、决策 4（同名靠 ID 末 4 位区分）、
  决策 5（谁都能改名）、决策 6（选择页列出全部学习者）；ADR 0074 其余各条继续有效
- 影响：`practice/nas_admin`（目录表、登录与登记接口）；`subjects/driver`（登录页、注册表）；
  `docs/REPOSITORY.md` 的 `Athena/users.json` 约定
- 延续：ADR 0070（本地优先）、0071（隔离机制）、0072（ID 与名字分离）、0073（全局目录）、
  0074（中心目录是权威）

## 背景

ADR 0074 把目录收归中心，但留下了三处不贴合家用场景的设计：

1. **ID 太长**：`u_` 加 16 位十六进制，只能复制粘贴，口头说不出来；而全家一共几个人。
2. **选择页列出全部学习者**：异地登录时能看到目录里所有人，为一个「重名很少见」的问题
   付出了暴露全员名单的代价。
3. **谁都能改任何人的名字**：没有必要，改自己的就够了。

使用者的判断是：**正常情况下，一个名字就能确定一个人**，重名是罕见情况，不值得为它设计
自动区分、采集设备标识之类的机制；真遇到了，多问一句编号就行。

## 决策

1. **学习者 ID 是服务端顺序分配的纯数字**，从 1 起，上限 999，永不变、不复用、不提供删除。
   超过上限时登记被拒绝（家用不会到）。ADR 0072 起的 `u_` + 十六进制格式从未随发行版发出
   （ADR 0073 后果：多用户版本尚未发行），直接弃用，不做兼容。
   tiger 由迁移脚本最先登记，在空目录上自然得到 1。
2. **登录 = 输入名字。**名字比较去首尾空白、忽略大小写：
   - 恰好一个同名学习者 → 直接进入；
   - 没有 → 提示「没有叫这个名字的学习者」，并给出「新建」；
   - 不止一个 → 再问「学习者编号」，名字与编号对上才进入，对不上不进入。
3. **新建是显式动作，与「进入」分开。**名字已有人在用时先确认「已有同名学习者，仍要新建吗」；
   新建成功后界面**显著展示分到的编号**，并说明「在别的电脑上登录，如果遇到同名会问这个
   编号」。
4. **重名不做特殊处理**：不加唯一约束、不自动区分、不采集设备或系统标识。重名时唯一的
   机制就是第二步问编号。
5. **改名只能改本机当前登录的学习者**，不能改别人的。界面只在当前学习者上提供改名入口；
   服务端改名接口校验请求头 `X-Athena-User` 必须等于被改的学习者。无口令的信任模型下这是
   防误操作，不防有意伪造（持令牌者仍可自己拼出请求头）。改名后可能出现重名，同样靠编号。
6. **查询不泄露名单。**按名字查询只在恰好一个匹配时返回该学习者的记录；多个匹配只返回
   匹配的个数；确认接口（名字加编号）才返回记录。没有「列出全部学习者」的接口。
7. **本机缓存与常用快捷项**：`Athena/users.json` 记录本机登录过的学习者（编号加名字）与
   `last`。启动时有多个本机学习者就显示成快捷项，点选即进入；这是本机用过的人，不是中心目录
   全员。输入的名字在缓存里唯一命中时无需联网即可进入；缓存里没有就需要联网查询。
   承接 ADR 0074 决策 3：新建与异地首次登录要联网，不为离线设计路径。

## 后果

- 异地登录的流程缩成「输名字（偶尔再输个位数或两三位数编号）」，不再需要抄 16 位 ID。
- 重名者之间无法被系统自动区分，靠使用者记住自己的编号；这是有意的取舍。
- 令牌持有者可以以任何一个名字进入（ADR 0071 的信任模型不变）；多问编号不是安全措施。
- ADR 0074 决策 8（服务端最终拒绝未登记的 `X-Athena-User`）继续有效，只是被校验的值从
  `u_…` 变成数字串；因为本地库文件名 `local-<编号>.db`、请求头与中心 `user` 列本来都是
  字符串，客户端与同步层不需要改。
- `docs/REPOSITORY.md` 的 `users.json` 一节、`subjects/driver/AGENTS.md` 的多用户一节要
  随实现一起改（ID 格式、不再有「续用输入 ID」）。
