# ADR 0089：出处要求按应用性质分档

- 日期：2026-10-09
- 状态：已接受
- 修订：ADR 0043 的适用范围（五条硬要求收窄至考试档）
- 依赖：ADR 0043（内容必须有出处）、docs/REPOSITORY.md 三类判据

## 背景

ADR 0043 把「判分或计入掌握度的内容必须有出处」定为跨应用统一规范。动机至今
成立——判分要公正、出处要能核对、凭印象写出处比自造更糟——但它落地成了对
`subjects/` 下所有应用的一刀切，两年下来攒出几处名实不符：

1. **约束的前提不是所有应用都满足。** 0043 管的是「判分或计入掌握度的条目」，
   而仓库的三类判据（REPOSITORY.md）早已把 `polaris`、`math-tools`（图谱/参考类）
   和 `design-patterns`（素材坑）划成不判分、不掌握度的应用。判分出处约束对它们
   前提不成立，检查器却对每个没有 `content-contract.json` 的目录报「未接入」。
2. **应用性质还有一根更细的轴：学的东西对不对着一张真实试卷。** `driver`（驾考
   科目一/四）、`softcert`（软考中级）、`english`（考研英语二）、`ascent`（四六级、
   专四专八）、`mathematics`（考研数学二）的产出直接对应外部考试，题目与考纲、
   真题、法条的对应关系是内容质量的一部分；`cpp`、`machine`、`dsa`、`gtkmm` 的
   产出是理解与技术能力，出处同样要可信可查，但不需要与考纲对表，写作时也应当
   有自由发挥的空间。
3. **现状恰好拧着。** 两个英语考试应用（english、ascent 相关方）因过渡原因处于
   只报告；两个纯技术学习应用（machine、gtkmm）反而是全量阻断；polaris（参考类）
   挂在判分出处名下；design-patterns（素材坑）被报「未接入」。谁该严、谁该松，
   没有一处说得出判据。

## 决策

### 1. 三档，写进各应用的 `content-contract.json`

新字段 `tier`，取值 `exam` / `open` / `reference`。档位判据只有一条：**这个应用的
学习成果是否对应一个真实存在的外部考试或等级认证。**

| 档 | 判据 | 当前应用 | 出处要求 |
|---|---|---|---|
| `exam` | 对应真实外部考试/认证 | driver、softcert、english、ascent、mathematics | ADR 0043 五条硬要求全部生效，违规即失败（`blocking: true`） |
| `open` | 学习应用，不对应外部考试 | cpp、machine、dsa、gtkmm | 出处是默认写作习惯，不做门禁：照实标注的条目受检查保护，未标注只报告不阻断，自造配额解除 |
| `reference` | 不判分（图谱/参考/素材坑） | polaris、math-tools、design-patterns；`practice/` 整体 | ADR 0043 不适用；应用自己若需要出处（如 polaris 的边来源校验），由应用自己的机制管 |

考试档不加新的仓库级硬要求——0043 的五条（可指到出处、出处可核对、关系分级、
authored 说明理由并受配额、机械检查兜住）加上阻断，就是「更严谨」的完整落地；
各考试应用已在自己的 AGENTS.md 里叠了更强的条款（driver 的法条条款级出处、
mathematics 的教材与考纲坐标必填、softcert 的真题编号禁止凭记忆编造），继续各自
有效。档位清单只是例子，过期了按判据重新归类，不改本 ADR。

### 2. 所有档共同的底线——「降低约束」不等于「可以胡编」

- **不得凭印象伪造出处。** 要么如实标 `authored`（open 档不设配额、也不必解释
  为什么外部材料覆盖不到），要么不标；把想不起来的来源冒充 `verbatim`/`adapted`
  比不标更糟——这一点与 0043 第 2 节同源，全档生效。
- **AI 现场出题不计入掌握度**（0043 第 7 节）：判分输入必须落盘、可审查、可
  版本化。这条与出处档位无关，全档保留。
- **已标注的出处仍受校验。** 引了 catalog 里不存在的来源 id、标了关系却指不到
  位置，任何档都照样报——标了就该是真的。

### 3. 本轮各应用的落地

- **english 收紧为阻断。** 它是考试档，1088/1088 已达标，契约里「分级内容扩充
  收尾后改成 true」的过渡理由兑现——扩充中的新内容当场被查，好过悄悄倒退。
- **softcert 维持只报告，记为考试档的已知欠账。** 契约已声明过渡状态：真题整卷
  未取得再分发授权，阶段内全部题目如实标 `authored`（带考纲 locator），自造过半
  配额必然触发。取得授权、导入 `past-exams` 真题后把 `blocking` 改回 true。
- **machine、gtkmm 从阻断降为 open。** 技术学习类，出处降为习惯；两者此刻都是
  100% 达标，降档不改变现状，改变的是扩充期漏标不再挡路。
- **cpp、dsa 维持只报告，清掉存量豁免名单。** 豁免名单是给阻断档「还账」用的
  （名单只能变短）；open 档没有需要豁免的失败，如实报告覆盖率即可——cpp 87 条
  中 6 条有出处、dsa 127 条中 0 条，看见真实状态比挂着一份静音名单更诚实。
- **polaris 的应用内出处校验原样保留。** 每条边有理由和出处是图谱可信度的自有
  机制（polaris ADR 0002，读取即校验），与跨应用判分出处规范脱钩：跨应用检查
  对它降为登记不阻断，应用自己的校验继续挡坏数据。

### 4. 新应用定档

在应用自己的 `AGENTS.md` 里声明属于哪一类（REPOSITORY.md「新增一个应用时动哪些
地方」第 2 条）时，顺便写明档位：有外部考试对表的就是 `exam`，其余学习应用默认
`open`，不判分的 `reference`。`reference` 与素材坑不建 `content-contract.json`，
跨应用检查器不再对它们报「未接入」。

## 后果

- `scripts/check-app-sources.mjs` 按 `tier` 分执行：`exam` 违规即失败；`open` 与
  `reference` 只报告；不判分类不再出现在「未接入」清单里。没有 `tier` 的旧契约
  按 `blocking` 布尔走旧行为，输出一行提醒。
- machine、gtkmm 扩充期漏标出处不再让 `check.py` 失败，但已标注的出处仍被逐条
  校验；四个开放档应用的应用内检查（各自的 `scripts/check.py`）不受影响。
- ADR 0052（激励与统计同回路）、ADR 0080（重组豁免不含出处）在考试档原样生效；
  open 档本无出处门禁，重组豁免无可保护者，该条款对它们自然空闲。
- 考试档的已知欠账只有 softcert 一笔，路径明确：真题授权 → 导入 → 收紧阻断。

## 补充（2026-10-09）：softcert 欠账的前提变化——授权不再是阻塞

使用者明确：软考应用是本机自编自用软件，不进入分发环节，**真题整卷不必考虑
授权**。上面后果一节里「真题授权 → 导入 → 收紧阻断」三步的第一步就此移除，
欠账的性质从「等授权」变为「待录入」——`content/past-exams/` 目录为空的理由
只剩「官方真题集还没按导入格式录入」（driver ADR 0008「自用软件不受版权束缚，
公开题库可以直接收录」是同一判断在先）。`authored` 过渡、`blocking` 维持只报告、
录入真题后收紧这三条不变；「年份与题号必须来自导入的真实试卷，严禁凭记忆编造」
的严谨要求同样不变——解除的是权限顾虑，不是录入的核对责任。
