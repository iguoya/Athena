# ADR 0091：实验能力长在学科应用内，不另建独立实验应用

- 日期：2026-10-09
- 状态：**提议（待 tiger 确认）**——本条修正了此前「按介质拆两个独立实验应用」的
  口头方案，理由见背景 3
- 关系：实践口径与章节归类见 softcert [docs/content-plan.md](
  ../../subjects/softcert/docs/content-plan.md)；应用拆分见
  [ADR 0090](0090-softcert-splits-esd.md)；内容驱动 UI 与实验块扩展点见
  [ADR 0058](0058-content-driven-ui.md)；实验骨架见 [ADR 0059](0059-skeleton-not-blank.md)；
  掌握度写入见 [ADR 0052](0052-motivation-stats-one-loop.md)；不内嵌工具链见
  [ADR 0057](0057-baseline-full-dev-machine.md)

## 背景

1. softcert 内容规划把两门考试的 15 个章节归为**实践性课程**，只有两条实践
   路径：**A 真硬件实验**（嵌入式第 2、4 章）与 **B 独立编码/可执行实验**
   （SQL 真跑、C 编码、正则匹配、设计模式、进程同步、socket、单元测试等）。
2. 曾考虑把实践课程按介质拆成两个**独立实验应用**（编码实验台、硬件实验台），
   学科实验作为内容包接入。
3. [ADR 0090](0090-softcert-splits-esd.md)（同日，已接受）决定软考按课程拆分：
   软件设计师留 softcert（React），嵌入式系统设计师独立成 esd（Vue 3）。拆分后
   **每个实验介质只剩一个学科应用**——编码介质对应 softcert 一家，硬件介质对应
   esd 一家。「按介质再拆独立实验应用」失去了归并收益，只剩成本：多两套工程、
   两个进度库、两条发布线，且把实验从章节学习流里割裂出去（跨应用跳转、进度
   分库），与「预期 → 实验 → 观察 → 修正」的闭环相悖。

## 决策

1. **不新增独立实验应用。** 实验能力作为学科应用的自身形态建设：
   - **编码实验 → softcert 的 `lab` 块类型**。Monaco 编辑器（本地打包）+
     Rust 侧白名单 spawn 本机工具链（gcc 等，ADR 0057：不内嵌编译器）+ SQL
     用 rusqlite 直接嵌进程（依赖已在）。承载软件设计师 8 个实践章（2、3、4、
     5、7、8、9、10）。
   - **硬件实验 → esd 的实验视图**。`serialport` 串口终端（十六进制/文本双视图）、
     实验步骤卡、可编译固件骨架工程（ADR 0059）、白名单烧录命令。承载嵌入式
     第 2、4 章；esd 按 ADR 0090 建 Vue 3 体系时一并规划。
2. **实验是可判分内容，遵守同一条掌握度规则**（ADR 0052）：每个实验带校验
   断言（输出比对 / 测试通过 / SQL 结果比对 / 串口观测记录），校验通过写入
   `attempts`，即该知识点的作答记录；不设「实验币」之类的旁路激励。
3. **安全边界**：应用只执行白名单内的预设命令与实验断言，参数模板化；不提供
   任意 shell。自由编码区（如有）明确标注在本机执行、无隔离保证。
4. **两应用实验形态各自实现、不共享代码**（ADR 0032、0062），只共享本条确立的
   上述规范；界面不要求对齐。
5. **试点先行**：第一个实验做 **SQL**（第 9 章）——rusqlite 已在依赖、教材例题
   现成，验证「骨架 → 校验 → 写进度」闭环后，再铺开 C、正则、进程同步；硬件
   实验待 esd 应用建成且 tiger 确认购置入门开发板（STM32F103C8T6 或 51 板 +
   ST-Link + USB-TTL，百元内）后启动。

## 后果

- softcert 新增 `lab` 块类型前，先立**应用级 ADR** 扩展 ADR 0058；esd 建成时
  应用级 ADR 直接把实验视图纳入形态清单。
- 应用数量、启动器分组、发布线都不变；理论性章节维持讲解 + viz 演示 + 记忆
  测验，不冒充实实验（content-plan 归类结论）。
- 若未来出现第三个实验介质（如仿真器生态自成体系），再按本条「介质对应唯一
  学科应用」的原则重审，不在本条预设。
