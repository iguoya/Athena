# ADR 0068：个人数据三层存储、凭据不进仓库、外网走 REST API（修订 ADR 0067）

- 日期：2026-10-02
- 状态：已接受；**修订 ADR 0067 第 4 条（外网通道）与第 5 条（纯在线）**，其余各条继续有效
- 影响：`subjects/driver`（数据层、测试）；`practice/nas_admin`（新增 REST API）；软路由 PostgreSQL（角色与权限）；CI
- 延续：ADR 0067、0037（一个应用一个库）、0060（`practice/` 项目应用）、0047（跨平台）
- 关联：`practice/nas_admin/docs/driver-api.md`（接口与部署说明）

## 背景

ADR 0067 落地当天，几件事暴露出它的缺口：

1. **凭据进了提交**：连接串（含口令，而且是弱口令）一度写死在客户端源码、后台配置和文档里，
   进了尚未推送的提交。靠事后重写历史才清掉。
2. **外网直连 PG 不成立**：0067 第 4 条让客户端离开内网时经隧道到 PG。这要把数据库端口经
   域名公开出去，且每台客户端都持有数据库口令——丢一台设备就等于泄露一次数据库访问权，
   而数据库本身没有「撤销单台设备」的办法。
3. **纯在线太脆**：0067 第 5 条在 PG 不可达时禁用做题。出门、地铁、隧道抖动都会让练习中断，
   而驾考的作答记录是只追加的事件，本来就适合先存本地、再补发。
4. **测试连生产库**：界面测试一度连路由器上的真实库并在打开时清全表，并行的测试文件互相清表，
   CI（GitHub，没有内网）根本跑不了。

另外，把「驾考本身要不要有本地存储」说清楚：题库不是个人数据，不该进数据库（见决策 2）。

## 决策

1. **凭据不进仓库，每台机器各自配置。** 来源只有两处：环境变量，或本机 600 权限的本地配置文件
   （客户端 `db.json`、后台 `db-local.json` / `driver-db.json`，均不进版本库）。缺配置时客户端弹
   对话框、后台拒绝启动，**不写默认值**。口令一律随机强口令；文档里不出现真实口令。
2. **三层存储，各管一类数据：**

   | 层 | 存什么 | 位置 | 权威性 |
   |---|---|---|---|
   | 内容 | 题库、答案、解析、出处、课程 | 仓库里的 JSON（`content/`），启动时读入内存 | 唯一内容源 |
   | 本地 | 个人数据的副本与**待发送队列** | 客户端本地 SQLite（用户数据目录，不进仓库） | 缓存，可丢可重建 |
   | 中心 | 个人使用记录与统计 | 软路由 PostgreSQL，一应用一库（ADR 0067） | **权威** |

   **题库不进 SQLite 作为源头**：每题带出处、要能逐行 diff 与评审、`check.py` 要校验「有出处、
   自造不过半」，二进制库全丢；这也正是 ADR 0053 时代 SQLite 进 git 带来合并冲突的根源。若将来
   需要全文检索，可从 JSON **生成**只读索引（可重建、不进 git），不作为源头。
3. **外网通道改为 REST API，取代 0067 第 4 条的「隧道直连 PG」。** 由 `practice/nas_admin`
   提供 `/api/driver/v1`：设备令牌认证（库里只存哈希、可单独撤销、有限流）；外网还要过
   Cloudflare Access（程序调用用 Service Token）。**数据库端口不出内网**，客户端离开内网时只持
   令牌，不持数据库口令。内网内客户端仍可直连 PG。API 读写的就是客户端建的那批表，两条通路
   数据天然一致。
4. **离线靠「本地队列 + 幂等上传」，取代 0067 第 5 条的纯在线。** 作答、考试、练车记录是只
   追加的事件，上传按「题号 + 时间」等业务键去重，重复上传被跳过，所以队列很简单：断网照常
   做题，联网后补发，拉取按游标增量。成就取更早时间、试卷草稿按 `saved_at` 覆盖。
5. **测试连本机的库，不连软路由，并发安全。** 本机和 CI 各起 PG（角色带 `CREATEDB`），每个测试
   文件按文件名建自己的库（`athena_driver_test_<文件名>`），`flutter test` 并发跑也互不清表；
   widget 测试里查询固定回建立连接的 zone，避免 fake-async 与真实 socket 冲突。账号是公开的测
   试约定值，不是任何生产凭据。
6. **路由器上 PG 的权限收紧：** 一个应用一个库一个账号；撤销 `PUBLIC` 对各库的 `CONNECT`，只授
   予属主；非超级用户、不能建库建角色；单账号并发连接数设上限。API 用**专用低权限角色**，只有
   表的增删改查、**没有 DDL**，表由客户端首次在内网连接时建好。

## 后果

- 客户端要同时认识两种后端（内网直连 PG / 外网走 API），或统一走 API；取舍留到客户端接入时定，
  原则是**不让两种后端各自长出不同的语义**。
- 本地 SQLite 只是缓存与队列，丢了不丢数据（权威在 PG）；但队列里**还没发出去**的记录丢了就是
  丢了，要在界面上让使用者看得见「有 N 条待同步」。
- 路由器成为单点（PG 与 API 同机）：宕机时本地队列兜住做题，数据库本身靠手动 `pg_dump` 备份
  （使用者定：不设定时备份，升级固件或大改前手动做一次，把备份拷出路由器）。
- 点位照片是文件，不在 PG 也不在 API v1 里，仍随仓库走（`launcher sync` 继续收集 `progress/`）；
  是否迁走留作后续决定。
- 路由器上仍有一份旧版后台配置含明文弱口令（已收紧文件权限，口令与 `SECRET_KEY` 待换），
  需在用新版配置重新部署时一并处理。
