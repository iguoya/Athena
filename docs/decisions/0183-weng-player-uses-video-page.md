# ADR 0183：翁恺应用的播放窗格改用 B 站视频页（外链播放器登录后也不能切换清晰度）

- 日期：2026-10-23
- 状态：已接受（使用者实测：「登录后我还是不能自由切换分辨率」）
- 关系：**修订** [ADR 0182](0182-weng-c-programming.md) 决策 3 与决策 4 的两处实现细节——播放窗格加载的页面（外链播放器 → 视频页）、登录方式（独立窗口 → 窗格内导航）；其余不变
- 验证记录：`comms/video-course/artifacts/claude-code/SPIKE-player-bridge.md`（外链播放器的原始验证）；本 ADR 的实测见「背景」

## 背景

ADR 0182 把 B 站**外链播放器页面**（`player.bilibili.com/player.html`）放进播放窗格，并写明由使用者登录、自己选清晰度。真机测试发现两件事：

1. 登录窗口是同步命令里新建的 webview 窗口，在 Windows 上永远停在 `about:blank`（调试口里能看到 `page about:blank`）。已改为把播放窗格导航到官方登录页，登录后点「回到视频」。
2. 登录成功后（`/x/web-interface/nav` 返回 `isLogin: true`，等级 4，非大会员），外链播放器**仍然只有 360p 且不能切换**：菜单列出 720P/480P/360P，点击无反应；调用其 `requestQuality(64)` 得到 `Permission denied`；页面还显示「进入哔哩哔哩，观看更高清」。外链播放器本身限制了清晰度切换。
   同一个窗格改载**视频页**（`www.bilibili.com/video/<bvid>/?p=<p>`）后，登录状态下直接是 720p，`requestQuality` 可用，清晰度由站点自己的菜单切换。

## 决策

1. 播放窗格加载 **B 站视频页** `https://www.bilibili.com/video/<bvid>/?p=<p>`，不再用外链播放器页面。`player_url` 仍只拼这一种地址，bvid 与分集号逐项校验。
2. 播放桥继续只用标准 `<video>`（优先 `.bpx-player-video-wrap video`），不依赖站点私有 API。
3. **专注**：视频页自带推荐、评论等内容。注入脚本在控制条出现后点站点自己的「网页全屏」按钮一次，让播放器占满窗格，其余页面自然不在视野里；不修改、不隐藏页面内容。这是站点自己的功能，使用者可随时在播放器里退出网页全屏。
4. **能力范围**：IPC 请求只带来源（origin），带路径的 `https://www.bilibili.com/video/*` 匹配不上（实测被拒），所以 `capabilities/player.json` 放行整个 `https://www.bilibili.com/*` 来源，但命令仍然**只有 `bridge_report` 一个**。该命令只把「时间、是否暂停、时长」写进 Rust 里的最近状态，不读写文件、不开窗口、不联网。
5. **登录**：「登录 B 站」把播放窗格导航到官方登录页（`passport.bilibili.com/login`，不在放行来源内，调不了任何应用命令），使用者自己登录并选清晰度；「登录完成，回到视频」重新载入视频页。应用不读取、不保存账号与密码。
6. 页面可能晚几秒才自己起播：注入脚本在课堂区发出播放令之前的前 8 秒里持续把它暂停。

## 后果

- 视频页比外链播放器页面更容易随站点改版失效，退路不变：退回档位 ①（文本 + 外链），课堂区不受影响。
- 放行来源变宽（整个 `www.bilibili.com`），但能力仍是单命令；如果以后站点把视频页挪到别的来源，需要同步改 capability。
- 外链播放器页面的原始验证记录保留，作为本 ADR 的前史。
