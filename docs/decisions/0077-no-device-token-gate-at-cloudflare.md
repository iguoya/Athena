# ADR 0077：取消设备令牌，外网的门放在 Cloudflare 访问规则上，应用里不认证

- 日期：2026-10-03
- 状态：已接受；修订主仓库 ADR 0068 决策 3（设备令牌认证）与 ADR 0070 中关于令牌的各条；
  ADR 0068 的核心——**数据库端口不出内网**——不变
- 影响：`practice/nas_admin`（驾考 API、学习者目录 API、令牌表与管理脚本、测试、文档）；
  `subjects/driver`（同步配置、同步器、目录客户端、配置页）；Cloudflare 侧的一次性配置
- 延续：ADR 0069（仪表盘外网靠 Access）、0071（无口令的信任模型）、0075（按名字登录）

## 背景

ADR 0068 为外网访问设计了「每台设备一个令牌」：库里只存哈希、可单独撤销、有限流。放到
实际场景里它显得太重：

1. **概念抽象**。使用者是几个家人，新电脑要先发令牌、再手动贴进配置页，才能同步；贴错、丢
   了、不知道是什么，都是门槛。
2. **信任模型本来就是「无口令」**（ADR 0071）：登录只靠名字，令牌挡不住家里人，只挡陌生人。
   挡陌生人这件事，Cloudflare 的访问规则（Access）已经在做。
3. **实测外网入口已经被 Access 挡住**。2026-10-03 对 `www.yatiger.cn` 做了只读检查
   （不带任何凭据的 GET）：`/`、`/api/health`、`/api/driver/v1/ping`、`/api/users/v1/login`、
   `/driver/` 全部在 Cloudflare 边缘被 302 到 `*.cloudflareaccess.com` 的登录页，没有一个请求
   到达应用。门已经在那里了，应用里再放一道是重复。

## 决策

1. **取消设备令牌这个概念。**应用的 API 不再校验 `Authorization`；令牌表、令牌哈希、
   `scripts/driver_token.py`、客户端配置里的令牌字段全部删除。库里已有的 `driver_api_tokens`
   表**不动数据、不再读取**，需要时可手动 `DROP`。
2. **访问控制放在网络层，分两条路：**
   - **内网**：客户端直连路由器上的后台，家用网络内视为可信，不需要任何配置或凭据。
   - **外网**：经 Cloudflare 隧道，整个主机名（包括 `/api/` 与 `/driver/`）由 Access 把守。
     浏览器看仪表盘走「允许」策略（如邮箱一次性验证码）；桌面客户端走「服务认证」策略，
     带一对 Access 服务令牌（`CF-Access-Client-Id` / `CF-Access-Client-Secret`）。**这对凭据
     全家共用、存在客户端的可选配置里，属于 Cloudflare 的概念，不是应用的**；只在家里内网用的
     人完全用不到。
3. **身份仍是学习者**：请求头 `X-Athena-User` 带学习者编号，服务端按它隔离读写，无口令
   （ADR 0071、0075）。防误看，不防对抗，这一点不变。
4. **限流改按来源地址**（优先 `Cf-Connecting-Ip`，没有则连接地址），沿用每分钟 300 次。目的只是
   不让失控的客户端把库打爆。日志记录来源地址与学习者，不再记设备名。
5. **客户端配置总是存在**：内网端点默认 `http://192.168.6.1:5000`；外网端点与外网访问凭据可选。
   「没配令牌所以不同步」这个状态消失：同步总是尝试，连不上就是「暂不同步」，离线队列照旧
   （ADR 0070）。旧配置里的 `token` 字段读取时忽略。
6. **被 Cloudflare 拦住要说清楚，不当成网络不通。**客户端请求不跟随重定向；收到 3xx、
   401、403，或带 `Www-Authenticate: Cloudflare-Access` 的响应，都按「外网访问被访问规则
   拦住」处理，提示检查外网访问凭据。
7. **`/api/driver/v1/ping` 不要求学习者头**，作为连通自检（配置页的「测试连接」用）。

## 风险与对策

- **应用里不再有第二道门。**Access 配置被误删或写错时，外网任何人都能读写数据。对策：
  每次改完 Access 后做一次自检——不带凭据请求应得到 Cloudflare 的 302 或 403，**不应**得到
  应用自己的 JSON 响应（命令见 `practice/nas_admin/docs/cloudflare-access.md`）。可选的后续加固
  是服务端校验 `Cf-Access-Jwt-Assertion` 的签名、通过隧道来的请求一律要求有效 JWT（失败即拒），
  需要在路由器上引入密码学依赖，暂不做。
- **内网里的任何设备都能读写所有人的数据。**家用网络信任；访客 Wi-Fi 若与内网同网段就会暴露，
  建议在路由器上做访客网络隔离。
- **失去单设备撤销。**外网访问凭据泄露时，在 Cloudflare 里换一对服务令牌，全家重新填一次。
- **失去按设备记录。**日志里只有来源地址与学习者。

## 后果

- 新电脑的上手从「先找人要令牌」变成「输入名字」：在家什么都不用配；在外面只多填一对外网
  访问凭据。
- `practice/nas_admin` 的认证代码大幅变少；驾考 API 与学习者目录 API 共用一个很小的限流模块。
- 本 ADR 修订的几处旧文字（ADR 0068 决策 3、0070 决策 3 与 8、0074 与 0075 里「令牌」的说法）
  保留原文不改，以本 ADR 为准。
