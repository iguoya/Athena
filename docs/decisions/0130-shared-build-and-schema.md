# ADR 0130：构建共享、schema 共享（取代「构建完全隔离、不共用 schema」）

- 日期：2026-10-11
- 状态：**暂缓实施，见 [ADR 0132](0132-defer-shared-layer.md)**；原为已接受（tiger 2026-10-11：构建完全隔离、不共用 schema 改为构建共享、共享 schema）；
  **原则先行，机制待定**——共享层的位置、工具与迁移顺序由后续 ADR 决定，本 ADR 不动代码
- 取代：[ADR 0032](0032-independent-apps-launched-as-processes.md) 决策 2（构建完全隔离）与决策 3
  末句（复用 schema 会产生耦合）；[ADR 0043](0043-sourced-content-across-apps.md) §1「schema 不共用」；
  根 `AGENTS.md` 与 `docs/REPOSITORY.md`「共用规范，不共用 schema」
- 修订：[ADR 0037](0037-independent-apps-own-their-progress-store.md)——进度**数据**仍各应用自管，
  进度库**表结构**走共享 schema；[ADR 0073](0073-global-user-directory.md) 的「唯一例外」不再是例外
- 不变：[ADR 0062](0062-apps-own-their-constraints.md)（约束不继承）——它管的是规则文本，不是代码

## 背景

隔离当初解决的是「主程序与异构应用互相牵制」（C 语言应用 vs. GTK 主程序）。现在的
形态已经变了：

- 26 个应用的壳都是 Tauri 2 + Node，阅读器、测验、进度写入、主题、检查脚本高度雷同；
  「完全隔离」意味着同一个 bug 要改几十遍，或者放任各份实现漂移。
- 漂移已经出现：进度库至少有 `knowledge_progress`、`attempts`、`progress/predictions`
  三种表结构，激励、复习由记录派生的能力只在个别应用里有。
- 每个应用独占一份 `node_modules` 与 Rust `target`（单个 1～2 GB），磁盘与冷构建时间
  线性膨胀。
- 近期要落地的教学能力（间隔复习、混合练习，ADR 0096、0113）本质是跨应用的**同一套
  机制**，在隔离前提下只能逐个应用重做。

## 决策

1. **构建共享。** 仓库设一个**共享层**，放各应用共用的代码（内容阅读/块渲染、测验与
   判分、进度读写与迁移、间隔复习调度、主题）和共用的构建基础（统一依赖版本、共享
   Cargo / Node 工作区、共享构建缓存）。应用以依赖方式引用共享层。
2. **schema 共享。** 内容块类型与内容契约（`content-contract.json` 的公共部分）、
   进度库表结构、字段名由共享层定义并版本化；应用只在**自己的领域扩展**处加字段，
   不在公共部分另起一套。
3. **应用仍是独立进程、独立目录。** 应用之间**不互相引用**：共享只经共享层，不经
   另一个应用的路径、头文件或内容配置。每个应用仍能单独开发与运行（依赖共享层，
   不依赖其他应用）。启动方式仍只声明 `app.json`（ADR 0046）。
4. **数据与规则不因此合并。** 进度库的数据各应用自管、随仓库走（ADR 0037、0053；
   driver 的 PG 例外照旧）；知识点 ID 前缀各用各的；每个应用的约束仍只来自仓库级原则
   和自己的 `AGENTS.md`（ADR 0062）。
5. **共享层变更要向下兼容或带迁移。** 共享层带版本号；应用声明依赖的版本；改公共
   schema 必须附迁移，并跑通依赖它的应用的 `check.py`（`scripts/check.py` 全量）。
6. **过渡期规则。** 共享层落地之前：现有应用的私有实现保持现状，不做大爆炸式改动；
   但**新增或重写**阅读器、测验、进度、复习这类通用能力时，不再新写一份私有版本，
   先问共享层是否已有或应当放进去。
7. **待后续 ADR 决定的事**（每项都是结构性决定，须使用者拍板）：
   - 共享层放在哪（如仓库根的 `shared/` 或 `packages/`）、拆几个包；
   - 工具选型（npm/pnpm workspace、Cargo workspace 如何组合，驾考的 Flutter 如何对接
     或排除）；
   - 公共进度 schema 的具体形态，以及现有三种库如何迁移；
   - 迁移顺序（建议先选一个有真实数据、内容充实的应用做试点，其余随改随迁）。

## 后果

- 仓库级与应用级文档中「构建完全隔离」「不共用 schema」的表述改写为本 ADR 的口径；
  各应用 `AGENTS.md` 里的「与其他应用构建完全隔离（ADR 0032、0062）」同步改为
  「不引用其他应用；通用代码与 schema 经共享层（ADR 0130）」。
- 耦合风险转移到共享层：它成为单点，改动门槛更高（决策 5）。这是有意接受的代价，
  换的是改一处全应用生效、schema 不再漂移、磁盘与构建时间不再线性增长。
- 「应用能脱离其他应用独立开发与运行」继续成立，但不再意味着「不依赖仓库里的任何
  共用物」。
- 在后续 ADR 落地前，本 ADR 只是方向声明；任何代理不得据此自行移动目录或抽取代码。
