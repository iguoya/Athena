# ADR 0036：「本章导览」置于首位，作为极简概要

- 日期：2026-09-12
- 状态：已接受；`type_semantics` 已把导览标签调到第一位，其余章节随大纲一起补
- 延续：ADR 0028（学习内容三层分工）——导览**不是第四层内容**，见下文
- 相关：ADR 0033（用活的可视化和互动表达）、ADR 0034（Markdown 手册已删除）

## 背景

`type_semantics` 的教学大纲写完后有 526 行 Blueprint：一句题注、五类风险各带一句说明、
心智模型及其展开、四档难度各带评定理由、知识点路线图、五个检查点各带解释。每一段都有
存在理由，合起来却读不完——用户的原话是"内容有点多"。

问题不在大纲写错了，在**同一份内容被要求同时服务两种场景**：

- **第一次进入一章**：需要理由。为什么这样分、为什么这个难度、为什么先学这个——没有
  理由，清单就是一堆要背的条目。
- **回顾、自查、隔一阵回来重建框架**：只需要骨架。这时候每条后面的解释句都是噪音，
  要在 500 行里滚动找那几个名字。

## 撤销的初版方案

本 ADR 初版提议**新增一个叫「简纲」的标签**，写法是"只留标签、删掉解释"的纯文字清单：
每条一行，不写理由、不举例，一屏看完。同日撤销，两条理由都值得记下来：

1. **不要为已有的东西再造一个新名字。**「本章导览」标签本来就在（86 行：一张思维导图、
   四个贯穿全章的问题、五节各一行），它就是这里要的极简概要。需要的只是把它提到第一位
   并说清职能，而不是在大纲和教学过程之外再立一层内容。

2. **"简明扼要"不等于"纯文字清单"。** 那份简纲设计把大纲里的可视化全删了，只剩标签
   文字。用户的反应是"感觉所有的思维导图等可视化元素都消失了，他们不是非此即彼的
   关系"——**简洁和可视化不是二选一**。极简概要恰恰最该以图承载：一张结构图比二十行
   标签更快说清"这章有什么、怎么串起来"。该删的是解释性文字，不是图。

## 决策

### 1. 「本章导览」是每章 Notebook 的第一个标签

顺序是「本章导览 → 教学大纲 → 各知识点」。学习路径自然：先用一张图知道这章有什么、
怎么串起来，再进大纲看为什么这样分，最后进教学过程学细节；回顾时直接开第一个标签。

### 2. 职能是极简概要：给结构，不给理由

导览回答"**这章有什么、怎么串起来**"。它**不做大纲那样的解释**——不写为什么这样分、
不写难度评定理由、不举例、不写 API 细节、不写易错点。

`type_semantics` 的现有导览就是体例参考：

- 一句话说明全章围绕什么展开
- **一张结构图**（`images/type_semantics_map.svg`），图注说明箭头含义
- 贯穿全章的几个问题（各一行，不展开）
- 每一节解决什么问题（各一行，不展开）

### 3. 以图为主

按 ADR 0033，导览是最该用图的地方：概念之间怎么串、哪节为哪节做铺垫，画出来比列出来
快得多。静态结构用 SVG；如果结构能由 `requires` 依赖图算出来，就画成活的并让节点可点
跳转，不要做成会和数据漂移的图片。

### 4. 信息与大纲同源，导览不引入新判断

导览里出现的每一条，都应当是大纲里已有的说法的浓缩。**不得给出大纲之外的新判断**
（比如大纲没排过的学习顺序、大纲没评过的难度）。

这条是为了防漂移：ADR 0034 删掉 Markdown 手册，正是因为同一章两份内容会各说各话。
导览如果变成另一处要独立维护的内容源，等于把刚扔掉的问题换个名字请回来。

因此 ADR 0028 的**三层分工不变**（大纲 → 教学过程 → 教学实验）。导览是第一层的另一种
呈现密度，不是第零层。

### 5. 与「小结」的分工

两者都短，容易混：

- **导览**在最前，答"这一章有什么、怎么串起来"，是地图。
- **小结**在教学过程末尾，答"讲过了什么、要点是什么、容易错在哪、各知识点怎么串起来"，
  是复盘。

导览不写易错点，小结不写章节结构图。

## 后果

- 不新增标签、不新增内容层次。`type_semantics` 的改动只是把两个标签对调，加上
  `m_section_tabs` 描述数组跟着换序。
- 大纲**不因此变短**。大纲继续承担解释责任，该有的理由一条都不删——导览存在的意义
  就是让大纲可以安心把话说完。
- 新增一处漂移风险：大纲改了说法而导览没跟。缓解靠第 4 条的同源约束加评审检查。
