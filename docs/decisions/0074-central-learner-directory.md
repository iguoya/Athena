# ADR 0074：中心学习者目录是权威，ID 由后台在登记时生成（修订 ADR 0072、0073）

- 日期：2026-10-03
- 状态：已接受；修订 ADR 0073 决策 2（「暂不开放 API」）与决策 4（续用靠输入 ID）、ADR 0072
  决策 2（「重名拒绝」）与决策 4（续用输入 ID）、ADR 0071 决策 4（「新用户无需预注册」），
  其余各条继续有效
- 影响：`practice/nas_admin`（用户目录表与接口）；`subjects/driver`（选择页、注册表）；
  `docs/REPOSITORY.md` 的 `Athena/users.json` 约定；将来接入中心的其他学习应用
- 延续：ADR 0070（本地优先）、0071（隔离机制）、0072（ID 与显示名分离）、0073（全局目录）

## 背景

ADR 0072、0073 把「身份」和「称呼」分开，并说了学习者目录是仓库级设施，但落地时留了一个缺口：
**名字与 ID 的绑定只存在各机的本地 `users.json`，中心的 `athena_users` 只有迁移脚本写过一行
tiger，没有人读、也没有人写。**由此带来：

1. **两个事实来源**：谁是学习者、叫什么，本地注册表说了算，中心表是摆设；新建的学习者中心
   根本不知道。
2. **名字到不了需要名字的地方**：只读仪表盘（ADR 0069）按 `user` 列聚合，拿到的只有 `u_xxx`，
   显示不出人名。
3. **改名不跨设备**：改名只改本机，另一台机器上还是旧称呼。
4. **续用靠手输 16 位十六进制 ID**：对真正要考驾照的家人太硬，也容易输错、并凭空造出一个
   不存在的「幽灵学习者」。

## 决策

1. **中心 `athena_users(id, name, created_at, updated_at)` 是学习者目录的唯一权威。**
   「有哪些学习者、各叫什么」以它为准；本机 `users.json` 退为缓存（见决策 6）。ID 格式不变
   （`u_` + 16 位十六进制），仍是身份、永不变、不复用（ADR 0072）。
2. **ID 由后台在首次登记时生成。**新建学习者 = 使用者输入名字 → 客户端调用登记接口 →
   服务端用安全随机数生成 ID、与名字绑定、返回。客户端不再自己造 ID。tiger 的规范 ID 仍由
   迁移脚本生成并登记（ADR 0073 决策 3 不变），只是此后它也在目录里被所有设备看到。
3. **登记需要联网，不为离线新建设计路径。**已登记的学习者照常离线做题（ADR 0070 不变，缓存
   里有名字就能选、能用）；而新建学习者是罕见的一次性动作，且设备本来就要先配置令牌才谈得上
   同步，所以不做「离线先建、联网补登记」。联网失败时选择页明说「现在连不上，稍后再新建」。
4. **名字不要求唯一。**身份是 ID，不是名字；允许两个学习者同名（取消 ADR 0072 决策 2 的
   「重名拒绝」）。界面遇到重名时在名字后附 ID 末 4 位区分。
5. **谁都能改任何学习者的名字。**与「无口令、令牌即设备级信任」的模型一致（ADR 0071 后果）：
   持有设备令牌就能改目录里的任何名字。改名只改 `name` 与 `updated_at`，不触碰 ID 和任何
   同步数据；改名即时对所有设备生效（下次拉取目录时）。本 ADR 不提供删除学习者。
6. **本机 `Athena/users.json` 降为目录缓存加本机偏好。**
   - `users[]` 是中心目录的本地副本：联网时拉取刷新，离线时用缓存。
   - `last`（上次使用的学习者）仍是本机独有，不进中心。
   - 选择页列出目录里**所有**学习者，点选即用，取代 ADR 0072/0073 的「手输 ID 续用」；
     tiger 收编也变成在列表里点 tiger（ADR 0073 决策 4 的手输步骤随之取消）。
7. **接口属于全局目录，不挂 driver 前缀。**最小集：登记（名字 → ID）、列出、改名。路径、
   令牌作用域（沿用设备令牌还是单独发）、错误码等细节由 `practice/nas_admin` 的接口文档
   定，不在本 ADR 里。
8. **服务端最终拒绝未登记的 `X-Athena-User`。**取代 ADR 0071 决策 4 的「行首次出现自然存在」：
   请求带的 ID 必须在目录里，否则 400，防止笔误产生幽灵学习者。**开启顺序是最后一步**——先让
   迁移脚本登记 tiger、先让客户端全部升级到会登记，再打开校验，避免旧客户端被误拒。

## 后果

- 目录与记录终于有统一的「谁」：仪表盘可以按目录显示人名，不再是 `u_xxx`；改名一次，处处一致。
- `docs/REPOSITORY.md` 的 `users.json` 一节需要同步修订：`users[]` 是缓存而非权威、
  「各机显示名互不影响」作废、读写约定增加「联网时刷新缓存」。随实现一起改。
- 目录成为新的单点：路由器或后台不可用时，无法新建学习者、无法改名；已登记者做题与离线
  缓存不受影响。
- 令牌能改任何人的名字，与 ADR 0071 一致（防误看，不防对抗）；若将来令牌发给家人以外的人，
  这条要重新评估，同时重新评估「无口令」本身。
- 同名学习者靠 ID 末 4 位区分，界面要处理；不做强唯一换来的是没有「抢名字」和「重名拒绝
  引发的离线冲突」。
