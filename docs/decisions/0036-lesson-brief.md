# ADR 0036：教学简纲——大纲的压缩视图

- 日期：2026-09-12
- 状态：已接受；`type_semantics` 先行，其余章节随大纲一起补
- 延续：ADR 0028（学习内容三层分工）——简纲**不是第四层内容**，见下文
- 相关：ADR 0034（Markdown 手册已删除）、ADR 0033（用活的可视化和互动表达）

## 背景

`type_semantics` 的教学大纲写完后有 526 行 Blueprint：一句题注、五类风险各带一句
说明、心智模型及其展开、四档难度各带评定理由、知识点路线图、五个检查点各带解释，
最后是小结。每一段都有存在理由，合起来却读不完——用户的原话是"内容有点多"。

问题不在大纲写错了，在**同一份内容被要求同时服务两种场景**：

- **第一次进入一章**：需要理由。为什么这样分、为什么这个难度、为什么先学这个——
  没有理由，清单就是一堆要背的条目。
- **回顾、自查、隔一阵回来重建框架**：只需要骨架。这时候每条后面的解释句全是噪音，
  要在 500 行里滚动找那几个名字。

把两种场景塞进一份内容，结果是两边都不称手。

## 决策

### 1. 增设**教学简纲**：大纲的压缩视图，不是新内容

简纲与大纲**信息同源**：简纲里出现的每一条，都必须是大纲里已经有的标题或标签。
简纲**不得引入大纲里没有的说法**，也不得给出大纲之外的新判断。

这一条是硬约束。它的意义是防止两份内容漂移——ADR 0034 删掉 Markdown 手册，正是因为
同一章两份大纲会各说各话。简纲如果变成"另一处要同步维护的内容源"，等于把刚扔掉的
问题换个名字请回来。

因此 ADR 0028 的**三层分工不变**（大纲 → 教学过程 → 教学实验）。简纲是第一层的另一种
呈现密度，不是第零层。

### 2. 写法：只留标签，删掉解释

| 大纲里的写法 | 简纲里的写法 |
|---|---|
| 「查有效期」+「对象此刻是否仍然存在，引用会不会活得比所指对象更久。」 | 「查有效期」 |
| 「进阶 · 必须掌握：值类别。规则密度高，第一遍能判断左值／纯右值／将亡值并说明它影响哪种绑定即可。」 | 「值类别 — 进阶 · 必须掌握」 |

具体约束：

- **每条一行，不写解释句、不写理由、不举例、不写 API**。
- 全章简纲**一屏看完**（约定：1440 逻辑像素高度内不滚动）。这是硬指标，超了就说明
  还在解释。
- 结构固定四块，缺一不可也不再多：
  1. **一句题注**——这一章承诺解决什么（直接取大纲题注）
  2. **主脊**——本章反复使用的那几个判断动作的名字（`type_semantics` 是五个检查点）
  3. **知识点清单**——每个知识点一行，带难度档与掌握目标，无评定理由
  4. **推荐顺序**——先修拓扑序，只给顺序不说为什么

### 3. 载体是 `.blp`，不是 Markdown

用户提这条需求时说"之前的 markdown 文档可以作为教学简纲"。本 ADR 把它理解为**参照
那种体量与文风**（短、纯文本、概要式），**而不是恢复 Markdown 文件**，理由两条：

- 简纲和大纲讲同一批知识点。一份 Markdown 简纲照样会成为写新章节时的锚，ADR 0034
  要解决的干扰问题会原样回来。
- 简纲的每一条**要能点进大纲对应位置**（见下条）。跨渲染器做不到这种联动，这正是
  ADR 0024 退出 WebView 时点名的"割裂"。

> 如果本意确实是要一份可离线阅读、可打印的 Markdown 简纲，这一条要推翻重写——
> 那是另一个取舍（可携带性 vs 不漂移），需要单独决定。

### 4. 简纲是可点的索引，不是静态清单

按 ADR 0033，简纲里的每一条都应当可点击，跳到大纲里对应的那一段；知识点行应当直接
跳到该知识点的教学过程标签。熟练度数据已经在学习库里，知识点行上顺带标出当前掌握
状态——这是"能由运行时数据算出来的就画成活的"在简纲上的应用。

这也是简纲相对"把大纲读一遍"的真正增量：它是**导航面**，不只是摘要。

### 5. 位置：Notebook 的第一个标签

顺序变成「简纲 → 教学大纲 → 本章导览 → 各知识点」。理由是学习路径自然：先知道有
什么、多难、什么顺序，再进大纲看为什么，最后进教学过程学细节；回顾时直接开第一个
标签，不必在大纲里滚动。

不做成大纲页顶部的折叠区——重要内容不藏在折叠区里。

### 6. 与「小结」的分工

两者都短，容易混：

- **简纲**在最前，回答"这一章有什么、多难、什么顺序"，是地图。
- **小结**在教学过程末尾，回答"讲过了什么、要点是什么、容易错在哪、各知识点怎么串
  起来"，是复盘。

简纲不写易错点，小结不写难度评级。

## 后果

- 每章多一个标签和一块要写的内容，但它派生自大纲，写作成本主要是"删"而不是"想"。
- 大纲**不因此变短**。大纲继续承担解释责任，该有的理由一条都不删——简纲存在的意义
  就是让大纲可以安心把话说完。
- 新增一处漂移风险：大纲改了标题而简纲没跟。缓解靠第 1 条的硬约束（简纲只用大纲已有
  的标签）加评审检查；如果将来把大纲内容结构化，简纲应改为从同一份数据渲染，机制上
  消除漂移。
- 知识点行的难度、掌握目标和熟练度都来自现有数据，不新增配置字段。
