# ADR 0040：学习内容拒绝八股——篇幅与掌握目标匹配

- 日期：2026-09-12
- 状态：已接受；`cpp.TypeSemantics` 已按此精简，后续章节写作以此为准
- 延续：ADR 0028（三层分工）、ADR 0029（难度与掌握目标两个维度）、ADR 0031（知识类型决定教学动作）、ADR 0039（撤销导览）

## 背景

第一章七个知识点的教学过程写完之后，把每节的篇幅和它在 `athena.json` 里的评级
放在一起看，出现了明显的倒挂：

| 知识点 | 难度 / 掌握目标 | 篇幅 |
|---|---|---|
| `decltype` | 4 / **一般了解** | 485 行 |
| `cast` | 2 / 必须掌握 | 494 行 |
| `enum_class` | **1** / 必须掌握 | 382 行 |
| `auto_deduction` | 3 / **需要精通** | 496 行 |
| `value_category` | 4 / 必须掌握 | 231 行 |
| `object_lifetime` | 3 / **需要精通** | 206 行 |

一个只要求"知道它解决哪类问题"的知识点，写得和要求精通的一样长；难度 1 的
`enum_class` 比难度 4 的 `value_category` 长出一半。

原因不是内容多，是**形式**：每一节都照着同一套模板配齐了组件——
"为什么 → 讲解 → 边界 → 去实验里核对 → 小结"，哪怕这一节的边界只有一句话、
小结只是把考核解析里的话换个说法再说一遍。大纲那一页更严重：既列「五类风险」又列「五个
检查点」，两节一一对应；末尾还有一节「回顾时尤其检查这些误区」，五条误区每条
都已在对应小节当场讲过。ADR 0039 撤销的「本章导览」是同一个病的另一个症状——
大纲太长，于是在前面加一份摘要，而不是把大纲写短。

用户的原话是："既要有套路格式，也不拘泥于套路格式，不要写成八股文，要言之有物、
言简意赅。"

## 决策

写学习内容时，**范式是参考，不是模具**。具体三条：

**一、篇幅与掌握目标匹配。** 写完一节，对照 `athena.json` 的 `difficulty` 与
`mastery_goal` 校准：难度低或只要求"一般了解"的知识点不该比要求"精通"的长。
篇幅倒挂就是该删的信号，删的是形式，不是内容。

**二、同一组东西不写两遍。** 一份内容在两处各写一遍，无论是"摘要 + 正文"、
"风险清单 + 检查点清单"，还是"大纲里的误区 + 小节里的误区"，都会漂移。
能合并的节直接合并；大纲只指方向，**必要的细节一律下放到对应的子章节**。

**三、固定组件不是必须凑齐的模板。** "边界"只有一句话时就并进结论；并排对照、
互动分类器、逐步演示这些手段按知识点性质选，不是每节都要有一遍。

反过来也一样：**这条不能被压缩成"有考核就不写小结"这类规则再套用**。考核逐题
判分给解析，验证的是单点判断；小结给整体脉络和"学到这里为止够了"的收束，两者
作用不同，可以并存。要拒绝的是为凑格式而写的、没有新信息的概括，不是"这一节
存在考核"这个事实。把判断原则规则化，是换个方向的机械化。

## 后果

按这三条重做第一章，篇幅从 3485 行降到 2858 行（-18%），其中：

- 大纲 756 → 477 行：九节合成五节，正好对上 ADR 0028 的范式（主次与顺序、
  五个检查点、心智模型、三组选择、落点）；
- `decltype` 485 → 330 行：问题与立场对照合成一节，边界从四条收到三条；
- `cast` 494 → 396 行：「选哪种转换」四条 callout 被下一节的对照表覆盖，
  只把表里没有的三处细节留下；
- `enum_class` 382 → 347 行：与对照表重复的 callout 删除，边界与小结合并；
- 精通级的三节（初始化、类型推导、对象生命周期）基本不动——它们的长度是内容
  带来的，不是形式。

**代价**：判断"这一节该有什么"比照模板填空更费神，也更依赖写作者对该知识点的
理解；两个人写出来的结构会不一样。这是有意接受的——统一的形状本来就不是目标，
读者能不能用最少的篇幅拿到判断力才是。

**执行**：`AGENTS.md`「学习内容」一节列出了这三条，写作时按它自查；代码评审时
把"篇幅是否与评级匹配"和"有没有一份内容写成两份"作为常规检查项。
