# ADR 0083：启动器的学习应用面板改为放射状思维导图，关系由 app.json 的 group / related 声明

- 日期：2026-10-03
- 状态：已接受
- 影响：`launcher/gui` 的学习应用面板；`app.json` 新增可选字段 `group`、`related`；
  `launcher-core` 新增纯函数的布局模块
- 关系：延续 [ADR 0044](0044-menubar-launcher.md)（常驻启动器）、
  [ADR 0046](0046-unified-dev-orchestrator.md)（新增应用启动器不改代码）、
  [ADR 0065](0065-one-colour-icon-per-app.md)（图标原样显示）；不改
  [ADR 0048](0048-menubar-launcher-stays-macos-only.md) 的菜单栏版

## 背景

学习应用面板把图块按清单顺序一行行排成网格，连线只有 `evolves_from` 一种（C → C++），
而且连线的位置是用「当前列数」现算的：窗口一拉宽，列数变了，线就可能穿过别的图块。
使用者的反馈：一行行太机械，不利于连线；想要思维导图那样的空间感。

网格的问题不只是难看：它没有「位置」这个信息可用。想表达「这几个应用属于同一个领域」
「这两个应用相关」，网格里没处放。

## 决策

1. **学习应用面板改成放射状思维导图。** 中心是虎头，向外一圈是领域分组节点，应用挂在各自领域外面
   的一圈（应用多了再往外加圈）。窗口小于画布时可滚动。实践面板仍是网格：那些小项目彼此没有关系可画。
2. **关系和分组由 `app.json` 声明，启动器只读：**
   - `group`（字符串，可省）：领域名，如「编程语言」「英语」。同名的应用归一组；省略归「其他」。
   - `related`（字符串数组，可省）：相关应用的 id。**无向**，只在一边声明就行；写了不存在的 id 忽略。
   - `evolves_from` 保留，画成带箭头的实线（谁从谁长出来）；`related` 画成细线、不带箭头。
3. **全自动布局，不存坐标，不能拖动。** 位置完全由清单算出，换机器、新增应用都不用管。
   布局是 `launcher-core` 里的纯函数：输入应用清单，输出节点、分组、圈和连线的坐标，有单元测试；
   GUI 只负责画。
4. **图标仍然原样显示**，不垫底色、不加光环、不随状态放大（ADR 0065 不变）。「立体感」来自中心的
   同心圈、领域的颜色和连线，不是给图标加阴影。
5. **不动契约。** `list --json` 的 `state` 不变；菜单栏版仍是列表；新增字段对旧前端只是被忽略的额外字段。
   启动器里仍然没有按应用写的分支（ADR 0046）：分组与关系全部来自数据。

## 后果

- 窗口默认比原来的托盘小窗大：思维导图需要约 700 像素见方的画布，放不下就滚动。
- 分组名是自由文本，写错一个字会多出一个分组——靠 `launcher/README.md` 里的字段说明约定。
- 新增应用要想挂对位置，在自己的 `app.json` 里写 `group`；不写也能显示，落在「其他」。
- 实践面板将来若也要分组，复用同一个布局函数即可，不需要再决定一次。
