# ADR 0166：协作观察台 comms-console 与通讯投影（comms v2）

- 日期：2026-10-15
- 状态：已接受
- 影响：新增 `tools/comms-console/`（Tauri 2 + React）；新增 PG 库 `athena_comms`（投影）；
  `comms/comms.py` 加固（原子写、status 乐观锁）；登记 REPOSITORY、根 README、根
  AGENTS.md、CI
- 关系：建立在 ADR 0165（按舱协作通讯）之上；PG 复用路由器上已有实例（`athena_driver`
  同一台，通路认知同 driver ADR 0070/0127：内网直连、端口不出内网）；工具类归 `tools/`
  （ADR 0146：做出能用的工具，不建进度库）

## 背景

ADR 0165 的协作通讯跑起来了（driver 舱第一批任务已流转），但有两个不足：

- **观察要跑命令**：看协作全貌（任务发布、状态流转、裁决、即时对话）得逐条跑
  `inbox` / `board` / `thread`，没有一个人能打开就看全貌的面。
- **数据只在 git 仓库里**：换一台机器要拉仓库才能看；「多机共用」没有集中点。

使用者要求：一个能观察智能体协作（即时对话、每个子项目的决策与任务发布记录）的
桌面软件，数据放路由器的 PostgreSQL 方便共用；并放开手脚把通讯机制本身做成熟。

## 决策

1. **数据分层：文件是唯一权威，PG 是投影，观察台只读。** 代理的写路径保持
   「CLI + 文件」不变（这是 ADR 0165 防覆盖铁律的根基，代理环境各异，文件最可靠）；
   路由器 PG（新库 `athena_comms`）只存投影。观察台**不提供任何写操作**——不回消息、
   不改状态、不发任务，写永远走 CLI。这样 UI 不会绕过「只增不改、各写各的」语义。
2. **观察台 `tools/comms-console`**（Tauri 2 + React，端口 1521，进程
   `athena-comms-console`，数据目录 `AthenaCommsConsole/`）：左栏舱列表（扫 PG 或本地
   `comms/*/`），主区三个视图——
   - **看板**：多舱任务泳道（todo / doing / review / blocked / done），负责人、优先级、
     依赖等待；
   - **任务**：任务书全文 + 流转时间线（创建、doing、review 附证据、done 验收、打回）+
     关联消息（leader 裁决、返工意见）——这就是「子项目的决策与任务发布记录」；
   - **对话**：正式消息与即时 chat 合并的统一时间线，线程折叠，leader/worker 角色标色；
   - 另附每舱活动统计（按日消息与任务事件数的条形图），自绘 SVG，不引图表库。
3. **投影与降级**：观察台启动时把本地 `comms/` 各舱增量 ingest 进 PG（幂等 upsert，
   按「舱 + 文件名 + 内容哈希」去重；表 `tasks` / `task_events` / `msgs` / `chats` /
   `sync_files`，ingest 首次运行自动建表）。查询优先 PG（多机汇聚：每台机器的观察台
   都投自己的本地文件，PG 是交集）；**PG 不可达或未配置时降级直读本地文件**，界面
   标明数据来源。DSN 从环境变量 `ATHENA_COMMS_PG` 或用户数据目录
   `AthenaCommsConsole/pg.json` 读，都不在仓库里；路由器侧建议建只读角色供查询。
4. **机制加固（v2）**：`comms.py` 全部写文件改**原子写**（临时文件 + rename，读方
   永远看不到半截消息）；`status` 加**乐观锁**（读-改-写前重读核对当前状态，别人刚改过
   就报重试）——leader 验收与 worker 交 review 同时发生的撞车保护。不做的：实时推送
   总线（`watch`/钩子轮询够用）、消息中心化存储为写路径（文件制是权威）、外网访问
   （协作观察是内网/本机需求）、观察台内编辑。
5. **通用化与自举**：舱就是通用化单元——任何子项目要多代理协作，建 `comms/<项目>/`
   舱即用（ADR 0165），观察台天然多舱总览，不绑定任何单个应用。本次开发的任务拆分
   与协作本身走 `comms/comms-console/` 舱（leader=zcode 主会话、worker=zcode-2 会话）：
   机制加固（决策 4）与「对话/决策口径」派给 worker，壳、数据层与界面由 leader 完成——
   用这套机制开发这套机制的工具。

## 后果

- 观察零门槛：打开窗口看全部舱的协作史；换机器装观察台即看，不必拉仓库。
- PG 里是协作史投影（含任务全文与消息全文），路由器上多一份协作数据备份；
  git 仍是档案权威。
- `comms.py` 写路径行为不变（命令、文件格式都不变），只更稳；旧舱（九州）迁移到
  公共工具后同样享受加固与投影。
- 观察台首版不做：消息全文检索、跨舱统计报表、通知中心——等真实使用反馈再议。
