# ADR 0167：多会话并行——按任务分箱的收件路由（comms v3）

- 日期：2026-10-15
- 状态：已接受
- 影响：`comms/comms.py`（inbox/ack/notify/status 四处）；`comms/README.md` 补「多标签页
  工作法」；实现派 comms-console 舱 T-102（cursor）
- 关系：在 ADR 0165（按舱协作）、0166（文件权威 + 投影）之上；v2 加固（原子写、乐观锁）
  是前置（comms-console 舱 T-001）

## 背景

当前身份模型是「代理名 = 单实例」。使用者实际会**开一个代理的多个标签页并行多任务**
（比如 cursor 一个标签页做驾考科目二、另一个做观察台增强）。这时：

- **收件箱混流**：每个会话跑 `inbox cursor` 看到的都是同一堆消息，要读完才能分辨
  哪条跟自己手上的任务有关——信息吵杂的直接来源。
- **已读游标互踩**：`read/cursor.txt` 是共享文件，一个会话 ack，其他会话的未读也消失，
  可能漏看本该自己处理的消息。
- **消息没有地址**：leader 对某个任务的问题发给 `cursor`，做别的任务的标签页也会被
  打扰。
- **任务与会话无绑定**：两个会话可能同时认领同一任务；任务进展记录里 `cursor：…`
  分不清是哪个会话干的。

## 决策

1. **任务是路由单位，不是会话。** 会话随标签页生灭，任务与状态机才是持久的。
   不新造「会话注册」机制——**`status T-xxx doing` 就是绑定声明**：一个任务同一时刻
   至多一个会话 doing；「这个任务正在被谁做」从任务状态即可推导。
2. **收件按认领分箱。** 消息带 `--task T-xxx` 的进该任务的箱；无路由的进公共箱。
   - `inbox <名>`：看全部（leader 与认领前的浏览）；
   - `inbox <名> --mine`：公共箱 + 名下 doing 任务箱——worker 会话认领后默认用这个；
   - `inbox <名> --task T-xxx`：只看一个任务的箱（接手别人做到一半的任务时也看得到
     该任务的历史箱）。
3. **已读跟着箱走。** `read/<名>.all.txt` 与 `read/<名>.<task>.txt` 分文件；一个箱
   ack 不动别的箱。同一任务换会话接手，箱与已读历史原样保留。旧的单文件
   `read/<名>.txt` 兼容读取（有它就并入 .all 箱）。
4. **认领冲突防护。** `todo → doing` 时核对当前状态：已经是 doing（且不是自己认领的）
   就报「该任务正在被认领，选别的或找 leader」——v2 的乐观锁在这里复用。
5. **打扰控制。** hook 用的 `notify` 支持同样的过滤：worker 会话只注入「紧急 + 认领
   任务相关」的摘要；其余消息安静躺在箱里，会话下一轮主动查。消息自身的分级约定
   不变（标题「紧急」才可打断、FYI 不需回）。
6. **可选会话标记。** `status --as <短标记>`（如 `--as tab2`）写进流转行
   （`cursor(tab2)：doing`），审计可分会话；可选参数，缺省行为不变，文件格式兼容。
7. **立刻可用的约定**（不依赖实现，写进 comms/README「多标签页工作法」）：
   一个标签页一个舱（跨项目 `--project` 天然分箱）；同舱开工先 `inbox` 认清全局再
   `status doing` 认领，认领后查收带 `--task`；看到任务已被别人 doing 就不碰；
   leader 对具体任务会话说话务必带 `--task`。

## 后果

- 多标签页从此「各看各的箱」：认领什么就看什么，不认领就只看广播，互不吵。
- leader 不用记「哪个消息发给哪个标签页」——带 `--task` 即可，投递由状态机推导。
- 代价：read 目录文件数变多（每人每任务一个），可接受；`--mine` 依赖任务状态干净
  （忘了把做完的任务从 doing 挪走，旧任务的消息还会进箱——review/done 本来就该及时标）。
- 实现与测试派 comms-console 舱 T-102（cursor，depends T-001 加固）；九州舱迁移后
  同享（ADR 0165 决策 4）。
