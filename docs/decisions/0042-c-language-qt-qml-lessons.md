# ADR 0042：C 语言学习应用用 Qt Quick / QML 写教案

- 日期：2026-09-14
- 状态：已接受
- 影响：`apps/c`；修正 ADR 0032 第 7 条、ADR 0041 第 4 条关于「启动 LVGL 小程序」的表述

## 背景

ADR 0032 把 C 语言做成独立进程，当时的窗口后端是 LVGL + SDL2：目的是先打通
「图谱点击 → spawn」这条链路，并给以后「看见内存」留一个自己画的壳。落地后
那个窗口只证明进程能起来，**并不是一份能教 C 的教案**。

C 语言最该教的是对象在内存里占哪一段、指针是地址、数组为什么会退化。这些
要用可交互的图来写，而不是再开一个空白 C 程序。LVGL 用 C 手搭控件，适合
做底层实验窗，不适合当教案的编写界面。

Qt Quick / QML 可以把一节课写成组件树：大纲、正反例、内存条、指针箭头都是
控件，改 QML 即时可见，和 DSA 用 JSON 块拼课、主程序用 Blueprint 写课是同一
类事——**教案有自己的描述语言**，不是「启动一个演示程序」。

## 决策

1. **`apps/c` 的主体是 Qt 6 Quick 教学应用。** 课表仍是 `content/curriculum.json`
   （知识点 ID、先修、难度、掌握目标）；**每一节的教学过程用 QML 写**，放在
   `qml/lessons/`，用共用组件（大纲五段、对照、内存条）拼出来。主程序图谱
   入口 spawn `scripts/dev.sh`，对着源码跑，不启动打包副本（ADR 0041）。
2. **原 LVGL 小程序保留在 `apps/c/playground/`。** 不删、不改它的职责；需要时
   仍可独立 `cmake` 构建。它不再出现在 `app.json` 里，也不是「C 语言编程」
   节点打开后看到的东西。以后若要把某种内存实验窗嵌进教案，从这里接，另说。
3. **QML 从源码树加载，不打进 qrc 当日常循环。** 改教案保存即可热加载；只有
   C++ 壳（读课表、监视文件）变了才重编。这是本应用的 `tauri:dev` 等价物。
4. **共用教学规范，不共用 GTK / Blueprint。** 大纲三层、难度与掌握目标、知识
   类型照 ADR 0028 / 0029 / 0031；载体是 QML。主程序 Meson 仍不引用 `apps/c`。

## 后果

- 点首页「C 语言编程」打开的是能改的教案，不是一个 LVGL 启动成功页。
- 本机需要 Qt 6（Quick / Qml）。开发脚本会找 Homebrew 的 `qt@6`。
- `playground/` 会和教学应用暂时两套窗口技术并存；教学应用稳定后，再决定
  内存实验窗是继续 LVGL 还是改成 QML 画布，不提前拆。
