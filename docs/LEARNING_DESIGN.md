# 学习页与多媒体教案规范

依据 [ADR 0027](decisions/0027-self-contained-multimedia-lessons.md)。这是后续页面设计的规范，
并非当前所有章节已经达到的状态。具体样例见 [类型推导教案](lessons/type_deduction.md)。

## 1. 学习页的责任

学习者不打开参考手册、不调用 AI，也应能从本页理解这个知识为什么存在、怎样工作、
解决什么实际问题、何时适用及哪里容易出错。手册提供扩展、完整规则与回查，不能承包必修解释。

先明确一个可应用的判断目标，例如“根据是否需要修改原对象选择值或引用”，再围绕它组织教学。
界面结构来自教案；Markdown 标题、源码文件顺序、成员函数数量都不决定教学顺序。
代码中的类/方法仍承担现有注册契约，一个学习段落可引用多个实验。

## 2. 讲解与练习怎样衔接

建议按下列线索编排，可根据内容往返与合并，不要求每节都有六张卡片：

| 讲解线索 | 页面需要交代 | 合适的学习动作 |
|---|---|---|
| 情境与用途 | 遇到什么问题；为什么值得学；学完能做什么 | 观察一个真实选择或现象 |
| 原理与模型 | 概念如何关联；规则在什么条件下成立 | 看图、比较、跟随演示 |
| 小范围尝试 | 刚才的解释在这个例子中怎样起作用 | 改一个条件、预测或选择 |
| 证据与解释 | 观察到了什么；为何如此；哪些结论不能由此推出 | 对照真实源码/结果或已核验的诊断 |
| 引申实践 | 换到实际代码应该怎么选；有哪些代价与边界 | 做一个不照抄原例的决策 |
| 回顾 | 整理规则、关系与易错点 | 用自己的话说明理由，按需回查 |

讲解是正常正文，不全部折叠为提示或答案。先讲后练完全有效；先预测适用于能够借已有知识
作出判断的问题，不强迫初学者在没有解释前猜陌生语法。预测题和学后确认题要有不同用途。
反馈不仅判对错，还说明原因，指出与图示或源码的联系。

不规定固定字数或“文字/练习比例”。每段推进一个具体理解，避免口号式短句，也避免
一整屏无层次的文字。解释要足够，删的是重复话，不是来龙去脉。

## 3. 页面排版

- 顶部简短交代主题、实际用途与必要前提；参考资料放在次要入口。
- 主体保持一条连续阅读线，小节标题用于定位，概念讲解默认展开。
- 一段文字就近配一张解释对应关系或过程的图，不把插图统一堆在页尾。
- 原理需要比较时用局部两列：文字/图示或两个语义分支。窄窗改为上下排列，保持阅读顺序。
- 动态图形需要空间时占整行，步骤解释紧跟图形；不让长篇源码长期挤占正文。
- 小练习穿插在相关解释之后，用轻量区域承载；主页面避免成为一串同等重量的题目卡。
- 专注实验继续承载完整真实源码与输出。教案写出进入前看什么、回来后怎样理解；
  返回保留学习位置和局部状态的能力应实际验证，不能靠方案宣称已经满足。
- 末尾小结说明知识关系、选择依据与常见误区；下一节入口明确，可选参考另列。

字体遵循全局可读下限，图内文字也要可读；不要为了塞进一屏缩小字号。
布局图中的尺寸只是方案，不替代 macOS/Ubuntu 与长内容的实际验证。

## 4. 媒介选择

| 媒介 | 用来解释 | 设计要点 |
|---|---|---|
| 图片、情境插画 | 真实用途、资源或操作环境 | 指明图中与知识有关的部分，避免只作装饰 |
| 静态对象图/关系图 | 对象身份、别名、所有权、类型关系 | 图例明确；名字与对象不要画成相同身份 |
| 流程图 | 决策条件、执行分支、选型过程 | 分支条件与结论同时可读，附上适用范围 |
| 动态图表/变体比较 | 一个参数或条件改变后发生什么 | 保留前后对照，同时显示数值/文字，避免只靠颜色 |
| 可控动画/时间线 | 创建、绑定、修改、转移、销毁等先后关系 | 每步有解释，能暂停、逐步、重置；结束后保留结果 |
| 真实代码与诊断 | 语义规则的实际验证 | 来源与验证环境明确，输出可追溯到对应代码 |

动画和图像是正式教学材料，可以成为一个小节的主要表达方式。文字说明原因、前提和
边界，图像展示关系与变化。选择静态或动态由这个知识需要观察什么决定。

### 每项视觉材料必须写清

1. **目的**：这一图或动作帮助理解什么，而不只是“增加可视化”。
2. **语义**：对象、名字、箭头、颜色与运动分别代表什么。
3. **分镜**：初始状态、触发动作、变化、结束状态与同步解释。
4. **控制**：需要哪些操作；暂停、重置、重复操作后如何表现。
5. **来源**：概念图解、作者编排的示意状态、程序结果或编译诊断。
6. **替代阅读**：静态状态表/文字说明；不能感知颜色或停止动画时仍能理解。

示意动画不是调试器。对象图中的矩形表示语义对象，不表示真实地址、物理内存布局或耗时，
除非数据确实来自对应测量。编译失败代码不能只被注释后再打印一句说明作为“验证”。

## 5. 作者交付与实现边界

一份可实施教案需要：目标与前提、实际讲解正文、页面区块顺序、视觉分镜、练习及解释、
证据来源、边界、小结、现有实现与待补能力的对照。语义核对以 C++20 为本项目基准。

学习页和手册可重复表达，但要一起核对规则；不能通过总结已有源码反向决定教什么。
源码展示从真实文件加载，不在 UI 维护另一份“可运行代码”字符串。

正式实现使用 Blueprint 页面与可组合模块；静态 SVG 沿用现有资源机制，确实需要动态
关系时用 GTK/Cairo。手册引用资产放在 `resources/articles/` 约定目录中并通过生成器检查。
本目录下的设计图是开发文档资产，不随应用打包。新增运行时媒体格式或依赖另行评估，
不为了一个教案建立通用课程引擎、动画引擎或 JSON 布局协议。

## 6. 评审标准

- 不打开参考资料，能否理解核心讲解并完成当前目标？
- 每个练习前是否具备必要解释，反馈是否说明原因？
- 图与动画是否解释了文字难以直接呈现的关系或变化？
- 图解、实际运行和诊断是否各自诚实说明来源，语义是否一致？
- 换一个情境后能否说明选择依据，而不只是重复原题答案？
- 停止动画、窄窗口、较大字号与键盘操作时，是否仍能完成学习？

先完成并亲自使用一个单元，再根据实际理解障碍修订教案和交互；测试通过与页面好看都
不能单独证明教会了。
