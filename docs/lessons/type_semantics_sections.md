# 类型与表达式：学习页子章节设计

- 状态：七节全部实现；后续修订按同一套流程（先摘大纲承诺，再定教学，最后派生实验）。
- 依据：[ADR 0028](../decisions/0028-outline-process-experiment-layering.md) 三层分工、
  [ADR 0031](../decisions/0031-knowledge-type-drives-teaching-actions.md) 知识类型决定教学动作、
  [LEARNING_DESIGN](../LEARNING_DESIGN.md) 第 3 节。
- 方向来自[教学大纲](../../resources/articles/cpp/type_semantics_overview.md)，不反过来。

## 1. 分节与顺序

一个标签一个知识点，与 `athena.json` 的 `subchapters` 一一对应——这样每个标签能显示
自己的难度星和熟练度圆点，掌握情况一眼可见。标签顺序就是大纲的推荐顺序，也就是
`requires` 的拓扑序：

| # | 标签 | 知识点 | 类型 | 掌握目标 | 现状 |
|---|---|---|---|---|---|
| 1 | 本章导览 | —— | —— | —— | 已有 |
| 2 | 初始化 | `initialization` | 概念 | 需要精通 | 已实现 |
| 3 | 对象生命周期 | `object_lifetime` | 概念 | 需要精通 | 已实现 |
| 4 | 类型推导 | `auto_deduction` | 策略 | 需要精通 | 已实现 |
| 5 | enum class | `enum_class` | 策略 | 必须掌握 | 已实现 |
| 6 | 类型转换 | `cast` | 策略 | 必须掌握 | 已实现 |
| 7 | 值类别 | `value_category` | 概念 | 必须掌握 | 已实现 |
| 8 | decltype | `decltype_deduction` | 概念 | 一般了解 | 已实现 |
| 9 | 运行实验 | 全章 | —— | —— | 已实现 |

第一个标签是章节教学大纲（第一层，GTK 控件手写），第二个是这一页自己的开局讲解
（第二层），两者不能互相替换。**实验固定在最后一个标签**：教学过程从头走到底不被
跳页打断，各节的「验证」按钮切到那里并载入对应源码，不再离开学习页。

## 2. 每节的唯一设计输入是大纲

动手写一节之前，先把[教学大纲](../../resources/articles/cpp/type_semantics_overview.md)
里属于这个知识点的承诺全部摘出来，当成这一节的需求清单：

- 「讲什么与边界」里属于它的那几条，连同难度与掌握目标评级
- 「落点」里对应的能力项
- 「判断与代价」里它涉及的检查点和权衡轴
- 「本章的主次与先后」给它的定位

然后逐条问：这一节讲到了吗？漏掉的就是缺口。**不要先去读实验源码**——那会让实现
划定教学范围。实验代码是这一节的产物：先定教学要让学习者确认什么，再看需要什么证据，
最后缺什么补什么。

这个核对是有效的：「类型转换」按四种命名转换写完后一对大纲，才发现「哪些类型变化会
**隐式**发生，范围、符号和精度可能怎样改变」整条承诺都没落地——写的时候脑子里是
"四个关键字"，不是大纲。`enum_class` 实验也是这样补上"裸整数放行了什么"和"显式转换
能造出列表外的值"两组证据的，它们都是教学要用、实验原先没有的。

## 3. 节内骨架按知识类型定，不套统一模板

**概念节**（初始化、生命周期、值类别、decltype）——目标是辨清边界：

1. 先给心智模型：这个概念把世界切成了哪几类
2. **正例与反例并排**，一次只改一个条件
3. 边界与近似案例：看着像、其实不是的那些
4. 一道分类判断，反馈解释为什么
5. 进真实实验核对
6. 小结：判准 + 最容易混的那一对

**策略节**（类型推导、enum class、类型转换）——目标是在情境里做选择：

1. 一个真实的选择场景，而不是语法罗列
2. 判据与代价：每个选项要什么前提、付什么代价
3. **换一个情境自己选，并说明依据**——不是四选一
4. 进真实实验核对
5. 边界：这个判断在什么情况下不成立
6. 小结：选择依据的一句话版本

技能节本章没有——这一章是判断类内容，没有"要能默写出来"的程序性操作。这不是漏标，
是这个维度确实有区分力。

## 4. 三个待补节的设计

### enum class（策略 · 必须掌握）

- **情境**：一个函数要表达"文件状态"，用 `int` 会怎样——两个不同枚举的值能互相比较、
  能当数组下标、能隐式转成整数打印，编译器一个都拦不住。
- **判据与代价**：什么时候值得给一组状态独立类型（跨接口传递、需要穷尽检查、
  值本身没有算术意义）；代价是要显式转换才能拿到底层值。
- **换情境**：给三个场景（协议里的状态字段、数组索引、位标志），各问该不该用
  `enum class`，说明依据——位标志那个正是它不方便的地方，答案不该是清一色的"用"。
- **实验**：`cpp.TypeSemantics.enum_class` 已存在，验证作用域、禁止隐式转换、显式取
  底层值。
- **边界**：作用域枚举不解决"值域完整性"——转换来的越界值仍是未定义行为。

### 类型转换（策略 · 必须掌握）

- **情境**：同一个转换需求，四种命名转换分别在承诺什么。
- **判据与代价**：按"你相信什么"选——相信数值关系用 `static_cast`，相信继承关系且要
  运行期检查用 `dynamic_cast`，只想去掉 `const` 用 `const_cast`，什么都不相信只想重解释
  位模式用 `reinterpret_cast`。检查发生在编译期还是运行期，是这一节的主线。
- **换情境**：三个真实片段，问该用哪种、哪些前提由你保证；其中一个的正确答案是
  "根本不该转换，应该改接口"。
- **实验**：`cpp.TypeSemantics.cast` 已存在，只展示可观察的合法边界。
- **边界**：写出了转换只说明你作了决定，不证明它安全；C 风格转换在真实代码里比
  `static_cast` 还常见，但它把四种意图糊成一个，正是要避免的。

### 值类别（概念 · 必须掌握）

- **心智模型**：表达式有两个独立属性——类型和值类别；值类别回答"它能不能被绑定到
  哪种引用、重载时选哪个"。它和对象寿命是两件事。
- **正反例并排**：同一个对象出现在不同表达式里（具名变量、`std::move(x)`、`x + 0`、
  函数返回值），分别是什么值类别——**同一个对象，不同表达式，不同值类别**是这一节
  最关键的对照。
- **边界案例**：`std::move` 之后对象还在，它只改变了表达式的值类别；将亡值不等于
  "马上要销毁"。
- **分类判断**：给四个表达式判值类别并说明能绑到哪种引用。
- **实验**：`cpp.TypeSemantics.value_category` 已存在，用重载选择显示实际结果。
- **边界**：本节只到"辨值类别、判断绑定与重载"；移动怎样真正发生留到 RAII 章。

## 5. 实施顺序与验收

按大纲推荐顺序补：enum class → 类型转换 → 值类别。每节完成后自查：

1. 不打开手册，仅本页能否理解并完成这一节的判断？
2. 教学动作和知识类型对得上吗（概念有没有反例，策略有没有换情境）？
3. 讲解、练习和实验输出的语义一致吗，来源标注诚实吗？
4. 这一节的能力是否对应大纲「落点」里的某一条？

不追求三节篇幅相同——`decltype` 标着"一般了解"，96 行是合理的；标着"必须掌握"的
三节不该停在 32 行的占位状态。
