# ADR 0002：思维导图从同心正圆改为椭圆分层布局

- 日期：2026-10-10
- 状态：已接受（tiger 2026-10-10：「采用合适的布局 充分利用启动器的界面空间 不要让
  图标都挤在一起」「你现在用的同心圆 我感觉没必要 因为大部分屏幕都是长宽比不一样的
  用同心圆对屏幕宽度不友好」）
- 关系：延续 [ADR 0083](../../../docs/decisions/0083-launcher-mind-map.md)（放射状思维
  导图，「应用多了再往外加圈」在这条里兑现）；同组兄弟同层不变（ADR 0101）；挂靠与
  引用的连线语义不变（ADR 0092、0116、0117）

## 背景

1. 引用挂靠与 408 五门科目课本体挂 cs408（ADR 0116、0118）之后，第一圈装不下全部
   成员，旧算法把**整圈**往外推：真实清单下第一圈半径从 258 被顶到 530，画布
   1588×1588。领域胶囊还缩在半径 161 的小圈上——胶囊与应用层之间空出一条 370px 的
   空白环带，图块全挤在外圈，组内两两紧贴、组间疏密不均。
2. 窗口设计是 700px 见方（画布放不下就滚动），1588 的画布在窗口里只能看到一角；
   而且正圆画布在横向长方形的屏幕上，左右两侧的内容全在滚动区外，「充分利用界面
   空间」无从谈起。

## 决策

1. **同心圈从正圆改为椭圆**：长短轴比 16:10（`ASPECT = 1.6`），长轴沿横向——内容
   铺进宽屏真正看得到的宽度。每层轨道沿两个轴各向外长一个层距（172，图块对角线，
   不变），斜着相邻的两层图块仍错不开对角线。
2. **层分配按径向深度贪心**：一层的椭圆轨道被两种块共享——本层成员组的图块，和内
   一层挂靠者的子节点。组的份额取大者（成员排开要的弧长，与子节点弧长按内外两层
   周长比折算回来的量）；**有子节点的组先占内层**——挂靠层要在成员层外再占一层，
   径向深度最大的组放最里面，整体层数才最少。同组兄弟必须同层（ADR 0101），一组
   大过整层才接受拆层。
3. **扇区按层独立切**：层的可用周长（打 97% 折扣留数值余量）按占用者份额切弧段，
   从正上方顺时针。成员块在组的扇区里按弧长均分；子节点围着挂靠者按弧长对称展开、
   钳在本组子扇区内，装不下压等距居中（语义同 ADR 0116 决策 6，从角度域换到弧长域）。
4. **胶囊按组方向排序后等弧长安放**：各应用层的扇区独立切，不同层两组的中点角可能
   撞在一起，照中点角放胶囊会永远重叠（旧算法靠无限放大胶囊圈「躲开」，实测把胶囊
   圈撑到近 2000px）。改为按组成员扇区中点角排序、沿胶囊椭圆等弧长排布，装不下先
   放大椭圆再抬高内层下限，层距保持 ≈152。
5. **画布按内容包围盒裁剪**：不再固定正方形。中心原点坐标系里摆完全部内容，取包围
   盒（含虎头与图块的标题悬挂）加边距，整体平移进画布。窗口 preferred 宽度提到
   960px 配合横向画布。
6. **界面画椭圆环**：Slint 的 `ArcTo` 不带椭圆半径参数，用四段三次贝塞尔近似
   （κ ≈ 0.5523，圆弧贝塞尔的标准系数），肉眼与真椭圆无差；从外到内叠出的「立体」
   底色照旧。

## 后果

- 真实清单下画布 1588×1588 → 1373×1051（面积 −43%，比例 1.31 贴横向窗口）；内容
  从「一条外圈环带」变成「胶囊 + 两层椭圆轨道」，中心空洞消失，间距均匀。
- 布局输出多一个 `AppNode.layer`（节点所在层，0 是最内层），测试用它断言「挂靠节点
  在挂靠者外一层」「引用节点与圈内成员同层」——椭圆上不同角度的径向距离不再是常数，
  距离差断言失去意义。
- `chord_angle` / `capacity`（角度域容量）删除，换成 `Ellipse` 的周长、弧长积分与
  弧长行走（数值弦长和，误差远小于 1px）。
- 挂靠子节点扇区与内层成员扇区是两套独立切分，极端清单下两组的子节点弧段理论上
  可能贴近；「仓库里的真实清单排得干净」测试守住不重叠，清单长到触发时再收紧。
