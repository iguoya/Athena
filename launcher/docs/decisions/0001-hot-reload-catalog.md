# ADR 0001：清单热刷新——托盘启动器被动感知 app.json 的增删改

- 日期：2026-10-08
- 状态：已接受
- 影响：`launcher/gui`（清单可热换、托盘菜单运行期重建、托盘悬浮提示动态化、
  Windows 开机自启开关）；`launcher-core` 新增 `manifest::fingerprint`
- 关系：延续 [ADR 0044](../../../docs/decisions/0044-menubar-launcher.md)
  （常驻启动器，状态从系统实况读）、
  [ADR 0046](../../../docs/decisions/0046-unified-dev-orchestrator.md)
  （新增应用启动器不改代码——本 ADR 把「不改代码」推进到「连重启都不用」）、
  [ADR 0048](../../../docs/decisions/0048-menubar-launcher-stays-macos-only.md)
  （`stopped` / `starting` / `ready` 契约不动）；
  开机自启只做 Windows，依
  [ADR 0047](../../../docs/decisions/0047-portable-by-default.md) 与
  [ADR 0049](../../../docs/decisions/0049-portability-is-a-cost-benefit-call.md)

## 背景

启动器的应用清单是启动快照：`discover()` 只在进程起来时扫一次，之后仓库里新增、
删除、修改 `app.json`，托盘菜单、学习应用思维导图、实践分区都不会变，必须重启
启动器。托盘菜单也是静态构建的，只能改现有条目的文字。

使用者的要求：启动器常驻托盘，清单「热更新」，**被动通知模式**——明确否掉了
高频率轮询重扫（应用清单的开发节奏不快，周期轮询是不必要的持续打扰）。

## 决策

1. **被动通知，不轮询清单。** 用 `notify` 订阅**发现根（`subjects/`、`practice/`）
   和每个应用目录本身**，非递归。`app.json`、`icon.svg`、应用目录的增删会来事件；
   构建产物、教学内容的海量文件改动不在订阅范围里，Flutter 编一次 Windows 也不会
   吵醒启动器。事件到重扫之间静默一秒（保存常是「写临时文件再改名」，事件成串来），
   一连串变更收敛成一次重建。
2. **每分钟一次兜底摸底。** 文件通知在个别环境会静默失效（网络盘、事件缓冲溢出）。
   这是保险丝，不是节拍：重扫便宜（一次 `read_dir` 加二十来个小文件），指纹没变
   就什么都不动。
3. **指纹在 core，界面只在真的变了之后才重建。** `manifest::fingerprint` 把清单
   展开成进程内稳定的文本（`{:?}`，以后加字段自动进指纹），图标文件另拼修改时间
   与长度——只改 `icon.svg` 不动 `app.json` 界面也要跟得上。重扫、比较、重建的
   编排在前端，判断「变没变」的依据只有 core 给的指纹，前端仍然不自己理解清单
   （ADR 0048 的口径）。
4. **托盘菜单运行期整条换。** `TrayIcon::set_menu` 是 `&self`，构建一份新菜单
   换上去即可；点击映射跟着换。Linux 的菜单活在 GTK 线程里，主线程发重建指令，
   换完把新的点击映射送回主线程——两边的动作永远成对。
5. **托盘悬浮提示动态报家底**：「Athena · N 个应用 · M 个在跑」，N 随清单热变，
   M 由两秒一次的状态轮询派生。状态轮询照旧——进程的生灭没有给普通应用用的
   被动通知，那部分维持从系统实况读（ADR 0044）。
6. **开机自启只做 Windows**（HKCU 的 `Run` 键），托盘菜单勾选开关，**默认关**：
   不先问就把启动器写进自启不是本分。勾选状态注册表现读，启动器不记自己的账；
   其他平台不显示这一项，不假装支持。

## 后果

- 「新增一个应用 = 放一份 `app.json`」的承诺升级：约两秒内它就出现在托盘和列表，
  删掉即消失，启动器照旧一行代码不改。
- 常驻期间清单可变成为常态，前端的消费点（open/stop 查找、状态刷新、托盘）全部
  改走共享可变清单，不再持有启动快照。
- macOS 菜单栏版（Swift）本 ADR 暂不覆盖：它的状态本来就是两秒轮询，清单仍是
  启动快照，待在 macOS 机器上按同一套口径补齐。
