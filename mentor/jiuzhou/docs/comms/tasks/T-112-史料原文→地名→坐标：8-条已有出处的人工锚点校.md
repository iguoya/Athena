## 目标
使用者要求把 GIS 与古籍数字化结合（路线见 `docs/GIS-TEXT-FUSION.md`，概念验证见 `docs/poc/text-geo-anchors.md`）。这是内容侧第一步：**把「史料原文 → 地名 → 坐标」做成人工校对过的数据**，不靠机器猜。

## 做法
1. 读 `docs/poc/text-geo-anchors.md`，跑一下 `python mentor/jiuzhou/scripts/poc_text_anchors.py` 看现状（词典匹配的结果在 `docs/poc/text-geo-anchors.json`，其中大量是噪音，因为简繁不通、没定位到段落）。
2. 对已有 `source` 的 8 条事件：到维基文库（或识典）取**繁体原文**，人工定位引语所在句，列出该句及前后文里出现的地名，逐个对应到我们的 `places`（或学术层政区），写成 `content/anchors.json`：
   `{ "<eventId>": [ { "text": "原文里的地名写法", "sentence": "所在整句原文", "placeId": "…" 或 "lonlat": [..], "basis": "依据：CHGIS 某切片 / places 的古名区间 / 维基" } ] }`
   每条都要人工确认，不确定的不写；同名异地（如「真定」）要写清为什么是这一个。
3. 统一出处来源：优先维基文库（开放、可批量取），已有 url 不是维基文库的，补一条维基文库对应页，不删旧的。
4. 提一个最小 schema 建议（字段、可选性），放进任务进展，供 cursor 之后做界面（原文旁地名、点击飞行）。**本任务不改前端**。

## 约束
- 简繁转换库（OpenCC）安装还在等使用者批准，**先不装**；本任务用人工校对，反而更稳。
- 出处必须核对原文，不凭印象（根 AGENTS.md 底线）。

## 验收
- `content/anchors.json` 覆盖那 8 条里能在维基文库取到原文的，每个锚点有整句原文与依据；`check_layers.py` 与 `check.py --skip-rust` 绿。
- 任务进展里写：遇到的歧义类型清单、schema 建议、你觉得哪里工序最费时。
