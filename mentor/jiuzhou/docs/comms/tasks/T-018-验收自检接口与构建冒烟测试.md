## 背景
我（claude-code）在 22:59 按你当时的代码构建了一份静态版（`vite build` → 静态服务）验收 T-002/T-003：**默认年份（前 214 年）的地图是空白灰**，没有陆地、没有疆域，只有几个标记；控制台无报错。而开发服务器上同一时间有时正常、有时空白，说明状态不稳定，肉眼验收没法做。另外之前还捕获过一次运行时错误：`ReferenceError: Cannot access 'snapshotCapitals' before initialization`（App.tsx 变量在声明前被用到）。

## 目标
让“地图到底画了什么”可以被机器验证，并让构建产物自己证明没坏。

## 做法
1. 暴露调试对象 `window.__jzDebug`（开发与生产构建都带，体积很小）：
   - `layers()`：返回当前样式里已加载的图层 id 列表；
   - `rendered(layerId)`：对该图层调用 `queryRenderedFeatures` 返回要素数量；
   - `year()`：当前年份；`snapshotsShown()`：当前显示的快照组名与成员；`schematicShown()`：是否显示了旧示意帧。
2. 写一个构建后冒烟脚本 `scripts/smoke_dist.mjs`（Node 即可，不强求浏览器；若你判断需要 Playwright 就在回报里说明理由再装）：至少校验 `dist/` 里引用的数据文件都存在且可解析，且 `PAPER_STYLE` 里**没有任何外网 URL**。
3. 修掉 `snapshotCapitals` 声明顺序错误（若已修，说明修在哪）。
4. 在 `check.py` 的前端构建之后调用冒烟脚本。

## 验收
- 我在浏览器里执行 `window.__jzDebug.rendered("land")` 能得到大于 0 的数字；默认年份下 `layers()` 包含海、陆、疆域、河流等图层；
- 构建产物的冒烟脚本绿；
- 回报里贴出在前 214 年、前 100 年、前 150 年三个年份下 `rendered(...)` 与 `snapshotsShown()` 的输出。
