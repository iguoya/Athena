# ADR 0003：史鉴——总结成败得失，服务现实

- 日期：2026-10-14
- 状态：已接受（使用者：从历史中得到经验教训，服务、指导现实，作为参考，总结成败得失，这才是历史的作用和意义）
- 衔接：本应用 [ADR 0002](0002-timeline-to-the-present.md)、[ADR 0001](0001-year-driven-spatial-history.md)

## 背景
九州此前只回答「发生了什么、在哪里」。使用者要求它回答「**这对今天有什么用**」：把成败得失总结出来，供现实参考。古人叫「鉴」——《资治通鉴》的名字就是这个意思。

## 决定
1. **新增「史鉴」层**：在主题叙事（`stories.json`，现有 9 个）上加可选字段 `lessons`，在重要事件上加可选一句 `lesson`。不另起一套系统。
2. **`lessons` 的结构（每个主题一份，不是鸡汤）：**
   - `problem`：它回应的**现实问题类别**（用固定标签，见下，供「按现实问题找历史」）；
   - `gains` / `losses`：做对了什么、付出了什么代价（**得**与**失**，各自可核对）；
   - `mechanism`：背后的机制一句话（为什么会这样）；
   - `applicability`：今天哪类问题可以参照；
   - `limits`：**不可简单类比的地方**（条件不同、时代不同）——没有这一条的史鉴不合格；
   - `today`：今日对照（接 ADR 0002 的「今天」）；
   - `basis`：依据（史料、古人评论如「臣光曰」「太史公曰」、当代学术研究，写明署名与出处）。
3. **现实问题标签（初版，可增补）：** 水资源与治水、区域协调与迁都、边疆治理与民族关系、粮食与财政、灾害应对、人口迁移与城镇化、对外开放与贸易、知识与技术传播、制度与治理。
4. **纪律（防止滥用历史）：**
   - **事实与评价分开**：`gains`/`losses` 写可核对的结果；评价性的判断必须署名来源（古人或今人），不替史料下结论；
   - **多种看法并列**，不挑对自己有利的；有争议就写争议；
   - **不做简单类比、不开药方**：只说「可参照什么机制，在什么条件下成立」；`limits` 必填；
   - **当代部分更严**：当代政策与事件的得失，只引用权威结论（如官方文件、权威统计、公认学术研究）并署名，不自己下判断；
   - 不预测未来。
5. **界面（cursor）**：主题与事件卡里有「史鉴」折叠区；新增**「按现实问题找历史」入口**——选一个问题标签，列出相关案例、各自的得与失、今日对照。

## 后果
- 数据新增可选字段：`stories[].lessons`、`events[].lesson`；前端读不到时静默降级。
- 新任务：T-115（zcode：史鉴内容，先做 9 个主题）、T-035（cursor：史鉴界面与问题索引）。
- 先内容与校验，再前端读取；写作质量以 `limits` 是否到位和 `basis` 是否可核为准。
