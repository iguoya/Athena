# 设计参考：好看的历史地图是怎么做到的

由 claude-code 维护。来源：使用者提供的对照（杨利辉、史图馆、左图右史、舆图、中研院 CCTS、GEOlayers
教程），以及我实际读过的两个 GitHub 项目。本文只写**我们采纳什么、不采纳什么、落在哪个任务**。
九州的底线不变：**本机离线可用、不依赖在线瓦片、不把学术数据提交进 git**（ADR 0157 / 0158）。

## 一、先说结论：好看靠的是五件事

| # | 它们做对了什么 | 我们现在的差距 | 对策（任务） |
|---|---|---|---|
| 1 | **底图本身像一张地图**：海陆分明、大陆轮廓完整，一眼认出“中国长什么样” | T-001 做了陆地面，但当前渲染有回归（图层没画出来） | T-018 修复；T-017 疆域贴海岸 |
| 2 | **地形有起伏且有色彩层次**：绿平原、黄丘陵、褐高原，不是纸片也不是单色 | 只有米色与灰青两种颜色 | T-007 彩色地形底图；T-019 配色与质感；T-022 山川注记 |
| 3 | **满图都是“地理名字”**：山脉、湖泊、沙漠、海洋、关隘有标注，读图不用猜 | 只有城邑标签，没有山川注记 | T-022 地理注记层（种子数据已提供） |
| 4 | **符号语言统一**：都城、关隘、港口、渡口各有符号，像手绘地图的图例 | 全是圆点 | T-023 分级符号 |
| 5 | **镜头与动画有节奏**：人物棋子沿路线移动、行军逐帧、河流流动、箭头生长 | 路线能画，没有棋子和流动感 | T-024 棋子；T-025 流动动画 |

## 配色与效率的平衡（2026-10-13 补）

使用者反映地图太单调。调研结论：
- **一张彩色地形栅格解决大半观感**：Natural Earth I（`NE1_50M_SR`，约 39MB 原件）按土地覆盖着色，自带山影；裁到东亚缩成 ≤3MB 的 WebP 即可，不用自己处理 DEM。
- **经典分层设色**：海蓝、平原绿、丘陵黄、高原棕褐、冰雪白；GIS 教程常把彩色地形以约 30% 透明度叠在山影上，河流用细线按等级设宽度。
- **效率手法**：调色用 MapLibre 栅格图层自带的 `raster-saturation/hue-rotate/contrast` 参数，不对整个画布加 CSS filter；近岸浅海用几层由宽到窄的模糊海岸线来做，不需要水深数据；暗角与纸纹用一层不拦截鼠标的 div 叠加。
- **政权色块是最大的单调来源**：同一势力跨快照颜色一致，同屏势力色相差 ≥40°，填充半透明并用 multiply 混合，让地形在色块下仍可见。

## 二、逐个参考的取舍

### 杨利辉《五代演义》（手绘底图 + 剧情棋子）
- **采纳**：人物头像棋子在图上挪动、行军逐帧；底图密度（满图政区与亲考位置）；古今地名一眼懂。
- **不采纳**：GIS+PS 超高清手工底图——我们没有人力逐州考县志，只做“示意 + 学术层可选”。
- 对应：T-024（棋子）、T-009（古今名，已做）、R3 学术层（T-010）。

### 史图馆《中国历代疆域变化》（断代色块时间轴，约 2858 帧）
- **采纳**：疆域“年年变”的观感、轮廓完整、色块清晰。
- **不采纳**：逐帧手绘——我们用 12 组多势力快照 + 窗口外淡入淡出，宁少而准。
- 对应：快照切换交叉淡入（并入 T-025）；后续快照由 zcode 在额度允许时补（T-106）。

### 左图右史 / 舆图·古代疆域（谭图数字化 + 现代底图 + CHGIS 政区）
- **采纳**：“真实”靠学术底图与古今对照，不靠特效；点政区出卡片；可播放。我们的左图右史布局已经成形。
- **不采纳**：把谭图数字化数据入库（版权，ADR 0158）。
- 对应：T-010（学术层运行时，数据本机放 `.cache`）。

### 中研院 CCTS 历史瓦片（WMTS）
- **不采纳**为默认：在线瓦片，违背离线原则。可作为将来的“联网时可选叠加层”，现在不排期。

### GEOlayers / AE 流水线（现代矢量上画古疆域、箭头、河流动画）
- **采纳**：箭头、河流流动、镜头运动这些“好看”的动画手法（纯前端可做）。
- **不采纳**：它的州县精度普遍不如考据派——我们不拿动画掩盖数据粗糙，而是**如实标注精度**（见下）。
- 对应：T-025。

### GitHub：pessimistcamellia/china-history-map（Leaflet，单文件）
我读了它的说明，有三点非常值得学：
1. **按数据可靠性标注精度**：它在应用里用颜色标出“这个朝代的西部区划数据不全”。我们同样要在图上**诚实标注“示意/考据/学术”三档精度**，不让人把示意帧当考据——并入 T-020。
2. **事件 ↔ 区划双向联动**：点事件高亮所在区划；点区划过滤出该地的事件。这是“地理与历史结合”最直接的体现——T-021。
3. **启动即做数据完整性检查**、搜索同时覆盖现代地名/历史别名/政区名。我们的搜索已覆盖前两项；完整性检查由 `check.py` / `check_layers.py` 承担，不必进运行时。
- **不照搬**：以朝代为唯一轴（我们是年份轴）；单文件 8MB 数据（我们走分片与简化）。
- 数据层来源：它用的 CHGIS/Hartwell 与 `aourednik/historical-basemaps`（GPL-3）网上都能取到，按 ADR 0159 默认公域，可直接用，数据旁记出处即可。

### GitHub：hopechen067/china-antique-maplibre（实际是 MapStage 地图调参工具，MIT）
它不是现成的古风地图，但它的**做法**能借：
1. **分层叠加、各层可独立开关**：卫星/底图、DEM 山影、矢量水系、城邑符号分层——与我们的图层思路一致。
2. **整体色调用 CSS 滤镜统一处理**（褐色调 sepia、暖色、暗角 vignette），而不是逐层改色。成本极低、观感立竿见影——T-019。
3. **城邑分级**：capital / large / medium / small / pass / station，对应我们已有的 `tier`；符号按等级区分——T-023。
4. **配置可导出为 JSON 预设**，便于共享调参。我们暂不做。
- **不采纳**：它的瓦片与 DEM 都要联网。离线方案是我们自己的：把 Natural Earth 灰度晕渲栅格缩成小图烘焙进包（T-007，≤3MB）。

### GitHub：aourednik/historical-basemaps（全球粗粒度政权 GeoJSON，GPL-3）
- 精度不够当主疆域，且 GPL-3 不能并入。仅作“同期世界背景”的灵感，**现在不做**（见“暂缓”）。

### GitHub：Hasasasa/China_History（React + 时间轴 + 点位）
- 数据与视觉深度都不够，不借。

## 三、我们的“精度三档”规则（来自 china-history-map 的启发）

在地图图例里固定出现，所有疆域面都带其中之一：

| 档 | 含义 | 视觉 |
|---|---|---|
| **学术** | 来自学术层（CHGIS / 谭图类，`packages/maps/geo/academic/`，入库后才有） | 实线边，正常填充 |
| **快照示意** | 我们手画的多势力快照，边界大体可信但**不是考据** | 实线边，略淡 |
| **阶段示意** | 旧的一阶段一框 | 虚线边 + “示意”水印 |

前端可由 `kind`（`snapshot` / `schematic`）与是否来自学术层直接推出，**不需要改内容数据**。
