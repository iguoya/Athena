# 概念验证：史书原文 → 地名锚点（2026-10-14）

脚本：`scripts/poc_text_anchors.py`（词典匹配，无机器学习）。输出：`poc/text-geo-anchors.json`。

## 做通了什么
- 地名词典：我们 163 个地点的全部古名 + 学术层 19 切片的政区名，共 **1388 个名字**，每个带起止年与坐标（政区取质心）。
- 维基文库 MediaWiki API 取古籍纯文本可行（`宋史/卷025` 等能取回）。
- 匹配时按事件年份过滤名字的有效期，并给出命中处前后文，输出「名字→坐标→原文那一句」。

## 暴露的阻塞点（比成功本身更有价值）
1. **简繁不通**：事件 `source.loc` 是我们写的简体，维基文库是繁体；没有 OpenCC 就无法按引语定位到段落（本次 3 个维基文库来源的事件全部「定位失败」，只能退回取页面开头，结果是噪音：命中的「河州、東勝州、平壤」与事件无关）。→ 需要简繁转换（待使用者批准安装）。
2. **来源不统一**：8 条已有出处里只有 3 条是维基文库；其余是识典古籍、guoxue123、古诗文网和两本纸质书。→ 以后统一优先维基文库（开放、可批量），其余作对照。
3. **短地名误报**：「真定」「太原」这类在宋金元的政区表里重名多，需结合事件所在地、年份和上下文消歧；词典匹配之后必须有一步**人工确认**，不能直接入库。
4. **镜像数据没有 `SYS_ID`**：学术层的政区无法与 CHGIS 官方 ID 对齐，限制了和 MARKUS/CBDB 的互联；官方数据被 Dataverse 的 WAF 挡住，镜像是现实选择。

## 结论
链路是通的，瓶颈在**简繁转换、消歧、人工确认**三处，都不是技术难题，是工序。可以按 `GIS-TEXT-FUSION.md` 的分阶段推进。
