# ADR 0018：以不偏科的成长阶梯为骨架，用能力域衡量均衡，并补上高端纵深方向

- 日期：2026-10-06
- 状态：已接受
- 修订：ADR 0016 决策 2（新增路线的可选字段 `pitfalls`、`profile`）、决策 3（开放地图增加 `frontier`）；ADR 0012 与 ADR 0016 的其余部分不变
- 相关：ADR 0012（指南针）、0014（阶段与军工兼顾）、0016（底盘与路线）、0017（取消解锁）；仓库级 ADR 0043（出处）、0054（宁增勿删）

## 背景

使用者的要求：北极星要少受他个人认知的束缚，**去看 GitHub 与相对权威的计算机、电子信息站点上资深人士怎么讨论**，再自由设计。方向是**软硬结合、融会贯通，冲击高端就业方向，但循序渐进、不急功近利、不营养不良，技术要全面、不偏科**。

2026-10-06 的调研（只读一手来源；全部进入来源目录，字段见 `content/sources/catalog.json`）：

| 来源 | 读到什么 | 对设计的意义 |
|---|---|---|
| Interrupt（Memfault）《Embedded Systems Roadmap: Bridging the Gap》 | 多数人进入嵌入式时只强一边；路线把硬件、软件分开讲，再单列二者的**交集**；选资料时先问「我此刻要解决什么具体问题」，避免资料瘫痪 | 路线要显式分软、硬、交集；每个阶段给具体问题和验收，而不是资料清单 |

| Tenstorrent「Staff, Firmware Engineer」招聘（2026-10 读取） | C/C++；MCU 与 SoC；RTOS 与嵌入式 Linux；启动、电源、复位序列；用实验室工具定位软硬件交界处的问题；强调「架构、实现、调试与系统层面的思考」 | 固件与可信方向的能力画像；说明高端岗位要的是**跨界面的系统思维**，不是单点技能 |

另外，招聘页是**时效性样本**，只用来校准技术需求，不得当作「学完即可入职」的承诺（ADR 0012、`AGENTS.md` 内容边界不变）。

**对照现有内容的缺口（查实）。** 现有底盘有软硬接口与基础课程，但缺：数字芯片实现与验证方法学、性能建模与微架构探索、开放指令集、并行与加速器编程、模型编译与推理优化、高可靠软件与功能安全、固件工程化、系统工程与接口管理、可信硬件。同时没有任何一处**衡量一条路线是否偏科**。

## 决策

1. **十二个能力域，每个开放地图的节点必须归入一个。** `domain` 取值：`foundations` 数学与理论、`programming` 程序设计与工程方法、`algorithms` 数据结构与算法、`architecture` 体系结构、`systems` 操作系统、网络与并发、`digital` 数字逻辑与 HDL、`circuits` 电路、测量与电源、`signals` 信号、控制与通信、`embedded` 嵌入式与软硬接口、`assurance` 验证、可靠性与系统工程、`security` 安全与可信、`acceleration` 并行、加速与 AI 系统。它们按 CS2023、CE2016 与上面的资深讨论归并，软件侧、硬件侧、交界处都有。这是**新增字段**，不改任何节点的 id、内容与分级（ADR 0054）。

2. **均衡度由数据算出，不靠自我评估。** 一条路线覆盖了哪些能力域、各占多少，由它引用的节点的 `domain` 统计得到；界面据此画出覆盖雷达，并给出**偏科提示**：这条路线没有碰到的域，以及补哪些节点（取自通才阶梯里对应的节点）。不记录任何个人进度（ADR 0012 的边界不变）。

3. **通才阶梯是骨架，高端方向是纵深。** 新增路线 `route.generalist-ladder`：五个阶段，**十二个能力域一个都不缺**，每个阶段的验收是做出来的东西。方向类路线是在这条阶梯之上选的纵深，每条路线必须写 `pitfalls`（该方向最常见的偏科与补法）。阶梯覆盖所有域是**测试守着的不变量**。

4. **补上高端纵深：新增开放地图 `frontier`。** 收上面「缺口」里的九到十个节点，每个节点仍须有 `stage`、`priority`、`domain` 与出处，不要求 `targets`、`contract`。开放地图因此是 `academic`、`codesign`、`frontier` 三类（`OPEN_VIEW_KINDS` 在契约与前端各一份，测试防漂移）。

5. **高端方向写能力画像，不写承诺。** 新增五条纵深路线：CPU 与 SoC 架构、数字芯片设计与验证、AI 加速器与推理系统、系统固件与可信、高可靠与航天航电系统。有真实招聘样本支撑的方向可写 `profile`（高端岗位通常要什么），必须带出处，并写明是时效性样本。路线标题仍用技术方向，不用岗位名，不暗示学完即可入职。

6. **学习原则成为数据：`principles`。** 把调研得到的、被反复验证的原则（广度是底座、刻意练习要十年、先问具体问题、调试是一等能力、软硬要在交界处练、由小到大的项目、纵深在广度之后）作为顶层 `principles` 数组，每条带出处，总览页展示。原则里的话必须能在引用的来源里找到依据。

7. **只增不删。** 本次全部是新增：新字段、新地图、新路线、新来源；现有节点的内容、id、阶段、边一概不动。

## 后果

- `scripts/contract.py` 增加 `domain`、`frontier`、`principles`、`pitfalls`、`profile` 规则并配反例；`OPEN_VIEW_KINDS` 双份定义与防漂移测试同步更新。
- 界面：路线视图加覆盖雷达与偏科提示；总览加学习原则；`frontier` 图与新路线自动进入既有的底盘与路线视图，不另造页面。
- 阶梯与方向的节点选取是一次**有依据的判断**，会随调研变化；它们是路线，不是底盘，调整时不动节点。
- 十二个能力域是衡量「全面」的尺子，不是课表：域内节点数量悬殊，雷达看的是**是否碰到**与相对覆盖，不是追求每域一样多。
