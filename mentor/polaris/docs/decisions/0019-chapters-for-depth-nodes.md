# ADR 0019：高端纵深路线的每个节点细化到章节

- 日期：2026-10-06
- 状态：已接受
- 修订：ADR 0014 决策 6（「每门课有自己的细分学习流程」只管课程图）的适用范围；章节的格式与掌握度分档不变
- 相关：ADR 0016、0018；仓库级 ADR 0043（出处）、0054（宁增勿删）

## 背景

使用者要求把五条高端纵深路线细化到**每个节点的章节**。此前只有两张课程图的 35 个节点带 `chapters`（ADR 0010、0014），五条纵深路线用到的 44 个节点里有 29 个没有：软硬接口图与纵深图的节点，以及一个实践主干节点。路线只写到「哪些节点、什么顺序」，节点自己没有「具体按什么顺序学什么」。

## 决策

1. **`chapters` 不再只属于课程图。** 任何开放地图的节点都可以写；写了就必须合格：至少三章，每章有 `id`、`title`、`summary`、CS2013 三档掌握度（familiarity 认识 / usage 运用 / assessment 评估），运用与评估必须标实践。
2. **章节按学习顺序排。** 课内先修 `requires` 只能指向排在它前面的章节，这样「循序渐进」是契约保证的，不是口头约定。
3. **每章可带出处 `ref`。** `ref` 是 `{source_id, locator}`，`source_id` 必须是**该节点自己引用过的来源**，每一章因此都能追到节点级出处（ADR 0043）。没有合适出处的章节不写 `ref`，不为凑数编造。
4. **五条纵深路线用到的节点必须全部有章节**，由测试守着（路线仍是引用，章节写在节点上，不在路线里复制）。
5. 本次为 29 个节点补章节（共 173 章），按「认识 → 运用 → 评估」排列，最后一章都是**做出来的验收**，与节点的 `practice` 与 `validation_note` 对应。

## 后果

- 契约：章节规则从「课程图专用」放宽为「有章节就要合格」，新增先修只指向前面章节与 `ref` 必须属于本节点来源两条规则并配反例。
- 界面：抽屉里的「细分学习流程」显示每章的出处与课内先修；路线与首页显示章数。
- 章节是对节点内容的**细化**，不改节点的定义、分级与边。其余路线的节点以后按需补，不影响现有节点。
