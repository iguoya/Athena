# ADR 0010：C++ 首页知识图谱按原结构收成两章

- 日期：2026-09-20
- 状态：已接受
- 相关：ADR 0009（吸收原料与字段契约）、仓库级 ADR 0054（宁增勿删）

## 背景

ADR 0009 把 `apps/cpp` 首页那张学科知识图谱吸收进 polaris，并把技术体系层扩到
八张。扩的理由是一张图塞二十个节点会横向拉到 2500px 以上。

那张图原本就不是八张。`registry/domain_graph.h` 写得很清楚：

> 图谱分两张：计算机（软件 / 系统）方向和电子信息（电路 / 嵌入式）方向。
> 两张各自成图、各自分层，跨方向的依赖单独作为“关联”列出，不混排。

28 个节点、34 条带理由的依赖、10 条不建节点的理论科目、五个入门起点、实线门槛
与虚线来路——这些是一张知识图谱的内容，不是六门彼此无关的短课。拆开之后：

- 同一条学习线被切成「程序设计 / 机器基础 / 并发网络」三张，层间依赖变成跨图跳转；
- 弱先修（汇编 → C、C → C++）被写成图内 `requires`，虚线来路丢失；
- 使用者看不到原来那张「从哪进、先修是什么、哪些只是渊源」的完整图。

## 决策

1. **吸收来的 28 个课程节点按原图两侧收成两章，不再拆成六张。**

   | 地图 id | 标题 | 收哪些 |
   |---|---|---|
   | `computer-science` | 计算机科学与技术 | 原计算机侧 15 个节点 |
   | `electronic-information` | 电子信息技术 | 原电子信息侧 13 个节点 |

   图内 `requires` 只收**同侧且 strong** 的先修，用于分层。同侧但 `strong=false`
   的来路写成 `relation: enables` 的虚线边，**不写入**节点的 `requires`，否则
   布局会把「可以后补的渊源」当成入学门槛。两侧之间的依赖继续放顶层
   `cross_edges`（C 语言 → 51 单片机这类）。

2. **原有两张实践主干原样保留。** `computer-practice` 与 `electronic-practice`
   是 polaris 自己的实践链，节点 id 与课程节点不同。ADR 0054：新方向用新增表达，
   不删已有条目。被撤掉的是 ADR 0009 为同一批 28 个节点临时切出来的六张碎片图
   ——它们从来不是独立的知识对象，节点 id 全部迁入两章，一条内容都没有少。

3. **知识图谱的呈现一并移植，不只搬字段。** 原图卡片上能看见的判断，polaris 也要
   能看见，否则吸收等于没吸收：

   - 入门起点徽章（`entry`）
   - 验证方式徽章（`verify`：编程 / 开发板 / 硬件）
   - 领域色条（原 `track`：编程语言 / 结构与工程 / 系统 / 电路与嵌入式 / 模型与端侧 / 综合应用）
   - 边上的编号，以及按同一编号列出的依赖理由
   - 选中节点时高亮相邻边；未选中时右侧给出理论科目

   掌握度进度条不移植：polaris 不做学习进度（本应用 `AGENTS.md`）。

4. **默认打开计算机这一章。** 它是原图的主入口；实践主干仍可从侧栏进入。

## 后果

- 技术体系层从八张变为四张：两章课程知识图谱 + 两张实践主干。
- ADR 0009 的字段契约、出处校验、职业目标反推必要程度、理论科目不建节点，全部
  继续有效；第 2 条「扩到八张」被本 ADR 收窄为「课程知识图谱恢复为两章」。
- 画布会变宽，靠平移和缩放阅读，与原图同一取舍：不压缩卡片来塞进一屏。
