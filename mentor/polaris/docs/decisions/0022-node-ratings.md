# ADR 0022：给节点与路线评级——六个维度、五个等级，推导型与编辑型分开，路线另给优劣与推荐方向

- 日期：2026-10-07
- 状态：已接受
- 修订：无（新增字段与界面能力；不改变节点的阶段、优先级与路线）
- 相关：ADR 0012（北极星是指南针）、0018（能力域与均衡度）、0020（每个开放节点都有章节）、0021；仓库级 ADR 0054（宁增勿删）

## 背景

使用者希望从多个维度给节点评级，用不同颜色区分、强调：实用性、实践性、理论实用性、可验证性、学科核心骨干、就业需求度；随后又要求**路线本身**也从这些维度标记优劣，并推荐发展方向。现有的 `priority`（必要 / 重要 / 可选）只有一个轴，回答「缺了它培养目标是否成立」，不能回答「这个节点动手多不多、结果好不好验证、市场上用得多不多」。

风险也在这里：评级很容易变成个人口味。北极星的底线是「不以个人经验或岗位口味裁课」（AGENTS.md），公开招聘只是时效性样本、不得暗示学完即可入职。所以评级必须有明文口径，能由内容推出的就由内容推出，只能靠判断的要写明依据并标出是判断。

## 决策

1. **六个维度，每个五级（1–5）。** 顶层 `rating_scheme` 定义维度：`id`、名称、要回答的问题、依据类型、五个级别的名称与判据；并写 `as_of`（评估日期）。维度如下：

   | id | 名称 | 回答什么 | 依据类型 |
   |---|---|---|---|
   | `utility` | 实用性 | 学完能直接用于日常工程工作的程度 | 编辑评估 |
   | `hands_on` | 实践性 | 学习过程里动手实践所占的比重 | 由章节推导 |
   | `theory` | 理论实用性 | 理论内容能转化成判据、设计方法，并迁移到多个场景的程度 | 编辑评估 |
   | `verifiable` | 可验证性 | 学没学会、做得对不对，能被客观、独立地检查的程度 | 由节点字段与章节推导 |
   | `core` | 学科核心骨干 | 在学科知识结构里是不是承重的那一部分 | 由优先级与被依赖数推导 |
   | `demand` | 就业需求度 | 在典型技术岗位的公开要求里出现得有多普遍 | 编辑评估（时效性） |

2. **节点写 `ratings`。** 形如 `{"utility": {"level": 4, "reason": "…"}, …}`，六个维度都写，`level` 是 1–5 的整数，`reason` 是一句依据。开放地图（academic、codesign、frontier）的每个节点必须有；参考层不评级（那些图不开放、不被路线引用）。

3. **推导型与编辑型分开，推导型由契约重算。**
   - 实践性：章节里 `kind: practice` 的占比，≤0.4 为 1 级，≤0.55 为 2，≤0.7 为 3，≤0.8 为 4，其余为 5。
   - 可验证性：`validation` 的基础分（实测、基准对比 3；联调、仿真 2；分析、评审 1），加 1 如果最后一章是有动手的评估章（有可交的验收），再加 1 如果 `verify` 是 `board` 或 `bench`（仪器或板上测量给出独立于被测代码的证据），合计 1–5。
   - 学科核心骨干：`priority` 的基础分（必要 3、重要 2、可选 1），加 1 如果被依赖数（图内 `requires` 与跨图 `requires` 边合计）≥3，再加 1 如果 ≥6，合计 1–5。
   - 这三项的 `level` 必须等于契约按上面规则重算的结果，`reason` 由同一规则生成；改了章节或优先级而忘了更新评级，契约会报错。
   - 编辑型三项（实用性、理论实用性、就业需求度）由人评估，依据写在 `reason`，界面标「编辑评估」。就业需求度还写明是 `as_of` 时点的估计、不是统计，不暗示学完即可入职，随时间要重评。

4. **评级只用来强调与比较，不用来取舍。** 不因评级低而删节点、改阶段或改优先级；也**不合成总分**——这六个维度没有公认的权重，合成一个数等于把口味藏进公式里。界面允许按单个维度着色，不提供「综合排名」。

5. **界面。** 图面（底盘与路线）加「着色维度」选择：选定后节点卡片按该维度的等级着色，并显示等级名；节点抽屉里有评级区，六个维度各一行，显示五格等级条、等级名、依据与「推导 / 编辑评估」标记；图例说明该维度五级的含义。路线卡片显示推荐等级与六维迷你条；路线页有评估面板（六维评级、优劣、推荐的后续方向，可点过去）；总览按推荐等级给出「推荐发展方向」。等级色是一条五级序列色（两套主题各自取值），**除了颜色还有数字与名称**，不只靠颜色传达。

6. **路线的评级由节点汇总，不另手写。** 路线写 `ratings`，六个维度同样 1–5 级，`level` 是它引用的全部节点（去重）在该维度上等级的算术平均再四舍五入（x.5 进位），`reason` 由规则生成（含节点数与均值）。契约重算校验。这样路线与节点用同一把尺，路线的强项与弱项就是它所含知识的强项与弱项。
7. **路线另有 `assessment`（编辑评估）：优劣与推荐方向。**
   - `verdict`：推荐等级，四级——`priority` 优先推荐、`recommended` 推荐、`optional` 可选、`advanced` 进阶（有明确前置，不宜作起点），附 `verdict_reason` 一句依据。判断时参照的是路线评级的强弱项、起步门槛（第一阶段需要什么前置）、方向的时效性与是否被通才阶梯或专业类阶梯覆盖；**不是由评级算出来的分数**，所以仍标「编辑评估」。
   - `strengths`、`weaknesses`：各 1–3 条，写评级之外也要知道的优势与代价（例如门槛、设备要求、时效性、与别的路线的重叠）。
   - `next`：推荐的后续方向，1–3 条 `{route_id, reason}`，指向另一条存在的路线，说明学完这条之后顺着往哪走、为什么。
   - 弱电优先（ADR 0021）在这里落到具体判断上：同等条件下，弱电方向的路线推荐等级不低于强电方向。
8. **只增不删。** 本次全部是新增：顶层 `rating_scheme`、节点与路线的 `ratings`、路线的 `assessment`、契约规则、类型与界面。已有节点与路线的任何现有字段不动。

## 后果

- 契约：`rating.scheme`（维度齐全、五级、判据不空）、`rating.fields`（节点与路线六个维度齐全、级别 1–5、依据不空）、`rating.derived`（节点推导型、路线汇总型与重算一致）、`assessment.fields`（推荐等级合法、优劣非空、后续方向指向存在的别条路线）；每条规则配反例。
- 内容：140 个开放节点各有六条评级，编辑型的 420 条依据逐条写出；每条路线有汇总评级与评估；评估日期 2026-10。
- 风险与缓解：编辑型评级仍含判断。缓解办法是口径明文、依据逐条可见、推导型不靠判断、就业需求度标注时效性；要推翻某条评级，改 `level` 与 `reason` 即可，不动别的内容。
- 暂不做：按评级筛选或排序节点、把评级并入路线均衡度、为个人生成「推荐路线」（北极星不记录个人数据，ADR 0012）。要做时另写 ADR。
