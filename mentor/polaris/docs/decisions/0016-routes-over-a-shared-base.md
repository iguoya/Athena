# ADR 0016：路线成为一等对象——同一知识底盘，按角度与技术方向划分多条路线，软硬结合是主线

- 日期：2026-10-06
- 状态：已接受
- 修订：ADR 0012 决策 4（「侧栏只按计算机、电子信息两大学科列目录；职业图从界面拿掉」）；ADR 0012 的其余决策继续有效
- 相关：ADR 0001（软硬融合的远方）、0002（内容契约）、0011（真先修）、0012（指南针）、0013（表达与可视化）、0014（阶段分层）、0015（Web 壳与契约校验迁出）；仓库级 ADR 0043（出处）、0054（宁增勿删）、0056（可视化即内容）、0080（重组豁免）

## 背景

使用者要求：参照 GitHub 上 star 很高的路线图，把北极星按**不同角度和职业技术方向**划分成多条路线，并**重点关注软硬结合**。

**现状的结构限制。** 一张图既是「知识本身」又是「一条路」：同一个知识点在不同角度下被各写一遍——FPGA 在课程图里是 `polaris.ei.fpga`，在实践主干里是 `polaris.ei.dsp-fpga`，在职业图里是 `polaris.hw.fpga-pipeline`，在目标图里又是 `polaris.target.hw.fpga`。角度一变就要重写节点，改一处漏三处。另有 13 张职业 / 目标图（5 张职业与工程、8 张目标）按 ADR 0012 决策 4 锁在界面之外，使用者看不到任何「按方向走」的入口。

**对照调研（2026-10-06，原料与许可证见 `content/sources/reference/roadmaps/MANIFEST.json`）。** 这些路线图划分路线的角度并不相同：

| 来源（star） | 划分角度 | 本次如何使用 |
|---|---|---|
| roadmap.sh（约 36.9 万） | **职业角色**：后端、前端、DevOps、系统设计、网络工程、AI 工程…… | 保留版权，只引用链接。计算机路线里硬件相关只有「计算机如何工作、CPU 缓存、中断、寄存器」几项，没有软硬结合与电子路线 |
| coding-interview-university（约 36.2 万） | **阶段与面试准备**：一份顺序学习计划 | CC BY-SA，只引用链接 |
| ossu/computer-science（约 21 万，MIT） | **学位阶段**：Intro → Core → Advanced → Final project，Core 内再分编程、数学、系统、理论、安全…… | 入库，作计算机一侧的完整性对照 |
| open-source-cs（约 2.4 万，MIT） | **学科领域**：编程、数学、系统、理论、应用 | 入库 |
| Embedded-Engineering-Roadmap（约 1.3 万，CC BY-SA） | **软件 / 硬件 / 软技能三块**，并指出岗位名称往往偏重其中一块 | 只引用链接。它的微控制器一节（GPIO、ADC、定时器、中断、DMA、时钟与电源管理、引导加载）几乎就是软硬接口层 |
| ai-hardware-engineer-roadmap（约 286，MIT） | **终点产物 + 跨层契约**：先定终点制品，再倒推数字设计 → 体系结构 → 嵌入式 → FPGA / Jetson / 推理优化；用「工作负载 / 运行时 / 硬件」三份契约把层连起来 | 入库（只取说明、许可证与目录大纲） |
| kitspace/awesome-electronics（约 8.2k，CC0） | 资源清单，不是路线图 | 入库，仅作资源对照 |
| ACM / IEEE-CS **CE2016**（课程标准，非 GitHub） | **12 个知识领域**，共 420 核心学时：电路与电子、数字设计、体系结构、嵌入式、系统资源管理（含实时操作系统）、信号处理、系统与项目工程（含「软硬件并发设计」「软硬件过程」）等 | 软硬结合最权威的参照，只引用 |

**从中读出三点**：

1. 好的路线图至少有三种切法——按**职业技术方向**（角色）、按**层次**（学位阶段 / 技术栈）、按**终点产物**。它们是同一块知识的不同走法，不是三份知识。
2. 软硬结合的核心不是「又一门课」，而是**跨层契约**：时序、存储与数据通路、总线、功耗、启动与可信、可验证。AI 硬件路线图用契约连层，CE2016 用「系统与项目工程」连层，嵌入式路线图用「软件 / 硬件」两块的重叠连层，说法不同，指的是同一个接缝。
3. GitHub 上**没有**面向「电子工程师」整体的高 star 路线图，最接近的是上面的嵌入式路线图（电子侧的深度由 CE2016 与 ABET、认证标准校准，见 ADR 0012）。

**与现有内容的缺口（查实）。** CE2016 里学时最多的知识领域是体系结构（CAO，60 学时），而北极星现有 125 个节点里**没有一个独立的体系结构节点**，它只是「计算机系统基础」里的一部分。中断、DMA、时钟与复位、寄存器与内存映射、引导、功耗这类软硬接缝知识，散落在 36 个节点的正文里，没有任何一处把它当作跨层知识单独成点。

## 决策

1. **底盘与路线分离。** `maps` 继续是**底盘**：知识本身，节点 id 全局唯一，一个 id 只装一个东西（ADR 0054）。新增顶层 `routes`，一条**路线**是从某个角度走过底盘的顺序，**只引用节点 id，不复制节点**。同一个知识点在任何角度下都是同一个节点；角度变了，改的是路线，不是知识。

2. **路线的数据模型与三种角度（`lens`）。** 一条路线必须写：
   - `id`、`title`、`summary`；
   - `lens`：`direction`（职业技术方向）、`stack`（技术栈层次，自底向上或自顶向下）、`artifact`（以终点产物倒推）三者之一；
   - `balance`：`software`、`balanced`、`hardware` 之一，诚实标出这条路线偏软还是偏硬——这是嵌入式路线图指出的事实，也是软硬结合可视化的横轴；
   - `audience`：适合谁；`artifact`：**终点产物**，必须是可检查的东西（一块自己点亮的板、一个测出抖动的实时任务、一个跑过时序报告的 FPGA 设计），不是「掌握某某」；
   - `stages`：有序阶段，每个阶段含 `title`、`goal`、`nodes`（节点 id 列表）、`checkpoint`（这一阶段结束时能拿出什么）；
   - `source_refs`：出处，同节点的写法。
   路线标题用**技术方向**的名字（「嵌入式与实时软件」「FPGA 与数字设计」），不用招聘岗位名；不暗示学完即可入职（ADR 0012、`AGENTS.md` 内容边界）。

3. **路线契约（写进 `scripts/contract.py`，每条规则配反例）。** 引用的节点必须存在；路线只能引用**开放地图**里的节点（`view_kind` 为 `academic` 或 `codesign`，即下面第 4 条之后新增的软硬接口图）；同一条路线里，若 A 强先修 B 且两者都在路线中，B 所在阶段不得晚于 A；每个阶段至少一个节点并写 `checkpoint`；`artifact` 与 `source_refs` 必填。**路线图类来源本身不是证据**（ADR 0043）：它们只能放在 `lens` 的取舍说明里，路线与新节点的每一处内容仍要有自己的出处。

4. **软硬结合是主线：新增 `codesign`（软硬接口）地图与体系结构节点。** 新增一张 `view_kind` 为 `codesign` 的开放地图，收「软件看见的硬件、硬件承诺给软件的东西」这一层知识，**以及**缺失的体系结构节点。`codesign` 节点在 `academic` 节点的必填字段之外，还必须写：
   - `contract`：它属于哪一份跨层契约，取值 `timing`（时序）、`memory`（存储与数据通路）、`bus`（总线与协议）、`power`（功耗与热）、`boot`（启动与可信）、`verify`（可验证与观测）；
   - `hw_side` 与 `sw_side`：**同时**写清硬件一侧提供什么、软件一侧依赖什么——只写一侧的节点不属于这张图。
   `codesign` 节点不要求 `targets`（那是职业目标层的指向，与此无关）。参照 CE2016 的体系结构、数字设计、嵌入式、系统资源管理、系统与项目工程各领域，以及上面的「跨层契约」思想校准；不拷贝任何一份路线图的文字或节点命名。

5. **职业与目标图降为参考层，职业方向路线进入主导航。** 现有 13 张 `career`、`engineering`、`target` 图**一个节点、一条边都不删**，也不改 id（ADR 0054），继续在内容里，作为参考层保留，不进入新的路线引用。ADR 0012 决策 4 的「职业图从界面拿掉、职业方向不进侧栏、不提供跳转」**由本条修订**：按技术方向划分的路线（决策 2 的 `direction`）进入主导航。ADR 0012 的其余决策不变：先写学科必要性、再兼顾军工（ADR 0014 决策 1）；不以岗位口味裁课；不把岗位名称做成节点，不暗示学完即可入职；不加入学习进度、掌握度、账号、网络同步。

6. **重组范围：只增不删，不声明重组豁免。** 本次对内容的改动全部是**新增**：新增 `routes`、新增 `codesign` 地图及其节点与边、新增来源。现有 `maps` 的节点、边、id、阶段、出处原样保留，已开放的 4 张学术图仍是默认入口，不需要也不声明 ADR 0080 的重组豁免。字段的重命名、合并、删除仍要先另行决定。出处与语义基准不受影响（ADR 0054）。

7. **对照来源的使用规则。** 许可证允许再分发（MIT、CC0）的才拷贝入库，并带许可证与 commit；保留版权的（roadmap.sh）、带相同方式共享义务的（CC BY-SA 4.0）、未声明许可证的、GPL 的，只记链接与不拷贝的理由。拷贝入库的原料是**对照原料**，不进入应用界面，也不被直接搬进节点正文。新增的路线与节点，用的是北极星自己的语言与出处。

## 后果

- `scripts/contract.py` 增加路线与 `codesign` 规则并配反例；`content/polaris.json` 增加 `routes` 与 `codesign` 地图。底盘的 17 张图一行不动。
- 界面的主导航从「选一张图」变成「选角度 → 选路线，或回到底盘看全景」。路线在底盘图上以高亮和阶段顺序呈现，不另画一套节点；软硬权重（`balance`）是路线总览的一根轴。具体形态属于 ADR 0013 允许自由推翻的范围，不在本 ADR 里定。
- 开放范围从「4 张学术图」变成「4 张学术图 + 1 张软硬接口图」。ADR 0015 第 6 条写的「新版保持同样的可打开范围」据此更新：`codesign` 是本 ADR 新增的开放图，13 张参考层图仍然锁住。
- 体系结构与软硬接口一旦成为独立节点，现有 36 个节点里零散提到的中断、DMA、时钟等，可以用节点间的边指向它们，而不是各自再讲一遍。是否回头精简那些正文，另行决定，不属于本 ADR（ADR 0054）。
- 第一批路线先落在软硬结合最重的几个技术方向与「自底向上、自顶向下」两条层次路线上，后续再按需增减。路线可以随学科变化新增或调整，这是它与底盘的区别：底盘求稳，路线求准。
- 内容的实际数量由实现决定，并不保证覆盖 CE2016 的全部知识单元；覆盖缺口应当明确写在节点或路线里，不用「看起来全」来掩盖。
