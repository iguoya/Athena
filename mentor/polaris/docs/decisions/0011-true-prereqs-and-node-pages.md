# ADR 0011：两章完整学科知识体系，只连真先修，节点开专页

- 日期：2026-09-20
- 状态：已接受
- 相关：ADR 0010（两章课程图）、ADR 0009（吸收字段）、ADR 0012（路线图与指南针）、仓库级 ADR 0054（宁增勿删）

## 背景

两章课程图从 C++ 学习首页迁过来之后，总目标是：**从计算机科学与技术、电子信息两个学科把知识体系建完整**，对照培养方案里的核心课和这两门学科要培养出的能力，图上不能留下「这门课根本不存在」的认知盲点。

原先有三处会破坏这个目标。

1. **列课被个人岗位经验裁过。** 航天研制线上用得少的课（编译、数据库、数电、通信）从培养要求看仍是核心；只用「我交固件用不用得到」裁图，会产生学科空洞。
2. **有些线是教法顺序，不是先修。** 数据结构并不依赖 C++，DSP 并不依赖某颗 STM32。强行划线会让独立的工具课、方法课看起来像闸门。
3. **节点说明开在右侧窄栏。** 完整学科说明需要整页，不能挤在一条侧缝里。

## 决策

1. **两章是完整学科图，不是岗位选修菜单。** 计算机一章覆盖计科培养里的程序设计、数据结构、组成、操作系统、网络、编译、数据库、软件工程与系统能力；电子信息一章覆盖电路、模电、数电、信号、DSP、通信、电磁、微机/嵌入式与电子系统实践。原 28 个节点只增不删。缺的核心课用新节点补上；纯数学、纯证明的部分仍进 `theory`，避免和实践课排成一排。

2. **分级表达培养要求里的主次，不靠删课。** `priority` 三档的判据是「对这门学科的培养目标和实现目标有多必要」：
   - `essential`（必需）：培养方案里的专业核心，缺了就不构成这个学科；
   - `important`（重要）：实现目标里的系统/工程能力，或方向主干；
   - `optional`（可选）：教学台阶或方向选修——**仍必须出现在图上**，否则就是盲点。
   侧栏与画布的主列已改由 ADR 0014 的阶段（初级 / 中级 / 资深）承担；`priority` 仍写在节点上，**先回答它对这门学科有多必要**。军工里它还支撑什么写在 `industry_reason`，不能倒过来裁课。

3. **没有真正的先修就不划线。** `requires` 只表示「离开前者，后者的核心练习做不了」。教学用哪门语言、实验室用哪块板、课表第几学期先开，都不构成 `requires`。原图里被拆掉的教法边，理由写进 `unforced_prereqs` 留档。

4. **节点说明改成左侧子菜单 + 独立页面。** 侧栏在当前地图下按必需 / 重要 / 可选展开；点节点进入整页。理论科目和编号理由挂在图谱页本身。

## 后果

- 图上会出现一批没有入边的节点，这是完整列举后的预期形态。
- 51 单片机保留为可选台阶，不再挡住 STM32。
- 编译、数据库、软件工程、数电、模电、DSP、数字通信进入图内，避免「学完两章仍不知道这门学科还有这些核心课」。
