# ADR 0004：教案的图示手段——章节内嵌 Mermaid 图块

- 日期：2026-10-12
- 状态：已接受（使用者 2026-10-12：「落实下来……核心目标是更清晰地描述整个程序的组织结构，不要被我的认知局限和约束」）
- 关系：是仓库 ADR 0056（可视化与交互是内容本身）在本应用内容层的接入；讲解格式的扩展，不改变 [0001](0001-independent-raylib-chapters.md) 的每章单程序

## 背景

教案此前只有文字 body。相位流转、模块边界、构建依赖、数据流这些内容，文字的描述
密度远低于图；而图如果画成图片文件，改一次要重画一次，很快就会与代码脱节。

## 决策

1. 章节 JSON 的 sections 支持 `role: "diagram"`，带 `diagram` 字段（Mermaid 源码），
   壳渲染成图；渲染失败时显示源码——图挂了要能看见图是怎么写的。
2. 按描述对象选图，不为画图而画图：
   - 相位流转 → 状态机图（第 6 章）；
   - 模块边界 → 分层 flowchart，main 呈现层 / logic.hh 规则层（第 8 章）；
   - 构建依赖 → 目标与链接图，测试不链 raylib 用虚线表达（第 9 章）；
   - 数据流 → 键盘到蛇身（第 4 章）、一帧之内的全景（第 10 章）；
   - 应用总览 → README 的全局结构图（GitHub 可渲染，面向打开仓库的人）。
3. 接口不用类图：logic.hh 的接口就是头文件本身，讲解用文字与调用样例承担。
4. 「为什么这样分」仍由 ADR 承担；图只回答「是什么」。

## 后果

`package.json` 引入 mermaid（前端体积变大，本地应用可接受）；`check.py` 校验 diagram
块有合法图源；写图时同一章仍只讲一个主题，图是讲解的浓缩不是替代。
