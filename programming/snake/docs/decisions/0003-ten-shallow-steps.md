# ADR 0003：十级台阶——控制章间的难度跳跃

- 日期：2026-10-12
- 状态：已接受（使用者 2026-10-12：「按照明确的阶段，一步一个台阶，不要章节间跨度太大太高，循序渐进，控制难度跳跃程度」）
- 关系：修订 [0002](0002-eight-evolutionary-chapters.md) 的八章切分；演化的显式化不变

## 背景

八章里有两处台阶过陡：第二章到第三章一口气引入队列、方向枚举、输入缓冲、函数分解
四件事；规则出窗到完成版之间捆着插值和音频合成两个硬概念。更重要的是，输入缓冲在
八章版里是从天而降的正确答案——它本该是一个 bug 逼出来的发明。

## 决策

1. 十章，每章一次只上一个台阶：
   1. 窗口与循环；2. 格子与节拍；3. 蛇身（方向直接改写，**折叠 bug 有意留在这章**）；
   4. 输入缓冲（为第三章的 bug 而发明的机制）；5. 食物与变长（自吃成为死法）；
   6. 状态机（收编凑合重开）；7. 计分与最高分；8. 规则出窗（logic.hh）；
   9. 测试（tests/、断言、CTest，作为独立的一步）；10. 手感（插值、声音、加速）。
2. 「bug 先被看见，再被发明出来的机制修掉」是新的台阶形态：第三章的折叠 bug 和
   第四章的缓冲是一对，出题与解题分开两章。
3. 第八章只搬运不改行为且不带测试；第九章的程序与第八章逐行相同，差别全在 tests/——
   「测试作为规则的第一个客户」单独一步。第十章才改行为（加速）并加呈现（插值、声音）。
4. 目标名 `snake-01` … `snake-10`；第 9、10 章各带 `logic-test` 目标。

## 后果

`check.py` 与壳白名单各十项；`--native` 编十章、跑两份规则测试。台阶仍不设上限：
再往后长出新阶段（AI 对手、道具、资源管线），按同一判据插章或续章，插章时后面
章节的编号顺延。
