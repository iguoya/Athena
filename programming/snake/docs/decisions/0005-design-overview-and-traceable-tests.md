# ADR 0005：设计总览与可追溯的测试——补写成品的设计，不走重型两篇体例

- 日期：2026-10-12
- 状态：已接受（使用者 2026-10-12：「按修正后的方案来，先写 ADR 0005；一篇设计总览 + 补测试 + 追溯表」）
- 关系：补充 [0001](0001-independent-raylib-chapters.md)、[0003](0003-ten-shallow-steps.md)，不改十章的结构与 id；不改变 [0004](0004-mermaid-diagrams-in-lessons.md)

## 背景

十章是演化教学：每章回答「怎么长出来的」。没有任何一处回答「长成了什么样、为什么是
这样、怎么确认它确实是这样」。这三件事正是软件工程里设计文档的职责。

曾考虑按 GB/T 8567 的体例补一篇概要设计说明书加一篇详细设计说明书。对一个单人维护的
教学项目偏重，而且详细设计里的函数契约、边界用例，在现行主流做法里由类型、头文件和
测试承担——写进文档最容易过期，写进测试则会被机器每次拦住。

## 决策

1. **性质是回溯性的成品设计（as-built）**，对象是第 10 章成品（`logic.hh` + `main.cc`
   + `tests/` + CMake）。它不是教学大纲，不据此反推该教什么（仓库 ADR 0028：三层方向
   自上而下）；文档开头写明这一点，并说明与十章的关系：十章讲演化，总览讲成品。
2. **一篇设计总览**：`docs/design/overview.md`。内容：目标与非目标、需求与质量属性
   （带编号）、架构（上下文 + 分层 + 模块职责含「不负责什么」）、运行时视图（一帧、相位）、
   数据与不变式、接口、构建视图、关键设计决策（链到 ADR）、已知问题、追溯矩阵。
3. **不写独立的详细设计说明书**。其内容分配：函数契约 → `logic.hh` 与测试；边界用例 →
   测试；不变式、状态转移、算法里不显然的部分 → 总览对应小节。
4. **需求与质量属性编号**（`FR-n`、`NFR-n`），**追溯矩阵**列出：需求 → 承担模块 → 验证
   方式（`测试` / `人工` / `未覆盖`）→ 证据位置。「未覆盖」如实写，不隐藏。
5. **补测试**：新增 `exercise/10-polish/tests/rules_test.cc`，目标 `snake-10-rules-test`
   （CTest 名 `snake-rules`），不链接 raylib。
   - 不动 `logic_test.cc` 的断言——第九章到第十章「只多一条加速断言」的讲法保持成立；
     只在其注释里加 `@covers` 标记。
   - 用自带的 `CHECK` 宏，不用 `assert`：Release 构建会定义 `NDEBUG`，`assert` 整个消失，
     测试就成了空壳。
   - 含一条固定种子的随机游走，每步检查不变式。
   - 只补第 10 章；第 9 章不动。
6. **测试里用 `@covers <ID>` 标注**它验证哪条需求。`scripts/check.py` 新增静态的设计文档
   检查（不编译，默认就跑）：
   - 总览存在；
   - 矩阵里验证方式为「测试」的 ID，`tests/` 下必须有对应 `@covers`；
   - 测试里出现的 `@covers` ID 必须在矩阵里存在；
   - 接口表列出的函数名必须在 `logic.hh` 中出现；
   - `logic.hh` 与 `tests/` 不得含 `raylib`（NFR-1 的机械守卫）。
7. **写设计文档时发现的缺陷，先修代码和教学内容，再写文档**（使用者 2026-10-12）。
   总览描述的是修好之后的成品，「已知问题」小节只留确实没修的限制。修复要同步改讲解与
   题目里引用到的写法，不留下教学内容与代码不一致。
   「头进入当前尾格判死」是现行行为而不是缺陷，记为设计决策并用测试钉住。
8. **教程里加「设计篇」导读**：正本是 Markdown（决策 2），教程里是以它为蓝本的教学化
   导读，用现有的讲解块与图块，不新增块类型。导读新开 id，不占用、不改嫁十章的 id。
   导读只做第 10 章成品这一套，不给十章各加「本章设计增量」。

## 后果

- 改规则或接口时要同步总览与矩阵；漂移会被 `check.py` 拦住。
- 十章的 id、题目、讲解的主旨不变；新内容不占用任何已有 id。修复缺陷牵动的局部文字除外。
- 总览的 Markdown 是正本；导读与正本冲突时以正本为准，并回头改导读。
- 壳不渲染 Markdown 正本，开发者在仓库里读它。
