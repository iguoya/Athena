# ADR 0001：每章一个窗口，章与章不抽公共库，学习者改工作副本

- 日期：2026-10-18
- 状态：已接受（使用者 2026-10-18：「模仿中国象棋应用的方式」；「象棋同款：Tauri 壳 + gtkmm 章节」）
- 关系：立项见仓库 ADR 0169。做法借自 `programming/chinese-chess` 的应用 ADR 0001、0002、0003，其中「每章两个窗口」不借，理由见下

## 背景

要做的是一个能解任意状态的二阶魔方程序，同时用它讲层先法怎样一步步变成程序。窗口上的控件、魔方的两个视图、求解和回放，都在程序里。若画在教程网页里，讲解和能玩的程序就缠在一起，某一章无法单独打开。

象棋那边每章做两个窗口（界面文件版和代码版），是因为它要教「界面文件和代码搭窗口」这件事本身。魔方不教这个：窗口是壳，教的是魔方的状态、转动和求解。再做一套代码版窗口只会让维护量翻倍，没有对照的价值。

## 决策

1. `exercise/` 下七章，每章一个 Meson 工程、**一个窗口**，包含自己的源码和 glib 垫片。不抽共享库。后一章是前一章长出来的样子，源码另写一份。
2. 控件树写在 `ui/window.blp`，颜色写在 `ui/style.css`。Blueprint 编成 GtkBuilder 的界面，打进该程序的资源。C++ 只创建 `Application`、装上样式、把自绘的魔方视图放进空位，并把控件交给 `Session`。魔方的绘制、转动、求解都不进界面文件。
3. 每章带一个不依赖 GTK 的测试可执行文件 `cube-test`：模型、转动的性质、求解、距离表都在这里验证。默认的 `scripts/check.py` 不编译 gtkmm，`--native` 才编译并跑测试。
4. 教程壳只按章节 id 白名单调用 `meson` 并启动对应可执行文件，不接受任意路径。
5. 学习者要改某一章，壳把它复制到 `workspace/<章>/`（已有副本则不覆盖，跳过 `build/`），用 VS 2022 打开副本；运行按钮在有副本时编译副本；「还原」删掉副本。`exercise/` 是课程原件，`workspace/` 不进版本库。

## 后果

- 七章七份 `cube.cc`、`view.cc`、`session.cc` 有意重复：合并成一个库会让「这一章当时只有这些代码」讲不清楚。代价是改一处缺陷要看七份里哪几份带着它，`AGENTS.md` 已写明。
- 魔方模型的两份实现（C++ 与网页）的一致性靠黄金向量守住，见本应用 ADR 0002。
