# ADR 0002：转动从三维坐标推出；C++ 与网页各一份模型，用黄金向量对齐

- 日期：2026-10-18
- 状态：已接受
- 关系：立项见仓库 ADR 0169；每章源码重复的理由见本应用 ADR 0001

## 背景

旧版 `practice/pocket_cube` 也是从三维坐标推出转动的，但注释里有一句：R、F 两个面的顺时针/逆时针文字「调换过」，因为画面观感和标准定义对不上。这说明方向和手性一旦靠「看着对」去调，后面所有结论都建在不确定的地基上。

新应用要在两个地方画魔方：gtkmm 窗口（C++）和教程页里的回放图（TypeScript）。两处都需要一份转动模型。

## 决策

1. **转动从几何推出，不手写置换表。** 24 张贴纸各有所在角块的中心坐标（分量 ±1）和朝外方向。转一个面，是把这一层里的贴纸的位置和朝向绕轴顺时针转 90°（从轴的尖端往原点看，`v' = a(a·v) − a×v`）。置换表在程序启动时算出。
2. **方向和手性用测试断言，不靠画面。** 测试断言：R 把前面一列翻到顶上，U 把前面转到左边，F 把顶上转到右边；转四次回到原样；`(R U R' U')⁶ = 1`；只转 U、R、F 时 DBL 不动；配色里红、白、蓝绕 DBL 角块顺时针（维基百科 Rubik's Cube 的标准配色）。
3. **贴纸颜色号 = 它在复原态属于的面号**，面的顺序 U R F D L B，每面 4 格按展开图从左到右、从上到下。姿势是白下绿前。
4. **两份实现**：C++（每章 `cube.cc`）和 TypeScript（`src/cube.ts`）。一致性靠 `scripts/cube_golden.json` 里的黄金向量（11 条，含 D、L、B 面和长转法，由 C++ 模型生成）：C++ 在 `cube_test.cc` 里逐字断言，TypeScript 在 `scripts/check_model.ts` 里断言，`scripts/check.py` 默认就跑后者。讲解内容里的每张回放图另由 `scripts/check_content_cubes.ts` 核对记号和 `expect`。

## 后果

- 改模型要两边一起改，并重新生成黄金向量。
- 黄金向量由 C++ 生成，所以它们守的是「两份实现一致」，守不住「模型本身正确」；后者靠第 2 条的独立断言。
