# ADR 0002：每一章两个窗口，教程以界面文件为主

- 日期：2026-10-12
- 状态：已接受（使用者 2026-10-12 确认两套都要能跑、自己对照；同日补充：独立布局更有前途，教程里重点讲这一套）
- 关系：修订 [0001](0001-independent-gtkmm-chapters.md) 的「每章一个程序」。章与章仍不共用库。仓库 ADR 0151 不动。

## 背景

窗口上的按钮、侧栏、标题可以用 C++ 一个个 `append` 出来，也可以写成独立的界面文件。后一种把「有哪些控件、怎么排、什么颜色」从走子和绘制里分开。使用者要两套都能打开，用来对照；并认定界面文件这条路更值得学，教程不能把两套写成同等篇幅。

## 决策

1. 每一章仍是一个 Meson 工程、一个目录，里面两个可执行文件：`chess-NN-ui` 与 `chess-NN-code`。
2. **界面文件版是教程的主路径。** 控件树写在 `ui/window.blp`，颜色写在 `ui/style.css`。Blueprint 编成 GtkBuilder 的界面，打进该程序的资源。C++ 只创建 `Application`、装上样式、把自绘棋盘放进名为 `board_slot` 的空位，并接按钮信号。
3. **代码版用来对照，不作为主讲。** 同一布局写在 `code/main.cc`，样式是一段 C++ 字符串。它不读 `.blp`。
4. 棋盘绘制和走子规则不进界面文件。第 3 章起，两个程序编译同一份 `BoardView`。第 5 章再编译同一份 `Position` 和 `Session`：点选、记谱、悔棋、新局只有一份，避免两套窗口各写各的规则。
5. 章与章仍然不链接。后一章不随前一章自动更新。
6. 教程先展示界面文件和它为什么这样拆，再放一节较短的代码对照。讲解打开就能读。题目只考讲解里已经写出的重点、要点、难点、考点。两个运行按钮始终可用，界面文件版放在前面。

## 后果

五章十个程序。改某一章的布局要同时改那一章的 `.blp` 和 `code/main.cc`，规则只改 `05-move` 的 `Position`。教程壳的白名单认 `01-window/ui` 这种 id，不接受任意路径。
