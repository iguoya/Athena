# 核对点写作须知

习题的「核对点」是手写的、可机器判的最终答案：学习者先作答，系统判对错，再展开原书解答。写好它是「练习有反馈」的关键，
也是本应用最费功夫的部分——**答案必须经过独立计算复核**，不能照抄原书解答（原书解答偶有笔误）。

## 你领到什么

几节的习题。对每道题决定：能不能给一个**可机器判的最终答案**。

| 题型 | 怎么做 |
|---|---|
| 答案是一个数、一组数、向量、矩阵（按行展开成数列）、个数（秩、维数、解的个数）、行列式值、特征值 | `numbers` |
| 判断题、「下面哪个对」、分类（线性相关/无关、可逆/不可逆、有无解/唯一解/无穷多解） | `choice` |
| 要写证明、要写出文字解释、解集带参数（答案不唯一的写法）、画图 | **不写核对点**，跳过 |

覆盖要务实：能写的写，勉强的不写。宁可少一些，也不要写一个会误判对错的核对点。多问自己一句：**学习者算对了但写法不同，会不会被判错？**
（例：「解为 $(1,0)$」用 `numbers` `[1, 0]`，学习者写 `1, 0` 或 `(1,0)` 都认。带参数的通解就别做 `numbers`。）

## 文件格式

`content/checks/<节 id>.json`，键是习题 id（`ex1`、`ex2`……，与快照里 `exercises[].id` 一致）：

```json
{
  "ex2": {
    "kind": "numbers",
    "ask": "求出交点 $(x,y)$，依次写出 $x$、$y$。",
    "answer": [0.7692307692307693, 0.07692307692307693],
    "hint": "把两个方程联立，用代入或消元；先化到一个未知数。"
  },
  "ex5": {
    "kind": "choice",
    "ask": "这三个平面有公共点吗？",
    "options": [
      {"text": "没有公共点", "ok": true, "why": "消元后出现 $0=1$，方程组不相容。"},
      {"text": "恰有一个公共点", "why": "唯一解要求主元列数等于未知数个数，这里不是。"},
      {"text": "有无穷多个公共点", "why": "有无穷多解要求方程组相容，而这里不相容。"}
    ]
  }
}
```

- `ask`（numbers 必填）：用中文说清**答案写成什么形式**——写几个数、按什么顺序（矩阵按行）。公式用 `$…$`。
- `answer`：数字数组（小数用 Python 的 float 全精度，如 `10/13` 写成 `0.7692307692307693`）。含根号等无理数也写 float。
- `hint`：答错时显示，只说**该回头复习什么或怎么下手**，**不能泄露答案**。
- `choice`：≥ 2 个选项，**恰好一个** `ok: true`，**每个**选项都有 `why`（对的说为什么对，错的说常见的错误想法为什么不成立）。
  选项要有迷惑性（对应真实的误解），不要凑数。选项顺序别总把正确项放第一个。

## 复核（必须）

用仓库里带 SymPy 的 Python 独立重算每个 `answer`，并与原书解答（快照里的 `sol`）对照：

```sh
/home/user/Athena/postgraduate/mathematics/engine/.venv/bin/python your_script.py
```

- 你算的和原书解答一致 → 入库。
- 不一致 → **先确认自己没算错**；确认是原书笔误的话不要写这道题的核对点，并在汇报里写明题号与你的结果。
- 题目表述有歧义的也不写，汇报里说明。

## 校验与汇报

写完用 `python3 scripts/lint_checks.py <节 id> ...` 检查结构（只检查结构，答案对不对靠你的复核）。
只改 `content/checks/` 下属于你这几节的文件，不要碰别的文件，不运行 git / sync_upstream.py / check.py。

最后汇报：每节写了几道、跳过几道及原因（一句话）、发现的原书疑似笔误。
