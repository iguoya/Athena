# ADR 0005：翻译单元以官网 PO 翻译单元为准，词数聚合只作兜底

- 日期：2026-10-07
- 状态：已接受
- 延续：应用 ADR 0002（官方教程全量翻译是内容基准）、0004（自译分层）；
  主仓库 ADR 0043（内容必须有出处）

## 背景

阅读单元（一次「显示译文」「看懂了」的范围）此前按词数估算：连续短段
聚合到 50–200 词为一组。这个口径与官网 PO 的翻译单元（msgid）无关，而
贡献上游（ADR 0004 的目标）必须以 msgid 为准——export_contribution.py
的逐段指纹匹配在「官网把连续几段合并成一条单元」时对不上，译文挂不上
（apply_po.py 整条 msgid 指纹 ↔ 单段指纹）、导出覆盖不了。

实测：Damned Lies 的 reference.zh_CN.po 里正常条目基本是单段单元
（1322/1405 段可单段精确对齐）；存在少量脏条目（msgid 混入重复英文与
中文译文），对不上是正确行为。

## 决策

1. **对齐是构建期产物**：`scripts/align_po.py` 把每节快照的连续文字段
   做成「区间拼接指纹」（连续 1..n 段的 snapshot_plain 以空格连接），
   逐条 PO msgid 精确匹配；产出 `content/po-units/<章>.json`
   （单元 = 段落 sha 列表 + 整条官方译文，id 锚定首段 sha）。
   sync_upstream.py 之后重跑即可；应用运行时对内容层只读（ADR 0004）。

2. **显示、自评、自译同口径**：PageView 优先按映射分组阅读单元；
   多段单元的译文整条呈现（不拆挂到段、不做逐句交错），段级不再显示
   「此段待译」；自译存储键 = 单元首段 sha（与「看懂了」的 unitSha
   同口径），单段单元与既有段级数据自然兼容。多段单元的官方译文若
   上游本身缺失，单元尾部给「✍️ 自己译」，写整条。

3. **词数聚合只作兜底**：未对齐的段（上游模板没有的条目、脏条目、
   映射过期）沿用词数聚合，设置项「翻译单元划分」只影响这部分。

4. **导出走同一对齐**：export_contribution.py 以单元指纹（各段拼接）
   匹配 msgid——我们的译文 = 单元自译优先，否则各段 zh 拼接
   （须全段有译文，残缺不猜）；未对齐段回退单段指纹。

## 后果

- 应用内的阅读/翻译粒度与将来提交给上游的 PO 条目一一对应，自译
  可直接按 msgid 进贡献文件，不再受「单元 ≠ 段落」的指纹损耗。
- 多段单元不再有段级译文：句级英中交错（sentenceMode）只对单段单元
  生效，多段单元整条显示——句对齐没有可靠依据，不猜。
- 「看懂了」的粒度随分组变化：已按旧词数分组作答的记录部分失效，
  需要重新点一次（进度库是作答流水，无迁移价值）。
- PO 模板更新（Damned Lies 重新导出）后需重跑 align_po.py 刷新映射；
  映射过期时单元分组自动降级为兜底聚合，不崩溃。
