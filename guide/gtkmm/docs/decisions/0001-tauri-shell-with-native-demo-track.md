# ADR 0001：Tauri 文档壳 + 原生演示/实验双轨架构

- 日期：2026-10-06
- 状态：已接受；应用骨架与内容工程按此搭建
- 延续：主仓库 ADR 0032（独立应用）、0046（dev 编排）、0053（进度随仓库）、0056（可视化即内容）、0058（内容驱动 UI）、0059（骨架实验）、0062（约束不继承）

## 背景

自学 gtkmm 的现实痛点：网上实验代码零散、互不关联、实验目的不明，讲解文档与
可运行的示例程序彼此分离。本应用以**理论文档为主体、实践是理论的具象化演示**
为定位（理论引导实践，不是相反），把讲解、交互模拟、真机演示、可编辑实验
统一在一个软件里。

选型过程中排除的路线（记录取舍，避免重提）：

- **纯 gtkmm 单体**（文档与实验同为 GTK）：所见即所学，但富文本文档、代码高亮、
  交互动画的开发效率比 Web 低一个数量级，与「文档为主」的定位相反。
- **GTK 窗口嵌 WebKitGTK 显示文档**：WebKitGTK 在 Windows 上没有可靠支持，
  与平台优先级（macOS ≈ Windows > Linux，主仓库 ADR 0051）冲突。
- **Electron / 纯 Web + 伴生服务**：可行备选；前者体积大，后者「一个软件」的
  整合感打折。仓库内 Tauri 已是主流轨道（dsa、english、mathematics、math-tools、
  拾阶五个在产应用），选 Tauri 是加入已有轨道而非引入新技术。
- **演示脚本化（PyGObject 等）**：教学目标是 C++ API，演示源码本身就是教材，
  双语言会产生两份代码漂移。

## 决策

1. **定位与标识**：学习应用；GTK4-only（`gtkmm-4.0`，Windows 走 MSYS2 工具链）；
   目录 `subjects/gtkmm`，进程 `athena-gtkmm`，知识点 ID 前缀 `gtkmm.`；进度写
   `progress/learning.db` 随仓库走（主仓库 ADR 0037、0053）。

2. **壳与前端**：Tauri 2（Rust 主进程）+ Vite + React + TypeScript + Tailwind +
   motion（参照拾阶的已验证体系）。文档是应用主体，用有限块类型组件承载
   （主仓库 ADR 0058）；壳要薄，Rust 侧只管路径、进程、进度与协议转发，
   业务文案与课树不进 Rust。

3. **双轨呈现与强制配对**：理论模型用 **Web 交互模拟**呈现（SVG/组件画布局
   分配、信号流动等 GTK 内部规则），每个模拟块必须在 `content/demos.json`
   清单里登记对应的**真机演示** id——没有真机锚定的模拟不上线。模拟讲理论、
   演示锚定真实；模拟的行为以 GTK C 文档为语义基准校准（见 ADR 0002），
   简化处在界面上标明。这是 dsa「前端不重写一份算法真相」原则在本应用的
   对应答案：前端必然重写模型，所以强制可验证的锚。

4. **原生侧工程形态**：每个演示与实验是**独立的 CMake 工程**（`CMakeLists.txt` +
   `src/main.cpp`），工程模板本身是教材——学习者从第一天看到真实 GTK 项目
   结构。骨架只读，首次打开复制到独立工作区，学习者改副本、编译副本，
   可一键重置；学习产物不进 `content/`。

5. **协议**：壳与原生进程之间用 **JSON-RPC 2.0 over stdio**（NDJSON 行分隔，
   stdout 上行、stdin 下行、stderr 日志）。消息集：
   - 壳→演示请求：`initialize`（demo_id、protocol_version、工作区路径，返回能力集）、
     `shutdown`、`ping`；
   - 演示→壳通知：`ready`、`state`（内部状态摘要）、`signal`（控件 id、信号名、
     时间戳，供文档联动与观察题）、`log`；
   - `--self-check` 模式：构造界面、自答 `initialize` 后退出 0，供 check 全量验证。
   第一版壳按清单直接 spawn 演示进程；**常驻演示宿主**（单窗口 GtkStack 切换）
   是后续增量——协议与清单按宿主形态设计，收编时壳代码不动。

6. **清单是唯一事实源**：`content/demos.json` 收录全部演示与实验实体：
   - `demos[]`：`id`、`title`、`purpose`（演示目的）、`theory_refs[]`（对应理论点）、
     `source_dir`、`build_target`、`translation_ref`（教程章节锚）、`source_refs[]`；
   - `experiments[]`：同上加 `skeleton_dir`、`acceptance`（跑通标准）。
   `content/curriculum.json` 的教学块只引用 id。壳、`scripts/check.py`、将来的
   宿主三方直接读清单，不解析整份课表；课程重排不影响演示实体。
   演示粒度：一理论点一演示，目标 ≤150 行、可通读，演示源码即教材。

7. **掌握度与作答**：随堂选择题、章末 checkpoint，外加**演示观察题**（观察真机
   演示后作答，出处即演示条目）。掌握度只由作答写入（主仓库 ADR 0052）；
   判分内容必须有出处（主仓库 ADR 0043）。

## 后果

- 壳与内容之间是「清单 + 协议」两个不变量，进程形态（spawn → 宿主）是可演进
  的变量；换壳（Electron 等）也不触及这两个不变量。
- 代价：Rust 与 C++ 双工具链并存，Windows 上要养 MSYS2 GTK4 运行时，分发
  体积不小——开发期直接用 MSYS2 环境，打包是独立阶段的事。
- 模拟失真风险由三条纪律共同压制：强制配对、语义基准（ADR 0002）、界面标注
  简化处。
- 演示源码 ≤150 行的目标使「演示即活教材」成立：读完文档即可通读演示源码。
