# 译员须知（并行翻译用）

本应用的译文是逐段手写的（原文不手写，由 `scripts/sync_upstream.py` 从上游生成）。你会领到一页或几页，只改这几页的快照，不碰别的。

## 先读

1. `AGENTS.md` 的「内容规则」；2. `docs/GLOSSARY.md`；3. 如果该页已译了一部分，看已译单元的语气。

## 流程（每一页各走一遍）

```sh
cd guide/octave-manual
python3 scripts/tr.py export <页 id> > /tmp/ex-<页 id>.json     # 待译单元 [{"sha","en"}]
# 写译文到 /tmp/tr-<页 id>.txt：每条一行 `@@ <sha>`，下一行起是译文
python3 scripts/tr.py import <页 id> /tmp/tr-<页 id>.txt        # 校验并写回
```

`import` 会拒绝有问题的条目并写明原因；改好重导，直到「拒绝 0 条、还剩 0 个单元未译」。**先 export 对应页再翻译**：sha 属于具体的页。
页较大时分几批写、分几个译文文件，但只 export 一次。

## 译文要求

- **公式 `$…$` 与行内代码 `` `…` `` 逐字符不动**，数量与内容必须与原文一致（导入时校验）。代码里的函数名、选项字符串、变量名不翻译。
  只能改公式和代码之外的文字。**原文里斜体的变量名（如 `*A*`、`*tol*`）保持斜体标记与英文字母不动。**
- 单元里的 `**粗体**`、`*斜体*` 标记保留。函数签名与示例代码块不在可译单元里，你看不到也不用管。
- 一个单元是一段话、一个标题、一个定义列表的条目名（如 `` `"balance"` (default) ``）或表格的一格；条目名里的代码原样，只译「(default)」之类的文字。
- **忠实、通俗易懂**：面向想用 Octave 学线代与高数的读者；不省略条件，不改变含义；术语按 GLOSSARY，GLOSSARY 没有的词查国内通行译法，
  **不要自己改 GLOSSARY**，在汇报里列出。
- 不用「显然」「容易看出」「不难证明」「易知」「众所周知」等把难度推给读者的词（检查会拦）。
- 中文标点全角，粗体/斜体标记与相邻中文之间不加空格。
- 上游文本里偶有笔误或过时说法：照译，不纠正；发现了在汇报里写明位置。对被裁掉章节的引用（如「另见：`eigs`」）照译。

## 汇报

只汇报：翻译了哪几页、多少单元；是否每页都「拒绝 0、剩余 0」；GLOSSARY 之外你定的新术语；发现的上游笔误。
不要改任何别的文件，不运行 git、`sync_upstream.py`、`check.py`。
