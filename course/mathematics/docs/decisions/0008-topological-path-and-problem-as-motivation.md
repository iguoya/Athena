# ADR 0008：学习路径按先修图拓扑序；现实问题作为引入动机而非课后应用

- 日期：2026-09-13
- 状态：已接受
- 依赖：ADR 0003（建模独立成线）、0005（动机先于定义）、0007（先做数学二）

## 背景

使用者要求：**先易后难、循序渐进**，并且尽量把数学学习过程与现实世界的认识
关联起来，**而不是人为割裂**。

### 1. 数学一与数学二的难度差异（影响策略，故记录）

**数学一是广度难，数学二是深度难。**

| | 数学一 | 数学二 |
|---|---|---|
| 范围 | 大得多（多概率统计整科、无穷级数、空间解析几何、三重积分与曲线曲面积分） | 小 |
| 高数分值占比 | 约 56% | 约 **78%** |
| 单点深度 | 覆盖面要求高，单考点挖得浅 | **一元微积分挖得更深，计算量更大** |

结论：选数学二省下的是**范围**，不是难度。一元函数微积分必须按最高标准准备，
不可因为「数学二简单」而降低要求。

### 2. 「先易后难」与「自然顺序」有时冲突

ADR 0005 定了发生学顺序（动机先于定义）。它与「先易后难」多数时候一致，
但不总是：

- 一致的例子：ε-δ 难且抽象，两条规则都把它推后（先用「无限接近」做事，碰壁后
  再精确化）。
- **冲突的例子**：多元函数微分学在教材里排在一元之后，因为「更难」。但现实问题
  天然是多变量的（优化、拟合、多因素影响），一元反而是人为简化。严格按「先易后难」
  会把所有现实关联推迟很久。

需要一个调和机制，否则两条规则会在编写时互相拉扯。

### 3. 割裂的典型形态：先学完工具，再谈应用

教材通行做法是「学完极限学导数，学完导数学积分，全部学完才谈一句应用」。
等学到应用时，当初的动机早已遗忘。

**ADR 0003 的建模线有退化成这种割裂的风险**：如果主线只管学工具、建模线只管
谈应用，那只是把割裂从「前后」改成了「左右」，本质没变。

## 决策

### 1. 路径由先修图的拓扑序决定，不由教材章节序决定

知识点之间用 `requires` 声明先修（对齐主仓库 ADR 0030）。学习路径是这张有向图
的**拓扑序**，不是任何教材的目录顺序。

这同时满足两条要求：

- **循序渐进有保证**：依赖关系保证该先学的一定先学；
- **不人为割裂**：依赖图是网状的，它显式呈现「这个知识点支撑了后面哪些」，
  天然反对把知识切成互不相关的章节（呼应 ADR 0004 第 3 节的统一视角）。

**`difficulty` 与路径顺序是两回事**：`difficulty` 是单点难度，顺序由 `requires`
决定。一个 `difficulty: 1` 的知识点若依赖 `difficulty: 3` 的内容，照样排在后面。

### 2. 拓扑序有多个合法解时，选更早连上现实的分支

一张依赖图通常有许多合法的拓扑序。在合法解之间做选择时，**优先展开能更早接上
现实问题的分支**，而不是教材惯例的分支。

这就是第 2 节冲突的调和办法：不违反依赖（仍然循序渐进），但在自由度内向现实
倾斜。

### 3. 现实问题作为引入动机，不是学完之后的应用练习

**这是本 ADR 最重要的一条。** ADR 0003 的建模线与主线**在时间上交织**，不是
并行两条轨。

具体要求：

- 主线知识点的**引入**优先使用现实问题，而不是数学内部的问题。
  这是 ADR 0005 第 1 节「动机先于定义」的加强版：动机不仅要有，还要**优先来自
  现实**。
- 建模线的问题**在需要某个工具的前一刻出现**，让工具作为解决它的产物登场。
- **禁止**把现实应用统一堆到章末或单独的「应用」章节——那正是第 3 节描述的割裂。

| 知识点 | 错误做法 | 本 ADR 要求的做法 |
|---|---|---|
| 导数 | 先讲差商极限，章末举一个速度例子 | 从「瞬时速度到底是什么」入手，导数作为回答登场 |
| 微分方程 | 先讲解法分类，最后一节「应用举例」 | 从冷却、复利或传染病早期增长入手，方程是描述它的产物 |
| 线性方程组 | 先讲消元步骤，后面某处提一句现实 | 从一组实际约束出发，消元是解它的手段 |

### 4. 起点选择：二维线性变换的可视化

按第 2 节的原则，结合 ADR 0007 第 5 节（线代零返工）与 ADR 0004 第 3 节
（线代按线性变换组织），**第一章从二维线性变换入手**：

拖动一个 2×2 矩阵的四个数，实时看平面怎么被拉伸、旋转、压扁、翻转。

选它作为起点的理由：

1. **易**：不需要任何先修，看得见；
2. **现实关联即刻成立**：图像变换、坐标系转换就是它本身；
3. **一次铺垫全线代**：行列式＝面积伸缩比（带定向）、特征向量＝方向不变的那些
   方向、秩＝被压到几维——后面每一章都是回到这张图上追问一个新问题；
4. **技术上最省**：2D Canvas 即可，不依赖 ADR 0001 的符号引擎，可作为整套内容
   形态的首个验证样本。

高数起点另行决定；但**不以「函数、极限、连续」开局**——它是公认的难开头且现实
关联弱，按第 1、2 节应当推后到需要精确化时再登场（ADR 0005 第 4 节）。

## 后果

- `content/curriculum.json` 必须支持 `requires`，且需要一个环检测与拓扑排序的
  构建期校验，否则依赖写错会导致路径不可解。
- 第 3 节会显著提高编写难度：作者必须为每个主线知识点找到一个**真实且恰当**的
  引入问题，找不到时不得用伪应用题凑数（ADR 0003 第 2 节已禁止）。找不到的，
  说明该知识点可能本就属于应试区。
- 第 4 节的起点选择使首章不依赖符号引擎，**符号引擎的实现可以推后**，先验证内容
  形态与可视化交互。
- 拓扑序允许多解意味着路径不唯一，UI 需要能呈现「当前可学的知识点有哪几个」
  而不是一条写死的线性目录。
