# ADR 0001：导读合一；编写章节与大纲须充分使用可视与多媒体

- 日期：2026-09-12
- 状态：已接受；前端标签已合并为「导读」，写作规范即时生效
- 精神对齐：主仓库 ADR 0027（多媒体教案）、0028（三层分工）、0033（活的可视化）、
  0039（撤销单独「本章导览」）；本应用载体为 Web UI，不照搬 GTK 约束

## 背景

DSA 学习页曾并列「本章导览」与「教学大纲」。对单知识点工具章（如「复杂度度量」）
二者高度重复：导览是大纲的缩写，维护两份必然漂移——主仓库 ADR 0039 已因此撤销
导览标签。本应用同样采纳「一份导读」。

另一面：数据结构与算法的概念（增长形态、内存布局、指针改接、遍历顺序、状态转移）
天然适合图与可交互演示。若编写章节与大纲时默认堆长文，自学路径会退化成「读说明
再进实验」，浪费 Web 壳能承载的 SVG、对照表、步进示意、实验观察区等手段。

## 决策

### 1. 标签：导览并入导读，不再单开

知识点页标签顺序为：

1. **导读**（原导览主旨 + 原大纲五段，一份内容）
2. **讲解**（落实细节与教学动作）
3. **实验**（`labs[]` 工作台）

导读内部顺序固定为「先地图后理由」：本节在全课/本章的位置与掌握目标 →
`outline` 的痛点、模型、边界、判断、落点。不另维护缩写副本。

### 2. 编写章节与大纲时：可视与多媒体是默认手段，不是装饰

写 `curriculum.json` 的章节摘要、`outline`、`lesson.blocks`、以及日后导读内嵌的
示意时，遵守：

1. **先问媒介，再写长段。** 关系、分类、流程、状态变化、时空权衡——优先图、表、
   对照卡、可点击示意或短动画；正文只补「为什么」和判据。能一句话说清的不硬画图
   （对齐主仓库 ADR 0033「不为可视化而可视化」）。
2. **大纲层也要可视。** `outline` 不该只有六段纯文字：至少用结构化块表达模型与边界
   （例如正反例对照、量级锚点表、先修/去向示意）；能由课表数据算出的（`requires`、
   难度、掌握目标、熟练度）画成活的并允许点击跳转，不写成第二份清单。
3. **讲解层按知识类型选视觉动作**（ADR 0031 精神）：概念用并排正反例与边界图；
   技能用步骤条 + 变式指向实验；策略用情境卡。需要体感增长、布局、指针时，挂
   `labs[]` 或观察区，而不是用段落代替跑一遍。
4. **实验输出可被观察区消费。** 案例 `cout` 约定稳定字段（如 `key=value`），便于
   导读/讲解里预告的「你会看到什么」与观察区对照；示意动画不得冒充真实运行轨迹。
5. **媒介服务于自学闭环。** 预测 → 看图/跑实验 → 对照修正；动态过程应可暂停、逐步，
   停动效后仍能靠静态图 + 文字学下去。
6. **实现边界（本应用）。** 允许 SVG、CSS/Canvas/轻量前端动画、实验 stdout 驱动的
   观察区；不引入整页视频课或重型图表框架，除非另开 ADR。内容权威仍在
   `content/curriculum.json` 与 `content/cases/`。

### 3. 粒度提醒（与复杂度度量同类章）

工具型、记号共用的内容（如大 O + 时间 + 空间）保持**一个知识点 + 讲解内小节 +
多实验**，不为标签对称去拆「子章节独立讲解」。拆分判据是先修不同或掌握目标不同，
不是「又一个名词」。

## 后果

- 作者写大纲/讲解时必须主动设计视觉与实验挂钩；纯文字六段 outline 视为未完成。
- UI 少一个标签，导读略长，靠「地图在前」缓解扫读需求。
- 与主程序 ADR 0039 一致的是「不维护导览缩写」；本应用额外把**写作时的多媒体义务**
  写死，因 Web 壳比 GTK 更易落地示意与观察区。
