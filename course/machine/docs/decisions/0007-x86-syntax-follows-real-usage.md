# ADR 0007：x86-64 汇编语法不强制统一，按目标的实际用法并可切换（修订 ADR 0005 第 8 条的语法部分）

- 日期：2026-10-03
- 状态：已接受；修订 [ADR 0005](0005-machine-c-and-assembly-tracks.md) 第 8 条中「x86-64 统一用 Intel 语法」一句。
  0005 原文不改；第 8 条的其余部分（主线指令集、基准 ABI、汇编器统一为 GNU as）不变
- 依赖：ADR 0005、0006

## 背景

ADR 0005 第 8 条把 x86-64 统一定为 Intel 语法，理由是 `%` 与 `$` 前缀、源在前目标在后对初学者噪声大。

抓取来源时核实到的现实情况：

| 环境 | 实际用的语法 |
|---|---|
| Dive Into Systems 第 7 章（x86-64） | AT&T。页面原话：以 GCC 为例，所以讲 AT&T |
| Linux 上的 GCC、GDB、objdump | 默认 AT&T |
| Microsoft 文档、MASM、WinDbg、Intel SDM | Intel |

也就是说，学习者在 Linux 一侧读到的几乎都是 AT&T，在 Windows 一侧读到的几乎都是 Intel。强制统一成其中一种，
就等于让他在另一半现实里读不懂。使用者的决定：**取消这个强制要求，尊重实际现实使用。**

## 决策

1. **取消「统一 Intel」。** 本应用不规定唯一的 x86-64 汇编语法。ARM64 只有一种语法，不受影响。
2. **每个 x86-64 目标有自己的默认语法，取其环境的实际用法：**
   `sysv-x64` 默认 AT&T，`win-x64` 默认 Intel。
3. **观察层两种语法都生成，界面上可切换。** 预生成的汇编分别用 clang 的 `-masm=att`、`-masm=intel`
   产出；切换只改显示，不改内容（ADR 0006 第 1 条）。
4. **练习骨架用该目标的默认语法书写。** GNU as 能用 `.intel_syntax noprefix` 与 `.att_syntax`
   在同一个汇编器里汇编两种写法，所以汇编器仍统一为 GNU as（clang 的集成汇编器兼容），
   不引入 MASM、NASM。这是一个取舍：Windows 上现实里常见的是 MASM，但它与 GNU as 是两套工具链，
   本应用不教 MASM 语法。
5. **教案附一张 AT&T 与 Intel 的对照卡。** 内容：操作数顺序、寄存器与立即数前缀、内存寻址的写法、
   操作数宽度后缀。出处：GNU as 手册的 i386 语法页、Intel SDM、DIS 第 7 章。卡片待写。
6. **引用来源时不必转写。** DIS 是 AT&T、Intel SDM 与 Microsoft 文档是 Intel，`locator`
   里照原文的语法写即可。ADR 0005 第 8 条要求的「已转写」注明取消。

## 后果

- 预生成的汇编内容量翻倍，但是机器生成，几乎没有成本。
- 检查脚本在实现多目标实验台时，校验每个 x86-64 骨架在其默认语法下都能汇编（ADR 0006 第 6 条）。
- ADR 0005 在索引里的状态栏补「第 8 条语法部分由 0007 修订」。
- `scripts/fetch-sources.py` 里关于「已转写」的注释同步更新。
