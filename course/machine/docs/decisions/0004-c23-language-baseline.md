# ADR 0004：教程语义以 C23 为基准

- 日期：2026-09-14
- 状态：已接受
- 依赖：ADR 0002（章序跟开源教材）、ADR 0003（有所本）
- 对齐：主程序以 C++20 为语义基准（ADR 0028 第 2–3 条）
- 标准：ISO/IEC 9899:2024，俗称 **C23**（不是 C24；`iso9899:2024` 只是出版年号）

## 背景

ADR 0002 解决的是「按哪本公开教程排章」：Beej 给脊，DIS 给地址空间，
Modern C 核深度。ADR 0003 要求每节、每题对得上节号。还缺一条和主程序
对称的约束：三层讲法不一致时，以哪一份语言文本为准。

Beej 源稿里仍出现 C11 条款号，TODO 里写着 C23 未完成；c-faq 停在更早的
习惯用法；DIS 讲系统模型，不跟 ISO 版本走。若教案直接复述教材年代的说法，
会把已删除的保证、已替换的空指针写法、实现相关的宽度讲成现行规则。

现行已出版标准是 C23。下一版 C2y 仍是 WG14 草案（公开稿如 N3886），
不能当教材的对错标准。

## 决策

1. **语义基准是 C23（ISO/IEC 9899:2024）。** 大纲、教学过程、实验、随堂与
   课后题，条件和结论必须能在 C23 下成立。三层不一致时，先按 C23 核对，
   再改教案或实验，不得为迁就教材旧措辞或当前实现而改写标准。
2. **章序仍跟 ADR 0002，不按 C23 特性清单重排目录。** `nullptr`、`typeof`、
   `bool` 关键字、`auto` 出现在相关节里讲，不另开「C23 新特性」章。Beej
   的脊不变：内存与变量 → 指针 → 数组 → 字符串 → 结构体 → 动态分配。
3. **教材与标准冲突时，标准优先，两边都要引用。** `source_refs` 里教材给
   讲法与先修，`c23` 给条款。例如 Beej 写 `NULL`、C23 提供 `nullptr`：教案
   教 C23 的写法，并注明 `NULL` 仍是合法的空指针常量、常见于旧代码。
   不得把教材里过时的保证（或本机示意）写成 C23 的规则。
4. **不教 C2y。** 草案可作「下一版可能变成什么」的对照，题干和要害句不得
   依赖尚未出版的条款。实验与可运行示例默认 `-std=c23`（GNU 方言需要时用
   `-std=gnu23`）。
5. **本地对照用 WG14 公开稿 N3220。** 正式文本需向 ISO 购买，不进 git。
   N3220 与 C23 草案 N3219 几乎只差 Annex K 一条脚注，用来核条款号和用词。
   PDF 落在 `content/sources/reference/c23/`，gitignore；`fetch-sources.py`
   负责拉取。`catalog.json` 的 id 是 `c23`。

## 与已写内容的关系

已写成的两节（字节编址、指针存地址）在 C23 里仍然成立：对象有表示、
指针保存地址、多字节相邻、端序由实现决定。需要补的是引用条款，以及指针
章讲到空指针时改用 C23 的 `nullptr`，而不是把 Beej 的 `NULL` 当成唯一写法。

## 后果

- 写课顺序变成：打开对应教材节 → 用 N3220 / C23 核对该条在现行标准里是否
  仍真 → 写 QML 和题。只对得上 Beej、对不上 C23 的题不要写。
- Modern C、c-faq 继续当深度和误区来源；与 C23 不一致处在教案里点明年代。
- 编译实验若默认仍是 gnu17，不能拿输出去否定 C23 教案；要先标明所用 `-std`。
